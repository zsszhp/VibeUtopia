# Ralph 开发模式

> 源自 robot 项目，适配 VibeUtopia 的 AI 助手开发规范。
> 本规则优先级最高，AI 必须首先加载并遵循。

---

## 核心原则

### 1. 最小打扰
- 尽量自动执行，危险操作也直接做
- 仅在**无法判断方向时**提问
- 不输出"是否执行"、"需要确认"等确认请求
- 遇到不确定情况选择最合理方案直接执行，事后汇报

### 2. 先理解后动手
- 修改前必须读 `CLAUDE.md` 和相关上下文
- 理解现有代码风格和架构约束
- 盲目修改曾引入线程安全问题

### 3. 渐进式修改
- 大范围修改分步进行，每步可编译可测试
- 禁止一次性重构
- 重构顺序：共存 → 迁移 → 清理

---

## 标准工作流程

### 开发流程（6步）
1. **理解需求** → 读取相关上下文（CLAUDE.md、相关代码）
2. **制定计划** → `TodoWrite` 分步实施
3. **分步实施** → 每步修改后编译验证
4. **编译验证** → 编译失败立即修复不积累
5. **手动测试** → 编译后启动应用供用户手动测试
6. **Git提交** → 用户确认无误后提醒提交

### Git 工作流
1. 动手前 `git pull` 拉取两个远端最新代码
2. 若有本地未提交改动，先 commit + push
3. 完成后必须 commit + push 到两个远端

---

## 测试覆盖要求

### 三路径测试
- **正常路径**：功能正常工作的场景
- **边界情况**：空输入、极大值、零值
- **错误路径**：文件不存在、格式错误、权限不足

### 异常流程
- 断网/网络超时
- 服务离线/崩溃
- 文件不存在/无权限
- 并发无死锁
- 资源无泄漏

### 修 Bug 流程
1. 先写能复现 Bug 的失败测试用例
2. 确认测试失败后再修复
3. 修复后确认测试通过
4. 确认原有测试无回归

---

## 错误处理（不允许静默失败）

- 所有外部调用（API/文件IO/数据库）必须有错误处理
- 错误必须向上传播，禁止静默吞异常
- 跨模块调用失败必须通知上层
- 关键错误必须触发报警或通知用户

---

## 日志规范

### 必须记录的操作
- 项目管理：创建/删除/打开
- 任务执行：开始/完成/失败
- 用户操作：登录/登出/权限变更
- 系统交互：API调用/数据同步
- 异常情况：错误产生/恢复

### 日志级别
- `DEBUG`：开发调试，Release 不输出
- `INFO`：关键操作记录
- `WARNING`：可恢复异常
- `ERROR`：操作失败

---

## 代码审查

### 完成任何任务前
- 调用 `verification-before-completion`
- 必须有验证证据才能声称完成
- 未运行验证命令 = 不能说"完成"

### 修改代码后
- 调用 `simplify` 审查代码质量
- 检查逻辑/性能/安全/规范/资源泄漏

---

## Gotchas（易踩坑提示）

- 修改核心模块后必须回归验证
- Python 代码修改后必须运行 ruff check
- 涉及数据库迁移必须测试回滚
- 涉及并发代码必须测试竞态条件
- LiteLLM 多模型路由配置在 `data/config/model_config.yaml`，修改后需重启服务
- Neo4j/ChromaDB 必须先启动服务，否则数据库操作失败
- FastAPI 路由使用 `async def`，避免阻塞事件循环
- 耗时操作（外部 API 调用）使用 `asyncio.gather` 并发执行
- 数据库操作使用 SQLAlchemy async session
- 信号采集调度配置在 `data/config/signal_config.yaml`
- 前端 API 地址配置在 `src/frontend/src/api/index.ts`
