# VibeUtopia 系统架构设计

## 文档定位
- 本文档在主线中的角色：定义系统整体架构、技术栈选型、数据模型、部署方案
- 与"发前风控优先"的关系：架构围绕"输入→理解→评估→报告"主链路设计，仿真作为增强模块

## 本文档边界
- 本文档负责：技术栈选型、主链路架构、核心数据模型、API设计、部署架构
- 本文档不负责：各层详细设计（见06-12专项文档）、前端详细设计（见13）

## 对准确率的直接贡献
- 机制1：主链路架构确保内容理解→风险评估流程无断裂
- 机制2：硬件自适应架构确保不同设备均能获得最优模型效果
- 验证方式：端到端流程测试、模型路由正确性测试

## 1. 技术栈选型 (最终确立版)

基于行业最佳实践（如 Stanford Generative Agents, Mem0 等）及 VibeUtopia 核心需求，确定以下最终技术方案。

### 1.1 核心技术栈

| 领域 | 技术 | 选型理由 |
|------|------|----------|
| **后端框架** | Python FastAPI | **行业标配**。原生支持异步(AsyncIO)，极其适合长时间运行的仿真任务；Pydantic v2 确保严谨的数据校验。 |
| **前端框架** | Vue 3 + Naive UI | **高性能+深色美学**。Naive UI 提供极佳的暗色模式支持，组件库轻量且高度可定制，适合展示复杂风控数据。 |
| **关系数据库** | **MySQL 8.0** | **结构化核心**。存储用户信息、任务记录、风险报告及 Agent 元数据。提供成熟的事务支持。SQLite 为开发期/单用户降级方案。 |
| **向量数据库** | **ChromaDB** | **Agent 记忆引擎**。内嵌式部署，零运维负担，完美支持百万级 Agent 情景记忆(Memory Stream)的语义检索。 |
| **图数据库** | **Neo4j 5.x** | **关系推演**。存储社交网络拓扑、实体风险传导链。GraphRAG 架构的核心，用于处理"关系型风险"。 |
| **LLM 路由** | **LiteLLM** | **多模型兼容**。统一 OpenAI/DeepSeek/Qwen 等 100+ 模型 API，支持自动重试、负载均衡及硬件自适应 fallback。 |
| **多模态解析** | FFmpeg + PySceneDetect | **视频预处理**。行业标准工具，用于关键帧提取和转场检测。 |
| **异步任务** | asyncio.Queue | **内存级通信**。仿真引擎内部 Agent 间通信无需 Redis，进程内异步队列延迟极低且零外部依赖。 |
| **状态管理** | Pinia (Vue) | **简洁高效**。Vue 3 官方推荐，逻辑清晰。 |
| **样式系统** | Tailwind CSS 4 | **原子化开发**。极速构建响应式布局。 |

### 1.2 已移除的依赖

| 依赖 | 原用途 | 移除理由 | 替代方案 |
|------|--------|---------|---------|
| Redis | 缓存+消息总线+工作记忆 | 增加部署门槛，未大量使用 | asyncio.Queue + 内存LRU + 令牌桶 |
| Milvus | 向量检索 | 过重，10K Agent级别不需要 | ChromaDB内嵌式 |
| PaddlePaddle | 本地OCR | 专用OCR模型更优 | GLM-OCR / PaddleOCR-VL-1.5(独立) |
| yt-dlp | 在线视频下载 | 仅支持本地视频 | 移除 |
| MinIO | 对象存储 | 单用户不需要 | 文件系统 |
| Celery | 任务队列 | Redis移除后无broker | asyncio.Queue |
| Streamlit | 前端 | Vue更专业 | Vue3 |

### 1.3 硬件自适应架构

系统启动时自动检测硬件，选择最优模型策略：

| 层级 | GPU条件 | 模型策略 | 单次预估成本 |
|------|---------|---------|------------|
| **Lite** | 无GPU | 全API | ~¥2-3 |
| **Standard** | 12GB GPU | API视觉+本地OCR+本地音频+API文本 | ~¥1-2 |
| **Pro** | 24GB GPU | API为主+全部本地fallback | ~¥0.5-1 |
| **Ultra** | 多GPU | 全本地 | ~¥0 |

```python
def detect_tier():
    if not torch.cuda.is_available():
        return "lite"
    vram_gb = torch.cuda.get_device_properties(0).total_mem // (1024**3)
    if vram_gb >= 80: return "ultra"
    elif vram_gb >= 20: return "pro"
    elif vram_gb >= 10: return "standard"
    else: return "lite"
```

## 2. 系统整体架构

### 2.1 主链路架构（非5层平台化）

架构围绕"内容预审"主链路设计，仿真作为增强模块：

```
┌─────────────────────────────────────────────────────────────────────┐
│                       VibeUtopia 内容预审系统                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ┌─────────────┐   ┌──────────────┐   ┌──────────────┐            │
│  │  内容输入    │──▶│  内容理解     │──▶│  风险评估     │            │
│  │  (3模式)    │   │  (多模态)     │   │  (静态+仿真)  │            │
│  └─────────────┘   └──────────────┘   └──────┬───────┘            │
│                                                │                    │
│                                    ┌───────────▼───────────┐       │
│                                    │    报告输出            │       │
│                                    │  (7维+证据链+建议)     │       │
│                                    └───────────────────────┘       │
│                                                                     │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ 后台能力（系统自动调用，无用户入口） ─ ─ ─ ─ ─ │
│                                                                     │
│  ┌──────────┐  ┌──────────────┐  ┌──────────────┐  ┌───────────┐  │
│  │ 信号采集  │  │ 知识图谱     │  │ 人格工厂     │  │ 仿真引擎   │  │
│  │ (热搜聚合)│  │ (Neo4j)     │  │ (7层+故事)   │  │ (多Agent)  │  │
│  └──────────┘  └──────────────┘  └──────────────┘  └───────────┘  │
│                                                                     │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ 基础设施 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
│                                                                     │
│  MySQL/SQLite + ChromaDB + Neo4j + 文件系统                         │
│  多模态API + LLM API + 本地模型fallback                             │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 核心数据流

```
用户提交内容（视频/文案/混合）
    │
    ▼
[内容输入] ── 三模式解析 ──▶ 标准化内容对象
    │
    ▼
[内容理解] ── 视频理解(关键帧+OCR+音频) ── 文案理解(语义+情感+敏感) ── 跨模态校验
    │
    ▼
[风险评估] ── 静态评估(7维) ── 仿真增强(如需) ── 热点关联 ── 实体风险链
    │
    ▼
[报告输出] ── 风险评级+证据链+置信度+各平台反应+修改建议
```

### 2.3 主链路各模块职责

| 模块 | 核心职责 | 上游 | 下游 |
|------|----------|------|------|
| 内容输入 | 接收并解析用户输入（3模式） | 用户 | 标准化内容对象 |
| 内容理解 | 多模态内容理解+跨模态校验 | 标准化内容 | 理解结果 |
| 风险评估 | 静态评估+仿真增强 | 理解结果 | 风险评级+证据链 |
| 报告输出 | 生成结构化报告 | 风险评估 | 用户 |

## 5. API设计

### 5.1 核心端点（5个，收敛自38+）

| 方法 | 端点 | 描述 |
|------|------|------|
| POST | `/api/review` | 提交内容进行预审（视频/文案/混合） |
| GET | `/api/review/{task_id}` | 获取预审结果 |
| GET | `/api/review/{task_id}/progress` | 获取分析进度（WebSocket推送） |
| GET | `/api/history` | 历史记录 |
| GET | `/api/models` | 当前可用模型列表（基于硬件自适应） |

### 5.2 核心请求格式

```json
POST /api/review
{
  "mode": "video" | "text" | "mixed",
  "video_files": ["file_id_1"],
  "texts": [
    {"type": "script", "content": "..."},
    {"type": "title", "content": "..."}
  ],
  "options": {
    "depth": "quick" | "standard" | "deep",
    "platforms": ["auto"] | ["weibo", "bilibili", ...]
  }
}
```

### 5.3 核心响应格式

```json
GET /api/review/{task_id}
{
  "status": "completed",
  "result": {
    "overall_risk": 72,
    "risk_level": "orange",
    "dimensions": [...],
    "platform_reactions": {...},
    "suggestions": [...]
  }
}
```

## 6. 数据模型设计

### 6.1 核心实体

#### ContentInput — 内容输入

```python
class ContentInput:
    input_id: str
    mode: str                    # video/text/mixed
    video_paths: List[str]       # 本地视频路径
    texts: List[TextInput]       # 文案/脚本/标题
    created_at: datetime
```

#### ReviewTask — 预审任务

```python
class ReviewTask:
    task_id: str
    input_id: str
    status: str                  # analyzing/completed/failed
    depth: str                   # quick/standard/deep
    platforms: List[str]         # 分析的平台列表
    result: Optional[ReviewResult]
    created_at: datetime
    completed_at: datetime
```

#### ReviewResult — 预审结果

```python
class ReviewResult:
    task_id: str
    overall_risk: int            # 0-100
    risk_level: str              # red/orange/yellow/green
    dimensions: List[RiskDimension]  # 7维+证据链
    platform_reactions: Dict[str, PlatformReaction]
    suggestions: List[Suggestion]
    simulation_meta: Optional[SimulationMeta]
    propagation: Optional[PropagationResult]
```

#### AgentRecord — Agent人格

```python
class AgentRecord:
    agent_id: str
    platform: str
    archetype_base: str
    persona_json: str            # 7层人格JSON
    quality_score: float
    status: str                  # active/archived/evolved
    version: int
    created_at: datetime
    updated_at: datetime
```

#### AgentMemory — Agent记忆条目

```python
class AgentMemory:
    memory_id: str
    agent_id: str
    content: str                 # 记忆内容
    timestamp: datetime
    importance: int              # 1-10
    memory_type: str             # life_event/observation/reflection/plan
    access_count: int
```

#### SocialRelation — 社交关系

```python
class SocialRelation:
    id: int
    agent_id_a: str
    agent_id_b: str
    relation_type: str           # follow/friend/oppose/mentor/same_org
    weight: float
    platform: Optional[str]
```

### 6.2 存储架构

| 存储层 | 工具 | 存什么 | 为什么 |
|--------|------|--------|--------|
| 结构化数据 | MySQL/SQLite | Agent元数据、记忆条目、预审结果、社交关系 | 关系型查询，事务一致性 |
| 向量检索 | ChromaDB | 记忆条目的embedding | Memory Stream的Relevance因子，零部署 |
| 社交图谱 | Neo4j | Agent间关系、实体知识图谱 | GraphRAG+传播路径，Lite模式可跳过 |
| 原始文档 | 文件系统 | 完整人生故事(agents/{id}/story.md) | 太大不适合DB字段 |

```python

SQLALCHEMY_DATABASE_URL = (

    or "sqlite:///./vibeutopia.db"  # 默认SQLite，零依赖
)
```

```
┌─────────────────────────────────┐
```

## 关键流程/结构

- 输入：用户提交内容（视频/文案/混合）
- 处理：内容理解→风险评估(静态+仿真)→报告生成
- 输出：结构化风险报告

## 依赖与降级

- 依赖：多模态API、LLM API、硬件条件
- 失败降级策略：
  - 多模态API不可用 → 跳过对应模态，仅做文本分析
  - 仿真超时 → 降级为静态评估
  - Neo4j不可用 → 跳过GraphRAG，传播推演退化为简单模型
  - MySQL不可用 → 降级为SQLite

## 验收标准

- 指标：端到端流程可用性、API正确率、硬件自适应正确率
- 阈值：5个核心API端点全部可用
- 通过条件：Lite模式零外部依赖可运行，Pro模式全部本地fallback可用
