# VibeUtopia 系统架构设计 (MVP阶段)

## 1. 技术栈选型
基于“不懂技术，快速本地跑起来，使用DeepSeek/阿里云”的决策要求：
- **后端框架**：Python `FastAPI`（轻量级、响应快，AI生态最友好）。
- **前端框架**：`Vue3` + `Vite`（纯前端单页应用，开发极快）。
- **数据库**：`SQLite`（本地零配置直接可用，后续可平滑迁移 MySQL）。
- **LLM接入**：使用 `LiteLLM` 库或直接调用（统一封装 DeepSeek、阿里云百炼等大模型接口，方便随时切换）。
- **部署方式**：纯本地启动（`uvicorn` 运行后端，`npm run dev` 运行前端，满足“先本地跑起来”的需求）。

## 2. 系统整体架构

```text
[ Web UI (Vue3前端) ] 
      │  (REST API 通信)
      ▼
[ FastAPI 后端服务 ] ────────▶ [ 现实数据抓取模块 ]
      │                            │
      │                            ▼
      │                      抓取各平台热点/真实评论
      │                      (作为Agent背景知识库)
      ▼                            │
[ 分析编排引擎 ] ◀─────────────────┘
      │
      ├──▶ 文本预处理 (分句、段落切分)
      ├──▶ 风险分类器 (LLM 调用，对照7大维度找错)
      ├──▶ 平台人格模拟 (LLM + 爬虫真实语料 预测四大平台反应)
      ├──▶ 评分聚合与建议生成 (综合计算 0-100 风险分)
      │
      ▼
[ SQLite 数据库 ] (存储每次评估的历史记录、原文和结果)
```

## 3. 核心 API 设计

- `POST /api/v1/analyze`：提交文案进行风控评估。
  - 请求体：`{"text": "需要评估的文案内容..."}`
  - 返回：分析任务ID。
- `GET /api/v1/analyze/{task_id}`：轮询获取分析结果及详细报告（句子级风险、改写方案）。
- `GET /api/v1/history`：获取用户的历史评估记录列表。

## 4. 核心数据模型

- **Task**: 记录单次分析任务的状态（执行中/已完成/失败）、提交原文、模型版本号。
- **RiskItem**: 记录具体的风险句子原文片段、所属风险标签（如：性别议题）、严重程度（高/中/低）、具体判定依据。
- **PlatformReaction**: 记录各平台的预测倾向（正向比例/中性比例/负向比例）以及触发该平台特有争议的原因。
- **AnalysisSummary**: 最终的总体评分（0-100）、发布建议（可发/修改/禁发）及安全改写版本的数组。
