## 0. 执行摘要（一页看懂新旧差异）

### 0.1 一句话结论

**旧架构把视频当成"一堆要抽样的帧"，新架构把视频当成"一段有作者意图的多模态话语"。**
风险不在某一帧里，风险在时间×空间×模态×语用的**组合**里涌现；因此理解的基本单位必须从 Frame 上升为 Event/Narrative，帧只是可回溯的证据原子。

### 0.2 新旧对照

| 维度 | 旧架构（12 + 30） | 新架构（本文档） |
|------|-------------------|------------------|
| 理解单位 | 关键帧 / 密集帧 | 事件（Event）→ 段落（Episode）→ 叙事弧（Arc） |
| 采样策略 | 场景切换 + 固定间隔 + 1fps 密扫 | 语义密度驱动的自适应采样 + 锚点强制保留 |
| 时序建模 | 帧差异评分（多窗口 max） | 多时尺度联合：闪现(帧)/镜头/段落/全片四层 |
| 模态关系 | 三模态独立分析 → 加权/max 融合 | 全模态对齐到统一时间轴，交叉验证 + 冲突即证据 |
| 细粒度 | 4 个专项检测器（规则+VLM） | 猎手层：detector 提议 + VLM 确认 + 知识库核验，三重确认 |
| 证据链 | 风险帧列表 + 分数 | 事件级结论可下钻到帧/区域，含置信度分解与"不确定"标注 |
| 语用/舆论 | 跨模态冲突 +10/+15 | 叙事意图推理 + 舆论映射（受众、话术、历史同类事件） |
| 成本结构 | 全量帧过 VLM（贵）或漏检（险） | 快筛→精选→深析三级帕累托路由 |
| 评测 | 阈值指标（检出率） | 事件级召回 / 定位 IoU / 证据保真 / 新旧对照实验 |

### 0.3 核心增量（相对 30 号文档已实现部分）

1. **事件图（Event Graph）**作为中枢数据结构——所有模态、所有检测器的输出都挂在事件节点上
2. **选帧智能体**取代固定规则——按语义密度分配预算，而不是 1fps 一把梭
3. **叙事/意图层**——解决"每一帧都无害，合起来是危险叙事"的涌现型风险
4. **风险涌现公式**——从风险原子到全局定级的可计算路径，含反伪精确机制
5. **舆论预测接口**——事件图直接对接现有仿真引擎（persona/传播动力学），输出"发布后风险"而不只是"内容违规"

## 1. 第一性原理分析：视频是什么，风险如何涌现

### 1.1 视频的本质：时间轴上的多模态话语

从第一性原理出发，视频不是"图像序列 + 音频轨"的机械堆叠。它是：

```
Video = (时间轴 T, 视觉流 V, 听觉流 A, 语言流 L, 剪辑语法 E, 作者意图 I, 受众语境 C)
```

五个不可还原的性质：

1. **时间性（Temporality）**：信息在时间中展开，顺序即语义。倒放、跳剪、闪回都会改变含义。"先展示地图再打码"与"先打码再展示"是两件事。
2. **组合性（Compositionality）**：单帧/单句均无害的元素，组合后可以产生全新语义（反讽、并置、暗示）。这是逐帧方法在原理上不可达的能力。
3. **多模态绑定（Binding）**：画面里的手指向某处、嘴上说另一个词、字幕写第三个意思、BGM 是煽情的——四个信号**绑定在同一时刻**才有意义。拼接（concatenate）会破坏绑定，联合建模（joint）才保留。
4. **作者性（Authorship）**：视频是被剪出来的。镜头时长、切换节奏、特写选择都是**有意图的编码**。剪辑语法本身携带语义（快切=紧张/掩盖，长镜=真诚/压迫）。
5. **语用性（Pragmatics）**：风险最终发生在"受众如何解读"这一层。同一画面对不同圈层受众的引爆点不同（狗哨、地域黑梗、谐音、亚文化符号）。

### 1.2 风险的涌现模型

定义风险原子：

```
r = (evidence, modality, type, severity, confidence, verifiability)
```

其中 `evidence` 必须能回溯到时间轴区间 `[t_s, t_e]` 与空间区域 `bbox`。

风险不是风险原子的简单求和，而是**涌现函数**：

```
R_global = Φ( {r_i}, Arc, Intent, Audience )
```

涌现来源有且仅有四类，对应四个不可省略的分析层：

| 涌现来源 | 例子 | 需要的分析能力 |
|----------|------|----------------|
| **A. 空间细节涌现** | 地图缺台湾、文件夹名暴露开源项目 | 细粒度猎手层（区域放大+专项检测） |
| **B. 时间结构涌现** | 3 帧闪现、口播与画面节奏错位、关键帧故意短暂 | 多时尺度建模 + 异常区间定位 |
| **C. 模态冲突涌现** | 口播"自研"、画面闪过 GitHub；文案正能量、BGM 悲壮煽动 | 模态协同与冲突检测 |
| **D. 叙事语用涌现** | 单帧都合规，整体构成影射/带节奏/暗示性叙事；发布后被特定群体二次解读 | 叙事弧 + 意图识别 + 舆论映射 |

**推论 1**：只覆盖 A/B 的系统（现状 30 号文档）最多做到"细节不漏"，做不到"叙事不误判/不漏判"。
**推论 2**：只覆盖 D 的系统（纯文本舆情分析）会漏掉 A/B/C。四种涌现必须同架构覆盖。
**推论 3**：帧是证据的最小原子，但**不是推理的基本单位**。推理在事件层做，证据在帧层存。

### 1.3 为什么"逐帧识别图片"在原理上失败

不是工程问题，是方法论问题：

| # | 失败模式 | 原理性解释 | 量化后果 |
|---|----------|-----------|----------|
| 1 | **时序割裂** | 把谓词-论元结构切碎。"他指着地图说这是我们自研的"需要 3 秒内的联合，拆成 30 帧后变成 30 个孤立描述 | 因果/指代召回趋近 0 |
| 2 | **语境丢失** | 反讽、回调、铺垫-兑现（setup-payoff）都跨帧存在。前面 1 分钟的铺垫决定第 8 分钟一帧的含义 | 语用型风险几乎全漏 |
| 3 | **细节噪声/Token 压缩** | 整帧过 ViT 时，占画面 1% 的区域仅对应 1–2 token；小文字/小符号被压没 | 小目标识别率 ~40% |
| 4 | **成本爆炸** | 10 分钟 30fps = 18000 帧。全帧 VLM 调用成本不可接受；降采样又回到漏检 | 成本与召回死锁 |
| 5 | **漏短暂事件** | 均匀 8 帧/分钟采样时，0.33 秒画面命中概率仅 ~4%（30 号文档实测口径） | 闪帧/短暂画面漏检 ~70% |
| 6 | **无叙事与意图理解** | 逐帧输出"画面内容"，不输出"作者在干什么"。带节奏、影射、选择性呈现全部不可见 | 舆论风险预测失效 |
| 7 | **伪精确** | 把某一帧的 VLM 描述当成全片结论，置信度不可分解、不可回溯 | 误报无法申诉、漏报无法归因 |

### 1.4 现有 VibeUtopia 管线的现状定位

已有资产（`src/backend/services/`）不是要推倒，而是要**重新归位**：

- 已有"帧级证据原子"生产能力：`keyframe_extractor`（三级降级+去重）、`delta_frame_extractor`（帧差/SSIM/哈希）、`dense_frame_scanner`（1fps 密扫+多窗口异常分）、`frame_ocr`、`frame_risk`
- 已有"初步时序"能力：`frame_sequence_analyzer`（分段描述、因果链、动作事件）、`fine_grained/*`（地图/代码/符号/时序异常四猎手）
- 已有"跨模态冲突"能力：`cross_modal_detector`（画面-文案-音频冲突）
- 已有"证据链"雏形：`evidence_chain.py`（交叉校验、传播路径）
- **缺口**：没有事件图中枢、没有叙事意图层、没有自适应预算分配、没有舆论映射接口、融合仍是加权/max 而非联合建模

## 2. 旧架构失败模式深度批判

### 2.1 批判一：均匀采样 + 场景切换 ≠ 覆盖

`keyframe_extractor` 的三级策略（PySceneDetect ContentDetector 阈值 27.0 → FFmpeg 5s 间隔 → OpenCV 跳帧）本质是**镜头边界检测**。它的盲区：

1. 镜头内部的短暂异常（同一镜头里闪过一张图、切出一个文件夹）完全不可见——30 号文档已识别此问题并用密扫补丁
2. 场景切换阈值 27.0 是全局常数，对慢节奏口播（低差异）过敏、对快剪混剪（高差异）漏检
3. pHash 去重（汉明距离 < 8 判重）会把"相似但关键细节不同"的两帧合并——恰恰是地图有/无台湾这种细节差异会被去重掉

### 2.2 批判二：30 号密扫是"更密的帧"，不是"更好的理解"

30 号文档把漏检问题当作采样密度问题（1fps 密扫 + 多窗口异常分），这解决了 A/B 类涌现的一部分，但：

1. 异常分公式 `max(diff(i,i±w)) × 1/√w` 是**像素差**，对语义异常不敏感：字幕换了一个词、地图少了一个岛，像素差可能很小
2. 高异常帧必审 + 低异常抽 1/5，仍是静态规则，没有根据"这段在讲什么"分配预算
3. 四个专项检测器输出的是**并列报告**（+30/+20/+15/+10 分），没有回答"这些证据在叙事上意味着什么"
4. 结果融合仍是 `max(现有多模态风险, 细粒度升级)`，涌现型风险（单点低分、组合高危）被压平

### 2.3 批判三：模态"拼接/加权"而非"联合"

`multimodal_analyzer` 的融合是 `文本1.0 + 视觉0.8 + 音频0.7 + OCR0.6 → max(加权)`。问题：

1. **max 操作丢失联合信息**：画面风险 40 + 文案风险 40，冲突后可能是 80（带节奏），max 只给 40
2. **加权系数是全局常数**，与内容类型无关（知识科普 vs 时政评论的模态权重分布完全不同）
3. **时间对齐缺失**：音频情感与画面情感没有按时间戳对齐比较，只是全片摘要对比

### 2.4 批判四：证据链不可下钻、不可申诉

现有 `evidence_chain` 做了交叉校验，但输出仍是"风险条目列表"。审核场景要求：

```
结论："该视频存在地图完整性风险"
  └─ 依据：事件 E7（03:12–03:18 展示中国地图）
       └─ 证据原子：frame_5631.png @ 03:14.2，bbox(0.62,0.31,0.88,0.55)
            └─ 检测器：MapAuditor 置信 0.91；VLM 确认 置信 0.87；知识库核验：台湾缺失
            └─ 反证检索：同视频其他时刻是否有完整地图？（无）
            └─ 置信度分解：检测 0.91 × 确认 0.87 × 语境 0.95 = 0.75（"高置信"）
```

旧结构给不出这条链，或给出的链是事后拼的（伪精确）。

### 2.5 批判五：完全没有"发布后舆论"通道

现有风险评估停在"内容是否违规/高危"。但用户命题是**含发布后舆论风险**。这需要：

```
内容事件图 → 争议点抽取 → 受众分层映射 → 历史同类事件库 → 传播仿真输入 → 舆论风险预测
```

这条通道当前断链：`trend_predictor` / `simulation/*` 消费的是文本与人格，不消费视频事件图。

## 3. 设计原则

| # | 原则 | 含义 | 对架构的硬约束 |
|---|------|------|----------------|
| P1 | **事件优先** | 推理基本单位是事件，不是帧 | 必须有事件图层；帧只作为证据原子挂载 |
| P2 | **语境闭包** | 任何结论必须携带最小充分语境 | 证据帧必须能回放前后 N 秒/所属事件；孤立帧不产生最终结论 |
| P3 | **多时尺联合** | 毫秒闪现与全片立意同时建模 | 四层时间尺度（帧/镜头/段落/全片）并行，结果互为先验 |
| P4 | **模态绑定** | 模态在统一时间轴上联合，不拼接 | 所有输出带 `[t_s, t_e]`；融合发生在事件节点上 |
| P5 | **证据可回溯** | 结论→事件→帧/秒→区域，四级下钻 | 每个风险原子含 provenance + 置信度分解 |
| P6 | **反伪精确** | 不确定就标不确定 | 置信度 < 阈值输出"待核验"而非硬判；区分"检测置信"与"语义置信" |
| P7 | **预算感知** | 计算资源按语义密度分配 | 快筛/精选/深析三级路由，单视频成本可控 |
| P8 | **双确认** | 确定性风险必须 detector + VLM 双确认 | 猎手层强制双通道；单通道只能出"提示"不能出"定论" |
| P9 | **可评测** | 每个机制有可证伪指标 | 事件级召回、定位 IoU、证据保真度必须可测 |
| P10 | **渐进迁移** | 不推倒重来 | 明确保留/替换/新增三类清单，每阶段可编译可回测 |

### 4.2 核心数据结构：事件图（Event Graph）

```python
@dataclass
class TimeSpan:
    t_start: float
    t_end: float

@dataclass
class EvidenceAtom:
    """证据原子——可回溯的最小证据单位"""
    atom_id: str
    span: TimeSpan
    bbox: tuple[int, int, int, int] | None   # 画面内区域（可为空）
    modality: str                            # visual / audio / asr / ocr / text / music / edit
    content: str                             # 文本化内容（描述/转写/OCR结果）
    raw_ref: str                             # 原始文件引用（帧图/音频片段路径）
    detect_conf: float                       # 检测置信（机器可算）
    semantic_conf: float                     # 语义置信（模型判断，可低可标不确定）
    detector: str                            # 来源检测器名
    verified_by: list[str]                   # 双确认通道记录

@dataclass
class EventNode:
    event_id: str
    kind: str                                # scene / action / claim / display / speech_act
    span: TimeSpan
    actors: list[str]
    summary: str                             # 事件级一句话描述（LLM 生成）
    atoms: list[EvidenceAtom]                # 挂载的证据原子
    modalities_present: set[str]
    risk_atoms: list["RiskAtom"]

@dataclass
class EventEdge:
    src: str
    dst: str
    relation: str        # before / causes / same_entity / contradicts / supports / setup_payoff
    confidence: float

@dataclass
class NarrativeArc:
    episodes: list[str]        # Episode 节点 id
    arc_type: str              # exposure / tutorial / commentary / storytelling / mixed
    intent_vector: dict        # {"inform":0.2,"persuade":0.7,"provoke":0.4,...}
    setup_payoff: list[tuple[str, str]]
```

### 4.3 数据流一句话

```
解复用→四时尺感知→事件图构建→（智能体选帧/选段 + 猎手双确认）→事件级联合理解
     →叙事意图推理→风险涌现与舆论预测→证据链四级下钻→报告
```

## 5. 各层详细设计

### 5.1 L0 解复用与时基层

目标：把所有模态钉到同一条时间轴上，消灭"画面 03:14 对不上口播 03:12"的对齐误差。

```
FFmpeg 解复用：
  video.ts[]     → 帧序号 f ↔ 时间戳 t_f = f / fps
  audio.wav      → 16kHz 单声道
  asr[]          → (text, t_s, t_e, speaker)  ← faster-whisper 词级时间戳
  ocr_stream[]   → (text, t_frame, bbox)      ← 关键/密扫帧 OCR
  copy_text      → 全文（无时间戳，挂到全片级 Arc）
```

硬约束：下游所有结构必须携带 `TimeSpan`。禁止输出无时间定位的结论。

### 5.2 L1 感知基底层（多时尺）

四层并行，互为先验（粗层引导细层预算，细层修正粗层边界）：

| 层 | 粒度 | 主要特征 | 算子 | 对应风险涌现 |
|----|------|----------|------|--------------|
| T0 帧级 | ~0.03s | 帧差、pHash、光流幅度、小目标框 | OpenCV / 轻量检测 | 闪现、贴片、小文字 |
| T1 镜头级 | 1–10s | 镜头边界、镜头时长、运动强度、主体 | PySceneDetect + ShotClassifier | 剪辑节奏、镜头意图 |
| T2 段落级 | 10–120s | 语义分段、话题转移、事件簇 | ASR+视觉联合分段（TextTiling 变体） | 话题带节奏、段落反转 |
| T3 全片级 | 全片 | 锚点摘要、叙事骨架、立意 | 32/64 均匀+语义锚点 → 摘要模型 | 立意/立场/总体倾向 |

**语义分段算法（T2）**——视觉与 ASR 双通道边界融合：

```
boundary_score(t) = α·Δ_visual(t) + β·Δ_asr_topic(t) + γ·Δ_ocr(t) + δ·silence(t)

其中
  Δ_visual(t)   = 1 - cos(v(t-Δ), v(t+Δ))          # 镜头特征余弦距离
  Δ_asr_topic(t)= 1 - cos(e(topic_before), e(topic_after))  # ASR 段落嵌入距离
  silence(t)    = 停顿超过 0.6s 的指示函数
  边界 = peak-picking(boundary_score, min_gap=8s)
```

### 5.3 L2 事件图构建

**事件抽取流水线**：

```
Shot 序列 → 相邻镜头合并规则 → Event 候选 → LLM 事件规范化 → Entity/Claim 抽取 → 连边
```

事件规范化 prompt 的输出 schema（强制 JSON）：

```json
{
  "event_id": "E12",
  "kind": "claim|action|display|speech_act",
  "span": [192.5, 198.0],
  "summary": "博主展示自称自研的项目文件夹结构",
  "actors": ["博主"],
  "claims": [{"text": "这是我们的自研系统", "span": [192.5, 195.2], "modality": "asr"}],
  "displays": [{"what": "文件夹列表含 ByteTrack", "span": [195.8, 198.0], "modality": "visual"}]
}
```

**连边规则**：

| 关系 | 触发条件 | 用途 |
|------|----------|------|
| `before` | 时间不重叠且间隔 < 30s | 时序重建 |
| `contradicts` | Claim 与 Display/Claim 语义冲突（LLM 判定） | 模态冲突涌现 |
| `setup_payoff` | 前事件承诺/铺垫，后事件兑现/反转 | 反讽、回调识别 |
| `same_entity` | 跨事件同一实体（人物/项目/地图） | 证据聚合 |
| `supports` | 多事件共同支撑同一论点 | 叙事强度 |

### 5.4 L3 选帧/选段智能体（Adaptive Sampling Agent）

**核心公式：语义密度**

对时间窗 `w`（默认 2s）：

```
density(w) = α·novelty_v(w) + β·info_ocr(w) + γ·info_asr(w)
           + δ·entity_salience(w) + ε·narrative_role(w) + ζ·anomaly(w)

novelty_v(w)      = 与全片锚点集的最小余弦距离（新信息量）
info_ocr(w)       = 新增 OCR token 数 / 窗长（归一化）
info_asr(w)       = ASR 新词/实体密度
entity_salience(w)= 窗内实体的知识图谱重要性（博主、项目名、地名加权）
narrative_role(w) = 该窗在叙事弧中的角色权重（冲突/反转/结论 > 平铺）
anomaly(w)        = 多尺度异常分（继承 30 号，但升级为语义异常，见 5.5）
```

**预算分配（而不是 1fps 一把梭）**：

```
给定预算 B 帧（如 10 分钟视频 B=120 给精选层）：
  1. 强制锚点：镜头首尾、事件边界、Claim 播放窗、猎手表命中窗 → 不低于 40% 预算
  2. 剩余预算按 density(w) 的 softmax 温度采样（温度 τ 控制探索）
  3. 覆盖度约束：任意 30s 窗内至少 1 帧（防盲区）
```

伪代码：

```python
def allocate_frames(events, budget, tau=0.7, min_coverage_s=30):
    anchors = collect_anchors(events)          # 规则 1
    remain = budget - len(anchors)
    scores = [density(w) for w in sliding_windows(events)]
    probs = softmax(scores / tau)
    extra = weighted_sample_without_replacement(remain, probs)
    frames = dedup(anchors + extra)
    frames = enforce_coverage(frames, min_coverage_s)
    return sorted(frames)
```

**与旧方案差异**：旧方案"高异常必审 + 低异常抽 1/5"是异常驱动；新方案是**信息量+叙事角色+异常**三驱动，且有覆盖度下限。

### 5.5 L4 细粒度猎手层（detector + VLM 双确认）

保留 30 号四猎手（地图/代码/符号/时序异常），升级为统一的**三段式猎手协议**：

```
Stage-1 提议（Detector）：高召回、低精度，只负责"这里可能有问题"
Stage-2 确认（VLM）    ：对裁剪放大区域做细粒度理解，输出结构化判断
Stage-3 核验（Knowledge）：知识库/规则/检索做最终核验（地理知识库、GitHub 检索、符号库）
```

**语义异常分（升级 30 号的像素差）**：

```
anomaly_semantic(i) = max over w∈{1,3,10,30} of
    [ λ·pixel_diff(i,i±w) + (1-λ)·(1 - cos(embed(roi_i), embed(roi_{i±w}))) ] / √w

其中 roi 为感兴趣区域而非整帧；λ 随区域类型自适应
（文字/地图区 λ→0.3，重语义；纹理区 λ→0.7，重像素）
```

**地图完整性猎手（保持 30 号方案，补充反证检索）**：

```
输出必须包含：
  missing_regions: [...]           # 缺失区域
  counter_evidence: {              # 反证——同视频他处是否出现过完整地图
      "found_elsewhere": bool,
      "at": [t_s, t_e] | null
  }
  confidence_split: {det, vlm, kb} # 三通道置信分解
```

**代码溯源猎手**：OCR 提取项目名/路径/片段 → GitHub/Sourcegraph 检索 → 匹配度核验。关键升级：**检索失败≠安全**，输出 `unverified` 而非 `safe`（P6 反伪精确）。

**时序异常猎手**：聚类异常帧区间（现有 `_cluster_anomaly_frames`），但聚类边界用镜头边界对齐，避免跨镜头误聚类。

### 5.6 L5 多模态联合理解层

**事件描述生成**（不是全片摘要，是事件级）：

```
EventDesc(E) = LLM(
    frames = E.atoms[visual]（含前后文锚点帧 1-2 张，满足 P2 语境闭包）,
    speech = E.atoms[asr],
    ocr    = E.atoms[ocr],
    music  = E 窗口内 BGM 情绪标签,
    edit   = E 窗口内剪辑节奏（镜头均长、切换频率）,
    instruction = "描述该事件，并标注画面/口播/字幕之间的一致或冲突"
)
```

**冲突作为一等证据**：冲突不再只是 +10 分，而是生成 `RiskAtom(type="modality_conflict")`，挂到事件节点，可下钻。

冲突强度：

```
conflict_score = semantic_distance(claim_text, visual_summary)
               × co_occurrence_tightness          # 时间上是否紧邻
               × intent_relevance                 # 与整体叙事是否相关
```

### 5.7 L6 叙事/意图推理层（新增，旧架构完全缺失）

**输入**：全片事件图 + Arc 摘要。**输出**：意图向量 + 语用风险。

```python
@dataclass
class PragmaticRisk:
    risk_type: str      # insinuation(影射) / provocation(带节奏) / dog_whistle(狗哨)
                        # / selective_framing(选择性呈现) / sarcasm(反讽)
    trigger_events: list[str]
    explanation: str
    audience_segments: list[str]     # 哪些群体会被引爆
    confidence: float
```

**意图分类器**（LLM 结构化输出 + 规则先验）：

```
intent_vector = {
  "inform":    ...,  # 信息传递
  "persuade":  ...,  # 说服/安利
  "provoke":   ...,  # 挑动对立/引战
  "conceal":   ...,  # 掩盖/洗白（如声称自研实为开源）
  "satirize":  ...,  # 讽刺/影射
  "mobilize":  ...,  # 动员/号召
}
```

**setup-payoff 检测**（反讽/回调识别的关键）：

```
对 EventEdge.relation == "setup_payoff" 的事件对 (e1, e2):
  narrative_risk = contradiction(e1.claim, e2.content) × e2.prominence
  例：e1 "我们完全自研"（口播）→ e2 GitHub 文件夹一闪而过
      contradiction 高、e2.prominence 低（短暂）→ 高风险"欲盖弥彰"模式
```

### 5.8 L7 风险涌现与舆论预测

**涌现聚合公式**（替代 max 加权）：

```
R_content = clip( base + emergent , 0, 100 )

base     = Σ_i w(type_i) · severity(r_i) · conf(r_i)          # 风险原子加权和
emergent = λ1·narrative_risk + λ2·conflict_amplify
         + λ3·pattern_match(historical_pattern)               # 历史高危模式匹配
         + λ4·intent_threat                                   # 意图威胁度

conflict_amplify = max(0, max_pair_conflict - mean_atom_risk)  # 冲突放大项
```

**舆论风险通道**（对接现有仿真引擎）：

```
EventGraph
   │ 抽取
   ▼
ControversyPoint {话题, 立场张力, 情绪载荷, 可截图传播点, 二创风险点}
   │ 受众分层映射（复用 persona_archetypes / platform_weights）
   ▼
SimulationInput {初始种子帖, 立场分布, 情绪强度, 传播动能}
   │ 复用 simulation/engine + trend_predictor
   ▼
OpinionRisk {
   48h 峰值热度预测, 极化指数预测, 高危受众群, 转折点预测,
   平台差异（B站/抖音/微博 同一事件不同引爆逻辑）
}
```

**关键设计**：舆论预测的输入必须是**事件级**（"博主声称自研但画面暴露 GitHub"），而不是帧级（"03:14 有一张图"）。只有事件级才能映射到"争议点/立场张力"。

### 5.9 L8 证据链与回溯

**四级下钻协议**：

```
Level-0 结论   R_content=78，类型：内容失实 + 地图完整性
Level-1 事件   E7(03:12–03:18) 声称自研；E12(03:14.2) 地图展示
Level-2 证据帧 frame_5631.png @ 03:14.2 ± 0.5s 语境窗
Level-3 区域   bbox(0.62,0.31,0.88,0.55) 裁剪放大图 + 三通道置信
```

**置信度分解**（反伪精确）：

```
conf_total = conf_detect × conf_confirm × conf_context × conf_provenance

conf_detect    ∈ [0,1]  检测器输出
conf_confirm   ∈ [0,1]  VLM/知识库确认强度（未确认=0.5 中性，不假装 1.0）
conf_context   ∈ [0,1]  语境闭包完整度（缺前后文则衰减）
conf_provenance∈ [0,1]  证据可回放程度（有原始帧=1，只有描述=0.6）

输出分级：conf_total ≥ 0.75 → "高置信结论"
          0.5 ≤ conf_total < 0.75 → "疑似，建议人工复核"
          conf_total < 0.5 → "线索"（不得进入自动定级）
```

**反证检索**（防断章取义）：每个自动定级结论触发一次反证检索——同视频/同博主历史视频中寻找削弱该结论的证据（如其他时刻出现过完整地图、后续有更正声明）。找到反证则降级并记录。

### 5.10 贯穿层：三级帕累托路由

| 级 | 名称 | 触发 | 用什么 | 成本量级 |
|----|------|------|--------|----------|
| S1 快筛 | 全部视频 | L0-L1 特征 + 轻量分类 + 词表 | ~¥0.05 |
| S2 精选 | 快筛分数>阈值 或 事件图含 claim/display | L3 选帧 + VLM 事件理解 + 猎手 Stage-1/2 | ~¥0.5–1.5 |
| S3 深析 | 精选发现风险原子 或 意图可疑 | L6 叙事推理 + L7 舆论仿真 + 猎手 Stage-3 全开 | +¥1–3 |

**Video-LLM 直吞 vs 管线 的选择准则**：

```
if 时长 ≤ 3min 且 需要全局叙事理解 且 预算充足:
    可用 Video-LLM 直吞（Qwen-VL 视频模式）作为 Arc 层的一个投票通道
else:
    走事件图管线（可下钻、可预算、可回放）

原则：Video-LLM 直吞用于"叙事倾向的第二意见"，永远不用作唯一证据来源
      （不可回溯 = 不可申诉 = 违反 P5/P6）
```

## 8. 评测方案（如何证明"比逐帧好"）

### 8.1 金标准构建

构建**视频风险金标准集 VGOLD-200**：

| 类别 | 数量 | 构造方式 |
|------|------|----------|
| A 空间细节型 | 40 | 地图缺台湾/南海、GitHub 文件夹、敏感符号小区域（复用 30 号案例库扩展） |
| B 时间结构型 | 40 | 3 帧闪现、0.3s 短暂画面、口播与画面错位 |
| C 模态冲突型 | 40 | 口播与画面矛盾、字幕篡改、BGM 情绪反向 |
| D 叙事语用型 | 40 | 影射、带节奏、选择性呈现、setup-payoff 反讽 |
| N 负样本 | 40 | 外观相似但无风险（正常地图、正常开源引用、正常快剪） |

标注协议：每条样本标注 `风险类型 / [t_s,t_e] / bbox / 证据帧 / 舆论敏感度(0-5)`，双人标注 + 仲裁。

### 8.2 对照实验设计

```
S0 基线：逐帧/均匀 1fps + 逐帧 VLM（用户否定的方案，作为对照底线）
S1 现状：现有 VibeUtopia 管线（12+30 实现）
S2 新架构：本文档全量（事件图+智能体+猎手+叙事+涌现）
S3 消融：S2 分别去掉 {事件图 / 选帧智能体 / 叙事层 / 双确认} 看指标掉多少
```

### 8.3 指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 事件级召回 Event-Recall | 风险事件被检出的比例 | S2 ≥ 0.90，显著高于 S1 |
| 定位精度 Temporal-IoU | 预测区间与标注区间的 IoU | ≥ 0.5（中位） |
| 区域召回 Box-Recall | bbox 命中率（A 类） | ≥ 0.85 |
| 证据保真 Evidence-Fidelity | 抽查下钻链能否真实回放到证据帧 | ≥ 0.95 |
| 伪精确率 Pseudo-Precision-Rate | 低置信被硬判为结论的比例 | ≤ 0.05 |
| 误报率 FP-rate（N 类） | 负样本被判风险比例 | ≤ 0.10 |
| 舆论预测相关性 | 预测热度 vs 实际热度（若可回测） | Spearman ≥ 0.5 |
| 成本 | 单视频平均费用/耗时 | S2 ≤ S0 的 40%，或同成本下召回高 30pt |

### 8.4 "比逐帧好"的证明逻辑

1. **召回维度**：S0 在 B 类（短暂事件）与 D 类（叙事）上应显著弱于 S2——直接证明"帧方法在原理上漏这两类"
2. **成本维度**：同预算下对比召回-成本帕累托前沿，S2 曲线应全面压过 S0/S1
3. **可审计维度**：S0 无法给出四级证据链，S2 可以——用 Evidence-Fidelity 量化
4. **消融维度**：S3 证明每个新组件都有贡献，不是靠调参

## 10. 风险与开放问题

| # | 风险/开放问题 | 影响 | 缓解 |
|---|---------------|------|------|
| 1 | 事件图构建依赖 LLM，长视频事件数多时成本/误差累积 | 事件边界不准会污染下游 | 双通道边界（规则+LLM）+ 人工抽检边界质量 |
| 2 | 叙事意图判定主观性强 | 误判"带节奏"引发申诉 | 只输出"语用风险线索"+置信分级，不自动定罪；人工终审 |
| 3 | 狗哨/亚文化符号时效性强，知识库滞后 | 漏检 | 知识库热更新 + 博主历史对比发现新模式 |
| 4 | 舆论预测不确定性高（突发事件、外部事件干扰） | 预测失准 | 输出区间预测+情景分支，不给单点数字 |
| 5 | 双确认仍可能双错（detector 与 VLM 同源偏差） | 系统性误判 | 定期用金标准回归；反证检索兜底 |
| 6 | 词级 ASR 时间戳在嘈杂音频上漂移 | 模态绑定错位 | 时间戳置信度衰减 conf_context；关键段落强制人工核 |
| 7 | 平台多样性（横竖屏、花字、弹幕、贴纸） | OCR/区域检测域偏移 | 按平台配置检测器参数（复用 `platform_weights`） |
| 8 | 合规边界：意图判定的可解释性要求 | 审计风险 | 证据链四级可回溯 + 全结论带反证检索记录 |

## 关键流程/结构

- 输入：视频文件 + 文案 + 平台上下文
- 处理：解复用→多时尺感知→事件图→（选帧智能体 + 猎手双确认）→事件级联合理解→叙事意图→风险涌现与舆论预测
- 输出：内容定级 + 舆论风险预测 + 四级可回溯证据链

## 依赖与降级

- 依赖：FFmpeg、faster-whisper、PySceneDetect、OpenCV、VLM API/本地 VLM、GLM-OCR、地理知识库、GitHub 检索、现有仿真引擎
- 失败降级：
  - 事件图失败 → 退回镜头级分组（现有 frame_sequence_analyzer 路径）
  - 选帧智能体失败 → 退回 30 号"高异常必审+抽审"规则
  - 叙事层失败 → 只输出 A/B/C 类风险，标注"语用层未分析"
  - 舆论通道失败 → 只输出内容定级，标注"舆论预测不可用"
  - 任何降级必须在报告中显式声明，禁止静默降级（P6）
