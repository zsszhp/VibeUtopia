# VibeUtopia 蓝图路线图

## 文档定位
- 本文档在主线中的角色：定义产品各阶段目标、交付物、Go/No-Go规则和验收标准
- 与"发前风控优先"的关系：每个阶段必须回答"是否提升风控准确率"

## 本文档边界
- 本文档负责：阶段划分、交付物、验收标准、Go/No-Go规则、依赖关系
- 本文档不负责：功能需求细节（见`01_产品需求文档(PRD).md`）、技术架构细节（见`02_系统架构设计.md`）

## 对准确率的直接贡献
- 机制1：每阶段有明确的准确率提升目标，确保演进方向不偏离
- 机制2：Go/No-Go规则确保每个阶段的投入有可验证的产出
- 验证方式：回测对比、人工复检、一致性检查

---

## 总览

| 阶段 | 主题 | 核心交付 | Agent规模 | 对准确率的贡献 |
|------|------|----------|-----------|---------------|
| **1** | 回归核心 | 单入口工作台+核心流程串联 | ~100 | 建立准确率基线 |
| **2** | 全平台覆盖 | 25+平台补全+原型扩展 | ~500 | 提升平台覆盖率→更全面的评估 |
| **3** | 模型+人生故事 | 最新API+人生故事人格+ChromaDB | ~2000 | Agent更真实→仿真更准 |
| **4** | 效果提升 | Memory Stream+平台浸泡+社交网络 | ~2000 | Agent反应更稳定→准确率提升 |
| **5** | 规模化仿真 | GA-S3 Group Agent+极化检测 | ~10000 | 更大样本→更稳定的结果 |
| **6** | 扩展功能 | 博主历史、竞品对比等 | - | 附加价值（后置） |

> 已完成的MVP和技术底座（V2.1-V2.5）成果保留，但后续演进严格按"发前风控优先"原则裁剪。

## 阶段1：回归核心 — 单入口串联

> **目标**：将7个入口收敛为1个，核心流程端到端跑通，建立准确率基线
>
> **Go/No-Go**：核心流程端到端跑通，输出可读报告 → 继续；否则继续修核心流程

### 交付物

- [ ] Vue3 + Naive UI 暗色主题前端，单入口"内容预审工作台"
- [ ] 完全废弃Streamlit前端
- [ ] 三种输入模式：仅视频 / 仅文案 / 混合输入
- [ ] 核心流程串联：上传→视频理解→文案理解→舆论推演→风险报告
- [ ] 后台模块自动串联，用户无感
- [ ] 移除多余用户入口和页面
- [ ] 移除PaddleOCR/PaddlePaddle本地依赖，改用API或本地GLM-OCR
- [ ] 移除yt-dlp（仅支持本地视频）
- [ ] 移除Redis依赖

### 验收标准

1. 单页面完成从输入到报告的完整流程
2. 三种输入模式均可用
3. 报告包含7维风险评级+证据链+改写建议
4. 建立准确率基线（记录初始值）

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 前端重构工作量大 | 中 | 优先核心流程，可视化渐进增强 |
| 移除依赖导致功能回退 | 低 | API替代方案提前验证 |

---

## 阶段2：全平台覆盖

> **目标**：从5平台扩展到25+平台，每平台原型从6个扩展到15-20个
>
> **Go/No-Go**：平台覆盖有效率>60% → 继续；否则缩减平台范围，优先质量

### 交付物

- [ ] P0平台补全：微博人格模板、贴吧新增（共6平台，每平台20原型）
- [ ] P1平台新增：快手、公众号、豆瓣、虎扑、头条、NGA、视频号（7平台，每平台15原型）
- [ ] P2平台新增：小黑盒、TapTap、米游社、游民星空、澎湃、观察者网等（12平台，每平台10原型）
- [ ] 每个平台：人格模板 + prompt模板 + 模拟器 + 传播特征
- [ ] 原型扩展：每平台从6个扩展到15-20个原型（总计~345原型）

### 验收标准

1. 25+平台均有人格模板和模拟器
2. 平台覆盖有效率>60%（可稳定输出结果的比例）
3. 每平台至少15个原型覆盖主流/争议/极端/边缘/跨界群体

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 平台特性差异大，模拟器难统一 | 中 | 统一PlatformAction接口+平台特化适配 |
| 原型设计工作量大 | 中 | 参考CGSS人口统计+LLM辅助生成 |

---

## 阶段3：模型优化 + 人生故事生成

> **目标**：接入最新多模态API，引入人生故事驱动人格系统，让Agent更真实
>
> **Go/No-Go**：人生故事Agent比属性Agent仿真准确率提升>15% → 继续；否则保留属性Agent，人生故事降级为实验

### 交付物

- [ ] 接入最新多模态API（Qwen3-VL-Plus / GLM-5V / DeepSeek-V4）
- [ ] 接入阿里Paraformer API（音频转写主力）
- [ ] 模型路由策略：按任务类型自动选模型+硬件自适应
- [ ] **人生故事驱动人格系统**：
  - AI访谈生成器（A-tier Agent，6轮结构化访谈→数万字人生故事）
  - 人口统计采样+LLM丰富（B-tier Agent）
  - 模板变体+递增扩展（C-tier Agent）
  - 人生故事→Memory Stream记忆条目转化
  - ChromaDB向量检索接入（替代Milvus）
  - 人格完善性自动验证流水线（7维度+Big Five一致性）
- [ ] 报告质量优化：更可操作的风险标注和修改建议

### 验收标准

1. 最新多模态API正常调用，模型路由自动切换
2. AI访谈生成的人生故事质量经人工评审>7/10
3. 人生故事Agent vs 属性Agent仿真准确率对比有提升
4. ChromaDB向量检索延迟<100ms

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 人生故事生成成本高 | 中 | A-tier仅用于1-2%核心Agent |
| API模型版本更新频繁 | 低 | 模型路由支持配置化切换 |

## 阶段4：效果提升

> **目标**：Memory Stream+平台浸泡让Agent反应更真实稳定
>
> **Go/No-Go**：Memory Stream Agent反应一致性(Big Five重复测试r)>0.7 → 继续；否则简化记忆机制

### 交付物

- [ ] **平台信息浸泡系统**：Agent初始化后模拟刷平台7-30天，吸收热点形成近期态度
- [ ] Stanford Memory Stream + Reflection机制完整实现
- [ ] Agent间社交网络构建（基于Neo4j GraphRAG）
- [ ] 传播推演可视化（D3.js力导向图）
- [ ] 历史报告对比
- [ ] GPU加速音频转写（Pro/Ultra模式）

### 验收标准

1. 浸泡后Agent对热点话题有"近期态度"（vs 未浸泡Agent对比）
2. Big Five重复测试一致性>0.7
3. 社交网络传播路径可视化可渲染1000+节点

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 浸泡仿真成本高 | 中 | 简化浸泡（3天/20帖/天）作为默认 |
| Memory Stream检索慢 | 低 | ChromaDB向量检索+重要性过滤 |

---

## 阶段5：规模化仿真

> **目标**：Agent规模递进到万级，通过Group Agent扩展到等效十万级
>
> **Go/No-Go**：1000+Agent仿真结果稳定性（3次一致性>60%） → 继续；否则控制规模

### 交付物

- [ ] Agent规模递进：100→500→2000→10000
- [ ] GA-S3 Group Agent机制（统计模型替代相似Agent，一个群组Agent代表10-100个相似个体）
- [ ] 多轮仿真优化：传播5阶段模型
- [ ] 极化检测与舆论转折预测
- [ ] 批量分析优化

### 验收标准

1. 10000 Agent仿真在40分钟内完成
2. 3次仿真一致性>60%
3. Group Agent扩展后等效个体数>10万

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 大规模仿真LLM成本过高 | 中 | C-tier用规则引擎+Group Agent统计模型 |
| Group Agent统计模型不准 | 中 | 小规模对照验证后逐步扩展 |

## Go/No-Go 决策点总览

| 阶段 | Go条件 | No-Go处理 |
|------|--------|----------|
| 阶段1 | 核心流程端到端跑通，输出可读报告 | 继续修核心流程，不进入阶段2 |
| 阶段2 | 平台覆盖有效率>60% | 缩减平台范围，优先质量 |
| 阶段3 | 人生故事Agent仿真准确率比属性Agent提升>15% | 保留属性Agent，人生故事降级为实验 |
| 阶段4 | Memory Stream Agent Big Five重复测试r>0.7 | 简化记忆机制 |
| 阶段5 | 1000+Agent仿真3次一致性>60% | 控制规模，不追求万级 |

---

## 仿真启用与保留条件

- **启用条件**：静态评估达到风险阈值或用户主动选择深度分析
- **保留条件**：仿真相对静态评估在回测中带来稳定准确率提升
- **降级条件**：若提升不稳定，保留热点关联与实体风险链，减少仿真成本

## 关键流程/结构

- 输入：前一阶段完成的交付物和验收结果
- 处理：按阶段目标开发→验收→Go/No-Go决策
- 输出：通过验收的阶段交付物

## 依赖与降级

- 依赖：多模态API可用性、LLM API可用性、硬件条件
- 失败降级策略：每个阶段有明确的No-Go处理方案，不会因某个阶段失败导致整体停滞

## 验收标准

- 指标：各阶段验收标准见上文
- 阈值：Go/No-Go条件中定义
- 通过条件：所有验收标准达标+Go/No-Go决策通过
