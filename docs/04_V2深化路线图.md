# VibeUtopia V2 深化路线图

> 从MVP到成熟产品的完整演进蓝图：核心目标是发前风控——预测舆论风险，避免踩雷。逐步构建高保真平行数字世界，让风控越来越准，最终实现趋势预测与决策辅助。

## 调整说明

> **v3 修订**：重新锚定核心目的——发前审批、预测舆论风险、避免踩雷。V2.1-V2.6 主线方向正确（让风控越来越准），但存在验证缺失、基础设施滞后、多模态优先级低于博主服务等问题。本次调整：1）新增仿真增强风控和仿真验证两个前置阶段；2）多模态提前到博主服务之前；3）博主服务回归附加位置。详见 `.comate/specs/v2-roadmap-revision/doc.md`。

## 技术底座（已完成）

> V2.1-V2.5 构建了完整的技术底座，让风控从"静态Prompt"进化到"千级Agent仿真"。这些能力将在后续阶段直接接入风控流程，产出用户可感知的价值。

### V2.1: 现实增强 — 信号采集体系 ✅

> **目标**：从现实世界实时采集种子信息，构建种子事件库

- [x] 热榜聚合引擎（NewsNow API + 11平台）
- [x] RSS补充源（财经/科技/国际）
- [x] 增量检测器（新上榜 + 排名变化追踪）
- [x] LLM关键词提取器
- [x] 定向评论爬取（API优先 + Playwright降级）
- [x] 情感标注器（LLM情感标注，后续可替换为BERT-LoRA降成本）
- [x] 事件检测器（主题聚类 + 因果推理 + 信号强度评估）
- [x] 种子事件库（SQLite先行 + MySQL预留）
- [x] APScheduler定时调度器
- [x] API端点：`GET /signals/hot`, `GET /signals/events`, `POST /signals/crawl`

### V2.2: 知识图谱 — 世界模型构建 ✅

## 价值交付路线（待执行）

> 以下阶段让技术底座产出用户可感知的价值：风控更准 → 验证可信 → 预见未来 → 画面也能审

### V2.R1: 仿真增强风控 — 让风控变准

> **目标**：将V2.1-V2.5的技术能力接入风控流程，让博主感知到"风控比MVP更准了"
>
> **核心价值**：从"4个静态Prompt猜测反应"进化到"100个Agent仿真预测反应"
>
> **Go/No-Go**：仿真风控比MVP静态风控准确率提升>15% → 继续；否则只保留热点/实体关联，不做仿真风控

#### 交付物

- [ ] 轻量仿真模式：100 Agent × 6小时仿真（成本¥0.5-1/次，耗时<5分钟），专为风控场景设计
- [ ] 仿真风控流程：文案 → 生成Agent → 轻量仿真 → 预测各平台反应 → 增强风控报告
- [ ] 风控-信号关联：文案评估时，自动关联当前热点（"你的文案与当前微博热搜XX相关，可能被关联讨论"）
- [ ] 实体风险链：通过知识图谱识别文案实体→关联争议事件（"你提到的A品牌近期有B争议"）
- [ ] 动态风险权重：基于当前热点热度动态调整7维风险权重
- [ ] 仿真增强风控报告：在MVP报告基础上增加仿真平台反应+热点关联+实体风险链
- [ ] 对比测试框架：同一批文案，V2仿真风控 vs MVP静态风控，准确率对比
- [ ] API端点：`POST /analyze/v2`（仿真增强分析）, `GET /risk/context`, `GET /entities/{name}/risk-chain`

#### 技术依赖

- V2.1 信号采集（已实现）
- V2.2 知识图谱（已实现）
- V2.3-V2.5 仿真引擎（已实现，需增加轻量模式）
- MVP 风险评估流程

#### 验收标准

1. 轻量仿真完成时间<5分钟，LLM成本<¥1/次
2. 仿真风控比MVP静态风控在风险评估准确率上提升>15%
3. 热点关联准确率>80%
4. 实体风险链覆盖文案中80%以上命名实体
5. 仿真增强分析端到端响应<3分钟

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 轻量仿真结果不稳定 | 中 | 多轮取共识+不确定性标注 |
| 热点关联误报多 | 中 | 设置关联阈值+LLM二次判断 |
| 仿真风控不比MVP准 | 低 | 保留MVP流程，仿真作为补充维度 |

### V2.R2: 仿真验证与基础迁移 — 验证可信

> **目标**：验证仿真风控的可信度，完成数据库基础设施迁移，为趋势预测打基础
>
> **核心价值**：自证可信——"我们的预测有依据"
>
> **Go/No-Go**：回测方向准确率>55%，MySQL迁移完成 → 继续；否则暂停R3，先修仿真质量

#### 交付物

- [ ] 仿真回测框架：用3-5个真实历史案例，看仿真预测的方向是否与实际一致
- [ ] 多轮一致性检查：同一事件仿真3次，评估结果稳定性
- [ ] 仿真可信度标注：在风控报告中标注"基于X次仿真，置信度Y%，不确定性来源Z"
- [ ] SQLite → MySQL 数据库迁移：仿真轨迹+风控结果+报告数据迁移到MySQL
- [ ] V2仿真 vs MVP 对比报告：生成两种模式的风险评估对比，量化改善幅度
- [ ] API端点：`GET /validation/backtest`, `GET /validation/consistency/{run_id}`

#### 技术依赖

- V2.R1 仿真增强风控
- 历史案例数据（从cases/目录和reports/目录整理）

#### 验收标准

1. 回测案例中仿真方向准确率>55%（3-5个案例中至少3个方向正确）
2. 多轮仿真一致性>60%（3次中2次方向一致）
3. MySQL迁移完成，零数据丢失，查询性能不低于SQLite
4. 可信度标注覆盖率100%
5. V2 vs MVP对比报告可生成

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 回测数据不足 | 中 | 优先选择有完整传播路径的热点事件 |
| 回测准确率<55% | 中 | 不做R3，改为修仿真参数/降规模 |
| 数据库迁移风险 | 低 | 先备份，分批迁移，保留回滚方案 |

### V2.R3: 趋势预测与决策辅助 — 预见未来

> **目标**：从仿真中提取趋势预测，支持反事实推演——这是核心价值交付
>
> **核心价值**：在事件发生之前看到可能的未来，推演不同应对策略的效果

#### 交付物

- [ ] 4阶段趋势预测引擎（态势感知→模式识别→走势预测→决策建议）
- [ ] 5种舆论模式分类器（快速爆发/缓慢升温/争议分裂/短暂热度/持续发酵）
- [ ] 短/中/长期走势预测（含概率分布+不确定性标注）
- [ ] 风险等级评估（红/橙/黄/绿）
- [ ] 反事实仿真引擎（多分支创建+干预注入+并行仿真+结果对比）
- [ ] 决策建议生成器（应对策略+时机建议）
- [ ] 报告生成引擎（4类报告+7种可视化组件+HTML/PDF/JSON输出）
- [ ] 多轮仿真共识机制
- [ ] 人工审核入口
- [ ] API端点：`POST /report/risk`, `POST /report/simulation`, `POST /simulation/{id}/branch`

#### 验收标准

1. 短期趋势方向预测准确率>65%（基于历史回测）
2. 反事实仿真3个分支对比完成<90分钟
3. 报告生成<1分钟
4. 预测不确定性标注覆盖率100%

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 预测准确性不够 | 高 | 多轮共识+不确定性标注+历史回测 |
| 反事实仿真成本高 | 中 | 使用较少Agent(500)+较短时长(12h) |
| LLM分析不稳定 | 中 | 3阶段JSON解析+重试 |

| 阶段 | Go条件 | No-Go处理 |

| V2.R6 | 5位博主中3位认为选题推荐有用 | 只做风格画像，不做选题推荐 |
