> 从MVP到成熟产品的完整演进蓝图：先做博主的AI风控+运营助手，再逐步构建高保真平行数字世界，实现千级Agent社交仿真、舆论趋势预测与决策辅助。

## 调整说明

> **v2.1 修订**：对照原始需求，博主服务（选题推荐+竞品对标）是产品第二步的核心，不应排在第7阶段。本次调整将博主服务提前，同时保留V2.1-V2.5已构建的技术底座。新增仿真验证阶段，确保预测决策有可信基础。详细分析见 `.comate/specs/v2-roadmap-revision/doc.md`。

## 技术底座（已完成）

> V2.1-V2.5 构建了完整的技术底座，这些能力将直接服务于后续所有阶段。

### V2.1: 现实增强 — 信号采集体系 ✅

> **目标**：从现实世界实时采集种子信息，构建种子事件库

- [x] 热榜聚合引擎（NewsNow API + 11平台）
- [x] RSS补充源（财经/科技/国际）
- [x] 增量检测器（新上榜 + 排名变化追踪）
- [x] LLM关键词提取器
- [x] 定向评论爬取（API优先 + Playwright降级）
- [x] 情感标注器（LLM情感标注，后续可替换为BERT-LoRA降成本）
- [x] 事件检测器（主题聚类 + 因果推理 + 信号强度评估）
- [x] 种子事件库（SQLite先行 + MySQL预留）
- [x] APScheduler定时调度器
- [x] API端点：`GET /signals/hot`, `GET /signals/events`, `POST /signals/crawl`

### V2.2: 知识图谱 — 世界模型构建 ✅

> **目标**：从种子事件构建知识图谱，为Agent生成提供世界上下文

- [x] Neo4j图谱服务部署
- [x] 本体生成器（LLM从文档生成实体类型+关系类型）
- [x] 实体关系抽取器（LLM+NER，文档分块批量抽取）
- [x] 图谱存储与查询接口（CRUD + 图遍历 + 路径推理 + 社区检测）
- [x] 增量更新机制（新种子事件自动更新图谱）
- [x] 图谱可视化界面（简单版）

### V2.3: 人格工厂 — 7层人格与关系网络 ✅

> **目标**：生成具备7层人格结构和真实社会关系的Agent群体

- [x] 人格原型模板库（20+原型覆盖主要人群）
- [x] 7层人格LLM生成器（含Prompt模板）
- [x] 图谱关系注入器（知识图谱实体→Agent知识背景层）
- [x] 批量并行生成器（3-5并发LLM，1000个Agent/5分钟）
- [x] 人格质量校验器（一致性检查+LLM修复）
- [x] 社会关系网络生成器（5种关系类型+4步算法）
- [x] 长期记忆系统（三层：Redis工作记忆+Milvus情景记忆+MySQL语义记忆）
- [x] 记忆整合器（工作→情景→语义 + 遗忘机制）
- [x] 人格版本管理
- [x] API端点：`POST /agents/generate`, `GET /agents/{id}`, `PUT /agents/{id}`

### V2.4: 社交仿真 — 多Agent交互引擎 ✅

> **目标**：让Agent在5个模拟社交平台上自由交互

- [x] 三层Agent架构（Director/Watcher/Injector/Guardian + 市民Agent + 功能子Agent）
- [x] Agent行为决策引擎（感知-思考-行动循环 + LLM Prompt模板）

- [x] 仿真主循环（异步流水线优化）
- [x] ABC三级Agent分层调度
- [x] API端点：`POST /simulation`, `GET /simulation/{id}`, WebSocket推送

### V2.5: 裂变传播 — 舆论动力学 ✅

> **目标**：精确模拟舆论从小众到大众的裂变过程

- [x] 5阶段传播模型（种子注入→初级传播→社群扩散→立场分化→主流化/消退）

## 价值交付路线（待执行）

> 以下阶段以用户可感知价值为核心，优先交付原始需求 Idea 2+3（博主服务）。

### V2.P1: 信号增强风控 — 让风控更准

> **目标**：将V2.1信号采集和V2.2知识图谱的能力接入风控流程，让博主感知到"风控变准了"
>
> **对应原始Idea**：Idea1增强（更好的风控）
>
> **Go/No-Go**：信号采集稳定运行7天，风控评估比MVP准15%+ → 继续；否则降级为MVP+信号辅助

#### 交付物

- [ ] 风控-信号关联模块：文案风险评估时，自动关联当前热点事件（"你的文案与当前微博热搜XX主题相关，可能被关联讨论"）
- [ ] 实体风险链：通过知识图谱，识别文案中的实体→关联争议事件→风险传导提示（"你提到的A品牌近期有B争议，需注意"）
- [ ] 动态风险权重：基于当前热点热度动态调整7维风险权重（如某性别话题正在风口，性别维度权重自动提升）
- [ ] 前端展示：在MVP风控报告基础上增加"热点关联"和"实体风险链"两个展示区域
- [ ] API端点：`GET /risk/context`, `GET /entities/{name}/risk-chain`

#### 技术依赖

- V2.1 信号采集（已实现）
- V2.2 知识图谱（已实现）
- MVP 风险评估流程

#### 验收标准

1. 热点关联准确率>80%（文案确实与关联热点相关）
2. 实体风险链覆盖文案中80%以上命名实体
3. 动态风险权重使高风险文案检出率提升>15%
4. 风控评估响应时间增加<5秒

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 热点关联误报多 | 中 | 设置关联阈值+LLM二次判断 |
| 知识图谱实体覆盖率低 | 中 | 增量扩充+人工补全关键实体 |
| 性能影响 | 低 | 信号/图谱查询异步化 |

### V2.P2: 博主风格画像 — 知道我擅长什么

> **目标**：为博主提供风格画像和选题推荐，这是原始需求Idea2的核心交付
>
> **对应原始Idea**：**Idea2**（深入熟悉博主视频风格→检索热点→推荐选题+预测效果）
>
> **Go/No-Go**：5位博主盲测，3位以上认为选题推荐有用 → 继续；否则只做风格画像，不做选题推荐

#### 交付物

- [ ] 博主账号分析器：输入B站/抖音/小红书账号链接→批量提取历史视频文案→汇总分析
- [ ] 博主风格画像模型：
  - 词汇偏好（高频词、特色表达、口头禅）
  - 表达风格（叙事/说理/情感/幽默/科普等维度评分）
  - 主题偏好（内容领域分布+偏好强度）
  - 受众画像（目标受众特征推测）
  - 风险偏好（历史内容的风险倾向）
- [ ] 选题推荐引擎：当前热点 × 博主风格 → 选题建议 + 切入点 + 预期受众反应
- [ ] 博主风格画像数据模型（MySQL存储）
- [ ] 前端博主画像Tab：风格雷达图 + 选题卡片 + 历史内容时间线
- [ ] API端点：`POST /blogger/analyze`, `GET /blogger/{id}/profile`, `GET /blogger/{id}/recommendations`

#### 技术依赖

- MVP 视频文案提取（yt-dlp）
- V2.1 信号采集（热点数据源）
- V2.2 知识图谱（主题关联）
- LLM分析能力（风格分析+选题生成）

#### 验收标准

1. 博主风格画像与博主自评一致性>0.6
2. 选题推荐相关度>70%（与博主风格和当前热点均相关）
3. 账号分析支持至少3个平台（B站/抖音/小红书）
4. 单个博主分析耗时<3分钟

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 视频文案提取失败 | 高 | 多源降级（字幕→OCR→简介→手动） |
| 风格画像维度不够 | 中 | 迭代增加维度，先做核心5维 |
| 选题推荐泛泛而谈 | 中 | 约束Prompt输出具体切入点+理由 |
| 账号链接解析受限 | 中 | 先支持公开API平台，逐步扩展 |

### V2.P3: 竞品对标 — 知道别人为什么好

> **目标**：为博主提供竞品账号分析和差异化建议，这是原始需求Idea3的核心交付
>
> **对应原始Idea**：**Idea3**（竞品账号对标→拆解成功要素→给出建议）
>
> **Go/No-Go**：竞品分析要点与博主自评重合度>60% → 继续；否则简化为数据对比，不做深度拆解

#### 交付物

- [ ] 竞品账号分析器：输入竞品账号链接→提取历史内容→生成竞品风格画像
- [ ] 成功要素拆解器：LLM分析竞品内容的成功要素（选题策略+表达方式+发布节奏+互动技巧）
- [ ] 差异化建议引擎：博主画像 vs 竞品画像 → 差异点 + 借鉴点 + 差异化方向
- [ ] 选题对比视图：同一热点下博主 vs 竞品的选题角度对比
- [ ] 前端竞品对比Tab：双栏对比 + 差异化建议卡片
- [ ] API端点：`POST /competitor/analyze`, `POST /competitor/compare`, `GET /competitor/{id}/insights`

#### 技术依赖

- V2.P2 博主风格画像（复用账号分析和风格画像模块）
- V2.2 知识图谱（主题关联对比）
- LLM分析能力（成功要素拆解+差异化建议）

#### 验收标准

1. 竞品风格画像与博主主观判断一致性>0.6
2. 成功要素拆解覆盖3个以上维度
3. 差异化建议具体可执行（非泛泛而谈）
4. 对比分析耗时<5分钟

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 成功要素归因不准 | 高 | 标注不确定性，作为参考而非定论 |
| 竞品数据量不足 | 中 | 结合公开数据+人工补充 |
| 差异化建议太泛 | 中 | Prompt约束+具体示例引导 |

### V2.P4: 效果预测与仿真验证 — 发前预测效果，系统自证可信

> **目标**：1）为博主服务增加轻量效果预测；2）验证仿真可信度；3）完成数据库基础设施迁移
>
> **对应原始Idea**：Idea2（预测效果）+ Idea5（验证Agent认知完善度）
>
> **Go/No-Go**：轻量仿真效果预测与实际偏差<40%，回测方向准确率>55% → 继续；否则暂停效果预测，先修复仿真质量

#### 交付物

- [ ] 轻量仿真模式：100 Agent × 6小时仿真（成本¥0.5-1/次，耗时<5分钟），用于选题效果预测
- [ ] 选题效果预测：输入选题+切入点 → 轻量仿真 → 预测互动量级+受众反应+风险
- [ ] 仿真回测框架：用历史事件回测仿真准确度（3-5个真实案例）
- [ ] 多轮一致性检查：同一事件3次仿真，结果一致性评估
- [ ] SQLite → MySQL 数据库迁移（博主服务的用户数据需要更可靠的存储）
- [ ] 仿真结果可信度标注（在报告中标明置信度和不确定性）
- [ ] API端点：`POST /blogger/{id}/predict`, `POST /simulation/quick`, `GET /validation/backtest`

#### 技术依赖

- V2.3-V2.5 仿真引擎（已实现，需增加轻量模式配置）
- V2.P2 博主服务（效果预测的使用方）

#### 验收标准

1. 轻量仿真完成时间<5分钟，LLM成本<¥1/次
2. 效果预测方向（正向/中性/负向）与实际偏差<40%
3. 回测案例中仿真方向准确率>55%
4. MySQL迁移完成，零数据丢失
5. 多轮仿真一致性>60%（3次中2次方向一致）

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 轻量仿真结果不够准确 | 高 | 标注不确定性，作为参考趋势而非精确预测 |
| 回测数据不足 | 中 | 优先选择有完整传播路径的热点事件 |
| 数据库迁移风险 | 低 | 先备份，分批迁移，保留回滚方案 |

### V2.P5: 趋势预测与决策辅助 — 看到舆论走向

> **目标**：从仿真中提取趋势预测，支持反事实推演，这是远期愿景的核心交付
>
> **对应原始Idea**：远期愿景（社会模拟器）
>
> **Go/No-Go**：短期预测方向准确率>65%（3轮共识） → 继续；否则降低预测粒度+增加不确定性标注

#### 交付物

- [ ] 4阶段趋势预测引擎（态势感知→模式识别→走势预测→决策建议）
- [ ] 5种舆论模式分类器（快速爆发/缓慢升温/争议分裂/短暂热度/持续发酵）
- [ ] 短/中/长期走势预测（含概率分布+不确定性标注）
- [ ] 风险等级评估（红/橙/黄/绿）
- [ ] 反事实仿真引擎（多分支创建+干预注入+并行仿真+结果对比）
- [ ] 决策建议生成器（应对策略+时机建议）
- [ ] 报告生成引擎（4类报告+7种可视化组件+HTML/PDF/JSON输出）
- [ ] 多轮仿真共识机制
- [ ] 人工审核入口
- [ ] API端点：`POST /report/risk`, `POST /report/simulation`, `POST /simulation/{id}/branch`

#### 验收标准

1. 短期趋势方向预测准确率>65%（基于历史回测）
2. 反事实仿真3个分支对比完成<90分钟
3. 报告生成<1分钟
4. 预测不确定性标注覆盖率100%

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 预测准确性不够 | 高 | 多轮共识+不确定性标注+历史回测 |
| 反事实仿真成本高 | 中 | 使用较少Agent(500)+较短时长(12h) |
| LLM分析不稳定 | 中 | 3阶段JSON解析+重试 |

### V2.P7: 多模态扩展 — 视频画面也能审

>
> **Go/No-Go**：关键帧覆盖率>90% → 继续；否则多模态作为实验功能

#### 交付物

- [ ] 视频关键帧提取（FFmpeg + 场景切换检测）
- [ ] 关键帧OCR（PaddleOCR）
- [ ] 画面风险评估（视觉内容审核：敏感图像识别）
- [ ] 音频情感分析（faster-whisper转写 + 情感模型）
- [ ] 视频+文案综合评估

#### 验收标准

1. 关键帧提取覆盖率>90%
2. OCR准确率>85%
3. 音频转写WER<10%

#### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 视觉审核模型不准 | 高 | 人工审核兜底 |
| 音频情感分析难 | 高 | 降级为文本情感分析 |

## Go/No-Go 决策点总览

| 阶段 | Go条件 | No-Go处理 |
|------|--------|----------|
| V2.P1 | 信号采集稳定7天，风控评估比MVP准15%+ | 降级为MVP+信号辅助 |
| V2.P2 | 5位博主盲测，3位以上认为选题推荐有用 | 只做风格画像，不做选题推荐 |
| V2.P3 | 竞品分析要点与博主自评重合度>60% | 简化为数据对比，不做深度拆解 |
| V2.P4 | 轻量仿真效果预测与实际偏差<40% | 暂停效果预测，先修仿真质量 |
| V2.P5 | 短期预测方向准确率>65%（3轮共识） | 降低预测粒度+增加不确定性标注 |
| V2.P6 | 1000节点大屏渲染<2秒 | 渐进式渲染 |
| V2.P7 | 关键帧覆盖率>90% | 多模态作为实验功能 |
