# VibeUtopia 蓝图路线图

## 文档定位
- 本文档在主线中的角色：定义产品各阶段目标、交付物、Go/No-Go规则和验收标准
- 与"发前风控优先"的关系：每个阶段必须回答"是否提升风控准确率"

## 本文档边界
- 本文档负责：阶段划分、交付物、验收标准、Go/No-Go规则、依赖关系
- 本文档不负责：功能需求细节（见`01_产品需求文档(PRD).md`）、技术架构细节（见`02_系统架构设计.md`）

## 对准确率的直接贡献
- 机制1：每阶段有明确的准确率提升目标，确保演进方向不偏离
- 机制2：Go/No-Go规则确保每个阶段的投入有可验证的产出
- 验证方式：回测对比、人工复检、一致性检查

## 总览

| 阶段 | 主题 | 核心交付 | Agent规模 | 平台覆盖 | 对准确率的贡献 |
|------|------|----------|-----------|----------|---------------|
| **1** | 回归核心 | 单入口工作台+核心流程+回测案例库 | ~100 | 5核心平台 | 建立准确率基线 |
| **2** | 深度打磨 | 5核心平台深度覆盖+平台权重 | ~500 | 5核心平台 | 提升评估质量（先深后广） |
| **3** | 模型+人生故事 | 人生故事人格+ChromaDB+新API | ~2000 | 5→11平台 | Agent更真实→仿真更准 |
| **4** | 效果提升 | Memory Stream+平台浸泡 | ~2000 | 11平台 | Agent反应更稳定→准确率提升 |
| **5** | 规模化仿真 | GA-S3 Group Agent+极化检测 | ~10000 | 11→25+平台 | 更大样本→更稳定的结果 |
| **6** | 扩展功能 | 博主历史、竞品对比等 | - | — | 附加价值（后置） |

> 已完成的MVP和技术底座（V2.1-V2.5）成果保留，但后续演进严格按"发前风控优先"原则裁剪。

## 阶段1：回归核心 — 单入口串联

> **目标**：将入口收敛为1个，核心流程跑通，建立回测案例库并测出准确率基线
>
> **Go/No-Go**：3个测试案例风险等级正确率≥2/3，且 docker-compose up ≤10分钟跑通 → 继续；否则继续修核心流程

### 交付物

- [ ] Vue3 + Naive UI 暗色主题前端，单入口"内容预审工作台"
- [ ] 完全废弃Streamlit前端
- [ ] 三种输入模式：仅视频 / 仅文案 / 混合输入
- [ ] 核心流程串联：上传→视频理解→文案理解→舆论推演→风险报告
- [ ] **建立回测案例库（20+真实历史案例）**，为全阶段提供准确率验证基准
- [ ] 后台模块自动串联，用户无感
- [ ] 移除多余用户入口和页面
- [ ] 移除PaddleOCR/PaddlePaddle本地依赖，改用API或本地GLM-OCR
- [ ] 移除yt-dlp（仅支持本地视频）
- [ ] 移除Redis依赖

### 验收标准（量化版）

1. 3个测试案例（高/中/低风险各1个）报告风险等级正确率 ≥ 2/3
2. 开发者在新机器使用 `docker-compose up` 到跑通流程 ≤ 10分钟
3. 用回测案例库（20+案例）跑出第一版准确率基线（不设要求，仅记录）
4. 报告包含7维风险评级+证据链+改写建议

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 前端重构工作量大 | 中 | 优先核心流程，可视化渐进增强 |
| 移除依赖导致功能回退 | 低 | API替代方案提前验证 |

## 阶段2：深度打磨

> **目标**：不急于铺开平台，而是将5大核心平台做深做透，引入平台权重体系，建立Prompt版本管理
>
> **Go/No-Go**：回测案例库命中率≥60%，且P0平台影响占比≥70% → 继续；否则继续打磨单平台

### 交付物

- [ ] P0核心平台深度覆盖：微博、B站、小红书、抖音、知乎（共5个平台）
- [ ] 原型扩展：每平台原型从6个扩展到20+个（覆盖主流/争议/极端/边缘/跨界群体）
- [ ] 平台权重体系引入：不同平台的结果按权重（P0=1.0）影响总风险分
- [ ] 每个平台：人格模板 + prompt模板 + 模拟器 + 传播特征
- [ ] Prompt版本管理机制：支持 A/B Test 对比不同 Prompt 效果

### 验收标准（量化版）

1. 5个核心平台每平台拥有 ≥ 20 个具备差异化的人格原型
2. 回测案例库（20+案例）的风险等级命中率 ≥ 60%
3. 同一测试案例在不同平台预测出的情绪有明显可辨识的差异
4. P0平台（权重1.0）的评估结果在总分中占比 ≥ 70%

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 平台特性差异大，模拟器难统一 | 中 | 统一PlatformAction接口+平台特化适配 |
| 原型设计工作量大 | 中 | 参考CGSS人口统计+LLM辅助生成 |

## 阶段3：模型优化 + 人生故事生成

> **目标**：接入最新多模态API，引入人生故事驱动人格系统，让Agent更真实；向 P1 平台渐进扩展
>
> **Go/No-Go**：A/B回测对比，人生故事Agent命中率提升≥15%，且ChromaDB延迟≤100ms → 继续；否则保留属性Agent

### 交付物

- [ ] 接入最新多模态API（Qwen3-VL-Plus / GLM-5V / DeepSeek-V4）
- [ ] 接入阿里Paraformer API（音频转写主力）
- [ ] 模型路由策略：按任务类型自动选模型+硬件自适应
- [ ] **人生故事驱动人格系统**：
  - AI访谈生成器（A-tier Agent，6轮结构化访谈→数万字人生故事）
  - 人口统计采样+LLM丰富（B-tier Agent）
  - 模板变体+递增扩展（C-tier Agent）
  - 人生故事→Memory Stream记忆条目转化
  - ChromaDB向量检索接入（替代Milvus）
  - 人格完善性自动验证流水线（7维度+Big Five一致性）
- [ ] 报告质量优化：更可操作的风险标注和修改建议

### 验收标准（量化版）

1. A/B 回测证明：人生故事驱动的Agent 比 属性标签Agent 的命中率提升 ≥ 15%
2. 人工抽样评审人生故事质量评分 ≥ 7/10
3. ChromaDB 检索延迟 ≤ 100ms（在1000+记忆条目下）
4. 多模态API在 画面理解、OCR、音频转写 测试各1个案例完全正确

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 人生故事生成成本高 | 中 | A-tier仅用于1-2%核心Agent |
| API模型版本更新频繁 | 低 | 模型路由支持配置化切换 |

## 阶段4：效果提升

> **目标**：Memory Stream+平台浸泡让Agent反应更真实稳定；完成 P1 平台覆盖
>
> **Go/No-Go**：Big Five一致性测试 r>0.7，且浸泡效果显著(p<0.05)，总回测命中率≥75% → 继续

### 交付物

- [ ] **平台信息浸泡系统**：Agent初始化后模拟刷平台7-30天，吸收热点形成近期态度
- [ ] Stanford Memory Stream + Reflection机制完整实现
- [ ] Agent间社交网络构建（基于Neo4j GraphRAG）
- [ ] 传播推演可视化（D3.js力导向图）
- [ ] 历史报告对比
- [ ] GPU加速音频转写（Pro/Ultra模式）

### 验收标准（量化版）

1. Big Five 性格量表重复测试 r > 0.7
2. 浸泡Agent vs 未浸泡Agent 对热点话题的反应差异具有统计学显著性（p < 0.05）
3. 完成11个平台（P0+P1）的人格模板和模拟器覆盖
4. 总体回测案例命中率 ≥ 75%（较上阶段继续提升）

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 浸泡仿真成本高 | 中 | 简化浸泡（3天/20帖/天）作为默认 |
| Memory Stream检索慢 | 低 | ChromaDB向量检索+重要性过滤 |

---

## 阶段5：规模化仿真

> **目标**：Agent规模递进到万级，通过Group Agent扩展到等效十万级；扩展 P2 平台
>
> **Go/No-Go**：3次独立仿真一致性≥60%，且10000 Agent仿真≤40分钟，回测命中率≥85% → 继续

### 交付物

- [ ] Agent规模递进：100→500→2000→10000
- [ ] GA-S3 Group Agent机制（统计模型替代相似Agent，一个群组Agent代表10-100个相似个体）
- [ ] 多轮仿真优化：传播5阶段模型
- [ ] 极化检测与舆论转折预测
- [ ] 批量分析优化

### 验收标准（量化版）

1. 3次独立仿真，风险等级判断一致的案例比例 ≥ 60%
2. 10000 个 Agent 的仿真任务能在 40 分钟内跑完
3. Group Agent 等效个体数证明达到 10万 级别
4. 总体回测案例命中率冲刺至 ≥ 85%

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 大规模仿真LLM成本过高 | 中 | C-tier用规则引擎+Group Agent统计模型 |
| Group Agent统计模型不准 | 中 | 小规模对照验证后逐步扩展 |

## Go/No-Go 决策点总览（量化阈值）

| 阶段 | Go条件（必须全部满足） | No-Go处理 |
|------|------------------------|----------|
| 阶段1 | ① 3个测试案例评估正确率≥2/3<br>② `docker-compose up` ≤10分钟跑通 | 继续修核心流程，不进入阶段2 |
| 阶段2 | ① 每平台≥20原型<br>② 回测命中率≥60%<br>③ P0平台影响分占比≥70% | 继续深化核心单平台，暂不扩展 |
| 阶段3 | ① A/B回测命中率提升≥15%<br>② ChromaDB延迟≤100ms | 保留属性Agent，人生故事降级为实验 |
| 阶段4 | ① Big Five一致性r>0.7<br>② 浸泡效果统计显著<br>③ 回测命中率≥75% | 简化记忆与浸泡机制 |
| 阶段5 | ① 3次独立仿真一致性≥60%<br>② 1万Agent仿真≤40分钟<br>③ 回测命中率≥85% | 控制仿真规模，不再强求扩展 |

---

## 仿真启用与保留条件

- **启用条件**：静态评估达到风险阈值或用户主动选择深度分析
- **保留条件**：仿真相对静态评估在回测中带来稳定准确率提升
- **降级条件**：若提升不稳定，保留热点关联与实体风险链，减少仿真成本

## 关键流程/结构

- 输入：前一阶段完成的交付物和验收结果
- 处理：按阶段目标开发→验收→Go/No-Go决策
- 输出：通过验收的阶段交付物

## 依赖与降级

- 依赖：多模态API可用性、LLM API可用性、硬件条件
- 失败降级策略：每个阶段有明确的No-Go处理方案，不会因某个阶段失败导致整体停滞

## 验收标准

- 指标：各阶段验收标准见上文
- 阈值：Go/No-Go条件中定义
- 通过条件：所有验收标准达标+Go/No-Go决策通过
