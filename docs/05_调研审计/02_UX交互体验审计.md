## 1. 执行摘要

VibeUtopia 前端已经具备一个**视觉完成度较高**的数据密集型工作台：三栏布局、分析流水线动画、风险仪表盘、传播推演图、极化曲线等都已落地，暗色科技感符合设计文档（`13_前端升级设计.md:24-28`）的定位。

但从「个人创作者第一次使用」走查来看，产品目前处于 **"功能堆满、任务走不通"** 的状态。核心结论：

| 维度 | 评分 | 一句话判断 |
|------|------|-----------|
| 视觉与氛围 | ★★★★☆ | 暗色渐变、流水线动画、ECharts 仪表盘完成度高 |
| 任务流连通性 | ★★☆☆☆ | 5 个已开发组件未接线，改写→验证闭环断裂 |
| 反馈与错误态 | ★☆☆☆☆ | 错误状态在 store 里写了但**没有任何 UI 读取**，失败是静默的 |
| 信息架构 | ★★☆☆☆ | 右栏 12 个区块纵向堆叠，无渐进披露；导航只有一个路由 |
| 可理解性 | ★★☆☆☆ | "Tier / 11维 / 反事实仿真 / 极化指数 / 信号ID"等黑话裸露 |
| 无障碍 | ★☆☆☆☆ | 全库仅 1 处 `alt`，无 aria / 键盘导航 / 焦点管理 |
| 文档一致性 | ★☆☆☆☆ | 用户手册约 40% 功能在 UI 中找不到入口 |

**最严重的 5 个问题（P0）：**

1. **错误完全不可见**：`stores/index.ts:63-71` 维护了 `error` 状态，但全前端无任何组件消费它；`CounterfactualPanel.vue:156-157` 更是 `catch { result.value = null }` 直接吞掉异常。用户遇到失败只会看到界面"没反应"。
2. **反事实仿真传参错误**：`RightPanel.vue:200` 把 `reviewStore.currentTaskId` 当作 `text` 传给 `CounterfactualPanel`，而组件期望的是**原始文案**（`CounterfactualPanel.vue:100-103` → `v3Api.counterfactualSimulate` 的 `text` 字段）。改写验证这条核心链路事实上不可用。
3. **提交后按钮状态错误**：`reviewStore.loading` 只在 POST 创建任务期间为 true（`stores/index.ts:74,88`），任务一旦入队按钮就恢复"开始预审"（`LeftPanel.vue:76-79`）。用户可以重复提交，且无法区分"排队中/分析中/已完成"。
4. **5 个功能组件成死代码**：`HistoryComparison.vue`、`BloggerProfile.vue`、`KnowledgeGraph.vue`、`SignalPanel.vue`、`AnalysisPipeline.vue` 全库无 import。用户手册花了 100+ 行描述的博主画像、竞品对比、历史对比、信号调度、知识图谱（`27_用户手册.md:273-415`）在界面上**找不到任何入口**。
5. **视频上传无失败处理**：`LeftPanel.vue:162-181` 的 `uploadVideoFiles` 循环上传无 try/catch，任一文件失败即中断且 `handleSubmit`（`LeftPanel.vue:183-200`）也无 catch，产生未处理 Promise 拒绝，用户只看到按钮恢复原状。

**总体判断**：当前体验更接近"给工程师看的调试面板"，而不是"给创作者用的发布前风控助手"。PRD 自己也承认 Phase A 面向技术用户（`docs/01_产品与需求/02_产品需求文档_PRD.md:47-59`），但 Phase B 需要的"新手引导 + 零门槛"（同文件 73-81 行明确后置）缺口，恰好是本轮审计发现的主要问题集中区。建议按第 10 节的 P0→P3 路线补齐任务闭环，再谈体验升级。

## 2. 当前用户旅程地图（As-Is）

### 2.1 全局旅程

```
进入页面 → 认知界面 → 输入内容 → 选深度 → 开始预审 → 等待分析 → 看结果 → 改写 → 复验 → 历史对比
   │          │         │          │          │           │          │        │        │         │
 App.vue   三栏同时    LeftPanel  LeftPanel  LeftPanel  Analysis    Workbench RightPanel ??      ??
 无引导    涌现信息    :8-61      :64-72     :74-80     Dashboard   :17-31   :59-203  断链   断链
```

### 2.2 分步走查与痛点

**步骤 0｜落地认知（App.vue:1-55）**
- 界面：顶栏（品牌 + Tier 标签 + 设置）/ 左栏 240px / 主区 / 右栏 320px / 底部状态条。
- 痛点：
  - 无任何 onboarding、示例内容、空态引导。`Workbench.vue:34-36` 空态只有一行灰字"在左侧输入文案或上传视频开始预审"，无按钮、无示例、无"看看示例报告"。
  - 顶栏 `Tier` 标签（`App.vue:10,85-89`）显示 Lite/Standard/Pro/Ultra，**无 tooltip、无解释**。创作者不知道这是硬件档位还是会员等级。
  - 右栏默认展开（`App.vue:70` `rightCollapsed = ref(false)`），但此刻无任何数据，12 个区块标题全部空着或显示"暂无风险数据"（`RightPanel.vue:96`）——首次印象是"一堆空盒子"。

**步骤 1｜输入内容（LeftPanel.vue:4-81）**
- 界面：文本/视频/混合 三 tab（:8-16）、文本域（:19-26）、拖拽上传（:29-48）、深度下拉（:64-72）。
- 痛点：
  - 文本域 placeholder 只说"输入至少10个字符"（:22），**不告诉用户系统会怎么分析、会输出什么**。
  - 字数要求 `>= 10` 的校验（:148）只体现在按钮 disabled，**无字数计数器、无内联提示**；用户输入 9 个字时按钮灰着，不知道差多少。
  - 视频模式支持 `multiple`（:33），但**无文件大小/时长限制提示**（手册写"最大 100MB"，`27_用户手册.md:78`，UI 未体现）。
  - `handleFileSelect`（:153-156）与 `handleDrop`（:158-160）直接 push，**不校验类型/大小/重复**，拖入 .txt 也会进列表。
  - 混合模式（:52-61）的文件列表区**完全缺失**——选了文件后看不到已选文件，也无法删除。
  - 手册承诺的"（可选）选择目标平台"（`27_用户手册.md:53`）在 UI 不存在。API 已支持 `options.platforms`（`api/index.ts:14`），前端从未暴露。

**步骤 2｜选择分析深度（LeftPanel.vue:64-72）**
- 选项：快速 60s / 标准 3min / 深度 10min / 大规模 30min。
- 痛点：
  - 只有时长，**没有代价说明**。手册给出 Agent 数/等效个体（`27_用户手册.md:225-230`）和 LLM 成本概念，UI 完全没有。用户不知道"大规模"意味着什么。
  - 默认 `standard`（:136），但设置弹窗里"默认分析深度"（`SettingsDialog.vue:17-23`）存进 localStorage 后**从未被 LeftPanel 读取**——设置项是死的。

**步骤 3｜提交（LeftPanel.vue:74-80, 183-200）**
- 痛点：
  - 按钮文案三态："开始预审 / 上传中... / 分析中..."（:79），但"分析中"只覆盖 POST 那一瞬（见 P0-3）。
  - `handleSubmit` 无 try/catch（:183-200）。上传失败、提交失败均无用户可见反馈。
  - 提交后**左侧输入不清空、不锁定**，用户可继续改动文本，与正在分析的内容不一致。

**步骤 4｜等待分析（AnalysisDashboard.vue + App.vue:41-47 + WebSocketManager.vue）**
- 亮点：流水线 5 节点动画（:10-45）、当前模块进度（:52-67）、维度进度双列（:69-96）、帧分析预览（:119-146）、序列描述+因果链（:148-194）、风险预警流（:199-229）是同类产品少见的实时透明度。
- 痛点：
  - **无取消/暂停**。深度 10min、大规模 30min 的任务一旦启动只能干等（`27_用户手册.md:41-43`）。
  - **无预计剩余时间**。只有总百分比（`App.vue:46`），不知道"还要等 3 分钟"。
  - WebSocket 降级为轮询时用户**无感知**。`WebSocketManager.vue:66-77` 静默 `startPolling`，`wsFallbackPolling` 状态在 store 里（`stores/index.ts:20`）但无 UI 消费。
  - WebSocket 断线重连只试一次 5s 后（`WebSocketManager.vue:79-87`），失败后永远停在轮询，无提示。
  - 帧预览 `alt="当前帧"`（:132）是全库唯一无障碍属性。
  - `frameType`（:138）、因果链事件 `JSON.stringify(event)` 兜底（:170,188）会把原始对象/英文枚举直接吐到界面上。
  - `delta-score` 配色语义反直觉（:899-905）：`delta-positive`（风险上升）是黄色、`delta-negative`（风险下降）是绿色——逻辑对，但没有图例，"+0.35"配黄色会让用户以为是好消息。

**步骤 5｜解读结果（Workbench.vue:17-31 + RightPanel.vue）**
- 主区：RiskGauge 仪表（200px 固定宽，`RiskGauge.vue:3`）、DimensionRadar 雷达、PlatformReactions 条形图。
- 右栏 12 个区块纵向堆叠（`RightPanel.vue:2-204`）：评估置信度 → 风险详情 → 证据链 → 传播推演 → 极化趋势 → 热点关联 → 实体风险链 → 交叉风险 → 修改建议 → 博主画像摘要 → 决策建议 → 反事实仿真。
- 痛点：
  - **决策建议被埋在第 11 位**（:185-194）。用户最想知道的"能不能发"要滚过 10 个区块才看到。
  - 右栏 320px 内塞 12 个区块，每区块标题 13px 灰字（:310-315），视觉权重完全均等，**无主次**。
  - 风险详情的 `severity-badge` 直接渲染英文枚举（:73 `{{ dim.severity }}`）——界面显示 `orange`、`red` 而非"高风险/极高风险"。
  - RiskGauge 中心显示 `level.toUpperCase()`（`RiskGauge.vue:41`）——`RED` / `ORANGE`，不是中文。
  - 博主画像摘要硬编码假数据（:171"风险偏好：中等"、:179"暂无趋势数据"），有结果就显示，**误导用户以为是真实画像**。
  - 决策理由是模板句（:274-278）"综合风险评分 X 分，共 Y 个风险维度"，**零解释力**——用户看完仍不知道"为什么不能发"。
  - 证据链只显示 3 个统计数（:100-116"证据条目/交叉验证/平均置信度"），**点不开单条证据**，无法看到"哪句话触发了风险"（PRD 承诺的可解释性，`docs/01_产品与需求/02_产品需求文档_PRD.md:43,155`）。
  - 平台反应名称映射表只覆盖 13 个平台（`PlatformReactions.vue:24-38`），后端 28 平台中其余的会显示英文 key（如 `nga`、`wechat_video`）。

**步骤 6｜改写（RightPanel.vue:152-160 + CounterfactualPanel.vue）**
- 修改建议卡片：原文划线 → 绿色建议（:154-159）。
- 痛点：
  - **无法一键应用建议**。没有"复制"、"替换到输入框"、"应用并复验"任何操作，用户必须手抄回左栏文本域。
  - 反事实仿真入口在右栏最底部（:197-203），且因传参 bug 不可用（P0-2）。
  - 即使能用，仿真结果文本 `slice(0, 200)` 截断无展开（`CounterfactualPanel.vue:44,52`）。
  - 仿真失败静默（:156-157），按钮恢复，无任何提示。

**步骤 7｜历史对比（LeftPanel.vue:84-98）**
- 界面：历史列表只显示风险色块 + 时间（:93-94），最大高度 200px（:422）。
- 痛点：
  - **无标题/摘要**——用户无法分辨哪条是"那条美妆视频"，只有时间戳。
  - **无分页/筛选**。API 支持 `page/per_page/risk_level`（`api/index.ts:187-188`），UI 一次拉 20 条硬塞进 200px。
  - 点击历史项只 `fetchResult`（:202-204），**不重置流水线/进度/预警流**，主区仍显示上一次分析的动画状态，造成"这是历史结果还是当前进度？"的认知混乱。
  - `HistoryComparison.vue`（对比组件，239 行，完成度不低）**从未被挂载**，对比功能物理不存在。

**步骤 8｜探索仿真（PropagationGraph / PolarizationChart / EntityRiskTimeline）**
- 有图，但：
  - 传播图（`PropagationGraph.vue`）无图例说明"节点大小=影响力、颜色=阵营"（设计文档 `13_前端升级设计.md:201-203` 有定义，UI 无）。
  - 极化指数（`PolarizationChart.vue`）刻度 0-1 无"这代表什么"的解释（手册 `27_用户手册.md:236-245` 有 4 档解释，UI 无）。
  - 实体风险链（`EntityRiskTimeline.vue`）显示 `风险分数`、`关联维度`、`时间` 三个裸字段，**无证据、无可点击下钻**。

## 3. 信息架构诊断

### 3.1 导航：单路由 = 无导航

`router/index.ts:3-13` 只有一条 `/workbench` 路由。设计文档明确"单路由，无多页面切换"（`13_前端升级设计.md:123-131`），把原 7 个路由收敛进三面板。

问题在于：**收敛之后没有补上"区内导航"**。用户手册描述的 16 个功能模块（`27_用户手册.md:5-22` 目录）全部挤在一个滚动页面 + 一个 320px 侧栏里，没有任何 Tab、锚点、折叠组或命令面板。结果是：

- 用户想找"博主画像"，必须知道它在右栏某个位置（实际上根本没接线）。
- 用户想找"历史对比"，无处可点。
- 没有面包屑、没有"返回"、没有深链（无法分享"这份报告"的 URL）。

### 3.2 层级：信息权重倒挂

按"用户决策优先级"排序应为：

```
1. 能不能发？（决策建议）        → 实际在右栏第 11 位
2. 哪里危险？（风险点+证据）      → 风险详情在第 2 位（合理），但证据不可下钻
3. 怎么改？（修改建议）          → 在第 9 位
4. 为什么？（置信度/传播/极化）   → 反而在第 1/4/5 位
5. 背景信息（热点/实体/画像）     → 挤在中间
```

主区 vs 右栏职责也不清：主区放"总分+雷达+平台分布"（结果摘要），右栏放"维度详情+建议+仿真"（结果深挖），但**平台反应同时出现在主区（`Workbench.vue:20`）和左栏热力图（`LeftPanel.vue:100-120`）**，两处数据同源（`platform_reactions`）却呈现方式不同、口径不同（左栏用 `negative/total` 当 risk，:239），用户会困惑"到底哪个是准的"。

### 3.3 命名与标签体系

| 位置 | 现状 | 问题 |
|------|------|------|
| 顶栏副标题 | "内容预审风控平台"（`App.vue:7`） | 与按钮"开始预审"一致，但与手册"开始分析"（`27_用户手册.md:33`）不一致 |
| 主区标题 | 无页面级标题 | 用户不知道自己在"工作台"还是"报告页" |
| 右栏 12 区块 | 全部用 13px 灰标题 | 无分组、无优先级徽标、无"核心/进阶"分层 |
| 风险等级词 | green/yellow/orange/red × critical/high/medium/low × 低/中/高/极高 | **三套并存**（见第 6 节） |
| 深度选项 | "大规模 (30min)" | "大规模"对创作者无意义，应说"最接近真实发布的推演" |

### 3.4 标签体系（Taxonomy）混乱点

1. **严重度两套枚举**：`RiskDimension.severity` 是 `green|yellow|orange|red`（`api/index.ts:38`），而 `risk_alert.severity` 是 `critical|high|medium|low`（`AnalysisDashboard.vue:328-335`）。同屏出现时用户无法建立映射。
2. **风险分数口径两套**：`overall_risk` 0-100（`RiskGauge`），但置信度是 0-1（`RightPanel.vue:8`），极化指数 0-1（`PolarizationChart`），关联度 0-1（`HotspotList.vue:17`），风险加成又是百分比（:12）。**同一页面至少 4 种数值尺度，无统一格式说明**。
3. **维度名称即黑话**：雷达图轴标签直接是 `dimension.name`（`DimensionRadar.vue:28`），即"政治敏感/法律合规/民族宗教…"（手册 110-135 行），对创作者 OK，但 `dimension_weight`、`risk_score` 字段在 API 里存在（`api/index.ts:44-45`）却无 UI 解释——用户看到"分数 72"不知道是加权前还是加权后。

## 4. 核心任务流走查

### 4.1 任务 A：提交分析

| 指标 | 现状 |
|------|------|
| 最短步骤数 | 4（贴文案 → 选深度 → 点按钮 → 等） |
| 含纠错的步骤数 | 6+（按钮灰了不知道为什么 → 猜字数 → 补字 → …） |
| 断点 | 上传失败无反馈；提交失败无反馈；重复提交无防护 |

**建议**：
1. 文本域下方实时显示 `0 / 10 字（最少）`，不足时按钮 tooltip 说明原因。
2. `handleSubmit` 全链路 try/catch，失败用 `useMessage` 弹红色 alert + 可重试。
3. 提交成功后：锁定输入区 + 显示"任务 #xxx 进行中，预计 3 分钟"+ 提供「取消任务」。
4. 增加"试试示例文案"快捷入口，一键填入 50 字示例。

### 4.2 任务 B：解读结果

| 指标 | 现状 |
|------|------|
| 需要滚动的区块数 | 12（右栏）+ 3（主区） |
| 结论出现在第几屏 | 第 3-4 屏（决策建议在右栏底部） |
| 证据可下钻深度 | 1 层（点风险项展开文字），**无法定位到原文哪句** |

**建议**：
1. **结论前置**：把"决策建议"卡片提到右栏顶部（或主区仪表下方横幅），一句话结论 + 3 个关键风险点 + CTA「去修改」。
2. 风险详情展开时，`evidence_source.location`（`api/index.ts:40` 已有字段）渲染成**原文高亮定位**：文案→文本域跳转高亮，视频→帧时间码。
3. 分数旁统一加"怎么算的" info icon，点开显示权重与归一化说明。

### 4.3 任务 C：改写建议

| 指标 | 现状 |
|------|------|

### 5.2 关键缺陷详述

**缺陷 1：错误黑洞**
```ts
// stores/index.ts:63-71 — 写入
function setError(msg: string | null) {
  error.value = msg
  errorTimestamp.value = msg ? Date.now() : null
}
```
全前端 grep `reviewStore.error` / `error.value` 的消费点 = **0 处**。同样地 `useMessage` / `NAlert` / notification 全库未使用。用户看到的现象是：点按钮 → 转一下 → 恢复原状，什么都没发生。

**缺陷 2：静默吞异常**
```ts
// CounterfactualPanel.vue:156-157
} catch {
  result.value = null
}
```
以及 `LeftPanel.vue:183-200` 的 `handleSubmit` 无 catch，`uploadVideoFiles` 循环内无 catch。

**缺陷 3：完成无仪式感**
`review_complete` 事件只做 `fetchResult + progress=100`（`stores/index.ts:164-168`），页面没有任何"分析完成"的成功态。对 30 分钟的大规模任务，用户切走再回来（无路由持久化、无任务列表）会彻底丢失上下文。

### 5.3 建议的状态设计规范

1. **错误**：顶部全局 `NAlert`（可关闭）+ 出错控件内联红字 + 「重试」按钮。store.error 自动 8s 消失或手动关闭。
2. **成功**：分析完成时右栏顶部决策卡短暂高亮 + `useMessage.success('分析完成，综合风险 72 分')`。
3. **降级**：状态条显示「实时连接已断开，正在用轮询更新（每 3 秒）」。
4. **空态三件套**：插图/图标 + 一句话说明 + 一个动作按钮（"试用示例" / "去提交" / "查看文档"）。
5. **草稿**：输入内容 debounce 写 localStorage，刷新可恢复，提供「清空草稿」。

## 7. 行业 UX 对标与最佳实践

> 调研来源：AnySearch 实时检索（2026-05），含 Nielsen Norman Group、IXDF、AWS 内容审核设计模式、YouTube Studio 案例等。

### 7.1 渐进披露（Progressive Disclosure）

NN/g 经典定义：*把高级/低频功能放到次级界面，降低首屏复杂度*（nngroup.com/articles/progressive-disclosure）。IXDF 2026 版进一步强调"复杂可视化界面中的分层呈现"（ixdf.org/literature/topics/progressive-disclosure）。Jakob Nielsen 近期针对企业仪表盘指出：*"你的产品首屏不应看起来像企业仪表盘"*——渐进披露是更优雅的中间地带。

**对 VibeUtopia 的映射**：右栏 12 区块全量平铺（`RightPanel.vue:2-204`）正是反例。应改为：
- 首屏只露 3 张卡：**结论卡 / Top3 风险 / Top3 改写**
- 其余折叠为「详细分析 ▾」，再按「内容风险 / 舆论推演 / 背景信号」分组

### 7.2 内容审核的可解释性（Explainable Moderation）

研究指出：内容审核系统不仅要标记，还必须**给出可理解的判定理由**，才能获得用户信任与合法性感（ResearchGate《Explainable AI to Mitigate the Lack of Transparency in Internet Moderation》；Meegle《Explainable AI For Content Moderation》）。AWS 内容审核设计模式也强调**分级呈现 + 证据定位**（aws.amazon.com/blogs/machine-learning/content-moderation-design-patterns-with-aws-managed-ai-services/）。

**对 VibeUtopia 的映射**：PRD 自己把"可解释"列为四大特性之一（`docs/01_产品与需求/02_产品需求文档_PRD.md:43`："每个风险判断都有证据链"），但 UI 只给了 3 个统计数字（`RightPanel.vue:100-116`）。**证据的"哪句话"层级完全缺失**——这是产品价值主张与实现之间最大的缺口。

### 7.3 创作者后台范式（YouTube Studio / B站创作中心 / 抖音创作者中心）

共性模式：
1. **发布前检查清单**（Checklist）：逐项 ✅/⚠️/❌，比雷达图更可执行。
2. **指标分层**：首屏 3-5 个核心 KPI，其余进"详细数据"。
3. **对标基线**：你的数据 vs 同类均值（YouTube Analytics 的"与频道平均比较"）。
4. **时间范围控件**：所有数据可切 7/28/90 天。
5. **操作驱动**：每个洞察都带 CTA（"去改标题"），而非纯展示。

**对 VibeUtopia 的映射**：
- 应有「发布前检查清单」式结果视图（11 项逐条 ✅/⚠️/❌）。
- 平台反应应与"同领域内容平均"对比（当前只有绝对值条形图，`PlatformReactions.vue:4-15`）。
- 缺少所有洞察的 CTA 闭环（改写→复验断链）。

### 7.4 数据可视化最佳实践

- **统一数值尺度与格式**：同一页面混用 0-100 / 0-1 / 百分比而无说明，是仪表盘设计常见失误。
- **颜色语义单一化**：当前 delta 分数（`AnalysisDashboard.vue:899-905`）"正值=坏"用黄色，与主流"绿=好/红=坏"一致但缺图例；`severity` 英文裸露进一步削弱颜色编码。
- **可交互下钻**：静态图表价值减半；NN/g 与企业仪表盘研究均强调点击下钻。

## 10. 实施优先级建议

### 阶段一：让任务走通（1-2 周，P0 全量 + P1-1/3/5）

1. 建立全局错误/成功反馈层（useMessage + 全局 NAlert），打通 `stores` 的 error → UI。
2. 修复 `RightPanel.vue:200` 反事实传参；store 增加 `submittedText`。
3. 引入 `taskRunning` 覆盖完整任务生命周期，锁定输入 + 显示 ETA + 支持取消。
4. `handleSubmit` / `uploadVideoFiles` 全链路 try/catch + 文件校验。
5. 结论卡前置 + 改写建议一键应用。
6. 点击历史时重置分析视图状态。

**验收**：从提交到失败/成功任一路径，用户 100% 能看到明确反馈；改写→复验闭环 ≤ 3 次点击。

### 阶段二：让结果可信（2-3 周，P1 其余 + P2-1/2/3/4/6/7）

1. 证据下钻到原文高亮 / 帧时间码。
2. 挂载 HistoryComparison + 历史列表升级（摘要/筛选/分页）。
3. 右栏渐进披露重构（结论 / 清单 / 详情三层）。
4. 术语字典 + 全站中文化 + 风险等级统一。
5. 清理死设置项，接通模型/深度/平台配置。
6. 决策理由改为真实解释（调用 decisionAdvise API）。

**验收**：任意风险结论可在 2 次点击内追溯到触发原句；新用户 5 分钟内完成首次预审且不看文档。

### 阶段三：让产品专业（3-4 周，P2 其余 + P3-1/2/5/6）

1. 发布前检查清单视图（替代/补充雷达图为主视图）。
2. 无障碍基线（aria、键盘、焦点、对比度）。
3. 响应式布局（窄屏抽屉/底部 Tab）。
4. 报告导出（PDF/图片）+ 路由深链分享。
5. 草稿自动保存 + 任务恢复。
6. 图表图例、下钻联动、对标基线（vs 同类均值）。

**验收**：通过键盘可完成全流程；导出报告可直接发给团队评审；窄屏可用。

### 阶段四：删减与收编（持续）

1. 对未接线组件做二选一：接线（BloggerProfile、SignalPanel、KnowledgeGraph）或从用户手册移除对应章节，**消除文档-实现落差**。
2. 移除假数据（`RightPanel.vue:171,179` 博主画像摘要）。
3. 移除生产 console.log，建立前端日志规范。
4. 建立 UX 基线回归清单（本报告第 5 节状态矩阵 + 第 8 节 P0 清单）纳入每次发版检查。
