# UI视觉体系审计

> **文档定位**：调研审计｜视觉层级、色彩、组件一致性审计
> **所属目录**：`docs/05_调研审计/`


> 审计范围：`src/frontend/src/` 全部 `.vue` 组件样式、`styles/main.css`、Naive UI 使用方式、ECharts/D3 可视化着色。
> 审计基准：Ant Design 5 暗色、Material 3 Dark、Carbon g100、Linear、Vercel Geist、Stripe Dashboard 暗色，以及 SOC/威胁情报类专业风控产品的视觉语言。
> 代码依据：全量通读 `App.vue`、`Workbench.vue` 及 18 个组件；脚本统计 25 个源文件中的色值/字号/圆角/间距声明。

---

## 1. 执行摘要

**结论：当前前端是一套"能跑通功能的深色原型"，尚不是一套可维护的视觉体系。** 四条核心判断：

1. **设计令牌层缺失（P0）**。`src/styles/main.css` 全文仅 `@import "tailwindcss";` 一行；全代码库 **0 个 CSS 自定义属性**（`var(--*)` 检索命中 0）；**456 处硬编码十六进制色值、46 个不重复色、94 处 rgba()** 散落在各组件 `<style scoped>` 与 ECharts/D3 配置里。Tailwind 4 已安装（`@tailwindcss/vite`）但**组件内 0 处工具类调用**——工具链与实现完全脱节。
2. **Naive UI 未接入暗色主题（P0）**。全库无 `NConfigProvider` / `darkTheme` / `themeOverrides`。`NTag`、`NButton`、`NList`、`NTimeline`、`NInput`、`NSelect`、`NTooltip` 均以**默认亮色**渲染在 `#0a0a0f` 背景上，形成刺眼的"白块贴黑底"断层，这是截图级最严重的观感缺陷。
3. **风险结果不突出（P0）**。"能不能发"的决策卡埋在右栏 12 个同级 section 之一（`RightPanel.vue` 的 `decision-summary-section`），字号 14px，与"博主画像摘要""热点关联"等权重完全相同；风险总分只出现在 200×200 的仪表盘里（`RiskGauge.vue`），主工作区无头部结论区。**用户 3 秒内无法一眼得到发布结论。**
4. **装饰噪音偏重、数据产品气质不足（P1）**。标题渐变字、卡片毛玻璃（`backdrop-filter: blur`）、节点辉光、3 组脉冲/流动动画、符号图标（⬡◈◉☰▦⟿⚠）并存；同时大量 9–11px 低对比文字（`#444`/`#555`/`#666` 于 `#0a0a0f` 上，对比度约 **1.9:1 / 2.4:1 / 2.7:1**，全部低于 WCAG AA 4.5:1）。这是典型的"赛博感装饰"与"信息可读性"双重问题。

**量化体检**：

| 指标 | 现状 | 健康值 |
|---|---|---|
| CSS 变量 / 设计令牌 | 0 | ≥ 40 个核心令牌 |
| 硬编码 hex | 456 处 / 46 色 | ≤ 20 处（全部进 token） |
| 字号档位 | 9 档（9/10/11/12/13/14/16/18/20px） | 6–7 档，中文正文 ≥ 12px |
| 圆角档位 | 8 档（1/2/3/4/6/8/10/12px） | 3–4 档 |
| 字重使用 | 600×42 / 700×21 / 500×4 / 800×1 | 400 主体 + 500/600 标题 |
| 小于 12px 声明占比 | 约 70%（10–11px 共 68 处） | 中文正文 ≤ 20% |
| Naive 暗色主题 | 未接入 | 接入 darkTheme + themeOverrides |
| 图表色板统一 | 无（ECharts dark 预设 + 零散 hex + d3.schemeCategory10） | 单一 charts token 组 |

## 2. 现状视觉体检（界面观感描述）

### 2.1 整体框架（`App.vue`）
顶部 48px 顶栏：产品名 "VibeUtopia" 为 18px/700 的 **靛蓝→紫渐变文字**（`#6366f1 → #8b5cf6`），旁挂 12px 灰色副标题"内容预审风控平台"；右侧是硬件档位 `NTag`（默认亮色）与圆形设置按钮。主体为 240px 左栏 / 弹性中栏 / 320px 右栏三栏；底栏 28px，内嵌 4px 进度条与百分比。折叠右栏的把手是一个 20×40 的方块，内容是纯文本 `<` / `>` 字符。整体骨架合理（符合 SOC 控制台三栏范式），但**四边框线全部 `#1e1e2e`、面板底 `#0f0f18`、页面底 `#0a0a0f`**，三层几乎无差别的深紫黑，边界全靠 1px 描边，层次偏平。

### 2.2 左栏（`LeftPanel.vue`）——输入区
"文本 / 视频 / 混合"三段式切换是手写 `<button>`（`#1a1a2e` 底、激活态填充 `#6366f1`），textarea 与下拉框也是原生控件重涂，与主按钮（靛紫渐变、圆角 6px、14px/600 白字）混用；同时同文件又使用 `NTooltip`。**同一栏内两套控件体系、两种圆角（4px vs 6px）、两种交互反馈**。历史记录列表仅显示 `RISK_LEVEL` 英文大写标签 + 时间，信息密度极低。底部"平台覆盖"18 格热力图以 `rgba(239,68,68,0.6)` 等半透明色直接作格子背景，低风险格是 `rgba(99,102,241,0.2)`（品牌靛）——**"低风险"被品牌色占用**，语义与强调混淆。

### 2.3 主区（`Workbench.vue` + `AnalysisDashboard.vue`）
主区顶部是约 900px 高的分析流水线面板：渐变底（`#0a0a14 → #0d0d1a → #0a0e1a`）+ `rgba(99,102,241,0.12)` 描边 + 毛玻璃内卡。五步节点为 40px 圆环，激活态有 `nodePulse` 呼吸辉光，连接线有 `flowRight` 流光动画；节点标题 11px（`#555570`），"已完成"徽章 9px。中段是双栏卡片：模块名 16px/700、百分比 20px/800 靛紫；"帧分析预览"含 48×36 缩略图与 Δ 分值；序列描述内嵌因果链箭头 SVG 与紫色行为标签。底部是风险预警流，左侧 3px 色条区分 critical/high/medium/low。**观感：信息量大、层级靠"卡片套卡片 + 发光 + 动效"区分，缺少一条从左到右的阅读主线**；跑分析时五个脉冲/流光同时存在，视觉噪音明显。

结果区 `dashboard-grid` 为 `200px 1fr 1fr`：左是 200×200 仪表盘（分段色环 35/55/75 三阈值），中是雷达图（整面靛蓝），右是平台反应堆叠条（绿/黄/红三段，**中性用 `#eab308` 黄——与"警告"语义撞车**）。

### 2.4 右栏（`RightPanel.vue`）——结论区（问题最集中）
自上而下 12 个 section 全部使用同一个 13px/600/`#888` 的 `.section-title`：评估置信度 → 风险详情 → 证据链 → 传播推演 → 极化趋势 → 热点关联 → 实体风险链 → 交叉风险 → 修改建议 → 博主画像摘要 → 决策建议 → 反事实仿真。**决策建议卡只是左缘 3px 色条 + 14px 粗体标签**（不建议发布 / 暂缓发布 / 修改后发布 / 直接发布），无总分数字放大、无全宽色块、无图标。风险详情行直接输出 `{{ dim.severity }}` ——**界面上会显示英文裸词 `red` / `orange` / `green`**（`RightPanel.vue:73`），属功能级视觉缺陷。

### 2.5 可视化模块
- `RiskGauge.vue`：ECharts `dark` 预设 + 自填色环，指针 + 28px 数字 + 等级标题，是全站唯一"大数字"，但尺寸被限制在 200px。
- `DimensionRadar.vue`：单色靛蓝多边形，填充 `rgba(99,102,241,0.2)`，无阈值环、无维度着色、无图例。
- `PropagationGraph.vue`：D3 力导向，阵营色 `#6366f1`/`#ef4444`/`#888`，边 `#2a2a3e`，节点标签 10px `#aaa`。
- `KnowledgeGraph.vue`：节点用 `d3.schemeCategory10`（亮黄/亮绿/亮橙…）——**与全站靛蓝暗色体系完全异质**，是"拼凑感"最强的一处。
- `PolarizationChart.vue`：四序列折线，**"极化指数"与"支持"同用 `#6366f1`**（仅实线/虚线区分）；轴标 9–10px。
- `BloggerProfile.vue`：第二套雷达 + 趋势线，手写 HTML 对比表格，决策卡与右栏决策卡是两套同义组件。

## 3. 设计令牌审计

### 3.1 现有 token 清单
| 类别 | 现状 | 代表值 |
|---|---|---|
| CSS 自定义属性 | **无** | — |
| `main.css` 全局层 | 仅 `@import "tailwindcss";` | 无 body/滚动条/选中态 |
| Tailwind 配置 | **无** `tailwind.config.*`（v4 需 `@theme`） | 工具类使用 0 |
| Naive UI 主题 | **无** `NConfigProvider` | 亮色默认主题 |
| ECharts 主题 | 零散 `echarts.init(..., 'dark')` + 内联 hex 覆盖 | 无共享 option 工厂 |
| 字体 | 系统栈写死两处 | `-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` |
| 数字对齐 | 零散 `font-variant-numeric: tabular-nums`（3 处） | 未全局化 |

### 3.2 硬编码统计（脚本全量扫描）
- **十六进制：456 处 / 46 个不重复值**。Top：`#6366f1`×60、`#888`×50、`#1e1e2e`×40、`#ef4444`×36、`#22c55e`×30、`#aaa`×21、`#2a2a3e`×18、`#666`×18、`#f97316`×17、`#12121a`×16、`#eab308`×16、`#1a1a2e`×15。
- **rgba()：94 处**（多为半透明品牌色/语义色叠加）。
- 近似色重复定义：中性灰有 `#888 / #aaa / #ccc / #e0e0e0 / #e0e0ec / #c8c8d4 / #c0c0d0 / #b0b0c4` **8 种**，语义边界不明；紫强调有 `#6366f1 / #818cf8 / #8b5cf6 / #a78bfa / #a5b4fc / #c7d2fe` **6 种**；绿有 `#22c55e / #4ade80 / #86efac`，红有 `#ef4444 / #f87171`，橙有 `#f97316 / #fb923c`。

### 3.3 缺失令牌（应建清单）
色彩（bg / surface / border / text / brand / semantic / chart）、字号、行高、字重、间距（4px 基线）、圆角、描边宽度、层级阴影、动效时长与缓动、焦点环、z-index 档、密度（compact/cozy）。建议最小集见 §10。

## 4. 色彩系统

### 4.1 背景层级（现状 → 建议）
| 角色 | 现状 | 问题 | 建议 token | 建议值 |
|---|---|---|---|---|
| 应用底 | `#0a0a0f` | 偏紫黑，与面层差太小 | `--bg-base` | `#0B0D12`（中性偏蓝黑，对标 Carbon g100 `#161616` 的低饱和思路，略更深） |
| 侧栏/面板 | `#0f0f18` | 与底仅差 5 亮度 | `--bg-surface` | `#11141B` |
| 卡片 | `#12121a` / `rgba(15,15,28,0.6)` 混用 | 实底与毛玻璃并存 | `--bg-elevated` | `#171B24` |
| 内凹/输入 | `#1a1a2e` / `#0a0a0f` 混用 | 同类控件不同底 | `--bg-inset` | `#0E1118` |
| 描边 | `#1e1e2e` / `#2a2a3e` | 两档但混用无规律 | `--border-subtle` / `--border-default` | `#232936` / `#2E3648` |
| 浮层 | `#1a1a2e` | 阴影不统一 | `--bg-overlay` | `#1C2230` + `0 8px 24px rgba(0,0,0,0.45)` |

> 原则：暗色产品背景应**中性灰蓝**（Carbon/Linear/Geist 均如此），现用紫黑会让品牌色渗透到"无色"区域，加剧 AI 味/模板感。

### 4.2 文字色与对比度（当前不达标项）
| 用途 | 现状色 | 对 `#0a0a0f` 对比度 | 判定 | 建议 |
|---|---|---|---|---|
| 空状态/次要 | `#444` | ≈1.9:1 | 严重不达标 | 提升至 `#7A8499`（≥4.5:1） |
| 弱文本/时间戳 | `#555` | ≈2.4:1 | 不达标 | `#8B94A8` |
| 标签/轴标 | `#666` | ≈2.7:1 | 不达标 | `#98A1B5` |
| 章节标题 | `#888` | ≈4.3:1 | 勉强（且仅 12–13px） | `#A6AFC2` |
| 正文 | `#aaa` / `#ccc` | 6.3 / 10.7:1 | 达标 | 保留为 `--text-secondary` / `--text-primary` |
| 主文字 | `#e0e0e0` | ≈13.5:1 | 达标 | `#E6EAF2` |
| 品牌强调 | `#6366f1` | ≈4.2:1 | 小字不达标 | 文本场景用 `#A5B4FC`；`#6366f1` 仅作填充/描边 |

**建议文字梯度（5 档收敛）**：`--text-primary #E6EAF2` / `--text-secondary #B7C0D4` / `--text-tertiary #8B94A8` / `--text-disabled #5C6578` / `--text-inverse #0B0D12`。

### 4.3 品牌与语义色
- **品牌**：`#6366f1`（indigo-500）作为唯一强调是合理的，但被同时用作：进度、低风险档、"支持"阵营、低极化阈值、因果链、统计数字、链接、焦点态——**语义过载**。建议拆分：`--brand-600 #6366F1`（填充）、`--brand-400 #818CF8`（描边/图）、`--brand-300 #A5B4FC`（文字）。
- **语义风险四档**（现有值本身可用，需固定命名与阈值）：

| 档位 | 现值 | 建议 token | 建议底/字（chip） | 用途 |
|---|---|---|---|---|
| 安全/绿 | `#22c55e` | `--risk-safe #22C55E` | `bg rgba(34,197,94,0.12)` / 字 `#4ADE80` | 0–29 分，直接发布 |
| 关注/黄 | `#eab308` | `--risk-warn #EAB308` | `bg rgba(234,179,8,0.12)` / 字 `#FACC15` | 30–59 分，修改后发布 |
| 高危/橙 | `#f97316` | `--risk-high #F97316` | `bg rgba(249,115,22,0.12)` / 字 `#FB923C` | 60–79 分，暂缓发布 |
| 严重/红 | `#ef4444` | `--risk-critical #EF4444` | `bg rgba(239,68,68,0.12)` / 字 `#F87171` | 80–100 分，不建议发布 |

- **必须修正的语义冲突**：
  1. `severity-low` 使用 `#6366f1`（品牌色）→ 改用中性 `#8B94A8` 或浅绿 `#86EFAC`，品牌色不再承担"低风险"。
  2. `PlatformReactions` 中性条 `#eab308`（警告黄）→ 中性改 `#4B5568`，正/负仍绿/红。
  3. 热力图低风险 `rgba(99,102,241,0.2)`（品牌靛）→ 低风险用 `rgba(34,197,94,0.18)`，或改用单色透明度阶（推荐后者，避免"绿=数据、黄=警告"双义）。
  4. `delta-positive` 橙 / `delta-negative` 绿在风控语境正确（风险上升为坏），但命名建议改为 `risk-up` / `risk-down`，避免与金融涨跌习惯对撞。

### 4.4 图表色板（缺失，建议 8 色）
现状 ECharts 用 `dark` 预设默认色 + 内联覆盖，知识图谱用 `d3.schemeCategory10`。建议建立 `--chart-1..8`：

`--chart-1 #6366F1`（主序列/极化指数）`--chart-2 #22D3EE`（支持）`--chart-3 #F472B6`（反对——替换现在的红，把红留给风险）`--chart-4 #A3E635`（中立/基线）`--chart-5 #FBBF24` `--chart-6 #38BDF8` `--chart-7 #C084FC` `--chart-8 #94A3B8`。

并约定：**风险序列永远用 §4.3 语义色，分类序列永远用 chart 色板**，两套色永不混用。极化趋势图需解决"极化指数"与"支持"同色问题（现为同 `#6366f1`），按上表分别取 `--chart-1` / `--chart-2`。

## 5. 排版与间距系统

### 5.1 字体
- 现状：`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`（仅 `App.vue`、`AnalysisDashboard.vue` 两处声明，未全局）。
- 问题：中文回退到系统默认（微软雅黑/苹方），**中英文数字混排宽度不稳**；无等宽数字字体，分数/百分比跳动。
- 建议全局栈：

```css
--font-sans: 'Inter', 'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif;
--font-mono: 'JetBrains Mono', 'SF Mono', 'Cascadia Code', ui-monospace, monospace;
--font-numeric: 'Inter', system-ui, sans-serif; /* 配 font-variant-numeric: tabular-nums */
```

分数、百分比、帧号、时间戳统一 `font-family: var(--font-numeric); font-variant-numeric: tabular-nums;`（现仅 3 处使用）。

### 5.2 字号刻度（9 档收敛为 7 档）
| 现用 | 次数 | 建议归并 | 用途 |
|---|---|---|---|
| 9px | 2 | **10px** | 仅角标 |
| 10px | 26 | 11px | meta / 轴标 |
| 11px | 42 | 12px | 辅助正文（中文可读下限） |
| 12px | 49 | 12px / 13px | 正文 / 小标题 |
| 13px | 15 | 14px | 章节标题 |
| 14px | 10 | 14px / 15px | 强调文本 / 按钮 |
| 16px | 6 | 16px | 卡片主标题 |
| 18px | 2 | 20px | 页面标题 |
| 20px | 2 | 28–36px | **风险总分 hero 数字（新增）** |

**建议刻度**：`--fs-2xs 10px` / `--fs-xs 11px` / `--fs-sm 12px` / `--fs-md 13px` / `--fs-lg 15px` / `--fs-xl 18px` / `--fs-2xl 24px` / `--fs-hero 32px`。行高：正文 1.6（中文），标题 1.35，数字 1.0。字重收敛为 400 / 500 / 600 / 700 四档，**删除 800**；正文 400，标签 500，标题 600，分数 700。

### 5.3 间距
现状 gap 集中在 4/6/8px（68 处），但 padding 出现 1–20px 共 11 档。建议 4px 基线：`--sp-1 4px` / `--sp-2 8px` / `--sp-3 12px` / `--sp-4 16px` / `--sp-5 20px` / `--sp-6 24px` / `--sp-8 32px`；卡片内边距统一 16px，卡片间距 16px，section 间距 24px；禁止 3px/6px/10px/14px 这类非基线值（现约 30 处）。

### 5.4 圆角
现状 8 档（1/2/3/4/6/8/10/12）。收敛为 4 档：`--r-sm 4px`（标签、输入、内条）/ `--r-md 8px`（按钮、列表项）/ `--r-lg 12px`（卡片、面板）/ `--r-full 999px`（chip、状态点）。

### 5.5 呼吸感与密度
右栏 320px 内挤下 12 个 section，标题 13px、正文 11px、行距贴紧，属**信息过载密度**。建议：右栏改为「结论区（固定顶部）+ 折叠分组（分析详情 / 仿真 / 画像）」；卡片间距提到 16–20px；每屏保证至少一处大留白承托结论。

## 6. 组件一致性问题

## 7. 数据可视化设计质量

### 7.1 雷达图（`DimensionRadar` / `BloggerProfile`）
现状：单色靛填充 + `echarts dark` 预设轴网，两处重复实现。缺陷：无风险阈值环（60/80 分界）、无维度色区分、无排名引导、标签拥挤时截断不可控。
建议：① 双雷达合并为一个组件，props 控制尺寸；② 轴网加 40/60/80 三条阈值圆环（`--risk-warn/high/critical` 10% 透明度）；③ 面积用 `rgba(99,102,241,0.18)`，折线 `--brand-400` 2px，顶点圆点按维度得分过阈值变语义色；④ 指标名 11px `--text-tertiary`，数值标签 11px `tabular-nums`。

### 7.2 力导向图（`PropagationGraph` / `KnowledgeGraph`）
- 传播图阵营色（支持靛 / 反对红 / 中立灰）可用，但**红=反对 与 红=严重风险** 语义冲突；建议阵营改用 `--chart-2 青` / `--chart-3 粉紫` / `--chart-8 灰`，风险仍走语义色。
- 知识图谱 `schemeCategory10` 亮色刺目（含纯黄 `#fdd835`、亮绿 `#33a02c`），必须换 `--chart-1..8`。
- 共同问题：无图例、无度数/影响力图例（节点半径已映射 influence 但未说明）、标签 9–10px 偏小、背景纯黑盒与面板无过渡。建议：统一画布底 `--bg-inset`、节点描边 `--bg-base` 1.5px、标签 11px `--text-secondary`、右上角图例（色点+名称+含义）、空态已达标可保留。

### 7.3 时间线/流（`EntityRiskTimeline` / `AnalysisPipeline` / 预警流）
Naive `NTimeline` 与手写 `event-dot`、手写 `pipeline-track` 三套并存。建议：预警流（信息密度最高）保持自绘但对齐 chip 与语义色规范；流水线步骤条改为 Naive `NSteps` 或保留自绘但**去掉 connector 流光动画**，只保留激活节点 1px 呼吸；实体时间线保留 `NTimeline`（需接入暗色主题）。

### 7.4 仪表盘与指标区
- `RiskGauge` 分段色环阈值 0.35/0.55/0.75 与决策卡阈值 30/60/80 **不一致**（35/55/75 vs 30/60/80）——必须统一为 30/60/80。
- 指针式仪表读数精度差；建议主视觉改为「大数字 + 横向 4 段阈值条」（见 §8），仪表可降级为辅助。
- `PlatformReactions` 堆叠条缺中性数值标签（只标了 pos/neg），且条高 18px 与右栏 4px 进度条差距过大，不在一个密度体系。

### 11.5 验收标准（视觉 DoD）
1. 任意截图上，「结论词 + 总分」是视觉焦点（字号 ≥ 24px，语义色，位于首屏顶部）。
