# 文档体系与上手体验审计

> **文档定位**：调研审计｜文档结构、上手路径与索引可用性审计
> **所属目录**：`docs/05_调研审计/`


> 审计范围：`docs/` 全部文档、`README.md` / `README_EN.md`、`CONTRIBUTING.md`、`metadata.json`，并与 `src/` 实际代码结构、`.env.example`、`scripts/` 交叉核对。
> 审计视角：信息架构、上手路径（10 分钟可跑通）、术语一致性、文档-代码漂移、用户手册可用性、API 文档准确性、贡献者文档、更新时效。
> 对标：Stripe / Vercel / FastAPI 文档、B 端 SaaS 帮助中心、开发者门户。

## 1. 执行摘要

**总体结论：文档"体量充足、骨架完整"，但"入口即失效、术语分裂、与代码严重漂移"，新用户 10 分钟内几乎不可能跑通并看懂结果。**

- **资产规模**：docs/ 约 40 份 Markdown（设计 16 / 指南 6 / 报告 8 / 根目录专题 8），加上双语 README、CONTRIBUTING，合计约 25 万字级内容。设计文档（尤其 09/10/12）质量较高，有阈值、有验收指标。
- **致命问题**：README「快速启动」章节的 5 处路径/文件全部与仓库实际不符（`frontend/`、`setup.sh`、`start.bat`、`docker-compose.yml`、`REFERENCE.md`）；README 罗列的核心 API（`/api/v1/analyze` 等）在代码中不存在，真实入口是 `POST /api/v1/review`；术语「七维」与「十一维」风险评估在多份文档中互相矛盾。
- **上手实测（桌面推演）**：创作者 10 分钟内卡在环境脚本路径与 API Key；后端开发者按 README 调第一个接口即 404；运维按部署指南找不到根目录 `docker-compose.yml` 与 `Dockerfile`。三条角色路径全部在第 1-2 步断裂。
- **最大结构性风险**：文档没有"文档测试"机制（链接检查、示例可执行性、路径存在性），导致"文档写完即漂移"。多份文档停留在 2026-05-15~17，而代码在 2026-05-25 / 06-12 仍在演进，约 6~8 周的窗口期没有回写。
- **评级**：信息架构 B-，内容深度 B+，准确性 D+，上手体验 D，时效性 C-，贡献者体验 C-。综合 **C（不可直接对外发布）**。

## 3. 文档质量与漂移问题

### 3.1 入口漂移（最严重，逐条核验证据）

| 文档声称 | 仓库实际 | 后果 |
|----------|----------|------|
| `bash setup.sh`（README:141） | 脚本在 `scripts/setup.sh`，根目录不存在 | 第一步失败 |
| `cd frontend`（README:175、CONTRIBUTING:100） | 实际为 `src/frontend` | 前端安装失败 |
| `python -m uvicorn backend.main:app`（README:193） | 代码在 `src/backend/`，需 `PYTHONPATH=src` 或等价配置 | 后端启动失败 |
| `docker compose up -d neo4j`（README:183） | `docker-compose.yml` 在 `scripts/`，根目录无 | 基础设施起不来 |
| 双击 `start.bat`（README:202） | 实际为 `scripts/start.ps1` / `scripts/start.sh`，无 start.bat | Windows 一键启动失效 |
| `REFERENCE.md`（README:389、424） | 不存在（只有 `references/` 目录） | 致谢链接 404 |
| 项目结构树 `backend/`、`frontend/`（README:344-391） | 实际 `src/backend`、`src/frontend` | 结构认知错误 |

### 3.2 API 文档漂移（准确性 D）

- **README / README_EN** 列出 `/api/v1/analyze`、`/api/v1/analyze/v2`、`/api/v1/analyze-video`、`/api/v1/agents/generate`、`/api/v1/simulation/create` 等约 50 个端点；实际 `src/backend/routes.py` 的核心是 `POST /api/v1/review`、`GET /api/v1/review/{task_id}`、`GET /api/v1/history`、`GET /api/v1/models`、`POST /api/v1/upload`、`/api/v1/persona/*`、`/api/v1/memory/*`。**按 README 调第一个接口就是 404。**
- **`03_使用与运维/02_API参考.md` 反而是准确的**（`POST /api/v1/review` 与代码一致），但目录按"阶段1/3/5/6"组织，对新人不友好，且未覆盖 `routes_v3` 大量 `/api/v3/*` 端点的完整清单。
- **双重前缀疑云**：`main.py:59` 挂载 `prefix="/api/v3"`，而 `routes_v3.py` 装饰器又写全路径 `@router.post("/api/v3/analyze-multimodal")`，实际路由会变成 `/api/v3/api/v3/analyze-multimodal`；同文件内 `/fine-grained/status` 等又写相对路径，前缀行为不一致。文档中出现的 `/api/v3/hardware-info`、`/api/v3/model-status`（25_运维手册健康检查脚本）**很可能全部打空**——这不仅是文档问题，运维监控会静默失效。
- **死代码被写进文档**：`routes_story.py`（人生故事）定义了 6 个端点，但 `main.py` **从未 include**，而 `23_API参考` 仍有「人生故事生成端点」章节。
- 部署指南示例 `build: .` 隐含 Dockerfile，但仓库无 Dockerfile；也没有 OpenAPI 导出、没有"以 /docs 为准"的单一事实源声明。

### 3.3 配置与环境漂移

| 来源 | 说法 |
|------|------|
| README 配置表 | 仅 `DEEPSEEK_API_KEY/BASE_URL/MODEL` + DB + Neo4j |
| `docs/16` §4.2 | `LLM_API_KEY` / `LLM_BASE_URL` / `VISION_API_KEY`（虚构命名） |
| `.env.example` 实际 | LongCat / DeepSeek / 阿里 / 硅基流动 / 智谱 / SenseNova / Agnes 七厂商 + `DEFAULT_PROVIDER` + 多 Key 池 |
| `docs/15` | 选型写 LiteLLM、MySQL、ChromaDB；README 技术栈写 SQLite(MVP)/MySQL(V2) |

Python 版本四处打架：README/CONTRIBUTING「3.10+」、`docs/16`「3.11 必须」、`docs/15`「3.11+ 必须」、`docs/24`「3.10+ 推荐 3.12」。包管理器打架：conda+pip（README/CONTRIBUTING）vs uv+pnpm（docs/16）vs npm（README）。端口打架：前端 3000（README）/ 5173（docs/16 start.sh）/ 8080（docs/16 QuickStart）。

### 3.4 时效与版本漂移

- 绝大多数 guides/design 停在 **2026-05-15 ~ 05-17**；`技术白皮书` 更新到 06-12；`src/backend/routes_v3.py` 06-12 仍在改。**约 6-8 周无回写。**
- `CLAUDE.md` 进度表写「V3.2 本地模型部署 🔜 待开发」，而 README / 00 索引 / 15 环境文档写「V3.2 ✅ 2026-05-16 已完成」——**同一仓库两套进度真相**。
- 无 CHANGELOG、无文档 "Last updated" 标注、无文档版本与 git tag 关联。
- `docs/15` 技术债务表自认：「routes.py 76 个旧端点待废弃」「视频上传前端只传文件名字符串」「analyzer 输出与前端期望不对齐」——但 `27_用户手册` 仍写「上传视频文件（最大 100MB）」的完整体验，**手册超前于实现**。

### 3.5 无关/垃圾内容

- **`metadata.json` 是 "scripture burrito" 圣经翻译工程元数据**（含 USFM 书卷清单、翻译系统提示词），与 VibeUtopia 毫无关系，属于误提交残留，对外部贡献者是严重困惑源。
- 根目录散落 `docker_df*.txt`、`docker_img*.txt`、`docker_pull*.txt` 等 20+ 调试残留文件。
- README 致谢列表 `VideoRAG` 重复出现两次（README.md:431-432）。

### 5.3 信息架构问题

1. FastAPI：文档本身就是可运行教程，每章给出"保存为 main.py → 运行 → 看输出"。

### 8.3 优先重写清单（按投入产出排序）

1. **`README.md` 快速启动 + API 一览 + 项目结构**（P0-1/2/7）— 唯一入口，ROI 最高。
2. **`docs/getting-started/01_快速开始.md`**（P0-6）— 新建，含样例输出与截图。
3. **`docs/reference/术语表.md`**（P0-4 + P2-3）— 统一 11 维、阈值、深度、版本号。
4. **`docs/reference/配置参考.md`**（P1-7）— 由 `.env.example` 生成。
5. **`docs/reference/API参考.md`**（P0-2/3 + P1-4）— 由 OpenAPI 生成，废弃手写端点表。
6. **`docs/03_使用与运维/05_用户手册.md`**（P1-5）— 补访问地址、截图、已知限制、案例库入口。
7. **`CONTRIBUTING.md`**（P1-6）— 对齐真实 Git/测试规范。
8. **`docs/README`**（P1-1/2/8）— 修死链、补资产、统一进度表。

10. **`README_EN.md`**（P1-9）— 修编码并与中文同步。

### 8.4 防再漂移机制（比再写 10 份文档更重要）

1. **单一事实源**：端点看 OpenAPI、配置看 `.env.example`、术语看术语表、进度看 CHANGELOG；其余文档只引用不复制。
2. **文档 CI**：markdown-link-check（含文件存在性）、示例 curl 冒烟测试、"文档中的路径必须存在"脚本校验。
3. **Definition of Done**：功能合并必须同步更新：API 参考（自动）+ 术语表（如涉新概念）+ 快速开始（如涉新手路径）+ CHANGELOG。
4. **时效水位**：每份文档头部 `最后更新 / 适用版本 / 负责人`；超过 90 天未验证的指南进入 `needs-review` 清单。
5. **垃圾门禁**：禁止调试 txt、无关 `metadata.json` 进入仓库根；`.gitignore` 补充规则。
