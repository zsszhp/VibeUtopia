# 创作者体验与增长路径

> **文档定位**：本文档以【创作者成功负责人 / 增长产品经理】视角，从目标创作者画像出发，设计完整体验闭环与增长路径。回答的问题是：产品如何插入创作者真实工作流、如何在 10 分钟内制造 Aha moment、如何把风险报告变成「改一句就安全」的具体动作、如何建立信任、如何形成习惯、如何传播增长，以及原始需求中「选题推荐 / 对标账号」的用户价值优先级。
>
> **上游依据**：`docs/01_产品与需求/01_原始需求.md`（党妹、les 等塌方案例）、`docs/01_产品与需求/02_产品需求文档_PRD.md`（11 维风控、证据链、内容预审工作台）、`docs/02_系统设计/10_博主服务.md`（选题推荐/对标账号概念设计，当前后置）。
>
> **外部调研**（AnySearch，2026-08）：创作者工具增长复盘（Canva/CapCut 三条成功定律）、SaaS Aha moment 设计方法论（Appcues）、国内 MCN 与创作者工具生态现状。关键结论已在正文中引用。

## 一、执行摘要

**核心判断**：VibeUtopia 的增长起点不是「做一个更全的风控平台」，而是「在创作者点下发布按钮之前的最后一分钟，替他拦住一颗雷」。个人创作者自助工具优先的定位决定了：**体验必须嵌入「发布前检查」这一动作，价值必须在 10 分钟内可感，报告必须落到「改哪一句」的粒度，信任必须靠证据链而不是权威口吻**。

**六条主线结论**：

1. **工作流插入点**：主插入点是「剪辑完成 → 平台上传」之间的**发布前检查闸口**（Gate）；次插入点是脚本阶段的「预检」与发布后的「复盘对账」。不要试图接管选题、脚本、剪辑全流程——那是 CapCut/飞书妙记/剪映的地盘，我们的地盘是「发布前最后 10 分钟」。
2. **Aha moment（10 分钟剧本）**：用户粘贴一段自己真实（或示例）的争议向口播文案 → 90 秒内看到「第 3 句触发性别议题 / 小红书负面预期 40%」→ 一键采纳改写 → 风险分从 72 降到 28 → 生成一张可分享的「改前/改后对比卡」。Aha 时刻 = **「原来那一句真的是雷，而且改完就安全了」**。
3. **可行动性**：每条风险从「维度+证据」升级为「风险卡三件套」：**触发句原文 + 谁会炸/在哪炸 + 保留创意的 2-3 条改写**，并显示「采纳后风险分变化」。产品承诺不是「告诉你有风险」，而是「帮你把风险改没，且不改掉你的味儿」。
4. **信任机制**：证据链（哪一秒哪一帧哪一句）+ 置信度分级 + 「这是创意选择」的误报豁免通道 + 公开的准确率与漏报误报数据 + 塌方案例复盘背书。原则：**只建议、不越权、可否决、会认错**。
5. **留存与习惯**：把检查做成「发布动作的肌肉记忆」——剪贴板唤起、浏览器扩展、发布前日历提醒、「本周你避开了 3 颗雷」的正向回执、发布后 72 小时「预测 vs 实际」对账单。习惯回路 = 触发（要发布了）→ 行为（粘贴检查）→ 奖励（风险下降 + 平安回执）。
6. **增长飞轮**：内容营销（塌方复盘拆解）拉认知 → 免费「单次快检」体验产品 → 报告卡片带水印形成「输出即广告」→ 创作者圈层口碑与 MCN 批量采购形成 B 端第二曲线。对照 Canva/CapCut 三条定律：具体完成场景（「发布前排雷」）、5 分钟内首次成功（示例报告 30 秒出）、输出自带传播（可分享风险卡）。

**对原始需求 2/3 的优先级结论**：选题推荐（Idea 2）是**留存与差异化增强件**，应做成「安全分加权的选题推荐」而非泛热点推荐，排 P2；对标账号（Idea 3）价值最低，排 P3 或与选题合并。**主线永远是发布前风控**（Idea 1），这与 PRD「仿真是增强不是主线」的决策一致。

## 二、用户画像与工作流

### 2.1 两位典型创作者画像

#### 画像 A：美妆区 UP 主「小柚」（对应原始需求中党妹型风险）

| 维度 | 描述 |
|------|------|
| 平台 | B站 48 万粉，同步小红书、抖音、微博 |
| 内容 | 测评、妆容教程、恰饭广告、品牌联名 |
| 更新节奏 | 周更 1 条主视频 + 3-5 条图文动态 |
| 商业模式 | 品牌商单（占收入 60%）、直播、自有品牌 |
| 核心恐惧 | **广告翻车**（绝对化用语/功效宣称踩广告法）、**不当言论塌方**（性别玩笑、地域梗、历史不当发言被扒）、**连带损失**（商单解约、掉粉、平台限流） |
| 工具现状 | 剪映/CapCut 剪辑，飞书文档写脚本，新榜/灰豚看数据，无任何发布前风控手段 |
| 决策特征 | 害怕风险但更怕「改得没味儿」；愿意为「保住商单」付费；对 AI 说教式建议反感 |
| 一句话需求 | 「帮我看看这条会不会出事，会出事的话告诉我怎么改，但别把我的风格改没了」 |

#### 画像 B：知识区 / 争议话题博主「老 K」（对应原始需求中 les 型风险）

| 维度 | 描述 |
|------|------|
| 平台 | B站 25 万粉 + 公众号 + 知乎，观点输出为主 |
| 内容 | 社会议题评论、历史科普、行业分析，偶尔踩性别/代际/职业争议话题 |
| 更新节奏 | 周更 1-2 条深度视频，日更动态 |
| 商业模式 | 知识付费、课程、平台激励、少量商单 |
| 核心恐惧 | **言论塌方**（一句话被断章取义上热搜）、**人设崩塌**（历史言论被挖坟对撞）、**平台处罚**（限流/删视频/封号）、**法律风险**（名誉侵权、虚假信息） |
| 工具现状 | 自建敏感词表（Excel），靠同行群「人肉互审」，团队 1-2 人 |
| 决策特征 | 极度重视「判断依据」，会逐条挑战 AI 结论；误报会直接卸载；对「平台差异」（B 站能说的微博不能说）有强诉求 |
| 一句话需求 | 「别告诉我这很危险就完了——告诉我哪个平台的哪类人会炸、为什么、证据是什么，我自己决定改不改」 |

### 2.2 创作者真实工作流与产品插入点

创作者完整工作流（以视频内容为例）：

```
选题 → 脚本/文案 → 素材拍摄 → 剪辑成片 → 定标题/封面/简介 → [发布前检查] → 上传发布 → 评论区互动 → 复盘数据
   │        │                                                      │                              │
   └────────┴── 可选前置预检 ──────────────────────────────────────┤                              │
                                                                  │         ┌── 发布后对账 ────────┘
                                                                  ▼         ▼
                                                          ★ 主插入点：发布前闸口 ★
```

**插入点策略（三级，按优先级）**：

| 级别 | 插入点 | 时机 | 产品形态 | 价值主张 | 优先级 |
|------|--------|------|----------|----------|--------|
| **主闸口** | 发布前检查 | 剪辑完成、上传前 10 分钟 | 内容预审工作台（现有主入口）+「粘贴即检」快捷模式 | 拦雷 + 改一句就安全 | **P0** |
| 前置预检 | 脚本阶段 | 写完文案/口播稿时 | 「查一段」轻量模式（纯文本快检） | 在返工成本最低时暴露风险 | **P1** |
| 后置对账 | 发布后复盘 | 发布后 24-72 小时 | 「预测 vs 实际」对账单 | 校准信任 + 喂养习惯 + 传播素材 | **P1** |

**为什么不主插入选题/剪辑环节**：
- 选题与剪辑已有强工具占位（热点宝、剪映、CapCut），正面抢位成本高、胜率低；
- 发布前是创作者**焦虑峰值时刻**，也是付费意愿最强时刻（「这条明天要发，千万别出事」）；
- 发布前检查天然形成**每次发布一次**的高频回访节奏，是习惯养成的最佳锚点。

**工作流兼容性原则**：
1. 不要求创作者改变创作方式——他照常用剪映，照常写飞书文档；
2. 输入形态对齐工作流末端产物：成片文件 / 口播文案 / 标题+简介+标签；
3. 输出形态对齐工作流末端动作：改哪句、删哪帧、标题换个说法——**能直接抄回剪映/发布框的粒度**；
4. 检查时长 < 内容时长的 10%（5 分钟视频 → 检查报告 < 3 分钟出，快检模式 < 90 秒）。

## 三、首次体验剧本（分镜级，10 分钟）

### 3.1 设计原则（外部调研对齐）

依据创作者工具增长复盘（Canva/CapCut 分析）与 Aha moment 方法论：

- **定律 1：具体完成场景**——产品回答的不是「我能做什么」，而是「今天下班前你能完成什么」。我们的场景 = **「发布前把这条内容的雷排掉」**；
- **定律 2：5 分钟内首次成功**——首个成功体验必须极快。Remove.bg 极端案例是 5 秒；我们承诺 **90 秒出首份风险快照，8 分钟内完成一次「改前→改后」闭环**；
- **定律 3：输出即广告**——风险报告卡片本身是可分享的传播素材（带轻水印），看到卡片的人成为下一批用户；
- **去摩擦**：示例内容兜底（Sprout Social 模式），不要求绑定账号、不要求上传成片、不要求付费，**先看到价值再谈注册**；
- **渐进披露**：首访只展示「快检」一条路径，深度仿真/多平台推演/博主画像全部折叠，防止功能巡游杀死 Aha。

### 3.2 十分钟分镜剧本

> 背景：小柚在 UP 主群看到一张「风险报告对比卡」，点开链接落地。老 K 则是搜「视频发布前敏感词检查」进来的。以下以小柚为主视角。

| 分镜 | 时间 | 画面 / 交互 | 用户心理 | 产品动作 | 北极星行为 |
|------|------|-------------|----------|----------|------------|
| **0** | 0:00-0:30 | 落地页：标题「这条视频发出去，会塌方吗？」+ 一张真实感十足的「改前/改后对比卡」示例 + 主按钮「免费排雷一次」+ 次按钮「先看示例报告」 | 「真的假的？看看再说」 | 不要求注册；示例报告预载（Sprout Social 式假数据演示） | 停留 > 20s 或点击任一 CTA |
| **1** | 0:30-1:30 | 三选一入口：① 粘贴文案/口播稿（默认推荐）② 上传视频 ③ 用示例内容试 | 「我不想传 2GB 成片，先贴文案」 | 默认聚焦文本粘贴框；字数限制放宽到 5000 字；示例按钮常驻 | 完成一次输入提交 |
| **2** | 1:30-3:00 | 分析动画：「正在逐句扫描… 识别到 2 处疑似风险点」实时滚动展示扫描到的句子 | 「还挺快，不是假的吧」 | 快检模式只跑静态 11 维评估（不跑仿真）；流式输出扫描进度；**90 秒内必出首屏** | 首屏风险快照展示 |
| **3** | 3:00-4:30 | **Aha 首屏**：整体风险分 72/100（橙）+ 两张风险卡。卡 1：「姐妹们这个粉底液绝了，男的涂了都能变仙女」→ 性别议题 · 高置信 → 「小红书/微博负面预期 40%」+ 3 条改写；卡 2：「这个成分绝对安全，孕妇都能用」→ 广告法/事实错误 | 「卧槽这句真的会炸，我自己都没意识到」 | 风险卡三件套完整呈现（见 4.2）；证据链可展开；置信度徽章 | **展开证据链** 或 **点击任一改写** |
| **4** | 4:30-6:30 | 改写采纳：点击改写 → 右侧出现「改前 / 改后 / 风险分变化 72→28」动效；支持「不太对，换一个」「这是我的风格，保留原句」 | 「改完分真的降了，而且没改掉我的梗」 | 采纳改写即时重评（本地快速重估）；保留原句记入「创意豁免」偏好 | **采纳至少 1 条改写** 或 **行使 1 次创意豁免** |
| **5** | 6:30-8:00 | 生成「排雷完成卡」：改前 72 → 改后 28，避开了「性别议题」「广告法」两颗雷，可保存图片 / 分享到群 | 「这卡发群里装个逼/提醒姐妹们」 | 生成带轻水印的对比卡（输出即广告）；一键复制改后全文 | 保存卡片 / 复制全文 / 分享 |
| **6** | 8:00-10:00 | 收尾转化：「要不要记住你的风格，下次检查更准？」→ 轻量注册（手机号/微信，1 步）；「深度模式」预告（多平台推演、仿真评论区）灰度展示 | 「注册能记住偏好，可以」 | 注册奖励：3 次深度检查额度；引导设置「发布日」进入提醒节奏 | **完成注册** 或 **预约下次检查** |

### 3.3 Aha moment 定义与度量

| 项目 | 定义 |
|------|------|
| **认知 Aha** | 用户意识到「我内容里真的有雷，而且工具能告诉我怎么改还不伤创意」 |
| **行为激活事件（Activation）** | 首次会话内完成：`提交内容 → 看到 ≥1 条风险卡 → 采纳改写或行使创意豁免 → 看到风险分变化` |
| **辅助激活信号** | 展开证据链、保存对比卡、复制改后全文 |
| **目标转化率** | 落地 → 激活 ≥ 35%；激活 → 注册 ≥ 50%；注册 → 7 日内二次检查 ≥ 40% |
| **失败模式** | 首屏全是「维度雷达图 + 技术术语」而无具体句子 → Aha 不成立；快检超时 > 3 分钟 → 流失主因 |

**双画像差异化 Aha**：
- 小柚（美妆）：Aha 触发在**广告法/功效宣称**卡——她立刻联想到「这条商单要被罚」；
- 老 K（知识/争议）：Aha 触发在**证据链展开**——「02:15 这个画面 + 这句话，在微博会被截图断章」。
- 因此 onboarding 需 1 个轻量分流问题（「你最怕哪类翻车？」：商单违规 / 言论塌方 / 平台限流 / 被挖坟），按答案调整风险卡排序与文案口吻（Appcues「个性化路径」实践）。

## 四、核心任务体验设计

### 4.1 任务一：发布前检查（主任务）

**任务定义**：创作者在发布前对「成片 + 文案 + 标题简介」完成一次风险体检，获得可执行的修改方案，做出发布/修改/放弃决策。

**流程与界面骨架**（对齐现有「内容预审工作台」单入口设计）：

```
输入区（粘贴文案 / 上传视频 / 混合） 
   → 快检流（90秒）：11维静态评估 + 敏感词/句级标注
   → 深度流（可选，3-5分钟）：多平台反应推演 + 仿真（对齐 PRD 性能档位）
   → 报告区：总分 + 风险卡列表 + 平台差异 + 改写工作台
   → 决策区：「按建议修改」「保留原句（创意豁免）」「导出报告」「带风险发布（记录在案）」
```

**体验红线**（违者视为体验失败）：
1. **永不阻断**——工具是顾问不是审核员，「带风险发布」永远可点，但记录用户知情；
2. **永不空转**——报告必须落到具体句子/画面/秒数，禁止只给维度分数；
3. **永不越权改写**——改写是「建议」，一键采纳也要显示 diff，用户保留最终编辑权；
4. **永不超时**——快检 90 秒、标准 5 分钟硬顶，超时给「先出部分结果」降级。

### 4.2 任务二：风险卡三件套（「改一句就安全」的核心载体）

每条风险从 PRD 的评估 JSON（维度/证据/建议）升级为面向创作者的**风险卡**：

```
┌─────────────────────────────────────────────┐
│ 🟠 风险卡 #1  ·  性别议题  ·  置信度 82%      │
├─────────────────────────────────────────────┤
│ 触发句（原文）                                │
│ 「姐妹们这个粉底液绝了，男的涂了都能变仙女」   │
│                                             │
│ 谁会炸 · 在哪炸                               │
│ · 微博：性别议题敏感人群，负面预期 40%        │
│ · 小红书：部分用户反感「男的」调侃，预期 25%  │
│ · B站：弹幕大概率玩梗化解，预期 12%           │
│                                             │
│ 为什么（证据链，可展开）                      │
│ · 「男的涂了都能变仙女」将男性气质与「美」     │
│   对立，触碰性别刻板印象强化（11维#6）        │
│ · 参考同类案例：某美妆视频因类似玩笑在微博     │
│   被截图传播（匿名案例库 #27）                │
│                                             │
│ 改写建议（保留你的风格，3 选 1）              │
│ A. 「姐妹们这个粉底液绝了，谁涂谁是仙女」     │
│ B. 「姐妹们这个粉底液绝了，直男看了都想下单」 │
│ C. 自己改一句 → 即时重评风险分                │
│                                             │
│ [采纳 A] [换一批] [这是创意选择，保留原句]    │
│ 采纳后风险分预估：72 → 41（-31）              │
└─────────────────────────────────────────────┘
```

**三件套的设计意图**：

| 组件 | 回答的用户问题 | 信任/行动作用 |
|------|----------------|---------------|
| 触发句原文 | 「你说的是哪句？」 | 可验证，不甩锅给用户 |
| 谁会炸·在哪炸 | 「至于吗？谁会在乎？」 | 把抽象风险变成具体的人和平台（平台差异是老 K 的强诉求） |
| 为什么 + 证据链 | 「凭什么这么说？」 | 对齐 PRD 可解释性；支撑信任 |
| 改写建议 | 「那我怎么改？」 | 可行动性的落点；「保留你的风格」话术降低创意防御 |
| 风险分变化 | 「改了有什么用？」 | 即时正反馈，Aha 的量化锚点 |
| 创意豁免按钮 | 「能不能不改？」 | 尊重创作者主权，反「说教式 AI」 |

**改写建议的体验约束**：
- 每条风险默认给 2-3 条改写，覆盖「最小改动」「更安全」「风格化保留」三档；
- 改写必须**保留原句语气词、人称、梗的结构**（用博主风格画像校准；画像未建立时用句式模仿）；
- 支持「自己改」输入框 + 即时重评（轻量本地重估 < 5 秒）；
- 采纳历史进入用户偏好，后续改写越来越贴他的口吻。

### 4.3 任务三：多平台差异视图

对齐 PRD「平台反应预测」，但降维呈现为创作者语言：

- **平台条形对比**：B 站 🟢 / 抖音 🟡 / 微博 🔴 / 小红书 🟡 / 知乎 🔴（同一句话不同平台预期）；
- **一句结论**：「这条内容 B 站可以发，微博建议改完再发」；
- **平台禁区提示**：「小红书近 30 天对『孕妇可用』功效宣称管控收紧」（信号采集层数据的用户侧呈现）。

### 4.4 任务四：发布后复盘对账（信任飞轮任务）

发布 24-72 小时后推送「对账单」：

```
预测 vs 实际
· 预测风险点 3 个 → 实际争议评论集中点与预测重合 2 个
· 预测微博负面 40% → 实际负面评论占比 35%（校准良好）
· 你采纳的 2 条改写 → 对应句子在评论区零争议
· 你豁免的 1 条 → 出现 12 条相关吐槽（点开看）
```

价值：① 校准信任（预测不是玄学）② 喂养留存（每次发布都有回访理由）③ 产出传播素材（「我用它对了账」的案例内容）。

### 4.5 输入形态矩阵

| 输入 | 覆盖画像 | 时长目标 | 备注 |
|------|----------|----------|------|
| 纯文本粘贴（文案/口播/标题） | 小柚、老 K 均适用 | 快检 90s | **默认推荐路径**，摩擦最低 |
| 混合（文本 + 视频） | 小柚 | 标准 3-5min | 跨模态一致性（PRD P1）在此体现 |
| 视频上传 | 小柚 | 标准 3-5min | 关键帧+OCR+转写（已有能力） |
| 示例内容 | 所有新用户 | 30s | 空状态兜底，保证「无输入也能 Aha」 |
| 粘贴历史爆款链接 | 老 K（挖坟自查） | P1 | 「查查我三年前那条」是强留存钩子 |

## 五、信任与误报处理

### 5.1 创作者为什么会信 AI 的风险判断？

信任不是靠「我们很准」的口号，而是靠**可验证、可挑战、可纠错**的机制叠加：

| 信任支柱 | 机制 | 创作者感知 |
|----------|------|------------|
| **可验证** | 证据链到句/帧/秒（PRD 已定义 evidence_source） | 「它指得出原句，不是瞎扣帽子」 |
| **可量化** | 置信度分级（高/中/低）+ 平台预期百分比 | 「它自己也知道哪些是猜的」 |
| **有依据** | 同类塌方案例库（匿名化党妹型/言论型案例，脱敏引用） | 「确实有人这么翻过车」 |
| **有对照** | 平台差异（同一句话不同平台结论不同） | 「它懂平台，不是一刀切」 |
| **会认错** | 公开准确率/误报率/漏报率（PRD §6 指标对外披露）+ 误报反馈闭环 | 「它敢晒成绩单」 |
| **不越权** | 只建议不强制；「带风险发布」永远可选 | 「决定权在我」 |
| **有背书** | 头部创作者/ MCN 顾问的公开使用案例；行业合规专家审校规则 | 「不是野路子工具」 |

### 5.2 误报处理哲学：「宁可漏提示，不可伤创意」

误报（False Positive）是创作者工具的头号杀手——老 K 类用户被误报 2 次即流失。处理原则：

1. **置信度分级展示，低置信默认折叠**
   - 置信度 ≥ 0.8：默认展开，强提醒；
   - 0.5-0.8：折叠在「其他提示」区，弱语气（「可能有部分用户这样理解」）；
   - < 0.5：不展示或仅进「扫描记录」，不打扰。

2. **创意豁免（Creative Override）**
   - 每条风险卡都有「这是创意选择，保留原句」；
   - 豁免时可选原因标签：「故意的梗」「讽刺/反串」「我的人设」「不认同此判断」；
   - 豁免永久生效于同类句式（学习用户风格边界），并降低后续同型误报；
   - **豁免不惩罚**——不降低评分、不弹挽留、不影响额度。

3. **误报反馈闭环**
   - 「判断不准」一键反馈 → 进入 Prompt 版本管理的回测案例库（已有 `backend/services/prompt_version_manager.py` + A/B 测试设施，可直接复用）；
   - 用户反馈作为标注数据回流，驱动 prompt 版本迭代（changelog 可对用户公开「本月误报率从 12% 降到 7%」）。

4. **风险表达的语气设计**
   - 禁用：「你这是性别歧视」「绝对不能发」等定性宣判式表述；
   - 启用：「这句话在微博可能被理解为……」「部分用户可能会……，是否是你想表达的？」；
   - 内部红线：产品文案中**永不出现对创作者人格/价值观的评判**。

5. **误报的技术侧抑制**
   - 11 维评估的「高敏感维度」（性别/群体/道德）依语境判定，必须结合上下文窗口而非孤立句扫描；
   - 博主风格画像建立后，以历史内容为基线做**个人化校准**（他一贯的讽刺风格不应当成恶意）；
   - 双通道判定：规则/词表（高精度低召回）+ LLM 语境判定（高召回低精度），仅双通道命中才进强提醒。

### 5.3 漏报与信任的平衡

- 漏报（真雷没报）比误报更致命（一次塌方即永久失信），因此**红线五维（政治/法律/民族/事实/平台禁区）不适用「低置信折叠」**，任何命中都强提醒；
- 对高敏感维度才执行「置信度折叠 + 创意豁免」的柔性策略；
- 公开承诺：「红线漏报免费赔」（赔服务额度/人工专家复核一次），把漏报成本变成信任资产。

## 六、留存机制：从工具到肌肉记忆

### 6.1 习惯回路设计

基于「触发-行为-奖励」习惯模型，目标是让「发布前检查」成为像「发之前看一眼封面」一样的无意识动作：

| 回路要素 | 设计 | 对应机制 |
|----------|------|----------|
| **触发** | 与「发布」动作绑定 | 浏览器扩展（打开 B 站/抖音创作中心自动提示）；剪贴板监测唤起（复制长文案弹「查一下？」）；自设「发布日」日历提醒 |
| **行为** | 极低成本的检查动作 | 「粘贴 → 回车」两步完成快检；模板化输入（标题/简介/标签一次填）；历史偏好免配置 |
| **奖励** | 即时正反馈 + 累积成就感 | 风险分下降动效；「避雷成功」回执；「本周你避开了 3 颗雷」周报；连续 4 周「平安发布」徽章 |
| **投入** | 沉淀越多离开成本越高 | 风格画像、豁免偏好、历史报告库、对账记录 |

### 6.2 留存功能清单

| 功能 | 留存作用 | 优先级 |
|------|----------|--------|
| **发布前快捷检查**（两步粘贴） | 降低单次使用成本 → 频次上升 | P0 |
| **风格记忆**（学习采纳/豁免偏好） | 个性化 → 替代品切换成本 | P1 |
| **「平安发布」回执 + 周报** | 正向情绪回路，对抗「风控工具=焦虑贩卖」 | P1 |
| **预测 vs 实际对账单** | 校准信任 + 复访理由 | P1 |
| **历史报告库**（按作品归档） | 内容资产沉淀 | P1 |
| **发布日提醒 / 浏览器扩展** | 行为触发自动化 | P2 |
| **挖坟自查**（查历史爆款） | 激活沉睡用户 + 事件驱动回访 | P2 |
| **团队/MCN 多账号工作台** | B 端留存（账号越多越离不开） | P2 |

### 6.3 留存北极星与阶段目标

- **北极星**：周活跃检查次数 / 用户（WAU checks per user）；
- 阶段目标：激活用户次周留存 ≥ 45%；月留存 ≥ 30%；习惯用户（连续 3 周每周 ≥1 次检查）占比 ≥ 20%；
- 流失预警信号：注册后 7 天未完成第二次检查 → 触发「用你上次的稿子再来一次」再激活序列（Appcues「再参与」实践：具体到「你还没查过你的标题文案」而非泛泛「回来看看」）。

## 七、增长策略

### 7.1 增长飞轮总览

```
内容营销（塌方复盘）──→ 认知与搜索流量
        │                      │
        ▼                      ▼
  看案例产生恐惧与好奇 ──→ 免费快检体验（单次排雷）
                                │
                                ▼
                    Aha：改一句就安全（激活）
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
              注册留存     分享风险卡     口碑推荐
                    │      （输出即广告）      │
                    ▼           │           ▼
                习惯与付费 ◄────┴─── 创作者圈层扩散
                    │
                    ▼
            MCN / 品牌批量采购（B 端第二曲线）
```

### 7.2 渠道打法

#### （1）内容营销：塌方复盘 IP（拉认知，成本最低、最贴原始痛点）

- 系列栏目《发之前，先看一眼》：每期复盘一个公开塌方事件（严格脱敏/公共事件，不做人身攻击），拆解「哪句话/哪个画面埋的雷 → 如果当时做一次检查会提示什么 → 怎么改能保住」；
- 分发：B 站/公众号/知乎/小红书图文，SEO 布局「视频发布前检查」「敏感词检查」「塌方原因」等长尾词；
- 转化钩子：文末附「用你的稿子免费试一次」入口（内容营销 → 免费快检直连）；
- 该栏目同时是**信任建设资产**（展现专业度）与**获客资产**（恐惧+求解是最强动机）。

#### （2）输出即广告：风险卡传播（对齐 Canva 水印 / CapCut 模板定律）

- 排雷对比卡、周报、「连续 N 周平安发布」徽章，均带轻水印与落地链接；
- 卡片内容做成**社交货币**：创作者愿意晒「我避开了什么雷」（利他 + 专业人设）；
- 群场景：UP 主群/运营群内「帮我看看这个」的转发行为天然带新用户。

#### （3）网红圈层：种子用户与口碑案例

- 冷启动锁定 20-50 位「高风险高敏感」中腰部创作者（美妆恰饭区、观点输出区、医疗/财经科普区）——他们恐惧最强、传播力足、对工具容忍度高；
- 免费深度额度换真实使用反馈与授权案例；优先打磨「用它避免了一次商单事故」的真实故事；
- 与创作者社群（UP 主群、运营人社群、知识星球）合作「发布前体检日」活动。

#### （4）MCN 渠道：B 端批量采购（第二曲线）

- 行业背景：国内 MCN 注册增速已降至 2.5%（36氪，2026-04），机构从扩张转向**存量博主的风险管理与商单合规**——「别让我的签约博主翻车」是 MCN 的真金白银诉求；
- 产品形态：MCN 工作台（多账号批量检查、签约博主风险档案、商单合规审查、月度风险简报）；
- 销售切入：先服务 1-2 家中型 MCN 打样（「为 N 位签约博主做发布前体检，季度风险下降 X%」），再行业复制；
- 定价：按账号数订阅 + 专家人工复核增值服务（对齐 PRD 附加服务商业化方向）。

#### （5）场景化增长黑客

- **商单场景**：与品牌方/星图类接单流程结合——「商单文案合规预检」是小柚付费意愿最强场景，可做独立小工具引流；
- **热点场景**：信号采集层数据产品化为「今日雷区提醒」（免费日报）——低门槛高频触点；
- **事件场景**：重大公共事件后 24 小时内发布「相关话题发布避雷指南」（蹭事件但提供避险价值，与产品主张一致）。

### 7.3 增长阶段与指标

| 阶段 | 目标 | 核心指标 | 主要手段 |
|------|------|----------|----------|
| 种子期（0-3 月） | 验证 Aha 与信任 | 激活率 ≥35%，NPS ≥40，误报反馈率 | 塌方复盘内容 + 种子创作者共创 |
| 口碑期（3-6 月） | 自传播启动 | 邀请率/卡片分享率，次周留存 ≥45% | 输出即广告 + 圈层社群 |
| 规模期（6-12 月） | 渠道放大 | 付费转化 ≥8%，MAU 增速 | MCN 渠道 + 商单场景工具 + 品牌合作 |
| 平台期（12 月+） | B 端第二曲线 | MCN ARR，账号留存 | 多账号工作台 + 人工复核服务 |

## 八、需求优先级重排（对照原始需求 2/3 条）

### 8.1 原始四条 idea 的用户价值重估

| 原始需求 | 内容 | 用户价值本质 | 与核心闸口的关系 | 重排优先级 | 结论 |
|----------|------|--------------|------------------|------------|------|
| **Idea 1** | 多人格多平台预测，发布前评估 | **避雷保命**（恐惧驱动，付费意愿最强） | 主线本身 | **P0 不动摇** | 一切体验与增长的锚点 |
| **Idea 2** | 熟悉博主风格 → 热点 → 推荐选题+预测 | **涨粉增收**（贪婪驱动，竞争激烈） | 增强留存与差异化 | **P2** | 做「安全加权的选题」，不做泛热点推荐 |
| **Idea 3** | 对标账号分析拆解 | **学习模仿**（咨询价值，低频） | 弱关联 | **P3** | 并入选题模块或后置 |
| **Idea 4** | Agent 人格完善/爬取认知 | 仿真真实度（内部能力） | 技术增强 | 内部优先级 | 服务于 1 的准确率，不单独立项对外 |

### 8.2 Idea 2（选题推荐）的正确打开方式

**为什么不能做泛选题推荐**：
- 泛热点选题与新榜/热点宝/巨量算数正面竞争，无胜算；
- 选题推荐不解决「塌方」这一原始痛点，拉不动付费；
- 但它是**极佳的留存钩子**（每周打开看选题）和**差异化表达**（别人推荐「什么火」，我们推荐「什么又火又安全」）。

**重定位：安全分加权的选题推荐**：
- 输出形态：「选题卡 = 热度分 × 安全分 × 人设匹配分」，明确标注「安全红线预警：此选题涉及性别议题，切入点建议 X」；
- 与主线共享数据资产：博主风格画像（14 号文档已有概念设计）、热点信号采集层、11 维规则库；
- 触发时机：不抢占创作起点，而在**复盘环节**呈现（「你下周的 3 个候选选题，安全分都帮你看过」）——顺着习惯回路走，不另起炉灶。

### 8.3 Idea 3（对标账号）的处置

- 价值密度低：对标分析是咨询/课程场景的高频需求，但工具化后用户买单意愿弱（「拆解得再好我也做不出第二个党妹」）；
- 建议：P3 后置；若做，以「对标账号的风险结构拆解」为切口（「他为什么翻车/他如何规避」），与塌方复盘内容 IP 共用素材，不单独立大项。

### 8.4 重排后的主线逻辑

```
P0 发布前风控体验（Idea 1）──→ 习惯与留存
        │                          │
        ▼                          ▼
P1 信任体系 + 复盘对账        P2 安全加权选题（Idea 2 重定位）
        │                          │
        └──────────┬───────────────┘
                   ▼
            P3 对标账号 / 扩展服务（Idea 3）
```

**一句话原则**：**先让创作者「活下来」，再帮他「火起来」**。塌方恐惧是刀刃上的付费动机，涨粉欲望是甜点而非主菜。

## 九、P0-P3 建议

### P0（0-3 个月）：把「发布前排雷」做成能用、能爱、能传的最小闭环

| 项目 | 内容 | 验收标准 |
|------|------|----------|

## 十、风险与开放问题

1. **内容安全边界**：塌方复盘内容本身需极严格的公共事件脱敏与法律审校，避免「消费他人塌方」的伦理反噬——建议法务+内容双审机制；
2. **预测准确率天花板**：舆论预测本质是概率产品，对账单必须呈现区间与不确定性（PRD 已定义 uncertainty_sources），避免「预测错一次即信任崩塌」；
3. **平台规则漂移**：各平台审核口径随时变化，信号采集层需建立「平台规则变更 → 规则库更新」的时效 SLA；
4. **付费意愿验证**：小柚（商单驱动）与老 K（人设驱动）的付费点不同，P0 阶段需并行做定价访谈，避免单一画像定价偏差；
5. **与剪映/CapCut 的竞合**：若剪辑工具内置简单敏感词检查，我们的护城河必须建立在「证据链 + 平台差异 + 改写保风格 + 对账校准」的深度上，而非词表扫描。
