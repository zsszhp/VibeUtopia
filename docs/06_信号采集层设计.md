# VibeUtopia 信号采集层设计

## 文档定位
- 本文档在主线中的角色：定义信号采集的完整方案——广度热榜聚合、深度评论爬取、信号增强（事件检测+关联+因果推理），为风险评估提供实时热点上下文
- 与"发前风控优先"的关系：信号采集为风险评估补充实时热点上下文，减少"静态评估盲区"导致的漏报；但信号采集本身不直接产出风险判断，仅被风险评估模块内部调用

## 本文档边界
- 本文档负责：三层信号采集架构（广度/深度/增强）、NewsNow API聚合+RSS-only降级、增量检测、深度评论爬取（API优先+Playwright降级）、事件检测与聚类、信号强度评估、因果链推理、种子事件库、定时调度、数据标准化、异常处理与容错
- 本文档不负责：风险评估逻辑（见`09_分析决策层设计.md`）、仿真增强机制（见`10_仿真增强风控设计.md`）、世界构建与人格工厂（见`07_世界构建层设计.md`）、前端展示（见`13_前端升级设计.md`）

## 对准确率的直接贡献
- 机制1：实时热点信号为风险评估提供上下文，减少"脱离现实"的静态评估误判
- 机制2：深度评论爬取+情感标注为Agent人格模拟提供真实情绪数据，提升仿真可信度
- 机制3：事件关联+因果链推理为风险传播推演提供结构化输入
- 验证方式：回测对比（有信号 vs 无信号评估准确率差异）、信号覆盖率统计

## 关键流程/结构
- 输入：各平台热榜API、RSS源、平台评论数据
- 处理：广度采集（热榜+RSS）→ 增量检测 → 深度爬取（评论+情感）→ 信号增强（聚类+强度+因果）→ 种子事件输出
- 输出：标准化SeedEvent（含多源信号+评论+情感+关联+因果链），供仿真引擎和风险评估模块消费

## 依赖与降级
- 依赖：NewsNow API（热榜聚合）、LLM API（关键词提取/事件检测/因果推理，使用DeepSeek-V4 / Qwen3.6-Plus）、MySQL+SQLite（数据持久化）、ChromaDB（向量检索）、Neo4j（事件关系图，Lite模式可跳过）
- 失败降级策略：
  - NewsNow API不可用 → 降级到RSS-only模式（仅RSS源采集，无热榜聚合，信号覆盖面降低但系统可用）
  - Neo4j不可用 → 跳过事件关系图和因果链存储，事件仍可在MySQL中独立运行
  - LLM API降级 → 关键词提取用TF-IDF规则替代，事件检测用关键词重叠替代，因果推理跳过
  - ChromaDB不可用 → 降级到MySQL全文检索
  - MySQL不可用 → 降级到SQLite（零依赖）

## 验收标准
- 指标：信号采集覆盖率（覆盖多少平台）、增量检测准确率、种子事件输出完整率
- 阈值：热榜聚合覆盖8+平台；RSS-only降级模式覆盖3+源；增量检测误报率<10%
- 通过条件：标准模式下采集覆盖率>70%，降级模式下系统仍可运行

## 1. 设计理念

信号采集层是VibeUtopia感知现实世界的"感官系统"。它需要回答三个核心问题：

1. **现在发生了什么？**（广度信号 - 热搜聚合）
2. **人们怎么看？**（深度信号 - 评论爬取）
3. **意味着什么？**（信号增强 - 事件检测与关联）

设计原则：
- **多源冗余**：同一事件从多个渠道获取，交叉验证
- **轻重分离**：轻量采集实时运行，重量采集按需触发
- **增量优先**：只处理新增/变化的数据，避免重复
- **成本可控**：根据信号强度决定爬取深度
- **降级可用**：NewsNow API不可用时降级到RSS-only模式，系统不因单点依赖而停摆

### 2.3 增量检测机制

**参考来源**：TrendRadar的`detect_latest_new_titles()`。

**核心逻辑**：
1. 获取当前批次所有标题
2. 与历史标题库对比（按`first_time`判断）
3. 识别新上榜标题（新事件）
4. 识别排名变化（事件升温/降温）
5. 识别下榜标题（事件消退）

**数据结构**：

```python
class Signal:
    """标准化信号"""
    signal_id: str                   # UUID
    source_platform: str             # 来源平台
    title: str                       # 标题
    url: Optional[str]               # 原始链接
    rank: Optional[int]              # 当前排名
    rank_timeline: List[RankPoint]   # 排名变化时间线
    first_seen: datetime             # 首次发现时间
    last_seen: datetime              # 最近发现时间
    appearance_count: int            # 出现次数
    is_new: bool                     # 是否新上榜
    signal_type: str                 # hotlist/rss

class RankPoint:
    """排名时间点"""
    timestamp: datetime
    rank: int
```

### 2.5 降级策略：RSS-only模式

当NewsNow API不可用时（网络故障、API下线、限流等），系统自动降级到RSS-only模式：

```python
class BreadthSignalCollector:
    """广度信号采集器（含降级）"""

    def __init__(self):
        self.hotlist_fetcher = HotlistFetcher()
        self.rss_fetcher = RssFetcher()
        self._newnow_available = True

    async def collect(self) -> List[Signal]:
        """采集广度信号，含降级逻辑"""
        signals = []

        # 尝试热榜聚合
        try:
            hotlist_signals = await self.hotlist_fetcher.fetch_all(PLATFORM_IDS)
            signals.extend(hotlist_signals)
            self._newnow_available = True
        except (httpx.TimeoutException, httpx.HTTPStatusError) as e:
            logger.warning(f"NewsNow API不可用: {e}，降级到RSS-only模式")
            self._newnow_available = False

        # RSS源始终采集（降级时为唯一来源）
        rss_signals = await self.rss_fetcher.fetch_all(RSS_FEEDS)
        signals.extend(rss_signals)

        return signals
```

**降级模式对比**：

| 模式 | 信号覆盖 | 平台数 | 数据粒度 | 适用场景 |
|------|---------|--------|---------|---------|
| 标准模式 | 热榜+RSS | 11+平台 | 标题+排名+时间线 | NewsNow API正常 |
| RSS-only模式 | 仅RSS | 3+源 | 标题+摘要 | NewsNow API不可用 |

### 3.4 反爬策略

| 策略 | 实现 | 配置 |
|------|------|------|
| 请求限速 | 每个平台独立的请求间隔 | `rate_limit: {weibo: 2s, zhihu: 3s}` |
| 代理池 | 付费代理服务 + 自建代理 | `proxy_pool: {min_size: 10, max_size: 50}` |
| UA轮换 | 随机User-Agent | `ua_rotation: true` |
| Cookie管理 | 登录态维护与刷新 | `cookie_refresh_interval: 3600s` |
| 请求指纹 | 随机化TLS指纹 | `tls_fingerprint: random` |
| 并发控制 | 每平台最大并发数 | `max_concurrent_per_platform: 3` |

### 4.3 信号强度评估

```python
class SignalStrengthEvaluator:
    """信号强度评估器"""

    def evaluate(self, event: SeedEvent) -> float:
        """评估信号强度 (0-1)"""
        scores = {
            "spread": self._spread_score(event),      # 传播广度: 多少平台出现
            "velocity": self._velocity_score(event),   # 上榜速度: 从0到Top3的时间
            "resonance": self._resonance_score(event),  # 多平台共振: 是否同时多平台热搜
            "engagement": self._engagement_score(event),# 互动强度: 评论数/情感极性
            "persistence": self._persistence_score(event) # 持续性: 在榜时长
        }
        return weighted_average(scores)

    def _spread_score(self, event) -> float:
        """传播广度: 出现在N个平台 → N/11"""
        return len(event.sources) / 11.0

    def _velocity_score(self, event) -> float:
        """上榜速度: 从首次出现到进入Top3的时间越短分越高"""
        # 30分钟内到Top3 = 1.0, 1小时 = 0.8, 3小时 = 0.5, 更久 = 0.2

    def _resonance_score(self, event) -> float:
        """多平台共振: 2个以上平台同时出现 = 高分"""
        # 同时3+平台 = 1.0, 2平台 = 0.7, 1平台 = 0.3

    def _engagement_score(self, event) -> float:
        """互动强度: 评论数多+情感极性大 = 高分"""
        # 基于评论数量和情感分布

    def _persistence_score(self, event) -> float:
        """持续性: 在榜时间越长越重要"""
        # 24h+ = 1.0, 12h = 0.7, 6h = 0.4, <3h = 0.2
```

### 5.3 存储策略

| 存储 | 用途 | 查询模式 | 降级方案 |
|------|------|----------|---------|
| MySQL | 事件元数据、评论、情感数据 | 结构化查询、分页、聚合 | MySQL不可用时降级到SQLite |
| SQLite | MySQL降级方案，零依赖单用户 | 同MySQL | - |
| Neo4j | 事件关系图、因果链 | 图遍历、路径查询、社区检测 | Neo4j不可用时跳过关系图，事件仍可在MySQL中独立运行 |
| ChromaDB | 事件向量索引、语义检索 | 向量相似度搜索 | ChromaDB不可用时降级到MySQL全文检索 |

> 注意：不使用Redis。增量检测状态存储在MySQL/SQLite中，热事件缓存使用内存LRU。

## 8. 异常处理与容错

| 异常场景 | 检测方式 | 处理策略 |
|----------|----------|----------|
| NewsNow API不可用 | HTTP状态码!=200 + 超时 | **降级到RSS-only模式**（仅RSS源采集，系统仍可运行） |
| RSS源不可用 | HTTP状态码!=200 + 超时 | 跳过该RSS源，其他源继续 |
| 全部信号源不可用 | 无新信号产出 | 使用已有种子事件库中的历史数据，风险评估模块仅走静态评估 |
| Playwright被封 | 页面返回验证码/空内容 | 切换代理+Cookie，3次失败后降级跳过 |
| LLM调用超时 | 30秒无响应 | 跳过LLM增强（关键词提取/事件检测/因果推理），用规则替代 |
| 增量检测误判 | 短时间内大量"新事件" | 触发频率阈值告警，人工确认 |
| 情感标注模型异常 | 推理超时/内存溢出 | 降级到LLM情感判断（模型：DeepSeek-V4 / Qwen3.6-Plus） |
| 数据库写入失败 | 异常捕获 | MySQL失败时降级到SQLite；均失败时写入本地文件队列，后台重试 |
| 种子事件过期 | TTL到期 | 自动标记为expired，归档 |
| Neo4j不可用 | 连接失败 | 跳过事件关系图和因果链存储，事件仍可在MySQL中独立运行 |
| ChromaDB不可用 | 连接失败 | 降级到MySQL全文检索 |
