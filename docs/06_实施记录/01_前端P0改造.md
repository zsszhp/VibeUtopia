## 一、改动清单

### 1. 设计令牌层（03 §10.2 Instrument Dark）

| 文件 | 改动 |
|------|------|
| `src/styles/tokens.css` | **新建**。CSS 变量：中性面（bg-base/surface/elevated/inset/overlay、border-subtle/default）、文字四级（text-primary/secondary/tertiary/disabled）、品牌靛（brand-600/400/300/soft）、风险语义四色 + soft 底、图表 8 色、字号 8 档（fs-2xs…fs-hero）、间距 4px 基线（sp-1…sp-8）、圆角 4 档（r-sm/md/lg/full）、动效（dur-fast/base、ease-out）。色值取自审计 §11.2 落地值。 |
| `src/styles/main.css` | 引入 `tokens.css`；补全局 `body` 底色/字色/字体、`.tabular-nums`、全局滚动条 6px、`:focus-visible` 焦点环、`prefers-reduced-motion` 降级。 |

改动涉及的组件样式（App/LeftPanel/RightPanel/Workbench/PlatformReactions/SettingsDialog）已改为 `var(--token)` 引用。

### 2. Naive UI 暗色主题（03 P0-1）

| 文件 | 改动 |
|------|------|
| `src/App.vue` | `NConfigProvider` + `darkTheme` + `themeOverrides` 全站包裹。themeOverrides 与 tokens 对齐：primaryColor `#6366F1`、bodyColor `#0B0D12`、cardColor `#171B24`、borderColor `#2E3648`、textColorBase `#E6EAF2`、borderRadius `8px`、fontSize `13px`；中文字体栈 Inter + PingFang SC / Microsoft YaHei。同时接入 `zhCN`/`dateZhCN` 语言包。 |

### 3. 错误可见性（02 P0-1）

| 文件 | 改动 |
|------|------|
| `src/App.vue` | 全局错误条：消费 `reviewStore.error`（NAlert error）与 `historyStore.error`（NAlert warning），均可关闭，关闭时调 `clearError()`。 |
| `src/stores/index.ts` | `historyStore` 增加 `clearError()`。 |
| `src/components/CounterfactualPanel.vue` | 不再吞异常：catch 中解析 `e.response.data.detail \|\| e.message` 写入 `errorMsg`，以 NAlert（closable）展示；`scoreClass` 阈值同步改为 30/60/80。 |
| `src/components/LeftPanel.vue` | 上传/提交失败写 `localError`，以 NAlert 展示（见第 6 条）。 |

### 4. 反事实传参 bug（02 P0-2）

| 文件 | 改动 |
|------|------|
| `src/stores/index.ts` | 新增 `submittedText`：`submitReview` 时保存 `req.texts` 拼接原文；`reset()` 时清空。 |
| `src/components/RightPanel.vue` | `CounterfactualPanel` 的 `:text="reviewStore.currentTaskId"`（错误）→ `:text="reviewStore.submittedText"`（正确文案）。 |

### 5. 任务生命周期状态（02 P0-3）

| 文件 | 改动 |
|------|------|
| `src/stores/index.ts` | 新增 `status: idle \| submitting \| analyzing \| done \| error`。`submitReview` 成功后进入 `analyzing` 且 **loading 保持 true**（原先 finally 里立即置 false）；失败置 `error` + loading false。`fetchResult` 成功/失败仅在 submitting/analyzing 阶段收口为 done/error（历史查看不影响状态）。`review_complete` WS 消息同步收口。 |
| `src/components/LeftPanel.vue` | 按钮文案状态机：开始预审 / 上传中… / 分析中 xx% / 完成 / 失败，点击重试；`submitting` 与 `analyzing` 期间禁用重复提交（`isBusy`）。按钮配色区分四态。 |
| `src/components/WebSocketManager.vue` | 轮询兜底：进度到 `report` 步时主动 `fetchResult(taskId)`，避免无 WS 时任务永不收口。 |

### 6. 上传容错（02 P0-5 / P2-11）

| 文件 | 改动 |
|------|------|
| `src/components/LeftPanel.vue` | ① `uploadVideoFiles`/`handleSubmit` 全链路 try/catch，失败提示（localError NAlert + store.error 全局条）；② 文件校验：仅 mp4/mov/avi、单文件 ≤100MB、同名同大小去重，非法文件逐条列出原因；③ 文本字数计数器 `N / 2000 字`，超限标红且禁止提交；④ 混合模式补文件列表与删除按钮；⑤ 上传中禁用输入；⑥ 点击历史先 `reset()` 再 `fetchResult`，避免旧进度残留（02 P1-5 顺手修）。 |

### 7. 严重度中文化（03 P0-4 / 02 P1-7）

| 文件 | 改动 |
|------|------|
| `src/utils/labels.ts` | **新建**统一词典：`riskLevelLabel`（green→安全、yellow→注意、orange→较高、red→高危）、`severityLabel`（兼容 critical/high/medium/low 与四色两套取值）、`RISK_THRESHOLDS = {30,60,80}`、`scoreVerdict`（四档结论词+建议）、`scoreLevel`。组件内禁止再散落 map。 |
| `src/components/RightPanel.vue` | `dim.severity` 裸英文徽章 → `severityLabel(dim.severity)`。 |
| `src/components/LeftPanel.vue` | 历史 `risk_level.toUpperCase()` → `riskLevelLabel(item.risk_level)`。 |
| `src/components/HistoryComparison.vue` | 两处 `risk_level.toUpperCase()` → `riskLevelLabel(...)`。 |
| `src/components/AnalysisDashboard.vue` | 删除本地 `severityLabel`，改用共享词典。 |

### 8. 风险结论 Verdict Banner（03 §8）

| 文件 | 改动 |
|------|------|
| `src/views/Workbench.vue` | 主区顶部结论条（约 96px）：左＝结论词 24px/700 语义色 + 处理项数/置信度 + 一句话建议；右＝总分 hero 大数字 48px/700 tabular-nums + 4 段阈值条（0-29/30-59/60-79/80-100，激活段点亮）。四档映射与 30/60/80 一致：可发布 / 建议修改后发布 / 建议暂缓发布 / 不建议发布。 |

| `src/components/RightPanel.vue` | 决策建议四档文案与阈值对齐（暂缓发布→建议暂缓发布等）。 |

## 三、验证结果

| 项 | 命令 | 结果 |

| 类型检查 | `npx vue-tsc -b`（src/frontend） | **0 error**（原 6 error 已清零） |

功能自测路径（代码级核验，UI 留待联调）：

1. 提交 → 按钮「分析中 xx%」禁用 → WS/轮询收口 →「完成」；失败 →「失败，点击重试」+ 全局错误条。
2. 反事实 `:text` 为提交原文（非 task_id）。
3. 历史点击先 reset 进度再拉结果。
4. 上传非法格式/超 100MB/重复文件有逐条中文提示。
5. 严重度全站中文（安全/注意/较高/高危 + 严重/高危/中危/低危）。
