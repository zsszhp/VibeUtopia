## 2. 逐项实施细节

### 2.1 R2-1 评测回归门禁

**入口**：`tests/run_eval_regression.py`（prompts/** 变更时手动触发）。

**数据源**（双源合并）：

| 源 | 期望标签来源 | 案例数 |
|----|-------------|--------|
| `data/backtest/cases.json` | `expected_risk_level` + `risk_score_range` | 25 |
| `data/test/cases/paperwork/*.md` | `回测案例库索引.md` 中「（高/中/低）」→ red/orange/green | 29 |

**运行模式**：

| 模式 | 行为 | 用途 |
|------|------|------|
| `--mode mock` | 关键词启发式 mock LLM，默认 6 条子集 | 离线验证链路与报告产出，**不代表真实准确率** |
| `--mode live` | `assess_risks` 真实 LLM + `calculate_overall_score` | 全量评测（需 API Key） |
| `--mode auto` | 有任一 API Key → live，否则 mock | 默认 |

**双口径**（对应审计 14 §「有效样本」纪律）：

```
valid_accuracy = 命中数 / 有效样本数     # 排除 API 失败样本（429/无 Key/解析失败）
valid_ratio    = 有效样本数 / 总样本数   # 环境完整性，防止 429 污染准确率结论
```

另附 `score_range_accuracy`（落入期望分数区间占比）与 4×4 混淆矩阵。

**输出**：`data/eval/eval_<时间戳>.json` + `.md`，并覆盖 `data/eval/latest.json` / `latest.md`。

**门禁**（可挂 CI）：

```bash
PYTHONPATH=src python tests/run_eval_regression.py --mode live --save-baseline   # 先存基线
PYTHONPATH=src python tests/run_eval_regression.py --mode live \
  --baseline data/eval/baseline.json --max-drop 5    # 跌幅>5 个百分点退出码 2
```

**用法已写入** `docs/03_使用与运维/04_运维手册.md`「评测回归门禁」一节。

**验证**（离线 demo）：

```
模式=mock 总案例=6 有效=6 API失败=0
valid_accuracy=0.8333  valid_ratio=1.0
```

报告中明确标注 mock 模式不代表真实准确率；live 全量数字待有 Key 环境执行后写入 baseline。

### 2.2 R2-2 成本/耗时计量

**新增** `src/backend/services/llm_meter.py`：

- `LLMUsageRecord`：ts / model / provider / call_kind(chat|vlm|image_gen) / task_type / analysis_id / latency_ms / success / error_type / prompt_tokens / completion_tokens / total_tokens
- 原子追加：`os.open(O_APPEND)` + 单次 `os.write` 整行 JSON（`data/metrics/llm_usage.jsonl`），并发安全由进程内锁 + O_APPEND 保证
- `summarize(n)`：最近 n 次分析（按 `analysis_id` 分组；无分组标记退化为最近 n 条调用）的调用数 / 失败率 / 耗时 p50-p99 / token 合计 / 按模型分解；无记录返回 `available=false` 空口径

**接入** `llm_client.py`：

- `_httpx_call` / `_urllib_call` / `_httpx_call_image_gen` / `_urllib_call_image_gen` 计时并解析响应 `usage` 字段（此前被丢弃，对应审计 05 P1-4）；失败记 `error_type`
- 计量写失败仅 debug 日志，**不影响主调用链路**
- `analyzer.run_analysis` 入口 `set_analysis_id(task_id)`，finally 中 reset，使计量自动归属分析任务

**API**：`GET /api/v1/metrics/summary?n=50`（`routes.py`），文档见 `docs/03_使用与运维/02_API参考.md` §5。

### 2.3 R2-3 置信度收敛（四套公式 → 唯一入口）

审计 06 §7.1 的四套并存公式（设计 A 多轮一致性 / 白皮书 B 等权 / 代码 C 加权 / 增强 D 模块计数）收敛为：

| 项 | 处置 |
|----|------|
| C. `confidence_calculator.py` 四因子加权 | **唯一入口**，保留并扩展 |
| D. `enhanced_analyzer` 模块计数（0.5+0.15+0.1+0.15+0.1） | **弃用**，改为调用 `ConfidenceCalculator`；模块信号降级为 `confidence_sources` 注释（只解释不加成），消除「开启功能越多越可信」的单调性错误 |
| A/B 文档公式 | 在 `confidence_calculator.py` 模块头注明已收敛，文档口径以代码为准 |

**输出扩展**（`calculate()` 返回值新增字段，旧字段 `overall_confidence`/`factors`/`breakdown` 不变，API 兼容）：

- `confidence_level`：`low` / `medium` / `high` / `very_high`（阈值 0.50 / 0.70 / 0.85；0.6 与 0.8 两条线与前端旧展示带兼容）
- `reason_labels`：原因标签，如 `consistency`（一致性高）、`low_consistency`（分歧）、`cross_validation`（交叉验证）、`no_cross_validation`、`data_quality`、`low_data_quality`、`platform_validation`、`weak_platform_validation`、`full_coverage`、`partial_coverage`

**报告/前端对齐**（不破坏 API，仅增字段）：

- `AnalysisSummary.confidence_json` 随 `calculate()` 自动带上新字段，`GET /api/v1/review/{task_id}` 的 `confidence_breakdown` 透传
- 前端 `ConfidenceBreakdown` 类型补 `confidence_level` / `reason_labels` / `overall_confidence`（可选字段）
- `RightPanel.vue`：置信度标签优先用服务端 4 级（极高/高/中/低置信），无该字段时回落旧阈值逻辑；新增原因标签展示（中文化映射）
- 前端 `npm run build` 通过

### 2.4 R2-4 红线 76+ 强制（审计 06 P0-3）

**规则**（与 Prompt「触碰即 HIGH 76+」标定、30/60/80 展示阈值语义一致，red=高风险档）：

1. **维度分自洽**：红线维度（政治敏感/法律合规/民族宗教/事实错误/平台禁区）判为 red/high 时，维度分强制抬升到 ≥76（`severity.enforce_redline_dim_score`），severity 与分数区间不再矛盾
2. **总体分保底**：任一红线维度 red/high → overall 至少 76（`severity.redline_triggers_floor` + `calculate_overall_score` 规则 3），在既有「HIGH 保底 50」「多 HIGH +15」之后执行

非红线维度 red 只触发既有保底 50，不强制 76（避免过度抬升）。旧词表 `high`/`critical` 经 `is_high_severity` 同样触发。

**效果对照**（BT007 演示场景：事实错误 red 80 + 法律合规 orange 70 + …）：修复前 overall=64（红线下仍落 orange 档），现强制 ≥76 落 red 档，与「red 类应为 red」的期望一致。

## 6. 结论

R2 四项必做全部落地：

1. 评测回归门禁可离线 demo、可挂 CI（跌幅>5pp 阻断），valid_accuracy/valid_ratio 双口径分离环境完整性与算法水平。
2. LLM 调用计量原子落盘（token/耗时/成败），`GET /api/v1/metrics/summary` 提供最近 N 次分析汇总，无数据返回空口径。
3. 四套置信度公式收敛到 `confidence_calculator.py` 唯一入口，输出 4 级 + 原因标签，enhanced 链路「模块计数」置信度已弃用，API 向后兼容。
4. 红线 76+ 由代码强制：红线维度 red/high ⇒ 维度分与总体分均 ≥76，不再依赖 LLM 对 Prompt 的服从率。

既有 API 未破坏，87 passed 无回归，前端构建通过。live 全量评测基线需有 Key 环境补跑，已在 §4 登记，不得对外宣称已有 live 准确率数字。
