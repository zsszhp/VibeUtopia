## 3. 逐项实施细节

### 3.1 P0-1 事件切分 `EventSegmenter`

**输入**：帧序列（`FrameObservation`：timestamp + 可选 description/ocr_text/diff_score）+ 转写（`TranscriptSegment`：start/end/text）。二者皆可空（空输入返回 `[]`）。

**输出**：`Event[] {event_id, start, end, kind, score, anchors, summary, density, modalities}`。

**算法**（无大模型）：

1. **边界候选分**（`_boundary_candidates`）：
   - 视觉通道：帧差 `diff_score` 超过 0.75 分位（绝对地板 0.15）→ 边界分；描述/OCR 词重叠 < 0.3 的文本翻转 → 0.55 分
   - 语义通道：相邻转写片段词重叠（中英混切：英文按词、中文按字+二元组）低于 0.12 → 0.6–0.9 分；停顿 ≥ 1.2s → 0.5 分
2. **peak-picking**（`_peak_pick`）：按分降序取峰，最小间隔 2.0s；强制首尾边界。
3. **事件构建**（`_build_events`）：超长事件（>90s）强制均分；过短事件（<2s）并入前一个；逐事件分类 kind（claim/display/speech_act/action/scene，词表启发）、计算语义密度、取锚点（首帧 + 帧差最大帧）。

**验证**（`test_event_segmenter_*`，5 项）：合成 60s 三场景帧序列（15s/30s 双尖峰）+ 7 段转写 → 切出多事件、15s 尖峰形成边界、时间轴无缝衔接、claim 类型可识别、空输入/纯转写降级正确。

### 3.2 P0-2 自适应选帧 `AnchorSelector`

**替代对象**：均匀 1fps 一把梭（及 30 号「高异常必审 + 低异常抽 1/5」静态规则）。

**算法**（`select(frames, events, budget)`）：

1. **强制锚点**（设计 §5.4「不低于 40% 预算」对应）：
   - `event_boundary`：每个事件首尾的最近帧
   - `diff_spike`：帧差 > 均值 + 1.5σ（且绝对值 > 0.15）
   - `high_density`：每个高密度事件内帧差最大帧
2. **剩余预算**：按「窗密度×帧差」确定性 top-k 补足（离线可复现，不用随机采样），reason=`budget_fill`。
3. **覆盖度约束**：任意 30s 窗至少 1 帧，缺则补该窗帧差最大帧，reason=`coverage`。
4. **同帧多理由合并**：`reason` 以 `+` 连接（如 `event_boundary+diff_spike`），score 取高者。

**输出**：`SelectedFrame[] {timestamp, frame_id, image_path, reason, score, event_id}`——`reason` 字段即 UI 证据下钻的「为什么选这帧」。

**验证**（`test_anchor_selector_*`，5 项）：reason 枚举合法、15s/30s 尖峰帧（f015/f030）强制入选、预算可调不越界、极小预算下 30s 覆盖度仍满足、空输入安全。

### 3.3 P0-3 叙事冲突检测（轻量）

**规则**（时序窗口默认 8s，`NarrativeConflictDetector`）：

| kind | 触发 | 说明 |
|------|------|------|
| `polarity_reversal` | 前句肯定（绝对是/保证/没有问题…）后句否定（不是/其实/存在…问题…），或反向，且共享主体词 | 「前句肯定后句否定」启发 |
| `ocr_asr_mismatch` | 口播关键词组与画面 OCR 关键词组对撞（如 口播"自研" × OCR"GitHub"；"免费"×"付费"；"官方"×"破解"） | 「画面字与口播不一致」启发 |
| `claim_contradiction` | 主张类口播（自研/原创/保证…）同窗出现否定性口播或暴露型画面信息 | 欲盖弥彰线索 |

**LLM 策略**（约束：不强制、可离线降级）：`enable_llm` 默认 **False**，规则路径永远可用；开启后 `call_llm` 失败只记 warning 并**降级回规则结果**（`test_conflict_llm_failure_degrades` 验证）；LLM 结果并入而非覆盖规则结果，且置信固定 0.5（单通道不过度承诺，P6）。

**反伪精确**：冲突只输出「线索 + confidence」，不自动定罪，供人工复核。

**验证**（`test_conflict_*`，5 项）：极性反转检出、OCR/口播不一致检出（证据含 asr+ocr 双模态）、主张矛盾检出、一致内容零误报、LLM 失败降级。

### 3.4 P0-4 接入主流程

**`resumable_analyzer.py`**：

- `ANALYSIS_STAGES` 新增 `event_understanding`（`fine_grained_video` 之后、`report_compilation` 之前）。
- 新阶段 `_understand_events`：复用细粒度阶段的帧元数据（若有）+ 文案提取文本 → `run_event_understanding`；异常时返回空结果 + `degraded`（不抛错、不阻断后续阶段）。
- `_compile_report` 输出增加 `events_summary` / `selected_frame_reasons` / `narrative_conflicts`。
- **断点兼容**：旧检查点缺少新阶段时自动补齐为 PENDING（不破坏历史 checkpoint 续跑）。

**`enhanced_analyzer.py`**：

- `EnhancedAnalysisResult` 新增字段（只增不删）：`events_summary`、`selected_frame_reasons`、`narrative_conflicts`、`event_understanding_meta`。
- Phase 2.7 内 Step 1.5：Delta 帧元数据（`frames_from_delta_frames` 适配器，只取 timestamp/diff_score/路径，不碰图像）+ 文案 → 事件级理解。
- `_persist_result`：事件级结果并入 `simulation_summary` JSON（与多模态字段同位置，UI 可从该字段下钻证据）。

**API 兼容性**：所有旧字段原样保留；新增字段默认空列表/空 dict；`EventUnderstandingResult.to_output_dict()` 保证四个新键恒存在（`test_pipeline_api_compatible_fields` 验证）。

## 5. 已知边界与后续（不在 P0 范围）

1. **事件质量上限**：边界分目前是词重叠/帧差启发，无语义嵌入——慢镜头内部语义切换（像素差小、话题变）依赖转写通道补位；纯画面无转写时会漏。P1 可加轻量句向量（本地模型，不外网）。
2. **选帧预算是静态配置**（默认 60），未做设计 §5.10 的三级 Pareto 路由与成本感知；猎手表命中窗联动留 P1。
3. **叙事冲突只有 3 条规则**，覆盖「反转/不一致/矛盾」三类最常见模式；影射、带节奏、狗哨等语用风险（design §5.7）明确不做，输出中不假装覆盖。
4. **LLM 增强路径**（`enable_llm=True`）已接 `llm_client` 且验证失败降级，但默认关闭——上线前需在有配额环境单独标定 prompt 召回，不能直接当高置信结论用（置信恒 0.5）。
5. **enhanced 路径**事件级理解在 Phase 2.7 内与帧序列建模串行，未做独立超时预算；若 Delta 提取失败则整个 Phase 2.7 降级（与既有行为一致）。
6. VGOLD-200 金标准与新旧对照实验（design §8）是 P0 验收的量化前提，本次只交付可测算法与合成用例，**不宣称检出率指标**。
