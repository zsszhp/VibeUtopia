# VibeUtopia 世界构建层设计

> 从种子事件构建完整的高保真平行数字世界：知识图谱、7层人格工厂、社会关系网络、长期记忆系统。

## 1. 设计理念

世界构建层是VibeUtopia的"造物系统"。它的核心任务是：**从种子事件出发，构建一个足够真实的平行数字世界，让其中每个Agent都像真实的人一样有身份、有立场、有记忆、有社会关系。**

设计原则：
- **图谱先行**：先用知识图谱建立世界模型，再从中生成Agent
- **人格分层**：7层人格结构从稳定到动态逐层构建
- **关系涌现**：社会关系不是硬编码的，而是从属性和价值观中自然涌现
- **记忆分级**：不同生命周期的记忆存储在不同介质中
- **持续演化**：世界不是一次性构建的，而是随种子事件持续演进

## 2. 知识图谱引擎

### 2.1 设计概述

**参考MiroFish的Zep Cloud方案，但用Neo4j自建，原因**：
- Zep Cloud是付费SaaS，成本不可控
- Zep Cloud图谱是一次性构建，不支持增量更新
- Neo4j自托管，完全可控，支持复杂图查询

### 2.2 本体生成器

LLM分析种子文档，生成图的本体定义（实体类型+关系类型）：

```python
class OntologyGenerator:
    """本体生成器 - LLM分析文档生成图谱本体"""

    PROMPT_TEMPLATE = """
    分析以下文档，提取实体类型和关系类型定义。

    文档内容：
    {document_content}

    async def generate(self, documents: List[str]) -> GraphOntology:
        """从文档生成本体定义"""
```

### 2.3 实体关系抽取器

```python
class EntityExtractor:
    """实体关系抽取器"""

    def __init__(self, llm_client, ner_model=None):
        self.llm = llm_client
        self.ner = ner_model  # 可选的NER模型，用于预标注

    async def extract_from_document(self, document: str,
                                     ontology: GraphOntology,
                                     chunk_size: int = 2000) -> ExtractionResult:
        """从文档中抽取实体和关系"""
        chunks = self._split_document(document, chunk_size)
        all_entities = []
        all_relations = []

        # 并行处理文档块
        tasks = [self._extract_from_chunk(chunk, ontology) for chunk in chunks]
        results = await asyncio.gather(*tasks)

        for entities, relations in results:
            all_entities.extend(entities)
            all_relations.extend(relations)

        # 去重合并
        merged_entities = self._merge_entities(all_entities)
        merged_relations = self._merge_relations(all_relations)

        return ExtractionResult(entities=merged_entities, relations=merged_relations)

    async def _extract_from_chunk(self, chunk: str, ontology: GraphOntology):
        """LLM从单个文档块抽取实体和关系"""
```

### 2.4 图谱存储与查询

```python
class GraphStore:

    async def add_entities(self, entities: List[Entity]):
        """批量添加实体节点"""

    async def add_relations(self, relations: List[Relation]):
        """批量添加关系边"""

    async def query_entities_by_type(self, entity_type: str) -> List[Entity]:
        """按类型查询实体"""

    async def query_related_entities(self, entity_id: str,
                                      max_depth: int = 2) -> List[Entity]:
        """查询关联实体（图遍历）"""

    async def find_paths(self, from_id: str, to_id: str) -> List[List[str]]:
        """查找两个实体间的路径"""

    async def detect_communities(self) -> List[List[str]]:
        """社区检测（用于构建社会关系网络）"""

    async def incremental_update(self, new_entities: List[Entity],
                                  new_relations: List[Relation]):
        """增量更新图谱（合并新数据，不重建）"""
```

### 2.5 与MiroFish的关键差异

| 维度 | MiroFish (Zep Cloud) | VibeUtopia (Neo4j) |
|------|---------------------|-------------------|
| 部署方式 | 付费SaaS | 自托管，完全可控 |
| 图谱构建 | 一次性 | 支持增量更新 |
| 查询能力 | 有限的实体读取 | 完整Cypher查询，路径推理，社区检测 |
| 用途 | 仅Agent生成 | 贯穿全流程：世界构建→Agent生成→仿真注入→分析推理 |
| 成本 | 按用量付费 | 服务器成本固定 |
| 数据隐私 | 第三方托管 | 完全本地化 |

## 4. 社会关系网络生成器

### 4.1 关系类型定义

| 关系类型 | 方向 | 生成依据 | 示例 |
|----------|------|----------|------|
| 关注 (FOLLOWS) | 单向 | 属性相似度+影响力 | 普通用户关注大V |
| 互关 (MUTUAL_FOLLOW) | 双向 | 亲密关系+属性相似 | 朋友/同事 |
| 同社群 (SAME_COMMUNITY) | 无向 | 兴趣/地域/职业 | "科技圈""养猫群" |
| 价值观同盟 (ALLIED) | 无向 | 立场一致 | 同一议题的支持者 |
| 对立关系 (OPPOSED) | 无向 | 立场对立 | 性别议题的对立双方 |

### 4.2 网络生成算法

```
┌──────────────────────────────────────────────────────┐
│              社会关系网络生成4步算法                     │
│                                                       │
│  Step 1: 基于属性的相似度计算                           │
│  ┌────────────────────────────────────────────────┐  │
│  │ 计算Agent间的多维相似度：                        │  │
│  │ - 地域相似度 (同城市=1, 同省=0.7, 同国=0.3)     │  │
│  │ - 职业相似度 (同行业=1, 相关行业=0.5)            │  │
│  │ - 年龄相似度 (差5岁内=1, 差10岁=0.5)            │  │
│  │ - 价值观相似度 (立场一致性)                       │  │
│  │ - 兴趣重叠度 (话题交集)                          │  │
│  │                                                │  │
│  │ 综合相似度 = 加权平均 → 关注概率                │  │
│  │ 相似度>0.6 → 50%概率关注                        │  │
│  │ 相似度0.3-0.6 → 10%概率关注                     │  │
│  │ 相似度<0.3 → 1%概率关注(偶然发现)               │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 2: 小世界网络结构                                │
│  ┌────────────────────────────────────────────────┐  │
│  │ 基于Watts-Strogatz模型：                        │  │
│  │ - 高聚类系数：同社区的人互相连接                  │  │
│  │ - 短路径长度：通过少数"桥梁"可到达任何人          │  │
│  │ - 重连概率p=0.1：10%的边随机重连                 │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 3: 幂律分布的影响力                              │
│  ┌────────────────────────────────────────────────┐  │
│  │ 基于Barabási-Albert模型：                       │  │
│  │ - 少数大V：粉丝数占前1%的Agent拥有50%的关注      │  │
│  │ - 中腰部：10%的Agent有中等粉丝                   │  │
│  │ - 长尾：89%的Agent粉丝很少                      │  │
│  │                                                │  │
│  │ 优先连接：新Agent更可能关注已有大量粉丝的Agent    │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 4: 社群结构                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │ 基于Neo4j社区检测(Louvain算法)：                 │  │
│  │ - 兴趣圈："科技圈""追星族""养宠圈"等             │  │
│  │ - 立场圈："女权圈""男权圈""自由派""保守派"       │  │
│  │ - 地域圈："北上广""川渝""东北"                   │  │
│  │ - 跨圈桥梁：少数Agent同时属于多个社群            │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

### 4.3 影响力分配

```python
class InfluenceDistributor:
    """影响力分配器 - 幂律分布"""

    def distribute(self, num_agents: int) -> List[float]:
        """
        分配影响力值(0-1)，遵循幂律分布：
        - 前1% Agent: influence > 0.8 (大V)
        - 前10% Agent: influence 0.3-0.8 (中腰部)
        - 其余89% Agent: influence < 0.3 (普通用户)
        """
        # 使用Pareto分布
        influences = np.random.pareto(a=1.5, size=num_agents)
        # 归一化到0-1
        influences = (influences - influences.min()) / (influences.max() - influences.min())
        return influences.tolist()
```

```python
                                     context: str,
                                     top_k: int = 5) -> MemoryContext:

            vector=query_embedding,
            top_k=top_k
        )

        # 3. 从MySQL获取稳定人格特征
        semantic = await self._get_semantic_memory(agent_id)

        return MemoryContext(
            working_memory=working,
            episodic_memory=episodic,
            semantic_memory=semantic
        )
```

### 6.3 演化流程

```python
class PersonaEvolver:
    """人格演化器"""

    async def evolve_after_simulation(self, agent_id: str,
                                       simulation_traces: List[SimulationTrace]):
        """仿真后人格演化"""

        # 1. 分析仿真中的关键经历
        key_experiences = self._extract_key_experiences(simulation_traces)

        # 2. 评估对每层的影响
        impacts = await self._assess_impacts(agent_id, key_experiences)

        # 3. 应用演化（受约束）
        for impact in impacts:
            if impact.target_layer == 2 and impact.magnitude > 0.3:
                # L2价值观变化需要重大事件，限制幅度
                impact.magnitude = min(impact.magnitude, 0.3)
            await self._apply_impact(agent_id, impact)

        # 4. 一致性校验
        is_consistent = await self._validate_consistency(agent_id)
        if not is_consistent:
            await self._repair_inconsistency(agent_id)

        # 5. 版本记录
        await self._record_version(agent_id, impacts)
```
