# VibeUtopia 仿真运行层设计

## 文档定位
- 本文档在主线中的角色：定义仿真运行引擎的内部实现——Agent行为决策、异步通信、多平台仿真器、传播模型、时间模型、调度编排——作为风控增强的条件性后端
- 与"发前风控优先"的关系：仿真运行层是风控增强的执行引擎，本身不是产品入口；用户永远走"提交内容→获取报告"主链路，仿真仅在风险评估环节按需启用

## 本文档边界
- 本文档负责：仿真触发与降级策略、四层Agent架构(A/B/C/Group)及行为决策引擎、asyncio.Queue异步通信、25+平台仿真器、5阶段传播模型、极化检测、仿真时间模型、仿真编排器(SimulationOrchestrator)、仿真终止条件、LLM调用量优化与成本控制
- 本文档不负责：仿真启用/保留/降级的业务决策逻辑（见`10_仿真增强风控设计.md`）、风险评估逻辑（见`09_分析决策层设计.md`）、世界构建与人格工厂（见`07_世界构建层设计.md`）、信号采集（见`06_信号采集层设计.md`）、前端展示（见`13_前端升级设计.md`）

## 对准确率的直接贡献
- 机制1：Agent仿真提供多视角验证——不同人格、不同平台的Agent对同一内容的差异化反应，补充静态评估无法覆盖的群体行为预测
- 机制2：5阶段传播模型+极化检测量化舆论演化路径，为风险评级提供动态证据而非静态推断
- 机制3：GA-S3 Group Agent以统计模型扩展覆盖范围，在有限成本下等效覆盖10万+个体，降低小样本偏差
- 验证方式：回测对比（同一批案例跑静态 vs 仿真增强，量化准确率增量）、多轮一致性检查（3次仿真结果一致性 > 60%）

## 关键流程
- 输入：种子事件（用户文案+上下文）+ Agent集合（从07世界构建层生成）+ 仿真配置（深度/平台/时长）
- 处理：
  1. 仿真编排器初始化Agent集合与平台仿真器
  2. 种子事件注入→Agent感知→行为决策→平台处理→社交反馈→循环推进
  3. 5阶段传播模型驱动舆论演化（种子→扩散→爆发→长尾→沉淀）
  4. 极化检测与终止条件监控
- 输出：仿真轨迹数据（各平台行为流+情感分布+传播路径+极化指标），供分析决策层(09)和仿真增强风控(10)使用

## 依赖与降级
- 依赖：
  - 07世界构建层：Agent Profile(7层人格) + 社会关系网络 + 知识图谱
  - asyncio.Queue：仿真内部消息传递，零外部依赖
  - LLM API：DeepSeek-V4-Flash / Qwen3.6-Plus / Qwen3-8B(本地fallback)
  - ChromaDB：Agent情景记忆检索（零部署）
  - Neo4j：实体关系查询与传播路径追踪（Lite模式可跳过）
  - MySQL/SQLite：Agent Profile与仿真结果持久化（SQLite降级零依赖）
- 失败降级策略：
  - LLM API不可用 → A/B-tier降级到本地模型(Qwen3-8B)，或仅保留C-tier规则引擎+Group-tier统计模型
  - Neo4j不可用 → 传播路径追踪跳过，极化检测降级为统计方法
  - ChromaDB不可用 → Agent情景记忆退化为最近N条记录线性检索
  - 仿真超时 → 提前终止，已收集轨迹仍有效，标注"仿真未完整运行"
  - 仿真结果一致性低 → 仿真输出标记为"低置信度参考"，以静态评估为主（详见10_仿真增强风控设计.md降级条件）

## 验收标准
- 指标：仿真完成率、Agent行为多样性(同一事件不同tier Agent反应差异度)、传播阶段识别准确率、极化检测灵敏度
- 阈值：
  - 100 Agent轻量仿真3分钟内完成，500 Agent标准仿真5分钟内完成
  - A-tier与C-tier对同一事件的反应差异度 > 0.4（归一化距离）
  - 5阶段传播模型能正确标注历史案例的传播阶段（回测5+案例）
  - 极化指数对已知极化事件的检测灵敏度 > 0.7
- 通过条件：
  - 4种深度(100/500/2000/10000)仿真均可在预估时间内完成
  - 仿真终止条件可正确触发（活动度低于阈值或最大轮次）
  - 降级路径测试：每个依赖项不可用时仿真仍可产出有效轨迹（降级标注）
  - 成本控制：各深度预算不超限（quick ¥0.5 / standard ¥2 / deep ¥5）

## 1. 核心定位：仿真 = 按需增强模块

仿真运行层不是一个独立产品入口，而是风控主链路中的**条件性增强引擎**。它在以下条件满足时被激活：

### 1.1 触发条件

| 触发条件 | 判断逻辑 | 启用的仿真深度 |
|----------|----------|---------------|
| 静态评估达到风险阈值 | 7维评估中任一维度 >= 橙色(50分) 或 总分 >= 60 | 轻量仿真(100 Agent) |
| 静态评估达到高风险阈值 | 任一维度 >= 红色(70分) 或 总分 >= 75 | 标准仿真(500 Agent) |
| 用户选择深度分析 | `options.depth = "deep"` | 深度仿真(2000 Agent) |
| 用户选择大规模分析 | `options.depth = "large_scale"` | 大规模仿真(10000 Agent + GA-S3) |
| 静态评估为低风险 | 总分 < 50 且无橙色维度 | 不启用仿真 |

### 1.2 降级策略

仿真运行过程中，如果仿真未能提供比静态评估更准确的判断，系统自动降级：

```
完整仿真（A/B/C/Group四层Agent全部运行）
     │
     ▼ 仿真增量不稳定（回测增量 < 5%）
缩减仿真（仅C-tier规则引擎 + Group-tier统计模型，跳过A/B-tier LLM推理）
     │
     ▼ 仿真仍无提升（回测增量 < 2%）
仅保留热点+实体风险链（关闭仿真，保留Step2低成本增强，详见10_仿真增强风控设计.md）
```

### 1.3 成本控制

每种仿真深度有硬性预算上限，超限自动终止仿真并以已有结果输出：

| 深度 | Agent数量 | LLM预算上限 | 单次成本上限 | 预估耗时 |
|------|----------|------------|------------|---------|
| quick | 100 | 200次调用 | ¥0.5 | 1-2分钟 |
| standard | 500 | 2000次调用 | ¥2 | 3-5分钟 |
| deep | 2000 | 8000次调用 | ¥5 | 10-15分钟 |
| large_scale | 10000 | 15000次调用 | ¥10-20 | 20-40分钟 |

> 成本计算依据：DeepSeek-V4-Flash约¥0.001/次输入+¥0.002/次输出，Qwen3.6-Plus约¥0.002/次。A-tier每次独立LLM，B-tier采样LLM，C-tier规则引擎零LLM，Group-tier统计模型零LLM。

### 2.3 GA-S3 Group Agent机制

Group-tier是大规模仿真的关键扩展机制，用统计模型替代大量相似Agent的独立计算：

```python
@dataclass
class GroupAgent:
    """GA-S3群组Agent - 统计模型代表10-100个相似个体"""

    group_id: str
    group_size: int                          # 代表的个体数量(10-100)
    demographic_profile: Dict                # 人口统计分布(年龄/性别/地域)
    stance_distribution: Dict[str, float]    # 立场分布{"支持":0.3,"反对":0.2,"中立":0.5}
    activity_distribution: Dict[str, float]  # 活跃度分布{"high":0.1,"medium":0.3,"low":0.6}
    platform_affinity: Dict[str, float]      # 平台偏好{"weibo":0.4,"douyin":0.3,...}

    def generate_reactions(self, content: SeedContent) -> List[GroupReaction]:
        """蒙特卡洛采样生成群组反应"""
        reactions = []
        for _ in range(self.group_size):
            # 根据立场分布采样个体立场
            stance = self._sample_stance()
            # 根据活跃度分布采样是否反应
            if random() > self.activity_distribution.get("active", 0.2):
                continue
            # 根据立场和内容情感强度决定行为类型
            action_type = self._decide_action(stance, content)
            reactions.append(GroupReaction(
                action_type=action_type,
                stance=stance,
                count=1  # 单个个体
            ))
        # 聚合同类反应
        return self._aggregate_reactions(reactions)

    def _decide_action(self, stance: str, content: SeedContent) -> str:
        """基于立场和内容决定行为"""
        alignment = self._calc_alignment(stance, content)
        if alignment > 0.7:
            return "SHARE"  # 高度认同→转发
        elif alignment > 0.4:
            return "LIKE"   # 认同→点赞
        elif alignment < -0.5:
            return "DISLIKE"  # 反对→踩
        else:
            return "DO_NOTHING"
```

## 3. 仿真编排器（SimulationOrchestrator）

替代原Director/Watcher/Injector/Guardian四角色设计，用单一编排器统一调度。原四角色的核心职能被精简合并：

| 原角色 | 核心职能 | 新归属 |
|--------|---------|--------|
| Director(仿真主持) | 全局调度与节奏控制 | SimulationOrchestrator主循环 |
| Watcher(舆论观察) | 实时监控舆论动态 | 传播阶段检测(内嵌于主循环) |
| Injector(事件注入) | 适时注入子事件 | 种子事件注入(仿真启动时一次性+传播阶段触发) |
| Guardian(应急干预) | 检测异常行为 | Agent纠偏层(L5自我约束，见07) + 异常检测(内嵌于主循环) |

### 3.1 编排器核心逻辑

```python
class SimulationOrchestrator:
    """仿真编排器 - 统一调度仿真全流程"""

    def __init__(self, config: SimulationConfig):
        self.config = config
        self.agent_pool: Dict[str, Agent] = {}
        self.platforms: Dict[str, PlatformSimulator] = {}
        self.event_queue: asyncio.Queue = asyncio.Queue()     # 事件队列
        self.action_queue: asyncio.Queue = asyncio.Queue()    # 行为队列
        self.feedback_queue: asyncio.Queue = asyncio.Queue()  # 反馈队列
        self.sim_clock = SimulationClock(config.time_acceleration)
        self.propagation_stage = "seed"  # 当前传播阶段
        self.polarization_index = 0.0
        self.total_cost = 0.0

    async def run(self) -> SimulationResult:
        """执行一次完整仿真"""

        # 1. 初始化
        await self._initialize()

        # 2. 注入种子事件
        await self._inject_seed_event(self.config.seed_event)

        # 3. 仿真主循环
        round_num = 0
        while not self._should_terminate(round_num):
            round_num += 1
            sim_time = self.sim_clock.advance()

            # 3.1 确定当前活跃Agent集合（基于时间模型+活跃度）
            active_agents = self._get_active_agents(sim_time)

            # 3.2 按tier分组处理
            await self._process_tier(active_agents, sim_time)

            # 3.3 平台处理提交的行为
            await self._process_platform_actions()

            # 3.4 分发反馈通知
            await self._distribute_feedback()

            # 3.5 更新传播阶段与极化指标
            self._update_propagation_stage()
            self._update_polarization_index()

            # 3.6 成本检查
            if self.total_cost >= self.config.budget_limit:
                break

            # 3.7 检查点（可选）
            if round_num % self.config.checkpoint_interval == 0:
                await self._save_checkpoint(round_num)

        # 4. 收集结果
        return await self._collect_results()

    def _should_terminate(self, round_num: int) -> bool:
        """仿真终止条件检查"""
        # 条件1: 活动度低于阈值（舆论已沉淀）
        activity_rate = self._calc_activity_rate()
        if activity_rate < 0.05:  # 活跃Agent占比 < 5%
            return True

        # 条件2: 达到最大轮次
        if round_num >= self.config.max_rounds:
            return True

        # 条件3: 传播阶段已进入沉淀期且持续3轮无变化
        if self.propagation_stage == "sedimentation":
            if not hasattr(self, '_sedimentation_rounds'):
                self._sedimentation_rounds = 0
            self._sedimentation_rounds += 1
            if self._sedimentation_rounds >= 3:
                return True
        else:
            self._sedimentation_rounds = 0

        # 条件4: 成本超限（在主循环中检查）

        return False
```

### 3.2 异常行为处理

替代原Guardian的独立Agent设计，异常检测内嵌于编排器，结合Agent自身纠偏层(L5)：

```python
class AnomalyDetector:
    """内嵌式异常行为检测"""

    RULES = [
        ("repeat_post", "Agent重复发布相同内容超过3次", "suppress"),
        ("irrelevant_extreme", "Agent对无关话题表现出极端情绪", "inject_reminder"),
        ("contradictory_stance", "Agent产生自相矛盾的立场声明", "flag_inconsistency"),
        ("profile_violation", "Agent行为与其人格Profile严重不符", "force_do_nothing"),
    ]

    def check(self, agent: Agent, action: PlatformAction) -> Optional[AnomalyAction]:
        """检查Agent行为是否异常"""
        # 依赖Agent L5纠偏层的self_constraints做第一道过滤
        # 编排器做第二道全局检测
        for rule_id, rule_desc, remedy in self.RULES:
            if self._matches_rule(rule_id, agent, action):
                if remedy == "suppress":
                    return AnomalyAction(suppress=True, reason=rule_desc)
                elif remedy == "inject_reminder":
                    return AnomalyAction(
                        inject_signal="你的好友提醒你冷静一下",
                        reason=rule_desc
                    )
                elif remedy == "force_do_nothing":
                    return AnomalyAction(
                        override_action="DO_NOTHING",
                        reason=rule_desc
                    )
        return None
```

### 4.3 C-tier规则引擎

C-tier Agent不需要LLM决策，使用规则引擎+本地小模型：

```python
class RuleEngine:
    """C-tier规则引擎"""

    def decide(self, agent: AgentProfile, perception: PerceptionContext) -> PlatformAction:
        """基于规则的行为决策"""

        # 规则1: 高情感内容 → 大概率点赞/转发
        if perception.content_sentiment_score > 0.6 and random() < 0.7:
            return PlatformAction(action_type="LIKE", target_id=perception.content_id)

        # 规则2: 关注的人发帖 → 30%概率查看+10%概率互动
        if perception.is_from_followee and random() < 0.3:
            if random() < 0.33:
                content = self.local_model.generate_comment(agent, perception)
                return PlatformAction(action_type="COMMENT", content=content)
            else:
                return PlatformAction(action_type="LIKE")

        # 规则3: 与自己立场一致的内容 → 更可能互动
        if self._stance_alignment(agent, perception) > 0.7 and random() < 0.5:
            return PlatformAction(action_type="SHARE")

        # 规则4: 默认 → DO_NOTHING
        return PlatformAction(action_type="DO_NOTHING")
```

### 5.1 队列架构

```
┌────────────────────────────────────────────────────────────┐

└────────────────────────────────────────────────────────────┘
```

### 5.3 vs Redis Streams 对比

| 维度 | Redis Streams | asyncio.Queue |
|------|--------------|---------------|
| 部署依赖 | 需要Redis服务 | 零外部依赖 |
| 延迟 | 网络+序列化，1-5ms | 进程内，<0.1ms |
| 持久化 | AOF/RDB | 无(仿真数据持久化到DB) |
| 扩展性 | 支持多进程/多机 | 单进程内(仿真规模足够) |
| 消费者组 | 原生支持 | 需自行实现(简单轮询即可) |
| 适用场景 | 分布式系统 | 单进程仿真引擎 |

> 选择理由：仿真运行在单进程内，Agent数量上限10000，asyncio.Queue完全满足性能需求，且消除Redis运维负担。仿真结果持久化由MySQL/SQLite负责，不需要消息队列持久化。

### 7.2 传播阶段自动检测

```python
class PropagationStageDetector:
    """传播阶段自动检测器"""

    def detect(self, state: SimulationState) -> str:
        """根据当前仿真状态判断传播阶段"""

        participation_rate = state.active_agent_count / state.total_agent_count
        interaction_velocity = state.recent_interaction_count / state.recent_time_window
        polarization = state.polarization_index

        # 种子期：极低参与度
        if participation_rate < 0.05 and interaction_velocity < 5:
            return "seed"

        # 扩散期：参与度上升，极化开始
        if participation_rate < 0.20 and interaction_velocity > 5:
            return "diffusion"

        # 爆发期：高参与度，极化快速上升
        if participation_rate >= 0.20 and interaction_velocity > 20:
            return "outbreak"

        # 长尾期：参与度下降，极化稳定
        if participation_rate < 0.20 and polarization > 0.3:
            return "long-tail"

        # 沉淀期：极低参与度
        if participation_rate < 0.05 and interaction_velocity < 3:
            return "sedimentation"

        # 默认维持上一阶段
        return state.current_stage
```

### 7.3 传播影响因素

| 因素类别 | 因素 | 影响机制 | 量化方式 |

## 8. 极化检测机制

### 8.1 极化指数计算

```python
class PolarizationDetector:
    """极化检测器"""

    def calc_polarization_index(self, agents: List[Agent]) -> PolarizationResult:
        """计算极化指数 (0-1)"""

        # 1. 收集所有Agent对当前事件的立场
        stances = [a.get_stance_on_topic(self.current_topic) for a in agents]

        # 2. 立场分布直方图 (-1到1，分20个bin)
        hist, bin_edges = np.histogram(stances, bins=20, range=(-1, 1))
        hist_normalized = hist / hist.sum()

        # 3. 双峰性检测 (Hartigan's dip test简化版)
        bimodality = self._calc_bimodality(hist_normalized)

        # 4. 中间派比例 (立场在-0.2到0.2之间)
        moderate_ratio = sum(1 for s in stances if -0.2 <= s <= 0.2) / len(stances)

        # 5. 极化指数 = 双峰性权重 + 中间派缺失权重
        polarization = 0.6 * bimodality + 0.4 * (1 - moderate_ratio)

        return PolarizationResult(
            index=polarization,
            bimodality=bimodality,
            moderate_ratio=moderate_ratio,
            stance_distribution=hist_normalized.tolist(),
            stage="polarizing" if polarization > 0.5 and self._is_rising() else "stable",
            confidence=self._calc_confidence(len(stances))
        )

    def _calc_bimodality(self, distribution: np.ndarray) -> float:
        """计算分布的双峰性 (0=单峰, 1=完美双峰)"""
        # 简化方法: 检查分布是否有两个明显的峰
        peaks = self._find_peaks(distribution)
        if len(peaks) >= 2:
            # 两个峰之间的谷有多深
            valley_depth = self._calc_valley_depth(distribution, peaks)
            return min(1.0, valley_depth * 2)
        return 0.0
```

### 8.2 极化预警

| 极化指数 | 等级 | 含义 | 风控建议 |
|----------|------|------|---------|
| < 0.2 | 无极化 | 立场集中，无分歧 | 低风险 |
| 0.2-0.4 | 轻度分化 | 开始出现不同声音 | 关注 |
| 0.4-0.6 | 中度极化 | 明显对立阵营形成 | 中风险，建议关注评论区 |
| 0.6-0.8 | 高度极化 | 两方对立激烈，中间派极少 | 高风险，建议调整内容策略 |
| > 0.8 | 极端极化 | 几乎无中间地带，情绪激烈 | 极高风险，建议撤回/修改 |

```python
class SimulationClock:
    """仿真时钟"""

    def __init__(self, acceleration: int = 60):
        self.acceleration = acceleration  # 1仿真小时=1真实分钟(=60x)
        self.sim_time: datetime = None
        self.time_step = timedelta(minutes=15)  # 仿真时间步长15分钟

    def advance(self) -> datetime:
        """推进仿真时间"""
        self.sim_time += self.time_step
        return self.sim_time

    def get_activity_multiplier(self) -> float:
        """获取当前时段活跃度乘数"""
        hour = self.sim_time.hour
        ACTIVITY_MAP = {
            range(0, 7): 0.1,
            range(7, 9): 0.8,
            range(9, 12): 0.4,
            range(12, 14): 0.9,
            range(14, 18): 0.3,
            range(18, 20): 0.9,
            range(20, 23): 1.0,
            range(23, 24): 0.5,
        }
        for r, mult in ACTIVITY_MAP.items():
            if hour in r:
                return mult
        return 0.5
```
