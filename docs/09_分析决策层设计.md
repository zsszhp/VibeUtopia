# VibeUtopia 风险评估与报告层设计

## 文档定位
- 本文档在主线中的角色：定义风险评估与报告生成的完整逻辑——7维风险评估、证据链追溯、置信度量化、不确定性标注、平台反应汇总、改写建议、报告输出。这是"提交内容→获取报告"主链路的**核心产出层**，用户的最终交付物即由本层生成
- 与"发前风控优先"的关系：本层是风控的最终出口——所有上游能力（内容理解、仿真、信号关联）的价值都体现在本层输出的风险报告中。报告质量直接决定用户对风控准确率的感知

## 本文档边界
- 本文档负责：7维风险评估引擎、证据链(Evidence Chain)机制、置信度(Confidence)量化、不确定性(Uncertainty)标注、平台反应汇总与差异对比、改写建议生成、报告输出结构（与01 PRD对齐）、5个核心API端点中的报告相关逻辑
- 本文档不负责：仿真引擎内部实现（见`08_仿真运行层设计.md`）、仿真增强机制（信号关联/实体链/动态权重，见`10_仿真增强风控设计.md`）、多模态内容理解（见`12_多模态风控设计.md`）、世界构建与人格工厂（见`07_世界构建层设计.md`）、前端展示细节（见`13_前端升级设计.md`）
- **已移除/降级的原核心特性**：
  - ~~趋势预测~~ → P2/后置，仿真可信度验证通过后方可考虑（见`04_V2深化路线图.md`）
  - ~~反事实仿真~~ → P1增强，主线稳定后作为仿真增强功能引入
  - ~~决策辅助~~ → P2/后置，本层核心输出是风险报告，不是决策建议

## 对准确率的直接贡献
- 机制1：7维评估体系提供结构化风险识别标准，确保不遗漏任何风险维度
- 机制2：证据链机制要求每个风险结论都有可追溯来源（哪句话/哪个画面/哪段音频触发了风险），杜绝"无证据风险判断"，减少误报
- 机制3：置信度量化表达风险判断的稳定性，基于多轮评估一致性计算，让用户知晓结论可靠程度
- 机制4：不确定性标注列出每个评估的未确定因素，避免过度自信，引导用户关注需人工复核的领域
- 验证方式：回测案例对比（证据链命中率、置信度与人工标注的相关性、漏报率/误报率）

## 关键流程/结构
- 输入：内容理解结果（文字风险项+画面风险项+音频风险项+跨模态冲突） + 仿真增强数据（信号关联/实体风险链/Agent仿真结果，如有）
- 处理：
  1. 7维静态评估 → 每个维度产出风险项+证据链+置信度+不确定性
  2. 叠加仿真增强数据（如有）→ 更新风险分数+补充动态证据+调整置信度
  3. 平台反应汇总 → 各平台正面/中性/负面比例+典型评论+关注焦点
  4. 综合裁决 → 总体风险评级+整体置信度+不确定性汇总
  5. 改写建议 → 高风险项的替代方案
- 输出：风险报告（总体评级 + 7维详情 + 证据链 + 置信度 + 平台反应 + 改写建议）

## 依赖与降级
- 依赖：内容理解层（文字/画面/音频风险项）、仿真增强层（信号关联/实体链/仿真结果，条件性）、LLM API（DeepSeek-V4-Flash / Qwen3.6-Plus / Qwen3-8B本地fallback）
- 失败降级策略：
  - 仿真数据不可用 → 仅基于静态评估生成报告，置信度标注"低"，不确定性来源增加"缺少仿真验证"
  - LLM API降级 → 降级到本地模型(Qwen3-8B)做评估，报告标注"模型降级，建议人工复核"
  - 部分模态缺失 → 仅基于可用模态评估，报告标注缺失模态及影响范围
  - 信号关联失败 → 跳过热点关联与实体风险链，报告标注"未关联当前热点"

## 验收标准
- 指标：7维评估覆盖率、证据链命中率、置信度与人工标注相关性、漏报率、误报率
- 阈值：7维评估覆盖率100%（每个维度必须产出结果）；证据链命中率>90%（风险项必须有可追溯来源）；置信度与人工标注相关性>0.6
- 通过条件：回测5+案例，所有维度均产出评估结果；人工复核中>90%的风险项有清晰证据链；置信度标注与人工判断方向一致

## 1. 核心定位：风险报告是唯一产出

本层的核心输出是**风险报告**，不是趋势预测，不是决策建议，不是反事实对比。用户提交内容后，最终拿到的是一份结构化的风险报告，包含7维评估、证据链、置信度、平台反应和改写建议。

```
主链路（用户可见）:
  用户提交内容 → 内容理解 → 风险评估 → 报告输出
                                  │
                                  ▼
                         ┌─────────────────────┐
                         │  风险评估与报告层     │
                         │                      │
                         │  Step 1: 7维静态评估  │ ← 每次必走
                         │    + 证据链           │
                         │    + 置信度           │
                         │    + 不确定性         │
                         │         │            │
                         │  Step 2: 仿真增强叠加  │ ← 条件性
                         │    (如有仿真数据)      │
                         │         │            │
                         │  Step 3: 平台反应汇总  │
                         │         │            │
                         │  Step 4: 综合裁决      │
                         │    + 整体置信度        │
                         │    + 不确定性汇总      │
                         │         │            │
                         │  Step 5: 改写建议      │
                         │         │            │
                         │  Step 6: 报告输出      │
                         └──────────────────────┘
```

设计原则：
- **证据必溯**：每个风险结论必须有可追溯的证据来源，不允许"凭空判断"
- **置信必标**：每个风险判断必须标注置信度，不允许100%确定性声明
- **不确定必列**：每个评估必须列出不确定性来源，让用户知晓判断边界
- **报告即交付**：报告是用户唯一需要理解的产出，所有内部机制必须转化为可读的报告内容

## 2. 7维风险评估引擎

### 2.1 维度定义（与01 PRD第5节对齐）

| 维度 | 定义 | 典型触发场景 | 严重度分级 |
|------|------|-------------|-----------|
| **1. 政治敏感** | 涉及政治人物、领土主权、外交关系等红线话题 | 不当评价政策、触及领土争议、调侃政治人物 | 任何触及均属高风险 |
| **2. 性别议题** | 性别对立、物化歧视、刻板印象强化 | 强化性别刻板印象、挑动性别对立、物化任何性别 | 依语境而定，对立性内容升级为高风险 |
| **3. 民族宗教** | 民族歧视、宗教冒犯、文化禁忌 | 不当引用宗教符号、地域歧视隐射民族问题 | 任何触及均属高风险 |
| **4. 道德伦理** | 违背公序良俗、与主流价值观冲突 | 鼓励不道德行为、挑战社会底线 | 依严重程度分级 |
| **5. 法律合规** | 广告法违规、侵权、虚假宣传 | 绝对化用语、未标注广告、虚假功效宣传 | 法律红线不可触碰 |
| **6. 群体冒犯** | 地域黑、职业歧视、年龄歧视 | "某省人都XXX"、贬低特定职业群体 | 依群体敏感度分级 |
| **7. 时事踩雷** | 不当蹭热点、关联翻车事件 | 在敏感事件期间发布可能被关联的内容 | 随时事热度动态变化 |

### 2.2 评估流程

```

│  输入：                                                       │
│  ├── 文字风险项（来自内容理解层）                               │
│  ├── 画面风险项（来自关键帧理解+OCR）                           │
│  ├── 音频风险项（来自语音转写+情感分析）                        │
│  ├── 跨模态冲突（来自跨模态一致性检测）                         │
│  └── 增强数据（信号关联+实体风险链+仿真结果，条件性）            │
│                                                               │
│  对每个维度独立评估：                                          │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 维度: 性别议题                                          │  │
│  │                                                         │  │
│  │ 1. 扫描所有风险项，匹配本维度                            │  │
```

### 2.3 评估输出数据结构

```python
@dataclass
class DimensionAssessment:
    """单维度评估结果"""
    name: str                          # 维度名称
    score: int                         # 风险分数 0-100
    severity: str                      # green/yellow/orange/red

    # 证据链（核心要求：每个风险结论必须有可追溯来源）
    evidence_chain: List[EvidenceItem]  # 证据列表

    # 置信度（量化风险判断的稳定性）
    confidence: float                   # 0-1, 综合置信度
    confidence_breakdown: Dict[str, float]  # 分来源置信度
    #   "static_assessment": 0.85    静态评估内部一致性
    #   "simulation_validation": 0.72  仿真验证一致性（如有）
    #   "signal_correlation": 0.68  信号关联支撑度（如有）

    # 不确定性（列出风险判断的边界）
    uncertainty_sources: List[UncertaintyItem]  # 不确定性来源列表
    uncertainty_level: str              # low/medium/high

    # 受影响平台
    affected_platforms: List[str]

    # 改写建议
    suggestion: Optional[str]


@dataclass
class EvidenceItem:
    """证据链条目"""
    source_type: str        # text/frame/audio/cross_modal/simulation/signal
    content: str            # 原始内容/描述
    location: str           # 定位信息
    #   文字: "第3段第2句"
    #   画面: "02:15关键帧"
    #   音频: "01:30-01:35"
    #   仿真: "Agent#127 (25岁女性, 小红书用户)"
    #   信号: "微博热搜#XX 当前热度0.85"
    explanation: str        # 该证据如何支持风险判断


@dataclass
class UncertaintyItem:
    """不确定性条目"""
    source: str             # 不确定性来源描述
    impact: str             # 对当前判断的可能影响
    direction: str          # 可能导致风险升高/降低/方向不明

    # 常见不确定性来源：
    # - "语境依赖": 脱离上下文可能有不同解读
    # - "受众差异": 不同群体可能有不同反应
    # - "时效性": 热点事件发展可能改变风险
    # - "仿真随机性": Agent仿真结果有一定随机性
    # - "模态缺失": 部分模态(如音频)未能分析
    # - "信号时效": 热点关联数据可能有延迟
    # - "实体不完整": 知识图谱中实体信息可能不完整
```

## 3. 证据链机制

### 3.1 核心要求

**每个风险结论必须有可追溯的来源。** 不允许出现"性别议题高风险"但没有说明哪句话/哪个画面/哪段音频触发了风险的情况。

### 3.2 证据来源分类

| 来源类型 | 说明 | 典型证据 |
|----------|------|----------|
| **text** | 文案/脚本中的原文 | "第3段第2句: 'XX都不行'" |
| **frame** | 视频关键帧 | "02:15关键帧: 画面出现争议性符号" |
| **audio** | 音频转写/情感 | "01:30-01:35: 语气从平和转为讽刺" |
| **cross_modal** | 跨模态冲突 | "画面与文案矛盾: 文案说XX但画面展示YY" |
| **simulation** | Agent仿真反应 | "68%的仿真Agent对'XX'表达负面态度" |
| **signal** | 热点信号关联 | "当前微博热搜#XX与文案提及的YY高度相关" |
| **entity** | 实体风险链 | "提及的品牌A近期有B争议" |

### 3.3 证据链构建规则

```python
class EvidenceChainBuilder:
    """证据链构建器"""

    def build_chain(self, dimension: str, risk_items: List[RiskItem],
                    simulation_data: Optional[SimulationResult] = None,
                    signal_data: Optional[SignalCorrelation] = None) -> List[EvidenceItem]:
        """为某个维度的风险判断构建证据链"""

        evidence_chain = []

        # 规则1: 每个触发该维度的原始内容必须出现在证据链中
        for item in risk_items:
            if dimension in item.matched_dimensions:
                evidence_chain.append(EvidenceItem(
                    source_type=item.modality,  # text/frame/audio/cross_modal
                    content=item.original_content,
                    location=item.location,
                    explanation=item.risk_explanation
                ))

        # 规则2: 如果有仿真数据，仿真验证必须出现在证据链中
        if simulation_data:
            for reaction in simulation_data.relevant_reactions(dimension):
                evidence_chain.append(EvidenceItem(
                    source_type="simulation",
                    content=reaction.agent_reaction,
                    location=f"Agent#{reaction.agent_id} ({reaction.agent_profile})",
                    explanation=reaction.how_it_validates
                ))

        # 规则3: 如果有信号关联，热点关联必须出现在证据链中
        if signal_data:
            for correlation in signal_data.relevant_correlations(dimension):
                evidence_chain.append(EvidenceItem(
                    source_type="signal",
                    content=correlation.hotspot_description,
                    location=f"{correlation.platform}热搜#{correlation.rank}",
                    explanation=correlation.relevance_explanation
                ))

        # 规则4: 证据链至少包含1条原始内容证据，否则该维度风险判断不可信
        if not any(e.source_type in ["text", "frame", "audio", "cross_modal"]
                   for e in evidence_chain):
            # 降级：仅有仿真/信号证据，标注"缺少直接内容证据"
            pass

        return evidence_chain
```

## 4. 置信度量化

### 4.1 置信度定义

置信度表达的是**风险判断的稳定性**——在相同输入下重复评估，得到相同结论的概率。不是"我们有多确定这个风险会真的发生"，而是"我们的评估系统对这个判断有多稳定"。

### 4.2 置信度计算

```python
class ConfidenceCalculator:
    """置信度计算器"""

    def calculate(self, dimension: str,
                  static_results: List[StaticAssessment],
                  simulation_data: Optional[SimulationResult] = None,
                  signal_data: Optional[SignalCorrelation] = None) -> ConfidenceResult:

        # 1. 静态评估内部一致性
        #    多次静态评估（不同LLM调用）的方向一致性
        static_confidence = self._calc_consistency(static_results)

        # 2. 仿真验证一致性（如有）
        #    多轮仿真中Agent反应的方向一致性
        if simulation_data:
            sim_confidence = simulation_data.consistency_score  # 0-1
        else:
            sim_confidence = None  # 未启用仿真

        # 3. 信号关联支撑度（如有）
        if signal_data:
            signal_confidence = signal_data.correlation_strength  # 0-1
        else:
            signal_confidence = None

        # 4. 综合置信度
        #    加权平均，静态权重最高（因为是最基础的）
        if sim_confidence is not None and signal_confidence is not None:
            overall = 0.40 * static_confidence + \
                      0.30 * sim_confidence + \
                      0.30 * signal_confidence
        elif sim_confidence is not None:
            overall = 0.55 * static_confidence + 0.45 * sim_confidence
        elif signal_confidence is not None:
            overall = 0.55 * static_confidence + 0.45 * signal_confidence
        else:
            overall = static_confidence

        return ConfidenceResult(
            overall=overall,
            breakdown={
                "static_assessment": static_confidence,
                "simulation_validation": sim_confidence,
                "signal_correlation": signal_confidence,
            }
        )
```

### 4.3 置信度分级与展示

| 置信度 | 标签 | 前端展示 | 用户指引 |
|--------|------|----------|----------|
| >= 0.8 | 高置信度 | 绿色标签 | 结论稳定，可信度高 |
| 0.6-0.8 | 中置信度 | 蓝色标签 | 结论较可信，建议关注不确定性 |
| 0.4-0.6 | 低置信度 | 橙色标签 | 结论参考性有限，建议人工复核 |
| < 0.4 | 极低置信度 | 红色标签 | 结论不可靠，仅供参考 |

## 5. 不确定性标注

### 5.1 核心要求

**每个风险评估必须列出不确定性来源。** 不确定性不是缺陷，而是诚实地表达评估边界——让用户知道哪些方面可能有变化、需要额外注意。

### 5.2 不确定性来源分类

| 类别 | 不确定性来源 | 典型影响 | 出现条件 |
|------|-------------|----------|----------|
| **内容理解** | 语境依赖 | 孤立看可能有不同解读 | 文案存在歧义或隐喻 |
| **内容理解** | 模态缺失 | 部分风险未被覆盖 | 音频/画面分析不可用 |
| **受众差异** | 群体反应差异 | 不同群体反应不同 | 内容涉及敏感群体话题 |
| **受众差异** | 地域文化差异 | 不同地区反应不同 | 内容涉及地域/文化元素 |
| **时效性** | 热点事件变化 | 风险等级可能随事件发展变化 | 涉及时事热点 |
| **时效性** | 政策法规变化 | 合规判断可能过时 | 涉及法规政策 |
| **仿真** | Agent人格不完整 | 仿真中Agent行为可能偏离真人 | 启用了仿真 |
| **仿真** | 仿真随机性 | 不同轮次仿真结果有差异 | 启用了仿真 |
| **仿真** | 平台算法未知 | 推荐算法影响传播预测 | 启用了仿真 |
| **信号** | 热点数据时效 | 关联的热点可能已过时 | 启用了信号关联 |
| **信号** | 实体信息不完整 | 知识图谱中实体可能缺失 | 启用了实体风险链 |

### 5.3 不确定性标注逻辑

```python
class UncertaintyAnnotator:
    """不确定性标注器"""

    def annotate(self, dimension: str, assessment: DimensionAssessment,
                 context: AssessmentContext) -> List[UncertaintyItem]:
        """为维度评估标注不确定性"""

        uncertainties = []

        # 1. 内容理解层面
        if assessment.has_ambiguity:
            uncertainties.append(UncertaintyItem(
                source="语境依赖",
                impact=f"文案中'{assessment.ambiguous_text}'脱离上下文可能有不同解读",
                direction="方向不明"
            ))

        if context.missing_modalities:
            uncertainties.append(UncertaintyItem(
                source="模态缺失",
                impact=f"{context.missing_modalities}未能分析，相关风险可能未被覆盖",
                direction="风险可能升高"
            ))

        # 2. 受众差异
        if assessment.has_audience_divergence:
            uncertainties.append(UncertaintyItem(
                source="群体反应差异",
                impact="不同年龄/性别/地区群体对此内容可能有截然不同反应",
                direction="方向不明"
            ))

        # 3. 时效性
        if context.has_time_sensitive_content:
            uncertainties.append(UncertaintyItem(
                source="热点事件变化",
                impact="涉及时事热点，风险等级可能随事件发展变化",
                direction="可能升高或降低"
            ))

        # 4. 仿真层面
        if context.simulation_enabled:
            if assessment.confidence < 0.7:
                uncertainties.append(UncertaintyItem(
                    source="仿真随机性",
                    impact="多轮仿真结果不完全一致，结论可能受Agent随机性影响",
                    direction="方向不明"
                ))

        # 5. 确定不确定性等级
        if len(uncertainties) == 0:
            uncertainty_level = "low"
        elif len(uncertainties) <= 2:
            uncertainty_level = "medium"
        else:
            uncertainty_level = "high"

        return uncertainties
```

## 8. 改写建议生成

### 8.1 生成原则

- **具体可操作**：不说"注意措辞"，而是给出具体的替代文案
- **保留原意**：改写不应改变内容的核心表达，只降低风险
- **量化效果**：预估改写后的风险降低幅度
- **多方案对比**：高风险项提供2-3个替代方案，让用户选择

## 10. 综合裁决引擎

### 10.1 裁决逻辑

综合裁决将7维评估结果、仿真增强数据、平台反应汇总为最终的报告输出：

```python
class RiskAssessmentEngine:
    """风险评估与报告引擎"""

    async def assess(self, content_understanding: ContentUnderstanding,
                     simulation_result: Optional[SimulationResult] = None,
                     signal_data: Optional[SignalCorrelation] = None) -> RiskReport:
        """执行完整的风险评估流程"""

        # Step 1: 7维静态评估
        dimension_assessments = []
        for dimension in SEVEN_DIMENSIONS:
            assessment = await self._assess_dimension(
                dimension, content_understanding
            )
            dimension_assessments.append(assessment)

        # Step 2: 叠加仿真增强（如有）
        if simulation_result:
            for assessment in dimension_assessments:
                self._apply_simulation_enhancement(assessment, simulation_result)

        # Step 3: 叠加信号关联增强（如有）
        if signal_data:
            for assessment in dimension_assessments:
                self._apply_signal_enhancement(assessment, signal_data)

        # Step 4: 构建证据链
        for assessment in dimension_assessments:
            assessment.evidence_chain = self.evidence_builder.build_chain(
                assessment.name, content_understanding.risk_items,
                simulation_result, signal_data
            )

        # Step 5: 计算置信度
        for assessment in dimension_assessments:
            assessment.confidence_result = self.confidence_calculator.calculate(
                assessment.name, assessment.static_results,
                simulation_result, signal_data
            )

        # Step 6: 标注不确定性
        for assessment in dimension_assessments:
            assessment.uncertainty_sources = self.uncertainty_annotator.annotate(
                assessment.name, assessment, AssessmentContext(...)
            )

        # Step 7: 汇总平台反应
        platform_reactions = self._summarize_platform_reactions(
            content_understanding, simulation_result
        )

        # Step 8: 综合裁决
        overall_risk = self._calculate_overall_risk(dimension_assessments)
        risk_level = self._determine_risk_level(overall_risk)
        overall_confidence = self._calculate_overall_confidence(dimension_assessments)
        overall_uncertainty = self._determine_overall_uncertainty(dimension_assessments)

        # Step 9: 生成改写建议
        suggestions = await self._generate_suggestions(dimension_assessments)

        return RiskReport(
            overall_risk=overall_risk,
            risk_level=risk_level,
            overall_confidence=overall_confidence,
            overall_uncertainty_level=overall_uncertainty,
            dimensions=dimension_assessments,
            platform_reactions=platform_reactions,
            suggestions=suggestions,
            method=self._determine_method(simulation_result, signal_data)
        )
```

### 10.2 总体风险分数计算

```python
def _calculate_overall_risk(self, dimensions: List[DimensionAssessment]) -> int:
    """计算总体风险分数"""
    # 取最高维度分数为基准（木桶效应：最危险的维度决定总体风险）
    max_score = max(d.score for d in dimensions)

    # 其他维度加权平均作为修正
    avg_score = sum(d.score for d in dimensions) / len(dimensions)

    # 综合分数 = 0.6 * 最高分 + 0.4 * 平均分
    overall = int(0.6 * max_score + 0.4 * avg_score)
    return min(100, max(0, overall))

def _determine_risk_level(self, score: int) -> str:
    """根据分数确定风险等级"""
    if score >= 75:
        return "red"
    elif score >= 55:
        return "orange"
    elif score >= 35:
        return "yellow"
    else:
        return "green"
```

## 11. 原核心特性降级说明

以下特性在原始设计中为核心功能，现已降级或移至后续阶段：

| 原特性 | 当前状态 | 理由 | 后续安排 |
|--------|---------|------|----------|
| **趋势预测** | P2/后置 | 仿真可信度尚未验证，在不可信仿真基础上做预测没有意义 | 仿真验证Go(见`11_仿真验证与基础迁移设计.md`)后考虑 |
| **反事实仿真** | P1增强 | 需要基础仿真稳定运行后方可引入分支对比 | 主线仿真稳定后作为增强功能 |
| **决策辅助** | P2/后置 | 本层核心是风险报告（指出风险），决策辅助（告诉用户怎么做）是更高阶能力 | 报告质量稳定、用户反馈明确需求后考虑 |
| **实时舆情监控** | P2/后置 | 需要信号采集层持续运行+仿真引擎实时调度，当前基础设施不支持 | 信号采集+仿真引擎稳定后考虑 |
| **历史回测** | 保留 | 回测是验证评估准确率的必要手段，保留 | 已在`11_仿真验证与基础迁移设计.md`中详细定义 |
| **人工审核入口** | 保留 | 低置信度评估需要人工复核机制 | 集成到报告流程的置信度分级中 |
