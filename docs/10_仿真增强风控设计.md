# VibeUtopia 仿真增强风控设计

## 文档定位
- 本文档在主线中的角色：定义仿真如何作为增强模块提升风控准确率，而非独立产品或用户入口
- 与"发前风控优先"的关系：仿真是风控的增强器，所有仿真能力围绕"让风控更准"展开，用户永远只走"提交内容→获取报告"主链路

## 本文档边界
- 本文档负责：仿真增强机制设计（信号关联、实体风险链、动态权重、Agent仿真增强）、仿真启用/保留/降级条件、回测与对照实验、增强报告格式、置信度与不确定性标注
- 本文档不负责：仿真引擎内部实现（见`08_仿真运行层设计.md`）、静态风险评估逻辑（见`09_分析决策层设计.md`）、前端展示细节（见`13_前端升级设计.md`）、信号采集实现（见`06_信号采集层设计.md`）

## 对准确率的直接贡献
- 机制1：信号关联+实体风险链+动态权重为静态评估补充实时热点上下文，减少"静态评估盲区"导致的漏报
- 机制2：Agent仿真提供多视角验证，通过回测对比量化仿真相对静态的准确率增量
- 验证方式：回测对比（同一批案例跑静态 vs 仿真增强，对比准确率/漏报率/误报率）、受控实验（A/B分流，统计显著性检验）

## 1. 核心定位：仿真 = 增强模块

仿真不是一个独立产品、独立入口、独立流程。它只在主链路"内容理解→风险评估→报告输出"中的风险评估环节，作为**条件性增强器**介入。

```
主链路（用户可见）:
  用户提交内容 → 内容理解 → 风险评估 → 报告输出
                                  │
                                  ▼
                         ┌─────────────────┐
                         │ 风险评估内部逻辑  │
                         │                  │
                         │ Step1: 静态评估   │ ← 每次必走，低成本
                         │   (7维+证据链)    │
                         │        │         │
                         │  风险≥阈值        │
                         │  或用户选深度?     │
                         │   ┌──┴──┐       │
                         │   否    是       │
                         │   │     │       │
                         │   │     ▼       │
                         │   │  Step2:      │
                         │   │  信号关联     │ ← 低成本高价值
                         │   │  实体风险链   │
                         │   │  动态权重     │
                         │   │     │       │
                         │   │     ▼       │
                         │   │  Step3:      │
                         │   │  Agent仿真   │ ← 条件性启用
                         │   │  传播推演     │
                         │   │  极化检测     │
                         │   │     │       │
                         │   │     ▼       │
                         │   │  Step4:      │
                         │   │  综合裁决     │ ← 置信度标注
                         │   │  不确定性标注 │
                         └───┴─────────────┘
```

用户在前端（Vue3 + Naive UI 内容预审工作台）只看到一个流程，后端根据条件自动决定增强深度。

## 2. 仿真启用/保留/降级条件

这是仿真模块的"生命线"决策逻辑，直接决定仿真投入是否值得持续。

### 2.1 启用条件（何时触发仿真增强）

| 条件 | 判断逻辑 | 触发的增强级别 |
|------|----------|---------------|
| 静态评估达到风险阈值 | 静态7维评估中任一维度 ≥ 橙色(50分) 或 总分 ≥ 60 | 信号关联 + 实体风险链 + 动态权重（Step2） |
| 静态评估达到高风险阈值 | 静态7维评估中任一维度 ≥ 红色(70分) 或 总分 ≥ 75 | Step2 + Agent仿真（Step3，标准级500 Agent） |
| 用户主动选择深度分析 | 前端 `options.depth = "deep"` | Step2 + Agent仿真（Step3，深度级2000 Agent） |
| 用户主动选择大规模分析 | 前端 `options.depth = "large_scale"` | Step2 + Agent仿真（Step3，大规模10000 Agent + GA-S3） |
| 静态评估为低风险 | 总分 < 50 且无橙色维度 | 仅Step1静态评估，不启用任何增强 |

### 2.2 保留条件（仿真是否值得持续运行）

通过**回测对比**判断仿真是否带来稳定的准确率提升：

```python
class SimulationRetentionDecider:
    """仿真保留决策器：基于回测数据判断仿真是否值得持续"""

    async def evaluate_retention(self, backtest_window_days: int = 30) -> RetentionDecision:
        """
        对过去N天的回测数据，对比静态 vs 仿真增强的准确率
        """
        # 从回测数据库取对比结果
        comparisons = await self.backtest_store.get_recent_comparisons(
            window_days=backtest_window_days
        )

        # 统计仿真相对静态的准确率增量
        improvements = [c.simulation_accuracy - c.static_accuracy for c in comparisons]
        avg_improvement = sum(improvements) / len(improvements)

        # 统计提升的稳定性（标准差越小越稳定）
        std_improvement = (sum((x - avg_improvement)**2 for x in improvements) / len(improvements)) ** 0.5

        # 决策
        if avg_improvement > 0.10 and std_improvement < 0.08:
            return RetentionDecision(
                action="retain_full",
                reason=f"仿真带来稳定提升({avg_improvement:.1%}+-{std_improvement:.1%})",
                keep_steps=["signal", "entity_chain", "simulation"]
            )
        elif avg_improvement > 0.05:
            return RetentionDecision(
                action="retain_partial",
                reason=f"仿真提升有限且不稳定({avg_improvement:.1%}+-{std_improvement:.1%})",
                keep_steps=["signal", "entity_chain"]  # 保留低成本高价值模块
            )
        else:
            return RetentionDecision(
                action="degrade",
                reason=f"仿真未带来可靠提升({avg_improvement:.1%}+-{std_improvement:.1%})",
                keep_steps=["signal", "entity_chain"]  # 仅保留信号+实体链
            )
```

### 2.3 降级条件（何时缩减仿真投入）

| 降级触发条件 | 降级动作 | 保留模块 |
|-------------|---------|---------|
| 回测显示仿真准确率增量 < 5% | 关闭Agent仿真，仅保留信号关联+实体风险链 | 信号关联 + 实体风险链 |
| 仿真结果3次一致性 < 50% | 仿真结果标记为"低置信度"，报告以静态评估为主 | 静态评估为主，仿真标注为参考 |
| LLM成本超过预算阈值 | 降低Agent数量（2000→500→100） | 信号关联 + 实体风险链 + 轻量仿真 |
| 仿真耗时超过用户容忍阈值 | 跳过传播推演和极化检测 | 信号关联 + 实体风险链 + Agent反应统计 |

### 2.4 降级路径总结

```
完整仿真增强（Step1+2+3）
     │
     ▼ 仿真增量不稳定
缩减仿真（Step1+2，关闭Step3 Agent仿真）
     │
     ▼ 信号关联/实体链也无提升
仅静态评估（Step1，关闭所有增强）
```

### 3.2 Step2：信号关联 + 实体风险链 + 动态权重

#### 3.2.1 信号关联模块

文案风险评估时，自动将文案内容与当前热点事件关联，提示风险上下文。

```python
class SignalRiskCorrelator:
    """信号-风险关联器"""

    async def correlate(
        self, text: str, risk_dimensions: list
    ) -> List[HotspotCorrelation]:
        """文案与热点事件的关联"""

        # Step 1: 从文案中提取关键词
        keywords = await self.keyword_extractor.extract(text)

        # Step 2: 在种子事件库(ChromaDB向量检索)中搜索匹配事件
        matching_events = await self.event_store.query(
            query_texts=keywords, n_results=10
        )

        # Step 3: 计算关联度与风险影响
        correlations = []
        for event in matching_events:
            relevance = self._calc_relevance(keywords, event)
            risk_impact = self._calc_risk_impact(event, risk_dimensions)
            if relevance > 0.5 and risk_impact > 0.3:
                correlations.append(HotspotCorrelation(
                    event=event,
                    relevance=relevance,
                    relevance_confidence=self._calc_relevance_confidence(keywords, event),
                    risk_impact=risk_impact,
                    risk_impact_confidence=self._calc_impact_confidence(event),
                    explanation=f"你的文案涉及[{event.topic}]，当前该话题热度{event.heat_score}，{event.sentiment_summary}",
                    uncertainty="热点事件关联基于关键词匹配，可能存在语义偏差"
                ))

        return sorted(correlations, key=lambda c: c.risk_impact, reverse=True)[:5]
```

输出格式（含置信度与不确定性标注）：


#### 3.2.2 实体风险链模块

通过知识图谱（Neo4j），识别文案中的命名实体 → 追踪关联争议事件 → 提示风险传导路径。

```python
class EntityRiskChain:
    """实体风险链"""

    async def trace(self, text: str) -> List[RiskChain]:
        """追踪文案实体的风险链"""

        # Step 1: 从文案中提取命名实体（DeepSeek-V4-Pro / Qwen3.6-Plus）
        entities = await self.entity_extractor.extract(text)

        # Step 2: 在知识图谱(Neo4j)中查询每个实体的关联
        risk_chains = []
        for entity in entities:
            paths = await self.graph_store.find_paths(
                start_node=entity,
                relation_types=["涉及", "引发", "关联"],
                max_hops=2,
                filter_label="争议事件"
            )

            for path in paths:
                risk_chains.append(RiskChain(
                    entity=entity.name,
                    chain=path.to_risk_chain_description(),
                    risk_level=path.end_node.risk_level,
                    chain_confidence=self._calc_chain_confidence(path),
                    explanation=f"你提到的[{entity.name}] → {path.description}",
                    uncertainty="知识图谱可能未覆盖最新争议事件，链路完整性受限于图谱更新频率"
                ))

        return risk_chains
```

输出格式（含置信度与不确定性标注）：

```json
{
  "entity_risk_chains": [
    {
      "entity": "某品牌A",
      "chain": "品牌A → 近期代言争议 → 性别歧视舆论",
      "risk_level": "orange",
      "chain_confidence": 0.72,
      "explanation": "你提到的[品牌A]近期因代言人言论引发性别歧视争议",
      "uncertainty": "图谱中该链路仅1条路径支撑，可能存在未收录的正面关联"
    }
  ]
}
```

#### 3.2.3 动态风险权重

基于当前热点热度，动态调整7维风险权重。热度数据来自信号采集层（ChromaDB存储）。

```python
class DynamicRiskWeighting:
    """动态风险权重"""

    BASE_WEIGHTS = {
        "政治敏感": 1.2,
        "性别议题": 1.0,
        "民族宗教": 1.2,
        "道德伦理": 0.8,
        "法律合规": 1.0,
        "群体冒犯": 0.8,
        "时事踩雷": 0.6,
    }

    async def calc_weights(self) -> Dict[str, WeightResult]:
        """计算当前动态权重"""

        # 从ChromaDB获取最近24h各维度的信号强度
        current_heat = await self._get_dimension_heat()

        weights = {}
        for dim, base in self.BASE_WEIGHTS.items():
            heat = current_heat.get(dim, 0)
            boost = 1.0 + heat  # heat=0.5 → 权重1.5, heat=1.0 → 权重2.0
            weights[dim] = WeightResult(
                weight=base * boost,
                base_weight=base,
                heat_boost=boost,
                heat_value=heat,
                weight_confidence=min(0.95, 0.5 + heat * 0.45),  # 热度越高权重越确定
                uncertainty="权重基于最近24h热点信号，历史波动可能导致权重滞后"
            )

        return weights
```

输出格式（含置信度与不确定性标注）：

```json
{
  "dynamic_weights": {
    "性别议题": {
      "weight": 1.85,
      "base_weight": 1.0,
      "heat_boost": 1.85,
      "heat_value": 0.85,
      "weight_confidence": 0.88,
      "uncertainty": "权重基于最近24h热点信号，时效性有限"
    },
    "时事踩雷": {
      "weight": 1.26,
      "base_weight": 0.6,
      "heat_boost": 2.1,
      "heat_value": 1.0,
      "weight_confidence": 0.95,
      "uncertainty": "时事维度热度波动大，权重可能在数小时内剧变"
    }
  },
  "weight_change_reason": "性别议题因XX事件热度0.85，权重提升85%；时事踩雷因YY事件热度1.0，权重提升110%"
}
```

### 3.3 Step3：Agent仿真增强（条件性启用）

当静态评估达到风险阈值或用户选择深度分析时，启动Agent仿真。

#### 3.3.1 Agent规模配置

| 分析深度 | Agent数量 | 仿真时长 | 预估耗时 | LLM成本 | 模型路由 | 适用场景 |
|----------|----------|---------|---------|---------|---------|---------|
| lightweight | 100 | 6h | 1-2分钟 | ~¥0.5 | DeepSeek-V4-Flash / Qwen3.6-Plus | 风险阈值触发 |
| standard | 500 | 24h | 3-5分钟 | ~¥2 | DeepSeek-V4-Flash / Qwen3.6-Plus | 标准深度 |
| deep | 2000 | 48h | 10-15分钟 | ~¥5 | DeepSeek-V4-Pro(核心Agent) + Flash(普通Agent) | 用户选择深度 |
| large_scale | 10000 | 72h | 20-40分钟 | ~¥10-20 | DeepSeek-V4-Pro + GA-S3 Group Agent | 大规模分析 |

| 平台 | Agent数 | A级(大V) | B级(活跃) | C级(潜水) |
|------|---------|----------|----------|----------|
| 微博 | 20 | 5(热搜机制) | 7 | 8 |
| B站 | 20 | 5(分区UP) | 7 | 8 |

| 抖音 | 20 | 5(头部达人) | 7 | 8 |

#### 3.3.4 标准级500 Agent分配

500个Agent覆盖更多平台和更细粒度人格：

| 平台组 | Agent数 | 覆盖平台 |
|--------|---------|---------|
| 核心平台(5) | 250 (每平台50) | 微博/B站/小红书/知乎/抖音 |
| 扩展平台(5) | 150 (每平台30) | 快手/公众号/豆瓣/虎扑/头条 |
| 垂直平台(5) | 100 (每平台20) | 贴吧/NGA/视频号/ TapTap/米游社 |

#### 3.3.5 深度级2000 Agent分配

- 核心平台每平台100 Agent（含人生故事驱动的A-tier Agent）
- 扩展平台每平台50 Agent
- 垂直平台+长尾平台共750 Agent
- Agent记忆系统(Memory Stream)通过ChromaDB检索相关记忆

#### 3.3.6 大规模10000 Agent + GA-S3 Group Agent

- 实际独立Agent ~2000-3000个
- GA-S3 Group Agent机制：统计模型替代相似Agent，1个群组Agent代表10-100个相似个体
- 等效覆盖 > 100000个体
- C-tier Agent使用规则引擎 + Group Agent统计模型，不调用LLM
- 传播5阶段模型：种子→扩散→爆发→长尾→沉淀
- 极化检测与舆论转折预测

#### 3.3.7 仿真流程

```
1. 从人格工厂批量生成Agent（7层人格 + 人生故事，存储于MySQL/SQLite + ChromaDB）
2. 将用户文案作为种子事件注入仿真世界
3. 运行仿真（时长根据深度配置）
4. 收集各平台的行为轨迹（通过asyncio.Queue异步传递）
5. 汇总分析：各平台情感分布 + 传播路径 + 关键节点
6. 将仿真结果转换为风控增强数据（含置信度和不确定性标注）
```

### 3.4 Step4：综合裁决与不确定性标注

将静态评估、信号关联、实体风险链、动态权重、仿真结果进行综合裁决。

```python
@dataclass
class EnhancedRiskReport:
    """仿真增强风控报告"""

    # Step1: 静态评估结果（每次必有）
    base_report: BaseRiskReport  # 7维评分+证据链+改写建议

    # Step2: 信号关联增强（条件性）
    hotspot_correlations: Optional[List[HotspotCorrelation]]  # 热点关联
    entity_risk_chains: Optional[List[RiskChain]]             # 实体风险链
    dynamic_weights: Optional[Dict[str, WeightResult]]        # 动态权重
    weight_change_reason: Optional[str]                        # 权重变化原因

    # Step3: 仿真增强（条件性）
    simulation_result: Optional[SimulationSummary]    # 仿真结果摘要
    simulated_platform_reactions: Optional[Dict]       # 仿真平台反应
    propagation_prediction: Optional[Dict]             # 传播预测
    polarization_trend: Optional[Dict]                 # 极化趋势

    # Step4: 综合置信度与不确定性标注（必有）
    method: str                    # "static" | "signal_enhanced" | "simulation_enhanced"
    confidence: float              # 整体置信度 0-1
    confidence_breakdown: Dict     # 各环节置信度分解
    uncertainty_sources: List[str] # 不确定性来源列表
    uncertainty_level: str         # "low" | "medium" | "high"
    enhancement_contribution: Optional[Dict]  # 增强模块相对静态的准确率增量估算
```

## 4. 前端展示（Vue3 + Naive UI）

### 4.1 热点关联区域

## 7. 回测与对照实验

### 7.1 回测框架设计

同一批测试文案，同时运行不同深度的评估，量化各增强模块的准确率贡献。

| 对比组 | 评估方法 | 对比目的 |
|--------|---------|---------|
| A组（基线） | 静态评估（Step1 only） | 建立准确率基线 |
| B组 | 静态 + 信号关联 + 实体风险链 + 动态权重（Step1+2） | 量化信号增强的增量 |
| C组 | 静态 + 信号增强 + Agent仿真100（Step1+2+3轻量） | 量化轻量仿真的增量 |
| D组 | 静态 + 信号增强 + Agent仿真500（Step1+2+3标准） | 量化标准仿真的增量 |
| E组 | 静态 + 信号增强 + Agent仿真2000（Step1+2+3深度） | 量化深度仿真的增量 |

### 7.2 对比维度

| 对比维度 | A组(静态) | B组(信号增强) | C-E组(仿真增强) |
|----------|----------|-------------|----------------|
| 7维风险评分 | 静态Prompt评估 | 动态权重+热点关联 | 动态权重+仿真验证 |
| 平台反应预测 | 规则+静态推理 | +热点上下文 | +多Agent仿真反应 |
| 风险句子标注 | 纯LLM判断 | +实体风险链+热点关联 | +仿真验证标注 |
| 改写建议 | 基于LLM | +热点规避建议 | +仿真验证改写效果 |
| 置信度 | 单一LLM置信度 | 多源交叉验证 | 仿真一致性+交叉验证 |

### 7.3 回测流程

```python
class BacktestRunner:
    """回测运行器"""

    async def run_backtest(self, test_cases: List[BacktestCase]):
        """对一批测试案例运行回测对比"""

        results = []
        for case in test_cases:
            # A组：静态评估
            static_result = await self.assessor.assess(
                case.text, method="static"
            )

            # B组：信号增强
            signal_result = await self.assessor.assess(
                case.text, method="signal_enhanced"
            )

            # C-E组：仿真增强（根据配置选择Agent数量）
            sim_result = await self.assessor.assess(
                case.text, method="simulation_enhanced",
                simulation_config={"agent_count": agent_count}
            )

            # 对比各方法与人工标注的一致性
            comparison = BacktestComparison(
                case_id=case.id,
                ground_truth=case.ground_truth_risk,
                static_accuracy=self._calc_accuracy(static_result, case.ground_truth),
                signal_enhanced_accuracy=self._calc_accuracy(signal_result, case.ground_truth),
                simulation_enhanced_accuracy=self._calc_accuracy(sim_result, case.ground_truth),
            )
            results.append(comparison)

        # 汇总统计
        return BacktestSummary(
            static_avg_accuracy=mean(r.static_accuracy for r in results),
            signal_enhanced_avg_accuracy=mean(r.signal_enhanced_accuracy for r in results),
            simulation_enhanced_avg_accuracy=mean(r.simulation_enhanced_accuracy for r in results),
            sample_size=len(results)
        )
```

### 7.4 受控实验（A/B分流）

在生产环境中，对新提交的预审任务进行受控实验：

- **实验组**：启用仿真增强评估
- **对照组**：仅静态评估
- **后验验证**：对两组结果进行人工复检，统计准确率差异
- **统计显著性**：要求 p < 0.05 才认定仿真增强有真实提升
- **最小样本量**：每组至少50个案例

```python
class ControlledExperiment:
    """受控实验管理器"""

    async def assign_group(self, task_id: str) -> str:
        """为任务分配实验组/对照组"""
        # 基于task_id的hash分流，确保可复现
        group = "experiment" if hash(task_id) % 2 == 0 else "control"
        await self.experiment_store.record_assignment(task_id, group)
        return group

    async def analyze_experiment(self, experiment_id: str) -> ExperimentResult:
        """分析实验结果"""
        assignments = await self.experiment_store.get_assignments(experiment_id)

        experiment_accuracies = []
        control_accuracies = []

        for assignment in assignments:
            human_review = await self.human_review_store.get(assignment.task_id)
            if not human_review:
                continue

            auto_result = await self.result_store.get(assignment.task_id)
            accuracy = self._calc_accuracy(auto_result, human_review)

            if assignment.group == "experiment":
                experiment_accuracies.append(accuracy)
            else:
                control_accuracies.append(accuracy)

        # t检验
        from scipy import stats
        t_stat, p_value = stats.ttest_ind(experiment_accuracies, control_accuracies)

        return ExperimentResult(
            experiment_group_size=len(experiment_accuracies),
            control_group_size=len(control_accuracies),
            experiment_avg_accuracy=mean(experiment_accuracies),
            control_avg_accuracy=mean(control_accuracies),
            accuracy_delta=mean(experiment_accuracies) - mean(control_accuracies),
            p_value=p_value,
            significant=p_value < 0.05,
            conclusion="仿真增强有统计显著提升" if p_value < 0.05 else "仿真增强提升不显著"
        )
```

### 7.5 回测目标

| 对比项 | 目标增量 | 验证方式 |
|--------|---------|---------|
| 信号增强 vs 静态 | 准确率提升 > 5% | 回测50+案例 |
| 轻量仿真(100) vs 信号增强 | 准确率提升 > 3% | 回测30+案例 |
| 标准仿真(500) vs 轻量仿真 | 准确率提升 > 2% | 回测30+案例 |
| 深度仿真(2000) vs 标准仿真 | 准确率提升 > 1% | 回测20+案例 |
| 大规模仿真(10000) vs 深度仿真 | 准确率提升 > 0.5% | 回测10+案例 |

> 注意：增量递减是预期的。仿真从100→10000 Agent，边际收益递减但稳定性提升。

## 关键流程/结构

- 输入：主链路风险评估结果（7维静态评估 + 风险阈值）
- 处理：
  1. 判断是否满足仿真启用条件（风险阈值/用户选择深度）
  2. 条件满足 → 信号关联 + 实体风险链 + 动态权重（Step2）
  3. 高风险/深度分析 → Agent仿真 + 传播推演 + 极化检测（Step3）
  4. 综合裁决 + 置信度标注 + 不确定性标注（Step4）
  5. 定期回测对比，根据结果决定仿真保留/降级
- 输出：增强风控报告（method标记 + 置信度 + 不确定性 + 增量贡献标注）

## 依赖与降级

- 依赖：
  - 静态评估模块（Step1，必须有）
  - ChromaDB（信号关联的向量检索，零部署）
  - Neo4j（实体风险链的图谱查询，Lite模式可跳过）
  - asyncio.Queue（仿真任务调度，零外部依赖）
  - LLM API（DeepSeek-V4 / Qwen3.6 / GLM系列）
  - MySQL/SQLite（结果存储，SQLite降级零依赖）

- 失败降级策略：
  - ChromaDB不可用 → 信号关联退化为关键词精确匹配
  - Neo4j不可用 → 实体风险链跳过，报告标注"实体风险链不可用"
  - LLM API不可用 → 仿真降级到本地小模型(Qwen3-8B)，或跳过仿真仅保留Step1+2
  - 仿真超时 → 降级为信号增强（Step1+2），报告标注"仿真超时降级"
  - 仿真结果一致性低 → 仿真结果标记为"低置信度参考"，以静态评估为主
  - 回测显示仿真增量不稳定 → 降级为仅保留信号关联+实体风险链，关闭Agent仿真

## 验收标准

- 指标：仿真增强相对静态评估的准确率增量、漏报率降幅、误报率变化、仿真结果一致性
- 阈值：
  - 信号增强(Step2)相对静态准确率增量 > 5%
  - 仿真增强(Step3)相对信号增强准确率增量 > 3%
