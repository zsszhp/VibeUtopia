# VibeUtopia 仿真增强风控设计

> 让V2.1-V2.5的技术底座产出用户可感知的价值：从"4个静态Prompt猜测反应"进化到"100个Agent仿真预测反应"。

## 1. 设计理念

当前状态：V2.1-V2.5 已构建完整的信号采集、知识图谱、7层人格、社交仿真、传播动力学能力，但这些能力**没有接入风控流程**。用户看到的风控报告和MVP一模一样——7维评分+4平台反应+改写建议。

V2.R1 的目标：**把仿真引擎变成风控引擎的增强器**，让博主感知到"风控变准了"。

设计原则：
- **渐进增强**：仿真风控是MVP风控的增强版，不是替代版。用户可以选择"快速评估"(MVP)或"深度评估"(仿真增强)
- **成本可控**：轻量仿真100 Agent × 6h，成本<¥1/次，耗时<5分钟
- **价值可量化**：内置对比测试，同一文案同时跑MVP和V2，量化改善幅度

## 3. 轻量仿真模式

### 3.1 设计目标

MVP 的静态人格模拟（4个平台各1个Prompt）成本约 ¥0.05/次，耗时约30秒。全量仿真（1000 Agent × 24h）成本约 ¥4/次，耗时约20分钟。两者之间存在巨大鸿沟。

轻量仿真模式填补这个鸿沟：**100 Agent × 6h，成本<¥1/次，耗时<5分钟**。

### 3.2 配置参数

```python
LIGHTWEIGHT_SIM_CONFIG = {
    "agent_count": 100,          # 50A级 + 30B级 + 20C级
    "simulation_hours": 6,       # 仿真6小时
    "time_acceleration": 6,      # 1仿真小时=10真实秒
    "platforms": ["weibo", "bilibili", "xiaohongshu", "zhihu", "douyin"],
    "llm_tier": "tier2",         # 使用Tier2模型降低成本
    "seed_injection": True,      # 自动注入文案作为种子事件
    "max_llm_calls": 200,        # 限制LLM调用次数
    "skip_coordinators": True,   # 跳过Director/Watcher/Guardian降低成本
}
```

### 3.3 Agent 分配策略

100个Agent按5个平台均匀分配，每个平台20个Agent：

| 平台 | Agent数 | A级(大V) | B级(活跃) | C级(潜水) |
|------|---------|----------|----------|----------|
| 微博 | 20 | 5(热搜机制) | 7 | 8 |
| B站 | 20 | 5(分区UP) | 7 | 8 |
| 小红书 | 20 | 5(种草博主) | 7 | 8 |
| 知乎 | 20 | 5(领域大V) | 7 | 8 |
| 抖音 | 20 | 5(头部达人) | 7 | 8 |

### 3.4 仿真流程

```
1. 从人格工厂批量生成100个Agent（使用V2.3的批量生成器）
2. 将用户文案作为种子事件注入仿真世界
3. 运行6小时轻量仿真（约5分钟真实时间）
4. 收集各平台的行为轨迹
5. 汇总分析：各平台情感分布 + 传播路径 + 关键节点
6. 将仿真结果转换为风控增强数据
```

### 3.5 与全量仿真的对比

| 维度 | 轻量仿真 | 全量仿真 |
|------|---------|---------|
| Agent数 | 100 | 1000 |
| 仿真时长 | 6h | 24h |
| 真实耗时 | ~5分钟 | ~20分钟 |
| LLM成本 | <¥1 | ¥4-6 |
| LLM调用量 | ~200次 | ~3900次 |
| 适用场景 | 日常风控 | 趋势预测 |
| 可信度 | 中（需标注不确定性） | 高（3轮共识） |

## 4. 信号关联模块

### 4.1 功能

文案风险评估时，自动将文案内容与当前热点事件关联，提示"你的文案可能与当前舆论热点相关"。

### 4.2 匹配逻辑

```python
class SignalRiskCorrelator:
    """信号-风险关联器"""

    async def correlate(self, text: str, risk_dimensions: dict) -> List[HotspotCorrelation]:
        """文案与热点事件的关联"""

        # Step 1: 从文案中提取关键词
        keywords = await self.keyword_extractor.extract(text)

        # Step 2: 在种子事件库中搜索匹配事件
        matching_events = await self.event_store.search(keywords, top_k=10)

        # Step 3: 计算关联度
        correlations = []
        for event in matching_events:
            relevance = self._calc_relevance(keywords, event)
            risk_impact = self._calc_risk_impact(event, risk_dimensions)
            if relevance > 0.5 and risk_impact > 0.3:
                correlations.append(HotspotCorrelation(
                    event=event,
                    relevance=relevance,
                    risk_impact=risk_impact,
                    explanation=f"你的文案涉及[{event.topic}]，当前该话题在微博热度{event.heat_score}，{event.sentiment_summary}"
                ))

        return sorted(correlations, key=lambda c: c.risk_impact, reverse=True)[:5]
```

### 4.3 输出格式

```json
{
  "hotspot_correlations": [
    {
      "event_title": "某品牌性别歧视争议",
      "platform": "微博",
      "heat_score": 0.85,
      "relevance": 0.72,
      "risk_impact": 0.65,
      "risk_dimension": "性别议题",
      "explanation": "你的文案涉及[品牌合作]话题，当前该品牌正陷入性别歧视争议，建议避免关联"
    }
  ]
}
```

## 5. 实体风险链模块

### 5.1 功能

通过知识图谱，识别文案中的命名实体→追踪其关联的争议事件→提示风险传导路径。

### 5.2 风险链查询

```python
class EntityRiskChain:
    """实体风险链"""

    async def trace(self, text: str) -> List[RiskChain]:
        """追踪文案实体的风险链"""

        # Step 1: 从文案中提取命名实体
        entities = await self.entity_extractor.extract(text)

        # Step 2: 在知识图谱中查询每个实体的关联
        risk_chains = []
        for entity in entities:
            # 查询该实体关联的争议事件（1-2跳）
            paths = await self.graph_store.find_paths(
                start_node=entity,
                relation_types=["涉及", "引发", "关联"],
                max_hops=2,
                filter_label="争议事件"
            )

            for path in paths:
                risk_chains.append(RiskChain(
                    entity=entity.name,
                    chain=path.to_risk_chain_description(),
                    risk_level=path.end_node.risk_level,
                    explanation=f"你提到的[{entity.name}] → {path.description}"
                ))

        return risk_chains
```

### 5.3 输出格式

```json
{
  "entity_risk_chains": [
    {
      "entity": "某品牌A",
      "chain": "品牌A → 近期代言争议 → 性别歧视舆论",
      "risk_level": "orange",
      "explanation": "你提到的[品牌A]近期因代言人言论引发性别歧视争议，文案中提及该品牌可能被关联讨论"
    }
  ]
}
```

## 6. 动态风险权重

### 6.1 功能

基于当前热点热度，动态调整7维风险的权重。当某维度话题正在风口时，该维度的风险权重提升。

### 6.2 权重计算

```python
class DynamicRiskWeighting:
    """动态风险权重"""

    BASE_WEIGHTS = {
        "政治敏感": 1.2,
        "性别议题": 1.0,
        "民族宗教": 1.2,
        "道德伦理": 0.8,
        "法律合规": 1.0,
        "群体冒犯": 0.8,
        "时事踩雷": 0.6,
    }

    async def calc_weights(self) -> Dict[str, float]:
        """计算当前动态权重"""

        # 获取当前各维度的热点热度
        current_heat = await self._get_dimension_heat()

        # 动态调整：热度高的维度权重提升
        weights = {}
        for dim, base in self.BASE_WEIGHTS.items():
            heat = current_heat.get(dim, 0)
            # 热度0-1映射到权重1.0-2.0
            boost = 1.0 + heat  # heat=0.5 → 权重1.5，heat=1.0 → 权重2.0
            weights[dim] = base * boost

        return weights

    async def _get_dimension_heat(self) -> Dict[str, float]:
        """获取各维度的当前热点热度"""
        # 从种子事件库中查询最近24小时各维度的信号强度
        events = await self.event_store.recent(hours=24)
        heat = {}
        for event in events:
            for dim in self.BASE_WEIGHTS:
                if dim in event.risk_dimensions:
                    heat[dim] = max(heat.get(dim, 0), event.signal_strength)
        return heat
```

## 7. 增强风控报告

### 7.1 报告结构

```python
@dataclass
class EnhancedRiskReport:
    """仿真增强风控报告"""

    # MVP报告（保持不变）
    base_report: BaseRiskReport  # 7维评分+平台反应+改写建议

    # 信号关联增强（Phase 2）
    hotspot_correlations: List[HotspotCorrelation]  # 热点关联
    entity_risk_chains: List[RiskChain]              # 实体风险链
    dynamic_weights: Dict[str, float]                # 动态权重
    weight_change_reason: str                         # 权重变化原因

    # 仿真增强（Phase 3，可选）
    simulation_result: Optional[SimulationSummary]   # 仿真结果摘要
    simulated_platform_reactions: Optional[Dict]      # 仿真平台反应
    propagation_prediction: Optional[Dict]            # 传播预测
    polarization_trend: Optional[Dict]                # 极化趋势

    # 可信度标注
    confidence: float                                  # 整体置信度
    uncertainty_sources: List[str]                     # 不确定性来源
    method: str                                        # "static" | "signal_enhanced" | "simulation_enhanced"
```

### 7.2 前端展示变更

在Streamlit现有风控报告基础上，增加三个展示区域：

1. **热点关联区域**：在7维雷达图下方，显示"当前相关热点"列表，每个热点标注关联度和风险影响
2. **实体风险链区域**：在高风险句子标注中，如果句子包含有风险链的实体，显示风险传导路径
3. **仿真增强区域**（启用仿真时）：平台反应部分从"MVP静态预测"切换为"仿真预测"，显示更多细节（传播路径、关键节点、极化趋势）

## 10. 对比测试框架

### 10.1 设计

同一批测试文案，同时运行 MVP 静态评估和 V2 仿真增强评估，对比两者在以下维度的差异：

| 对比维度 | MVP静态 | V2仿真增强 |
|----------|---------|-----------|
| 7维风险评分 | 静态Prompt评估 | 动态权重+仿真验证 |
| 平台反应预测 | 4平台各1个Prompt | 5平台各20个Agent仿真 |
| 风险句子标注 | 纯LLM判断 | LLM+实体风险链+热点关联 |
| 改写建议 | 基于LLM | 基于LLM+仿真验证改写效果 |
| 整体准确率 | 基准 | 需提升>15% |

### 10.2 测试流程

```python
class ComparisonTester:
    """对比测试器"""

    async def run_comparison(self, test_cases: List[str]):
        """对一批文案运行对比测试"""

        results = []
        for text in test_cases:
            # MVP评估
            mvp_result = await self.analyzer.analyze(text, method="static")

            # V2仿真增强评估
            v2_result = await self.analyzer.analyze_v2(text, enable_simulation=True)

            # 对比
            comparison = self._compare(mvp_result, v2_result)
            results.append(comparison)

        return results
```

## 11. 实现优先级
