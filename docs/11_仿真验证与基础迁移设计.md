# VibeUtopia 仿真验证与基础迁移设计

> 在投入趋势预测之前，验证仿真风控的可信度，完成数据库基础设施迁移。如果仿真不可信，预测就是空中楼阁。

## 1. 设计理念

V2.R1 构建了"仿真增强风控"，让用户感知到改善。但一个根本问题尚未回答：**仿真比MVP更准吗？**

V2.R2 的目标不是新功能，而是**可信度证明**。它回答三个问题：
1. 仿真风控的方向对不对？（回测验证）
2. 仿真结果稳定吗？（多轮一致性）
3. 数据基础设施撑得住吗？（SQLite→MySQL迁移）

如果R2验证失败，R3（趋势预测）不应启动。

---

## 2. 回测框架

### 2.1 设计思路

用已发生的历史热点事件作为测试用例，将事件发生前的信息（种子文案/新闻报道）输入仿真风控，看预测方向是否与实际结果一致。

### 2.2 回测用例来源

| 来源 | 说明 | 已有数据 |
|------|------|---------|
| cases/paperwork/ | 已有的9个真实案例文档 | 文案内容+风险分析报告 |
| cases/video_transcript/ | 4个B站视频转录 | 视频文案 |
| reports/analysis/ | 8个分析报告 | MVP分析结果 |
| tests/deep-analysis/ | 10个深度分析测试 | 更详细的分析 |
| 外部历史事件 | 补充3-5个已知舆论走向的事件 | 需手动整理 |

### 2.3 回测用例标准

每个回测用例需要包含：

```python
@dataclass
class BacktestCase:
    """回测用例"""
    case_id: str
    title: str                          # 事件标题
    seed_content: str                   # 种子文案/报道内容
    actual_outcome: ActualOutcome       # 实际结果
    risk_dimensions: List[str]          # 涉及的风险维度

@dataclass
class ActualOutcome:
    """实际结果"""
    overall_direction: str              # 上涨/持平/下降（舆论热度）
    platforms_affected: List[str]       # 实际波及的平台
    peak_heat_score: float              # 峰值热度(0-1)
    duration_days: int                  # 持续天数
    polarization_occurred: bool         # 是否出现立场极化
    key_groups_affected: List[str]      # 主要受影响的群体
    description: str                    # 结果描述
```

### 2.4 回测流程

```
回测用例（种子文案 + 实际结果）
     │
     ▼
Step 1: 输入种子文案到仿真风控
  ├── MVP静态评估 → 预测A
  └── V2仿真增强评估 → 预测B
     │
     ▼
Step 2: 对比预测 vs 实际
  ├── 预测A vs 实际 → 准确率A
  └── 预测B vs 实际 → 准确率B
     │
     ▼
Step 3: 量化改善
  ├── 方向准确率: V2 vs MVP
  ├── 平台预测准确率: V2 vs MVP
  └── 风险维度准确率: V2 vs MVP
     │
     ▼
Step 4: 生成回测报告
```

### 2.5 准确率评估维度

| 维度 | 定义 | 权重 |
|------|------|------|
| **方向准确率** | 舆论热度方向(上涨/持平/下降)预测正确 | 40% |
| **平台准确率** | 预测波及的平台与实际一致 | 20% |
| **维度准确率** | 预测的风险维度与实际一致 | 20% |
| **群体准确率** | 预测的受影响群体与实际一致 | 10% |
| **极化准确率** | 是否出现极化的预测正确 | 10% |

### 2.6 Go/No-Go判定

- **Go**：5个回测用例中，V2方向准确率>55%，且V2比MVP准确率提升>10%
- **No-Go**：V2方向准确率<55% → 暂停R3，先修仿真质量
- **Conditional Go**：55%<=V2<65% → 可启动R3但需降低预测粒度

## 3. 多轮一致性检查

### 3.1 设计思路

同一事件运行3次仿真，评估结果是否稳定。如果3次结果各不相同，说明仿真随机性太大，不可信。

### 3.2 一致性评估

```python
class ConsistencyChecker:
    """多轮一致性检查器"""

    async def check(self, seed_content: str, rounds: int = 3) -> ConsistencyReport:
        """运行多轮仿真，检查一致性"""

        results = []
        for i in range(rounds):
            result = await self.simulation_engine.run_lightweight(seed_content)
            results.append(result)

        # 评估方向一致性
        directions = [r.overall_direction for r in results]
        direction_consistency = self._calc_agreement(directions)

        # 评估平台反应一致性
        platform_consistency = self._calc_platform_agreement(results)

        # 评估风险维度一致性
        risk_consistency = self._calc_risk_agreement(results)

        return ConsistencyReport(
            rounds=rounds,
            direction_consistency=direction_consistency,  # 3/3=1.0, 2/3=0.67, 1/3=0.33
            platform_consistency=platform_consistency,
            risk_consistency=risk_consistency,
            overall_consistency=(direction_consistency * 0.5 +
                                platform_consistency * 0.25 +
                                risk_consistency * 0.25),
            verdict="high" if direction_consistency >= 1.0
                    else "medium" if direction_consistency >= 0.67
                    else "low"
        )
```

### 3.3 一致性标准

| 等级 | 方向一致性 | 含义 |
|------|-----------|------|
| 高 | 3/3一致 | 仿真稳定，结果可信 |
| 中 | 2/3一致 | 仿真有随机性，需标注不确定性 |
| 低 | 1/3或0/3 | 仿真不稳定，不可用于预测 |

## 4. 可信度标注

### 4.1 标注格式

在每个风控报告中标注可信度信息：

```python
@dataclass
class CredibilityAnnotation:
    """可信度标注"""
    method: str                    # static/signal_enhanced/simulation_enhanced
    confidence: float              # 整体置信度 0-1
    simulation_rounds: int         # 仿真轮次（仅仿真模式）
    direction_consistency: float   # 方向一致性
    uncertainty_sources: List[str] # 不确定性来源
    data_freshness: str            # 数据新鲜度（信号采集时间）

    # 不确定性来源枚举
    UNCERTAINTY_SOURCES = [
        "LLM生成随机性",
        "Agent数量有限(100个)",
        "仿真时长有限(6小时)",
        "当前热点数据可能有延迟",
        "知识图谱实体覆盖不完整",
    ]
```

### 4.2 置信度计算

```python
def calc_confidence(method, consistency, data_freshness):
    """计算置信度"""

    if method == "static":
        return 0.5  # MVP静态评估，置信度基准

    elif method == "signal_enhanced":
        base = 0.6  # 信号增强，比静态更准
        if data_freshness < "1h": base += 0.1
        elif data_freshness > "24h": base -= 0.1
        return min(base, 0.8)

    elif method == "simulation_enhanced":
        base = 0.5
        if consistency == "high": base = 0.75
        elif consistency == "medium": base = 0.6
        elif consistency == "low": base = 0.4
        return min(base, 0.85)
```

## 5. SQLite → MySQL 迁移

### 5.1 迁移范围

| 数据 | 当前存储 | 迁移目标 | 优先级 |
|------|---------|---------|--------|
| 风控任务+结果 | SQLite(tasks/risk_items/platform_reactions) | MySQL | P0 |
| 分析摘要 | SQLite(analysis_summaries) | MySQL | P0 |
| 仿真轨迹 | SQLite(simulation_records/traces) | MySQL | P1 |
| 热点关联/实体风险链 | SQLite(新表) | MySQL | P0 |
| 信号事件 | SQLite + Neo4j | MySQL + Neo4j | P2 |
| 博主数据 | 无 | MySQL(新表) | P3(R6用) |

### 5.2 迁移策略

```python
# 迁移步骤：

# Step 1: 更新 database.py，支持 MySQL
# - 新增 MySQL 连接配置
# - 保留 SQLite 作为降级方案
# - 通过环境变量切换

# Step 2: 更新所有模型
# - 确保所有 Column 定义兼容 MySQL
# - String → 需要指定长度
# - Text → MySQL的LONGTEXT

# Step 3: 数据迁移脚本
# - 读取 SQLite 数据
# - 写入 MySQL
# - 校验数据一致性

# Step 4: 切换
# - 更新 DATABASE_URL 环境变量
# - 重启服务
# - 保留 SQLite 文件作为备份
```

### 5.3 数据库配置变更

```python
# config.py 新增
MYSQL_URL = os.getenv("MYSQL_URL", "mysql+pymysql://root:password@localhost:3306/vibeutopia")

# database.py 变更
def get_engine():
    db_url = os.getenv("DATABASE_URL")
    if db_url and db_url.startswith("mysql"):
        return create_engine(db_url, pool_size=10, max_overflow=20)
    else:
        # 降级到SQLite
        return create_engine("sqlite:///./data/vibeutopia.db")
```

### 5.4 迁移校验

```python
async def verify_migration(sqlite_path, mysql_url):
```

## 6. V2 vs MVP 对比报告

### 6.1 报告内容

```python
@dataclass
class ComparisonReport:
    """V2 vs MVP 对比报告"""

    test_date: str
    test_cases_count: int

    # 方向准确率对比
    mvp_direction_accuracy: float       # MVP方向准确率
    v2_direction_accuracy: float        # V2方向准确率
    improvement: float                  # 提升幅度

    # 平台预测对比
    mvp_platform_accuracy: float
    v2_platform_accuracy: float

    # 风险维度对比
    mvp_dimension_accuracy: float
    v2_dimension_accuracy: float

    # 一致性
    v2_consistency: float               # V2多轮一致性

    # 结论
    conclusion: str                     # Go/Conditional/No-Go
    recommendation: str                 # 建议
```

### 6.2 生成方式

提供一个命令行工具：

```bash
# 运行对比测试
python -m backend.tools.comparison_test --cases cases/paperwork/ --output reports/comparison/

# 生成对比报告
python -m backend.tools.comparison_report --input reports/comparison/ --output reports/comparison_report.md
```
