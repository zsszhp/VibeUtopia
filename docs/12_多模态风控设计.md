## 1. 设计理念

当前风控若只分析文字，视频画面中的敏感图像、不当着装、争议性文字（字幕/贴图/水印），音频中的不当言辞、敏感背景音乐均无法覆盖。多模态风控的目标：**从只审文字到审画面+审音频，让风控覆盖视频的每个维度。**

设计原则：
- **文字为基础，多模态为增强**：文字风控是基础，多模态不可替代文字分析
- **关键帧策略**：不可能逐帧审核，通过关键帧提取+场景切换检测覆盖视频核心画面
- **跨模态冲突检测是MUST-HAVE**：视频/文字/音频三模态间的矛盾必须被检测，单模态漏报靠交叉校验补位
- **降级可用**：每个模态都可独立降级，不因单一模态失败阻塞整体评估
- **硬件自适应**：API为主+本地为辅+按GPU条件自动选模型，确保任何设备都有可用方案
- **仅本地视频**：不依赖yt-dlp等下载工具，仅支持本地视频文件输入

## 4. VRAM管理策略

多模态分析涉及多个本地模型，无法同时全部载入GPU。需要显式管理VRAM的分配和模型加载/卸载。

### 4.1 VRAM预算分配

| 层级 | 总VRAM | GLM-OCR | faster-whisper | Qwen3-VL-8B | 剩余 |
|------|--------|---------|----------------|-------------|------|
| Standard | 12GB | ~2GB | ~4GB | - | ~6GB（系统+缓存） |
| Pro | 24GB | ~2GB | ~4GB | ~16GB | ~2GB（系统+缓存） |

### 4.2 模型生命周期管理

```python
class VRAMManager:
    """VRAM管理器：控制模型加载/卸载顺序，避免OOM"""

    LOADING_ORDER = [
        "glm-ocr",            # 最先加载：小模型(0.9B)，全流程都需要
        "faster-whisper",     # 其次加载：音频转写需要
        "qwen3-vl-8b",       # 最后加载：大模型(8B)，Pro tier only
    ]

    async def load_model(self, model_name: str) -> bool:
        """加载模型到GPU，必要时卸载已有模型"""
        required_vram = self.MODEL_VRAM[model_name]
        available = self.get_available_vram()

        if available >= required_vram:
            return self._do_load(model_name)

        # 按逆序卸载非必要模型
        for candidate in reversed(self.LOADING_ORDER):
            if candidate in self.loaded_models and candidate != model_name:
                self.unload_model(candidate)
                available = self.get_available_vram()
                if available >= required_vram:
                    return self._do_load(model_name)

        return False  # 无法腾出足够VRAM，走API

    def unload_model(self, model_name: str):
        """卸载模型，释放VRAM"""
        if model_name in self.loaded_models:
            del self.loaded_models[model_name]
            torch.cuda.empty_cache()

    def get_available_vram(self) -> float:
        """获取当前可用VRAM（GB）"""
        if not torch.cuda.is_available():
            return 0.0
        allocated = torch.cuda.memory_allocated(0) / (1024**3)
        total = torch.cuda.get_device_properties(0).total_mem / (1024**3)
        return total - allocated
```

### 4.3 多模态分析执行顺序

Standard/Pro模式下，多模态分析的执行顺序受VRAM约束：

```
Step 1: 加载GLM-OCR → 执行所有关键帧OCR → 卸载GLM-OCR（释放2GB）
Step 2: 加载faster-whisper → 执行音频转写 → 卸载faster-whisper（释放4GB）
Step 3: [Pro only] 加载Qwen3-VL-8B → 执行画面理解 → 卸载
        [Standard/Lite] 直接走API画面理解
Step 4: 跨模态冲突检测（纯逻辑，无需GPU）
```

> 画面理解走API时，无需VRAM，与OCR/音频并行执行可提速。Pro模式下若VRAM充足，OCR和音频可并行。

## 5. 关键帧提取

### 5.1 提取策略

```python
class KeyFrameExtractor:
    """关键帧提取器——仅本地视频文件"""

    STRATEGIES = {
        "scene_change": {
            "description": "场景切换检测，提取场景变化帧",
            "tool": "FFmpeg + PySceneDetect",
            "typical_frames": "10-30帧/10分钟视频",
            "priority": 0  # 最高优先
        },
        "interval": {
            "description": "固定间隔提取，确保覆盖",
            "tool": "FFmpeg",
            "interval": "30秒",
            "typical_frames": "20帧/10分钟视频",
            "priority": 1
        },
        "face_detection": {
            "description": "含人脸的帧（可能涉及人物形象风险）",
            "tool": "OpenCV + face_recognition",
            "priority": 2
        },
        "text_detection": {
            "description": "含文字的帧（字幕/贴图/水印）",
            "tool": "OpenCV + East text detector",
            "priority": 2
        }
    }

    async def extract(self, video_path: str) -> list[KeyFrame]:
        """提取关键帧——仅接受本地视频路径"""

        # 1. 场景切换检测
        scene_frames = self._detect_scene_changes(video_path)

        # 2. 固定间隔补充（确保覆盖）
        interval_frames = self._extract_interval(video_path)

        # 3. 合并去重
        all_frames = self._merge_and_dedup(scene_frames, interval_frames)

        # 4. 限制总数（最多50帧）
        if len(all_frames) > 50:
            all_frames = self._rank_and_select(all_frames, max_count=50)

        return all_frames
```

### 5.2 关键帧数据模型

```python
@dataclass
class KeyFrame:
    """关键帧"""
    frame_id: str
    video_path: str
    timestamp: float          # 视频中的时间点（秒）
    image_path: str           # 提取的图片路径
    extraction_method: str    # scene_change/interval/face/text
    confidence: float         # 提取置信度
```

### 5.3 场景切换检测

使用PySceneDetect检测视频中的场景切换点，提取切换后的第一帧作为关键帧：

- **内容检测器（ContentDetector）**：检测画面内容突变（剪辑点）
- **阈值检测器（ThresholdDetector）**：检测画面亮度突变（转场/黑屏）
- 两检测器互补，确保不漏过重要场景变化

## 6. 画面理解

### 6.1 OCR文字识别

```python
class FrameOCR:
    """关键帧OCR——无PaddlePaddle依赖"""

    async def recognize(self, key_frame: KeyFrame) -> list[TextRegion]:
        """识别关键帧中的文字"""

        # 按硬件层级选择模型
        if self.tier in ("standard", "pro"):
            # 本地主力：GLM-OCR (0.9B params, 94.62% accuracy)
            results = await self._recognize_local(key_frame)
        else:
            # Lite模式：API降级
            results = await self._recognize_api(key_frame)

        text_regions = []
        for result in results:
            text_regions.append(TextRegion(
                text=result['text'],
                confidence=result['confidence'],
                position=result['position'],
                type=self._classify_text(result['text'], result['position'])
                # type: subtitle(字幕) / watermark(水印) / overlay(贴图) / background(背景文字)
            ))

        return text_regions

    async def _recognize_local(self, key_frame: KeyFrame):
        """本地OCR：GLM-OCR API → Qwen3-VL-Plus API 降级"""
        try:
            return self.glm_ocr.recognize(key_frame.image_path)
        except Exception:
            return self.qwen3_vl_api.recognize(key_frame.image_path)

    async def _recognize_api(self, key_frame: KeyFrame):
        """API OCR：Qwen3-VL-Plus"""
        return await self.vlm_client.ocr(key_frame.image_path)
```

OCR识别出的文字，直接送入文字风控流程进行11维评估。

### 6.2 画面内容审核

```python
class VisualRiskAssessor:
    """画面风险评估"""

    RISK_CATEGORIES = [
        "敏感人物形象",      # 政治人物/争议人物
        "不当着装/暴露",     # 衣着不当
        "暴力血腥内容",      # 武器/血腥画面
        "争议性标志/符号",   # 敏感标志/旗帜
        "不当手势/行为",     # 具有争议性的手势
        "低俗内容",         # 低俗/擦边内容
    ]

    async def assess(self, key_frame: KeyFrame) -> VisualRiskResult:
        """评估关键帧的画面风险——按硬件自适应选择模型"""

        # API-primary策略
        try:
            # 主力：Qwen3-VL-Plus（API）
            result = await self._assess_with_vlm(key_frame, model="qwen3-vl-plus")
        except Exception:
            try:
                # API降级：GLM-5V-Turbo
                result = await self._assess_with_vlm(key_frame, model="glm-5v-turbo")
            except Exception:
                # 本地降级：Qwen3-VL-8B（Pro tier only）
                if self.tier == "pro":
                    result = await self._assess_with_vlm(key_frame, model="qwen3-vl-8b")
                else:
                    result = self._rule_based_assess(key_frame)

        return result

    def _rule_based_assess(self, key_frame: KeyFrame) -> VisualRiskResult:
        """规则降级评估：当所有VLM不可用时，基于文件特征做简单启发式判断"""
        return VisualRiskResult(
            frame_id=key_frame.frame_id,
            timestamp=key_frame.timestamp,
            risk_level="unknown",
            risk_categories=[],
            description="VLM不可用，无法评估画面风险",
            confidence=0.0,
            ocr_texts=[],
            ocr_risk=None
        )
```

## 8. 跨模态冲突检测（MUST-HAVE）

跨模态冲突检测是多模态风控的核心差异化能力。单模态分析可能漏报，但不同模态间的矛盾往往是最高风险信号。

### 8.1 冲突类型定义

| 冲突类型 | 描述 | 示例 | 风险等级提升 |
|---------|------|------|------------|
| **画面内容 vs 文案描述矛盾** | 画面实际内容与文案声称不一致 | 文案说"推荐好物"但画面出现低价替代品暗示 | +2级 |
| **音频语气 vs 文案情感不一致** | 说话人语气与文案文字情感冲突 | 文案文字温和但音频语气激烈愤怒 | +1级 |
| **视觉元素 vs 文字声明不一致** | 画面中的视觉元素与文字声明矛盾 | 文字声明"无添加"但画面出现添加剂包装 | +2级 |

### 8.2 冲突检测实现

```python
class CrossModalConflictDetector:
    """跨模态冲突检测器——MUST-HAVE"""

    async def detect(self, multimodal_data: MultimodalInput) -> list[CrossModalConflict]:
        """检测三模态间的矛盾"""

        conflicts = []

        # 1. 画面内容 vs 文案描述矛盾
        visual_text_conflicts = await self._detect_visual_text_conflict(
            visual_results=multimodal_data.visual_risks,
            text_content=multimodal_data.text_content,
            ocr_texts=multimodal_data.ocr_texts,
        )
        conflicts.extend(visual_text_conflicts)

        # 2. 音频语气 vs 文案情感不一致
        audio_text_conflicts = await self._detect_audio_text_conflict(
            audio_emotion=multimodal_data.audio_emotion,
            text_content=multimodal_data.text_content,
        )
        conflicts.extend(audio_text_conflicts)

        # 3. 视觉元素 vs 文字声明不一致
        visual_claim_conflicts = await self._detect_visual_claim_conflict(
            visual_results=multimodal_data.visual_risks,
            text_claims=multimodal_data.text_claims,
        )
        conflicts.extend(visual_claim_conflicts)

        return conflicts

    async def _detect_visual_text_conflict(
        self, visual_results, text_content, ocr_texts
    ) -> list[CrossModalConflict]:
        """画面内容 vs 文案描述矛盾检测"""
        prompt = f"""
        对比以下视频画面描述和文案内容，检测是否存在矛盾或不一致：

        画面描述：{[r.description for r in visual_results]}
        OCR文字：{[t.text for t in ocr_texts]}
        文案内容：{text_content}

        请识别：
        1. 画面展示了什么，文案是否刻意忽略或歪曲
        2. OCR显示的文字是否与文案内容矛盾
        3. 画面中的物体/场景是否与文案声称不符

        输出JSON格式的冲突列表。
        """
        return await self.llm_client.analyze(prompt)

    async def _detect_audio_text_conflict(
        self, audio_emotion, text_content
    ) -> list[CrossModalConflict]:
        """音频语气 vs 文案情感不一致检测"""
        prompt = f"""
        对比以下音频情感分析和文案内容，检测语气-文字不一致：

        音频情感：{audio_emotion.overall_emotion}
        高唤醒片段：{audio_emotion.high_arousal_segments}
        文案内容：{text_content}

        请识别：
        1. 音频是否表现出与文字内容不一致的强烈情感
        2. 温和文字+激烈语气的反差是否暗示讽刺/阴阳怪气
        3. 情感不一致是否可能引发受众误解

        输出JSON格式的冲突列表。
        """
        return await self.llm_client.analyze(prompt)

    async def _detect_visual_claim_conflict(
        self, visual_results, text_claims
    ) -> list[CrossModalConflict]:
        """视觉元素 vs 文字声明不一致检测"""
        prompt = f"""
        对比以下画面中识别的视觉元素和文字声明，检测不一致：

        视觉元素：{[r.description for r in visual_results]}
        文字声明：{text_claims}

        请识别：
        1. 画面中的产品/物品是否与文字声明的一致
        2. 画面中是否出现文字未提及的争议元素
        3. 声明的效果/属性是否有画面证据支持

        输出JSON格式的冲突列表。
        """
        return await self.llm_client.analyze(prompt)
```

### 8.3 冲突数据模型

```python
@dataclass
class CrossModalConflict:
    """跨模态冲突"""
    conflict_type: str          # visual_text / audio_text / visual_claim
    severity: str               # low/medium/high/critical
    description: str            # 冲突描述
    evidence_visual: str        # 画面侧证据
    evidence_text: str          # 文案侧证据
    evidence_audio: str         # 音频侧证据（如适用）
    risk_upgrade: int           # 风险等级提升幅度（+1/+2）
    confidence: float           # 冲突判断置信度
```

## 9. 综合风控报告

### 9.1 多模态报告结构

```python
@dataclass
class MultimodalRiskReport:
    """多模态风控报告"""

    # 文字风险（已有）
    text_risk: EnhancedRiskReport

    # 画面风险（新增）
    visual_risks: list[VisualRiskResult]   # 各关键帧的画面风险
    ocr_risks: list[RiskAssessment]        # OCR文字的风险
    visual_summary: str                     # 画面风险总结

    # 音频风险（新增）
    audio_transcription: str                # 语音转写全文
    audio_risk: EnhancedRiskReport          # 转写文本的风控报告
    audio_emotion: AudioEmotionResult       # 音频情感分析
    audio_summary: str                      # 音频风险总结

    # 跨模态冲突（MUST-HAVE）
    cross_modal_conflicts: list[CrossModalConflict]  # 三类跨模态冲突
    conflict_summary: str                            # 冲突风险总结

    # 综合评估
    overall_risk: int                       # 综合风险分 0-100
    risk_level: str                         # safe/low/medium/high/critical
    key_findings: list[str]                 # 关键发现
    recommendations: list[str]              # 建议
```

### 9.2 综合风险计算

```
综合风险 = max(
    文字风险,
    max(画面风险),
    max(音频风险),
) + 跨模态冲突风险升级

跨模态冲突升级规则：
- 每个high级冲突：+10分
- 每个critical级冲突：+20分
- 封顶100分
```

## 10. API对接

多模态风控不定义独立API端点，而是通过系统5个核心端点提供服务：

| 方法 | 端点 | 多模态相关说明 |
|------|------|--------------|
| POST | `/api/review` | 提交内容预审，mode=video/mixed时自动触发多模态分析 |
| GET | `/api/review/{task_id}` | 获取预审结果，包含MultimodalRiskReport |
| GET | `/api/review/{task_id}/progress` | 获取分析进度，包含多模态各步骤进度 |
| GET | `/api/history` | 历史记录 |
| GET | `/api/models` | 当前可用模型列表（基于硬件自适应） |

多模态分析在 `POST /api/review` 内部自动串联，用户无需单独调用。

## 11. 降级策略

### 11.1 模态级降级

| 模态 | 主方案 | 降级方案1 | 降级方案2 | 最终降级 |
|------|--------|----------|----------|---------|
| 关键帧 | 场景切换+间隔提取 | 仅间隔提取 | 仅首帧+末帧 | 跳过画面分析 |
| OCR | GLM-OCR（本地） | Qwen3-VL-Plus（API） | Qwen3-VL-Plus（API） | 跳过OCR |
| 画面理解 | Qwen3-VL-Plus（API） | GLM-5V-Turbo（API） | Qwen3-VL-8B（本地Pro） | 规则启发式评估 |
| 语音转写 | faster-whisper（本地GPU） | Paraformer（API） | 使用视频内嵌字幕 | 跳过音频分析 |
| 情感分析 | 基于转写文本 | 跳过情感分析 | - | - |
| 跨模态冲突 | LLM对比分析 | 仅画面vs文字简单对比 | 跳过冲突检测 | - |

### 11.2 硬件级降级

| 场景 | 处理方式 |
|------|---------|
| GPU不可用 | 全API模式（Lite），成本增加但精度不降 |
| GPU VRAM不足 | VRAMManager按优先级卸载模型，被卸载的模型走API |
| API不可用 | 降级到本地模型（Standard/Pro），Lite模式提示用户检查API Key |
| API+本地均不可用 | 降级到规则启发式评估，标注"低置信度" |

### 11.3 降级不影响跨模态检测

> 跨模态冲突检测是MUST-HAVE，即使部分模态降级，只要有2个以上模态的结果，就必须执行冲突检测。仅当只剩1个模态时才跳过。

## 关键流程/结构

- 输入：本地视频文件 + 文案脚本（可选）
- 处理：关键帧提取 → 画面理解(API/本地) + OCR(本地/API) + 音频转写(本地/API) → 跨模态冲突检测 → 综合风险评估
- 输出：MultimodalRiskReport（文字风险 + 画面风险 + 音频风险 + 跨模态冲突风险 + 综合评估）

## 依赖与降级

- 依赖：
  - 多模态API可用性（Qwen3-VL-Plus、GLM-5V-Turbo、Paraformer）
  - 本地模型文件（GLM-OCR、faster-whisper-large-v3、Qwen3-VL-8B）
  - GPU硬件条件（Standard 12GB / Pro 24GB）
  - FFmpeg + PySceneDetect（关键帧提取）
- 失败降级策略：
  - 多模态API不可用 → 本地模型fallback（Standard/Pro），Lite模式提示用户
  - 本地模型加载失败（VRAM不足）→ VRAMManager卸载低优先级模型，被卸载的走API
  - 全部模型不可用 → 规则启发式评估，标注"低置信度"
  - 单模态失败 → 跳过该模态，不影响其他模态分析
  - 跨模态冲突检测至少需要2个模态结果；仅1个模态时跳过冲突检测

## 验收标准

- 指标：各模态独立准确率、跨模态冲突检测召回率、硬件自适应正确率、VRAM管理无OOM
- 阈值：
  - OCR准确率 >= 94%（GLM-OCR基准）
  - 跨模态冲突检测对已知矛盾案例召回率 >= 80%
  - 硬件自适应模型路由正确率 100%（Lite全API / Standard本地OCR+音频 / Pro全本地fallback）
  - VRAM管理：Standard模式连续分析10个视频无OOM
- 通过条件：三模态独立分析可用 + 跨模态冲突检测可用 + 三种硬件层级均正确路由 + VRAM管理稳定
