# T7 深度信号采集 - 定时任务配置示例

## 方案 1：Crontab 定时任务

### 每小时采集一次
```bash
# 编辑 crontab
crontab -e

# 添加以下行（每小时整点执行）
0 * * * * cd /workspace && PYTHONPATH=/workspace python3 tests/run_signal_collection.py >> data/signal_collection_cron.log 2>&1

# 每 30 分钟执行一次
*/30 * * * * cd /workspace && PYTHONPATH=/workspace python3 tests/run_signal_collection.py >> data/signal_collection_cron.log 2>&1

# 每天早晚各执行一次（9:00 和 21:00）
0 9,21 * * * cd /workspace && PYTHONPATH=/workspace python3 tests/run_signal_collection.py >> data/signal_collection_cron.log 2>&1
```

### 定期运行增强任务（信号关联验证 + 深度评论爬取）
```bash
# 每周执行一次（周一 2:00 AM）
0 2 * * 1 cd /workspace && PYTHONPATH=/workspace python3 tests/run_t7_enhancement.py >> data/t7_enhancement_cron.log 2>&1
```

## 方案 2：Systemd Timer（推荐）

### 1. 创建服务文件
```bash
sudo tee /etc/systemd/system/vibeutopia-signal.service > /dev/null <<'EOF'
[Unit]
Description=VibeUtopia Signal Collection
After=network.target

[Service]
Type=oneshot
User=root
WorkingDirectory=/workspace
Environment=PYTHONPATH=/workspace
ExecStart=/usr/bin/python3 tests/run_signal_collection.py
StandardOutput=append:/workspace/data/signal_collection_systemd.log
StandardError=append:/workspace/data/signal_collection_systemd.log
EOF
```

### 2. 创建定时器文件
```bash
sudo tee /etc/systemd/system/vibeutopia-signal.timer > /dev/null <<'EOF'
[Unit]
Description=Run VibeUtopia Signal Collection Hourly
Requires=vibeutopia-signal.service

[Timer]
OnBootSec=1min
OnUnitActiveSec=1h
Unit=vibeutopia-signal.service

[Install]
WantedBy=timers.target
EOF
```

### 3. 启用定时器
```bash
sudo systemctl daemon-reload
sudo systemctl enable vibeutopia-signal.timer
sudo systemctl start vibeutopia-signal.timer

# 查看状态
systemctl list-timers | grep vibeutopia
```

## 方案 3：APScheduler 内置调度（推荐用于生产环境）

### 在应用启动时运行调度器
```python
# backend/main.py 或应用启动脚本中
from backend.services.signal.scheduler import SignalScheduler

# 启动实时模式调度器
scheduler = SignalScheduler()
scheduler.start(mode="realtime")  # 5 分钟热榜、30 分钟 RSS、1 小时事件检测
```

### 调度模式配置
编辑 `backend/services/signal/signal_config.yaml`:
```yaml
schedule:
  presets:
    realtime:
      description: "实时监控模式"
      hotlist_interval: 300       # 5 分钟
      rss_interval: 1800          # 30 分钟
      deep_crawl_threshold: 0.7   # 信号强度>0.7 触发深度爬取
      event_detect_interval: 3600 # 1 小时

    standard:
      description: "标准模式（推荐）"
      hotlist_interval: 600       # 10 分钟
      rss_interval: 3600          # 1 小时
      deep_crawl_threshold: 0.7
      event_detect_interval: 3600

    economy:
      description: "经济模式"
      hotlist_interval: 1800      # 30 分钟
      rss_interval: 7200          # 2 小时
      deep_crawl_threshold: 0.9   # 仅强信号触发深度爬取
      event_detect_interval: 7200

    manual:
      description: "手动模式"
      auto_crawl: false
      api_only: true
```

## 监控和维护

### 查看日志
```bash
# 实时查看日志
tail -f /workspace/data/signal_collection.log

# 查看最近的采集统计
grep "采集统计摘要" /workspace/data/signal_collection.log | tail -5
```

### 检查定时任务状态
```bash
# Crontab
crontab -l

# Systemd Timer
systemctl list-timers | grep vibeutopia
systemctl status vibeutopia-signal.timer
```

### 数据清理
```sql
-- 清理 72 小时前的旧信号数据（避免数据库过大）
DELETE FROM signal_records WHERE last_seen < datetime('now', '-72 hours');
DELETE FROM seed_event_records WHERE status = 'expired' AND updated_at < datetime('now', '-7 days');
```

## 注意事项

1. **API 限流**: NewsNow API 和部分平台 API 有请求频率限制，建议不要设置过高的采集频率
2. **数据库大小**: 定期清理过期数据，避免数据库膨胀
3. **日志轮转**: 配置日志轮转（logrotate）避免日志文件过大
4. **错误告警**: 监控采集失败率，设置告警通知
