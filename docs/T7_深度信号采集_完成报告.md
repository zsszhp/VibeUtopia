# T7 完成报告：深度信号采集（评论爬取 + 情感标注）

## 任务概述

**任务名称**: T7 - 深度信号采集（评论爬取 + 情感标注）  
**预期准确率收益**: +8%

## 核心目标

基于 LLM 关键词提取，实现多平台定向评论爬取和情感标注，为 Agent 人格模拟提供真实情绪数据，提升仿真可信度和风险评估准确率。

## 已实现功能

### 1. 数据模型 (backend/services/signal/models.py)

✅ **核心数据模型**：
- `Signal` - 标准化信号模型（信号 ID、来源平台、标题、排名时间线等）
- `AnnotatedComment` - 情感标注评论模型（评论内容、情感极性、情感分数、置信度等）
- `SearchKeyword` - 搜索关键词模型（关键词、目标平台列表、优先级）
- `SeedEvent` - 种子事件模型（事件元数据、评论列表、信号强度、因果关系等）
- `RankPoint` - 排名时间点
- 枚举类：`SignalType`, `EventCategory`, `EventStatus`, `CrawlDepth`

**总代码量**: 95 行

---

### 2. 深度评论爬取器 (backend/services/signal/deep_crawler.py)

✅ **API 优先策略爬虫** (`ApiCrawler` 类)：
- `crawl_weibo()` - 微博移动端搜索 API 爬取（去除 HTML 标签，提取点赞/回复数）
- `crawl_zhihu()` - 知乎搜索 API 爬取（支持内容截断，提取投票数/评论数）
- `crawl_bilibili()` - B 站搜索 API + 评论 API 爬取（先搜视频再获取视频评论）
- `crawl_douyin()` - 抖音搜索 API 爬取（模拟移动端，提取统计信息）
- `crawl_xiaohongshu()` - 小红书 Web API 爬取（搜索笔记，提取互动信息）

✅ **深度爬取器** (`DeepCrawler` 类)：
- `crawl_comments()` - 按关键词爬取多平台评论并自动标注情感
- 平台路由：根据平台名称自动选择对应爬虫
- 并发控制：每平台独立请求限制
- 去重机制：基于内容前 50 字符去重
- 情感标注：集成 BERT-LoRA 情感标注器

**总代码量**: 311 行

---

### 3. 情感标注器 (backend/services/signal/sentiment.py)

✅ **BERT-LoRA 情感标注** (`SentimentAnnotator` 类)：
- `annotate()` - 单条情感标注（返回情感极性、分数、置信度）
- `batch_annotate()` - 批量情感标注（GPU 加速）
- `_detect_irony()` - 反讽检测（LLM 辅助）
- 支持情感极性：`positive`, `negative`, `neutral`
- 情感分数范围：-1 ~ 1
- 置信度范围：0 ~ 1

**降级策略**：
- BERT 模型不可用时，使用规则基的情感词典方法

**总代码量**: 139 行

---

### 4. 关键词提取器 (backend/services/signal/keyword_extractor.py)

✅ **LLM 关键词提取** (`KeywordExtractor` 类)：
- `extract()` - 从种子事件提取 3-5 个核心搜索关键词
- Prompt 模板：包含事件标题 + 描述，要求关键词具体、包含实体名、考虑平台差异
- 输出格式：JSON（关键词、适用平台列表、优先级）

**降级策略**：
- LLM API 不可用时使用 TF-IDF 规则替代

**总代码量**: 81 行

---

### 5. 广度信号采集 (backend/services/signal/fetcher.py)

✅ **热榜聚合器** (`HotlistFetcher` 类)：
- `fetch_platform()` - 抓取单个平台热搜
- `fetch_all()` - 批量抓取多个平台
- NewsNow API 集成：统一接口 `GET /api/s?id={platform}&latest`
- 支持平台：微博、百度、知乎、B 站、抖音、头条、贴吧、澎湃、华尔街见闻、财联社、凤凰网（11+ 平台）
- 请求间隔：100ms
- 重试机制：指数退避（3-5 秒）

**总代码量**: 134 行

### 6. RSS 补充源 (backend/services/signal/rss_fetcher.py)

✅ **RSS 采集器** (`RssFetcher` 类)：
- `fetch_feed()` - 抓取单个 RSS 源
- `fetch_all()` - 批量抓取多个 RSS 源
- 支持 RSS/Atom 统一解析
- 新鲜度过滤：`max_age_days` 参数
- 预设源：Hacker News、雅虎财经、澎湃新闻等

**总代码量**: 123 行

---

### 7. 增量检测器 (backend/services/signal/incremental.py)

✅ **增量检测机制** (`IncrementalDetector` 类)：
- `detect_incremental()` - 检测新上榜/排名变化/下榜
- 新上榜标题检测：与历史标题库对比
- 排名变化追踪：`rank_timeline`记录
- 跨平台标题去重：基于标题相似度
- 输出：增量信号列表

**总代码量**: 190 行

---

### 8. 事件检测器 (backend/services/signal/event_detector.py)

✅ **事件聚类与增强** (`EventDetector` 类)：
- `cluster_events()` - 将信号聚类为事件
- `_compute_similarity()` - 语义相似度计算（LLM+ 关键词重叠）
- `_merge_cluster()` - 合并聚类为种子事件
- 主题聚类：同一事件在不同平台的标题自动合并
- 因果链推理：LLM 分析事件间因果关系
- 信号强度评估：传播广度、上榜速度、多平台共振、互动强度、持续性

**总代码量**: 386 行

---

### 9. 调度器 (backend/services/signal/scheduler.py)

✅ **APScheduler 定时调度** (`SignalScheduler` 类)：
- 4 种运行模式预设：
  - `realtime` - 实时模式（热榜 5 分钟、RSS 30 分钟、事件检测 1 小时）
  - `standard` - 标准模式（热榜 10 分钟、RSS 1 小时、事件检测 1 小时）
  - `economy` - 经济模式（热榜 30 分钟、RSS 2 小时、事件检测 2 小时）
  - `manual` - 手动模式（默认，不自动调度）
- `start()` - 启动调度器
- `stop()` - 停止调度器
- `run_once()` - 手动执行一次采集
- 自动降级：NewsNow API 不可用时切换到 RSS-only 模式

**总代码量**: 351 行

## 核心流程

### 深度信号采集完整链路

```
1. 种子事件输入
   ↓
2. LLM 关键词提取 (3-5 个核心搜索词)
   ↓
3. 多平台定向评论爬取 (微博/知乎/B 站/抖音/小红书)
   ├─ API 优先 (Level 0)
   └─ 降级到 Playwright (Level 1)
   ↓
4. BERT-LoRA 情感标注
   ↓
5. 结构化存储 (MySQL/SQLite)
   ↓
6. 事件检测与聚类
   ↓
7. 种子事件库输出
```

## 使用方式

### 1. 基础使用

```python
from backend.services.signal.deep_crawler import DeepCrawler
from backend.services.signal.models import SearchKeyword

async def demo():
    crawler = DeepCrawler()
    keyword = SearchKeyword(
        keyword="某明星塌房",
        platforms=["微博", "知乎", "B 站"],
        priority=1
    )
    
    comments = await crawler.crawl_comments(keyword, max_comments=30)
    
    for c in comments:
        print(f"[{c.platform}] {c.sentiment}: {c.content[:50]}...")
```

### 2. 完整信号采集流程

```python
from backend.services.signal.scheduler import SignalScheduler

# 启动实时模式调度器
scheduler = SignalScheduler()
scheduler.start(mode="realtime")

# 或手动执行一次
await scheduler.run_once()
```

### 3. 关键词提取

```python
from backend.services.signal.keyword_extractor import KeywordExtractor
from backend.services.signal.models import SeedEvent, EventCategory

extractor = KeywordExtractor()
event = SeedEvent(
    title="某明星塌房事件",
    description="某知名明星被曝光涉嫌税务问题",
    category=EventCategory.CULTURE
)

keywords = await extractor.extract(event)
# 输出：[SearchKeyword(keyword="某明星 税务", platforms=["微博","知乎"], priority=1), ...]
```

### 4. 事件检测与聚类

```python
from backend.services.signal.event_detector import EventDetector
from backend.services.signal.models import Signal

detector = EventDetector()
signals = [...]  # 来自多个平台的信号列表

clusters = await detector.cluster_events(signals)
for cluster in clusters:
    print(f"事件：{cluster.title}, 信号强度：{cluster.signal_strength:.2f}")
```

## 降级策略

### API 不可用时的降级路径

| 层级 | 标准模式 | 降级模式 | 功能影响 |
|------|---------|---------|---------|
| 热榜采集 | NewsNow API (11+ 平台) | RSS-only (3+ 源) | 信号覆盖面降低但系统可用 |
| 评论爬取 | 平台 API | Playwright 模拟 | 速度变慢但数据完整 |
| 关键词提取 | LLM (DeepSeek-V4/Qwen3.6-Plus) | TF-IDF 规则 | 质量略降但可接受 |
| 情感标注 | BERT-LoRA 模型 | 情感词典规则 | 准确率略降但仍可用 |
| 事件聚类 | LLM 语义相似度 | 关键词重叠度 | 边界案例处理较弱 |
| 因果推理 | LLM 推理 | 跳过因果链 | 仅影响事件关系图 |

| 策略 | 实现 | 配置 |

| 并发控制 | 每平台最大并发数 | `max_concurrent_per_platform: 3` |
