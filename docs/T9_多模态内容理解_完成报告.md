## 核心功能

### 1. 关键帧提取

**策略**：
1. **PySceneDetect 场景切换检测**（首选）
   - ContentDetector：检测画面内容突变
   - ThresholdDetector：检测亮度突变
2. **FFmpeg 固定间隔提取**（备选）
   - 默认 30 秒间隔
3. **OpenCV 降级提取**（兜底）

**配置**：
```python
DEFAULT_CONFIG = {
    "max_frames": 50,             # 最多保留帧数
    "interval_seconds": 5.0,      # 固定间隔提取的间隔秒数
    "scene_threshold": 27.0,      # PySceneDetect 内容检测阈值
    "min_scene_length": 15,       # 最短场景长度 (帧数)
    "frame_width": 640,           # 输出帧宽度
    "frame_height": 360,          # 输出帧高度
    "dedup_threshold": 8,         # 感知哈希去重汉明距离阈值
}
```

**提取流程**：
```
视频输入
  │
  ├──▶ 场景切换检测 (scenedetect)
  ├──▶ 固定间隔补充 (ffmpeg)
  ├──▶ 合并去重 (感知哈希)
  └──▶ 限制总数 (最多 50 帧)
       │
       ▼
关键帧列表 (KeyFrame[])
```

### 2. OCR 文字识别

**硬件自适应策略**：

| 层级 | GPU 条件 | OCR 模型 |
|------|---------|---------|
| Lite | 无 GPU | Qwen3-VL-Plus (API) |
| Standard | 12GB GPU | GLM-OCR (本地) → PaddleOCR-VL-1.5 (降级) |
| Pro | 24GB GPU | GLM-OCR (本地) → PaddleOCR-VL-1.5 (降级) → Qwen3-VL-Plus (API) |

**FrameOCR 实现**：
```python
class FrameOCR:
    async def recognize(self, key_frame: KeyFrame) -> list[TextRegion]:
        # 按硬件层级选择模型
        if self.tier in ("standard", "pro"):
            # 本地主力：GLM-OCR (0.9B params, 94.62% accuracy)
            results = await self._recognize_local(key_frame)
        else:
            # Lite 模式：API 降级
            results = await self._recognize_api(key_frame)
        
        # 文字分类：subtitle/watermark/overlay/background
        text_regions = []
        for result in results:
            text_regions.append(TextRegion(
                text=result['text'],
                confidence=result['confidence'],
                position=result['position'],
                type=self._classify_text(result['text'], result['position'])
            ))
        
        return text_regions
```

### 5. VRAM 管理

**VRAM 预算分配**：

| 层级 | 总 VRAM | GLM-OCR | faster-whisper | Qwen3-VL-8B | 剩余 |
|------|---------|---------|----------------|-------------|------|
| Standard | 12GB | ~2GB | ~4GB | - | ~6GB |
| Pro | 24GB | ~2GB | ~4GB | ~16GB | ~2GB |

**模型生命周期管理**：
```python
class VRAMManager:
    LOADING_ORDER = [
        "glm-ocr",            # 最先加载：小模型 (0.9B)
        "faster-whisper",     # 其次加载：音频转写需要
        "qwen3-vl-8b",       # 最后加载：大模型 (8B)
    ]

    async def load_model(self, model_name: str) -> bool:
        """加载模型到 GPU，必要时卸载已有模型"""
        required_vram = self.MODEL_VRAM[model_name]
        available = self.get_available_vram()

        if available >= required_vram:
            return self._do_load(model_name)

        # 按逆序卸载非必要模型
        for candidate in reversed(self.LOADING_ORDER):
            if candidate in self.loaded_models and candidate != model_name:
                self.unload_model(candidate)
                available = self.get_available_vram()
                if available >= required_vram:
                    return self._do_load(model_name)

        return False  # 无法腾出足够 VRAM，走 API
```

### 6. 多模态分数集成

```python
def integrate_multimodal_score(
    text_score: int,
    visual_score: int = 0,
    audio_score: int = 0,
    ocr_score: int = 0,
) -> int:
    """将多模态分数集成到总体风险分
    
    策略：
    1. 各模态加权：文本×1.0, 视觉×0.8, 音频×0.7, OCR×0.6
    2. 取最高分作为基准
    3. 如果多模态同时高风险（>60），额外 +10
    """
    weighted_scores = [
        text_score,
        int(visual_score * 0.8),
        int(audio_score * 0.7),
        int(ocr_score * 0.6),
    ]
    
    overall = max(weighted_scores)
    
    # 多模态同时高风险，额外 +10
    high_count = sum(1 for s in weighted_scores if s > 60)
    if high_count >= 2:
        overall = min(100, overall + 10)
    
    return overall
```

## 技术实现细节

### 1. 硬件自适应架构

**三层架构**：
- **Lite（无 GPU）**：全 API 调用，成本~¥2-3/次
- **Standard（12GB GPU）**：API 视觉 + 本地 OCR+ 音频，成本~¥1-2/次
- **Pro（24GB GPU）**：API 为主 + 全部本地 fallback，成本~¥0.5-1/次

### 2. 模型路由策略

```python
MODEL_ROUTING = {
    "frame_understanding": {
        "primary": "qwen3-vl-plus",
        "fallback": "glm-5v-turbo",
        "local_fallback": "qwen3-vl-8b",
        "min_vram_gb": 16,
    },
    "ocr": {
        "primary": "glm-ocr",
        "fallback": "paddleocr-vl-1.5",
        "api_fallback": "qwen3-vl-plus",
        "min_vram_gb": 2,
    },
    "audio_transcription": {
        "primary": "faster-whisper-large-v3",
        "fallback": "aliyun-paraformer",
        "min_vram_gb": 4,
    },
}
```

### 3. 执行顺序优化

**Standard/Pro 模式下**：
```
Step 1: 加载 GLM-OCR → 执行所有关键帧 OCR → 卸载 GLM-OCR（释放 2GB）
Step 2: 加载 faster-whisper → 执行音频转写 → 卸载 faster-whisper（释放 4GB）
Step 3: [Pro only] 加载 Qwen3-VL-8B → 执行画面理解 → 卸载
         [Standard/Lite] 直接走 API 画面理解
Step 4: 跨模态冲突检测（纯逻辑，无需 GPU）
```

### 4. 降级链路

每个模态都有独立的降级策略：
- **OCR**: GLM-OCR → PaddleOCR-VL-1.5 → Qwen3-VL-Plus (API)
- **画面理解**: Qwen3-VL-Plus (API) → GLM-5V-Turbo (API) → Qwen3-VL-8B (本地)
- **音频转写**: faster-whisper (本地) → Paraformer (API)
