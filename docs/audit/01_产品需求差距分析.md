# 产品需求差距分析报告

> **文档定位**：对照原始需求（docs/28_原始需求.md）、PRD（docs/design/01_产品需求文档(PRD).md）与实际代码实现（src/backend、src/frontend），识别"文档写了没做 / 做了难用 / 做了没闭环"三类差距，给出分层路线图与 PRD 修订建议。
>
> **分析基准日期**：2026-05-17 代码库状态（commit 对应工作区）
> **分析方法**：文档逐条比对 + 代码路由/服务/前端组件三级核查 + 行业产品公开资料调研

---

## 1. 执行摘要

VibeUtopia 已建成**体量庞大但闭环不足**的技术底座：11 维风险评估、28 平台人格模拟、信号采集、知识图谱、反事实仿真等核心服务层均已落地（后端 50+ 服务模块、~80 API 端点），**单次文本预审主链路可跑通**。但产品层面存在三类系统性差距：

**（1）做了但没闭环**——4 个前端组件（BloggerProfile / SignalPanel / KnowledgeGraph / HistoryComparison）完全未挂载；`routes_story.py` 未注册到 main.py；`topic_recommender` 服务无任何 API 出口；反事实仿真入口把 `currentTaskId` 当原文传入（功能性 Bug）。

**（2）做了但没进主流程**——多模态视频风控（关键帧风险/画面 OCR 风险/细粒度视频理解）只存在于 `enhanced_analyzer` / `resumable_analyzer` / 独立 API，**主预审端点 `/api/v1/review` 仅做文本化提取**；大规模仿真引擎（GA-S3 / 传播动力学 / 极化检测）同样不在主链路，导致报告中 `polarization_data` / `simulation_data` 在标准用户旅程里恒为空。

**（3）文档写了没做**——`depth`（快速/标准/深度）选项被 API 接受但分析引擎完全忽略；README 宣称的 40 回测案例实际 27 条；README 列出的十余个端点（`/analyze`、`/backtest/run`、`/simulation/create`、`/prediction/trend`、`/report/*` 等）在代码中不存在。

**结论**：按"个人创作者发前自查"定位，当前产品可用性约 **55%**——文本预审报告（风险分+证据链+改写建议+平台反应）可交付，但视频风控断链、决策辅助降级为前端简单分数映射、博主/选题/对标闭环缺失。建议 P0 集中修闭环与主链路，而非继续扩展平台数量。

## 2. 原始需求闭环度评估（4 条 idea 逐条）

### Idea 1：多 AI 模拟人格 + 多平台声音，预测反应并整合评估

**期望**：多个 AI 模拟人格，覆盖小红书/知乎/B站/抖音等平台，预测不同人群反应，整合为整体效果评估。

| 维度 | 现状 | 证据 |
|------|------|------|
| 11 维风险评估 | ✅ 完整 | `risk_assessor.py` + `analyzer.py:206` 主流程 |
| 平台人格模拟 | ✅ 28 平台人格模板 | `persona_simulator.py:8-18`（28 平台列表）、`platform_weights.py`（28 个 PlatformProfile） |
| 人格原型库 | ✅ ~148 个原型 | `persona_archetypes.py`(100) + `p1_archetypes.py`(24) + `p2_archetypes.py`(24) |
| Agent 批量仿真 | ⚠️ 规模缩水 | `agent_simulator.py:52` `AGENTS_PER_PLATFORM=5`，主流程每平台仅 5 Agent（合计 140），非宣称的 100/500/2000/10000 |
| 平台反应展示 | ✅ 前端已接 | `PlatformReactions.vue` + `Workbench.vue:20` |
| 传播/极化整合 | ❌ 不在主流程 | `analyzer.py` 仅存 `platform_simulation_json`；`polarization_data` 读 `SimulationSummaryRecord`（`routes.py:445-465`），主流程不写入该表 |

**完成度：65%**。核心"预测反应→展示"已通，但"整合评估为效果预测"依赖的传播动力学与极化检测在标准旅程中缺席。

**差距**：
- `depth`（quick/standard/deep）参数在 `routes.py:225` 入库后，`analyzer.py` 全文无引用——深度选项是装饰。
- 用户手册宣称"仿真规模 10/50/200/500+"（27_用户手册.md:225-230），与主流程固定 5 Agent/平台矛盾。
- 报告的 `simulation_data`（传播树）字段恒为 None（`routes.py:417-424` 只回放已存数据，主流程不产数据）。

### 5.2 关键洞察

1. **"发前预测"是空白带**：国内内容安全（易盾/阿里/百度）是**发中/发后拦截**；创作者工具（新榜/蝉妈妈/飞瓜）是**发后数据**；海外 Brandwatch 是**发后监听**。"发布前模拟多平台反应预测塌方"目前无直接对标——这是 VibeUtopia 的护城河，也是最大风险（品类需教育）。

2. **Perspective API 关停**（2026 年底，官网明示）释放毒性检测需求，利于 VibeUtopia 类产品的国际叙事。

3. **行业 UX 范式**：
   - 审核类：API 为主，分数+分类+定位，强调低延迟与准确率（易盾/百度）。
   - 数据类：榜单/趋势/账号诊断，订阅制，信息密度高（新榜/蝉妈妈）。
   - 监听类：Dashboard+预警+报告导出，危机响应闭环（Brandwatch）。
   - **VibeUtopia 应融合**：审核类的"证据链定位" + 数据类的"账号诊断" + 监听类的"危机预警/报告导出"，但主打"决策辅助"而非单纯打分。

4. **商业模式参考**：SaaS 订阅（创作者个人 ¥99-299/月；MCN ¥999-9999/月）+ API 按量 + 品牌尽调定制报告。当前项目开源（AGPL-3.0）阶段可先跑通体验，商业版需云化+多租户。

5. **新榜矩阵通已含"内容合规管控"**（官网产品矩阵），说明大厂已把合规塞进管理工具；VibeUtopia 需强化"仿真预测"独特性，避免被降维成"又一个审核 API"。

## 7. 分阶段产品路线图建议

### 阶段 P0：个人创作者核心闭环（1-2 个月）— "发前自查真的能用"

**目标**：从粘贴/上传到"能不能发、改哪里、改完再看"闭环打通。

1. 修 P0-1：视频多模态+细粒度风险接入 `/review`（深度模式默认启用）
2. 修 P0-2/P0-3/P0-4：反事实 Bug、depth 生效、传播/极化数据或明示空态
3. 修 P1-4/P1-5：DecisionAdvisor 进报告 + "应用改写→重审"闭环
4. 修 P1-6：报告导出 PDF
5. 对外口径：README/手册与实现对齐（P2-1/P2-2/P2-3/P2-4）

**验收**：给定历史塌方案例（党妹/les 类），报告能定位画面+台词+文案三层风险并给出改写后再评对比；标准模式 <5min，深度 <15min。

### 阶段 P1：创作者增值（2-3 个月）— "不只避雷，还能做得更好"

1. 挂载 BloggerProfile / SignalPanel / KnowledgeGraph（P1-1）
2. topic_recommender API + UI（P1-2）：选题推荐含预期效果
3. routes_story 注册并接入人格质量面板（P1-3）
4. 历史对比（HistoryComparison）+ 账号风险趋势
5. 行业对标差异化：把"发前仿真预测"做成报告中的"如果发，各平台会怎样"叙事

**验收**：博主连续 10 次使用留存；选题推荐点击可用率 >60%。

### 阶段 P2：MCN 批量风控（3-6 个月）— "机构级"

1. 批量分析（batch_analyzer 已有基础）产品化：任务队列+结果看板
2. 多账号管理、角色权限、审核工作流（一审/复审）
3. 定制平台权重（MCN 所在赛道）、敏感词库私有化
4. API 计量计费、Webhook 回调
5. 数据安全：私有化部署包（对接 V3.2 Ollama/vLLM）

### 阶段 P3：品牌投放尽调（6-9 个月）

1. 博主风险尽调报告（对标 Idea 3 做深：成功因素拆解+可模仿路径）
2. 投放前内容风险评估批量 API（品牌方投前审查）
3. 与新榜/蝉妈妈类数据源集成（信号层强化）

### 阶段 P4：平台内容安全审核（9-12 个月）

1. 审核 API 形态（低延迟单句/单帧打分，对标易盾）
2. 人机协同审核台（漏报/误报标注→模型迭代）
3. 合规基线包（广告法/平台规则库）

**报告结论**：VibeUtopia 的工程广度已超过多数对标产品，但**产品深度（闭环、可达性、可信度）是短板**。下一阶段应停止"加平台/加模块"，集中把 P0 四项硬伤修完，让"发前自查→修改→再验证→导出"真正可用，再进入 MCN/品牌扩展。"发前仿真预测"品类无直接对标，是机会也是需要用户教育的成本——报告与 Demo 应用真实塌方案例讲清楚"为什么需要发前预判"。
