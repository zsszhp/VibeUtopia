# 合规与内容安全审计

> 审计对象：VibeUtopia 发布前舆论风险提示产品（11 维风控 + 多模态分析 + 信号采集 + 仿真决策）
> 审计视角：内容安全与合规专家 / 法务产品顾问
> 审计基准日：2026-06
> 证据范围：`src/backend/**`、`src/frontend/**`、`data/config/**`、`docs/design/**`、`docs/00_文档索引与阅读指引.md`、`.ai_context.md`
> 说明：本文为产品合规风险识别与产品化建议，不构成法律意见；正式上线前应由执业律师出具专项意见。

---

## 1. 执行摘要

VibeUtopia 的内容安全**判定能力**在国内同类工具中处于较完整水平：11 维风险评估（`prompts/risk_assessment_v2.txt:33-50`）、证据链、平台差异化权重（28 平台画像，`platform_weights.py`）、热点信号增强（`dynamic_weights.py`）与多模态检测（OCR/音频/帧序列）形成了"发布前提示"闭环。但产品**自身的合规基座几乎空白**：

1. **P0 级缺陷集中在"产品自身违法风险"**：深度爬取模块（`signal/deep_crawler.py`）伪造 User-Agent 调用微博/知乎移动端接口，设计文档明文写有"UA 轮换"反爬策略（`docs/design/06_信号采集层设计.md:419-425`）；全链路无用户协议/隐私政策/免责声明；API 无鉴权且 CORS 全开（`main.py:47-53`）；用户视频/文案原文经云端 LLM（DeepSeek/Qwen/阿里/智谱）外发处理。
2. **改写建议功能存在"帮助规避审核"的定性风险**：`prompts/rewrite.txt` 要求改写"不能让人感觉改过""仅消除风险触发点"——这与产品自身把"规避审核手段"列为红线（`risk_assessment_v2.txt:40`）自相矛盾，一旦被用于洗稿/绕审，产品可能从"风险提示工具"滑向"违规内容辅助生成器"。
3. **内容安全能力存在结构性缺口**：11 维未覆盖未成年人保护、隐私侵犯、色情低俗、知识产权等监管强红线的一等维度；红线词库无治理来源（硬编码 7 词列表 `cross_modal_detector.py:145`）；无人审工作流、无操作留痕、无双人复核。
4. **合规能力产品化是差异化机会**：对标网易易盾/阿里绿网（机审+人审+留痕）、UGC 平台社区公约、海外 Trust & Safety（Santa Clara Principles 通知与申诉、DSA 透明度），把"审核工作流、审计留痕、敏感词治理、数据生命周期"做成产品模块，可同时满足 B 端采购合规审查与监管备案要求。

**总体风险评级：高（上线前必须完成 P0 清零）**。当前形态适合内网/私有化/个人工具场景；若作为 SaaS 对外服务或处理真实商业发布内容，需先完成 P0/P1 整改，否则面临《网络安全法》《个人信息保护法》《生成式人工智能服务管理暂行办法》《网络信息内容生态治理规定》及平台服务条款的多重敞口。

## 3. 用户数据与隐私

### 3.1 数据清单与流转

| 数据类别 | 采集点 | 存储位置 | 外发路径 | 现状问题 |
|----------|--------|----------|----------|----------|
| 用户上传视频 | `POST /api/v1/upload`（`routes.py:653`） | `src/uploads/`（UUID 前缀原文件名） | 关键帧→视觉 LLM；音频→转写→文本 LLM | 无告知同意、无保留期限、无删除接口（仅 `routes_resume.py:223` 可删任务，不删原片） |
| 用户文案 | 分析请求 body | SQLite（`vibeutopia.db`）/分析记录 | 全文进 LLM prompt | 无脱敏选项、无"不用于训练"承诺 |
| 语音转写 | `audio_transcriber.py`（阿里云） | 转写文本入库 | 转写服务+LLM 双重外发 | 声纹属敏感个人信息，未取得单独同意 |
| 爬取评论/热榜 | 信号层定时任务 | 事件/信号库 | LLM 聚类与情感标注 | 评论含用户 ID 痕迹与观点，属个人信息处理 |
| 博主档案 | `routes_blogger.py` | Neo4j+SQLite | 画像/风险趋势 | 人物画像+风险标签，涉名誉与自动化决策（个保法第 24 条） |

### 3.2 核心缺口

1. **无隐私政策、无用户协议、无数据处理告知**：前端代码库零命中"隐私/协议/免责/同意"。不满足个保法第 17 条告知义务，亦无法证明同意链路。
2. **无数据生命周期**：上传 → 分析 → 落盘 → 永久保留，没有 TTL、没有用户可执行的删除权（个保法第 47 条）、没有导出权。
3. **无租户隔离与访问控制**：任意客户端可凭文件路径取回分析结果（`get_review_result`），上传响应直接返回服务器绝对路径（`routes.py:695`）——路径信息泄露 + 越权读取面。
4. **敏感个人信息（人脸/声纹/健康等可能出现在视频中）**：未做识别分级、未做单独同意、未做加密存储。
5. **自动化决策告知**：产品输出"可发/建议修改/不建议发"属于对内容主体的自动化决策建议，个保法第 24 条要求说明并提供拒绝/人工路径——当前无人审出口。
6. **等保影响**：一旦对外服务并处理个人信息，需完成等级保护定级备案（建议二级起步、涉敏感信息按三级建设）：安全物理环境、通信加密（当前 HTTP 明文风险）、日志审计≥6 个月、数据备份、应急响应。

### 3.3 合规基线建议（数据侧）

- 首次使用强制弹出《用户协议》《隐私政策》《数据处理告知》并留存同意日志（版本号+时间戳+用户标识）。
- 上传即声明用途（仅用于本次分析 / 可选匿名化），默认"分析完成后 N 天删除原片，仅留脱敏结论"。
- 本地优先：V3.2 的 Ollama/vLLM 路径应作为涉敏感内容的默认通道；云端外发必须在 UI 明示数据去向（模型提供方、是否留存、是否训练）。
- 管理端全量操作审计日志（谁、何时、对哪条内容、看了什么结论、导出了什么）。

## 4. 内容安全能力完备性（监管/平台红线）

### 4.1 11 维覆盖度对照

产品 11 维（`risk_assessment_v2.txt:35-50`）：红线 5 维（政治敏感、法律合规、民族宗教、事实错误、平台禁区）+ 高敏感 4 维（性别议题、群体冒犯、道德伦理、时事踩雷）+ 动态 2 维（情绪极化、价值观倾向）。

对照《网络信息内容生态治理规定》第 6-7 条红线、UGC 平台社区公约（微博/B 站/抖音/小红书）与常见审核体系：

| 监管/平台红线 | 11 维覆盖情况 | 缺口说明 | 建议 |
|---------------|---------------|----------|------|
| 违宪/涉政/领土主权 | ✅ 政治敏感（红线） | — | 保持 |
| 民族歧视、宗教伤害 | ✅ 民族宗教（红线） | — | 保持 |
| 虚假信息、谣言 | ✅ 事实错误（红线） | 医疗/金融谣言可再拆行业子类 | 子类化 |
| 违法信息（诈骗、赌博、毒品、枪支） | ⚠️ 归入"法律合规"，粒度粗 | 易漏检具体违法类型 | 拆分违法类型子维度 |
| **色情低俗、擦边** | ❌ 不在 11 维内（`.ai_context.md:448` 另有一套含"低俗擦边"的表述，与代码不一致） | 平台最高频违规类型之一 | **升为一等维度** |
| **未成年人保护** | ❌ 仅出现在回测案例（`backtest_cases.py` 有"未成年人保护"期望），不在评估维度 | 《未成年人保护法》+清朗专项行动强红线 | **升为一等维度** |
| **隐私侵犯/人肉/开盒** | ❌ 回测案例有（全红婵案例），评估维度无 | 高监管敏感 | **升为一等维度** |
| **知识产权/抄袭洗稿** | ❌ 缺失 | 平台投诉高发 | 新增 |
| 侮辱诽谤、网络暴力 | ⚠️ 部分在群体冒犯/情绪极化 | 受害人保护视角缺失 | 补充"网暴/人肉指向"规则 |
| 医疗/金融/法律等专业建议 | ⚠️ 在事实错误+法律合规中 | 广告法绝对化用语已有提示（PRD:181） | 行业合规模块化 |
| 灾难/事故不当消费 | ✅ 时事踩雷 | — | 保持 |
| AI 生成内容未标识 | ❌ 缺失 | 2025 标识办法 | 新增检测/提示项 |
| 历史虚无、歪曲英烈 | ⚠️ 价值观倾向覆盖部分 | 英烈法专项 | 明确规则句 |

**结论**：11 维对"涉政/涉民族宗教/谣言"类红线覆盖扎实，但对 UGC 平台实际处置量最大的**色情低俗、未成年人、隐私侵权、版权**四类没有一等维度，属于"能抓住政治红线、抓不住日常违规"的结构性偏差。另发现**文档漂移**：`.ai_context.md:448` 的 11 维表述（含"低俗擦边、侵权抄袭"）与 `risk_assessment_v2.txt` 实际维度不一致，术语治理失效本身就是合规风险（审计无法对齐口径）。

### 4.2 平台规则差异

- ✅ 已有 28 平台画像与维度敏感度（`platform_weights.py`，P0=微博/B 站/小红书/抖音/知乎），并按权重汇总（`calculate_platform_weighted_score`）。
- ⚠️ 敏感度为**静态硬编码**，无版本号、无生效日期、无变更日志。平台规则高频修订（如抖音医疗类、小红书医美类专项），静态配置会迅速失真。
- ⚠️ 境外平台（Twitter/YouTube/Telegram…）用同一套 11 维中文口径，未做本地化政策映射（如 YouTube 的 monetization policy 与国内红线并不对齐）。

### 4.3 动态热点（时事踩雷）更新机制

- ✅ 现有机制：热榜轮询（realtime 300s / standard 600s / economy 1800s，`signal_config.yaml:50-66`）→ 事件聚类 → `DynamicWeights` 按热点维度提权（上限 3.0，`dynamic_weights.py:31`）→ `SignalMatcher` 把文案与热点关联。
- ⚠️ 缺口：
  1. **无敏感日历**（纪念日、纪念活动、重大会议期、灾难哀悼期）——踩雷判定高度依赖日历语境；
  2. **无实体黑名单/谨慎名单**（翻车品牌、被封禁人物、争议当事人）的独立治理库，仅靠 LLM 记忆；
  3. 事件检测 `llm_clustering: false`（`signal_config.yaml:77`）纯规则聚类，长尾新梗识别慢；
  4. 热点数据源即 R1/R2 的合规风险源，"用违规采集的数据做合规提示"存在手段与目的的合法性错位。

### 4.4 审核工作流（人审）

- **现状：没有**。全代码库无"人审/复核/审核台"业务实现；仅有 `confidence_calculator.py:271` 一句"建议人工复核"的文案，以及 `main.py` 中的 WebSocket 推送（那是**分析进度**推送，不是人工审核工作流）。
- 影响：机器判定直接出口到用户，误判（漏判/误伤）无拦截、无申诉、无复核记录，不满足任何主流审核体系"机审+人审"的最低要求，也无法满足个保法自动化决策条款。

## 5. 免责与用户告知设计

当前状态：**报告模板无免责声明**（`report_generator.py` 四类报告均无），**前端无任何法律文本**。这是 P0 级合同与侵权敞口——产品输出的"可发/建议修改/不建议发"会被用户当作发布决策依据。

### 5.1 免责架构（三层）

1. **产品层（用户协议）**：
   - 明确产品性质为"辅助分析工具"，结论为模型概率输出，**不构成法律意见、平台最终审核意见或发布许可**；
   - 内容合法性责任由发布者自负；用户不得将本产品用于生成、改写、伪装违规内容；
   - 明确禁止用途清单：规避平台审核、洗稿、伪造合规证明、批量生产规避检测文案。
2. **报告层（每份报告页眉/页脚嵌入）**：
   - "本报告由自动化模型生成，存在误判与漏判可能；高风险结论建议人工复核后使用；报告时效受热点数据更新时点限制"；
   - 标注模型版本、评估时间、所用规则/词库版本（可追溯）；
   - AI 生成合成内容显式标识（对齐《标识办法》）。
3. **功能层（改写建议模块，最敏感）**：
   - **重写 `rewrite.txt` 目标函数**：从"消除风险触发点且不让人感觉改过"改为"合规化表达建议"——必须保留可识别的改写痕迹说明、明确"改写仅降低表述风险、不改变内容事实与违法性"；
   - 对红线维度（涉政、民族宗教等）**禁止输出改写版本**，仅输出"该内容建议不予发布"；
   - UI 强制展示"改写不是洗稿工具"提示 + 本次改写依据的规则条目。

### 5.2 误判责任边界

- **漏判（提示安全但实际违规）**：靠免责+责任自负+模型局限告知 + 建议人审兜底；完全免除责任的格式条款可能被认定无效，应以"合理提示+人工复核通道"降低过错认定。
- **误伤（提示高风险但实际安全）**：成本较低，但涉及名誉（给个人/品牌贴"高风险"标签）——报告应避免不可撤销的人格化定性，改用"内容风险"而非"人品风险"表述，并提供异议反馈入口。
- **建议边界**：产品建议应停在"风险提示 + 修改方向"，不输出"这样改就能过审"的确定性承诺。

## 6. 信号采集合规

### 6.1 现状盘点

| 采集方式 | 实现 | 合规评价 |
|----------|------|----------|
| 第三方聚合热榜 API | `newsnow.busiyi.world/api/s`（微博/百度/知乎/B 站/抖音…11 源） | ⚠️ 依赖第三方数据授权状态，自身未核验；接口非官方 |
| RSS 订阅 | Hacker News、雅虎财经、澎湃（经 RSSHub） | ✅ RSS 本身合规性较好；⚠️ RSSHub 实例为社区代理，稳定性与授权存疑 |
| 深度评论爬取 | 伪造移动端 UA 调 `m.weibo.cn`/知乎 API（`deep_crawler.py`） | ❌ 规避技术措施；评论是用户个人信息与 UGC |
| 反爬策略设计 | "UA 轮换、代理池、按平台限速"（`06_信号采集层设计.md:419-425`） | ❌ 设计意图即对抗平台技术措施，刑事/不正当竞争风险最高的一页 |

### 6.2 整改方向

1. **砍掉"反爬对抗"设计目标**：限速、退避、熔断（已部分具备：`request_interval`、`max_retries`）应以"友好爬取/遵守 robots"为原则写入设计文档，删除 UA 轮换、代理池对抗表述。
2. **数据源白名单制**：仅接入（a）官方开放平台 API（微博开放平台等，走授权与配额），（b）明确允许再分发的聚合商并签订数据协议，（c）RSS/官方公告页。深度评论采集改为"用户主动粘贴链接 + 平台官方接口授权"模式。
3. **采集即最小化**：评论只取文本+聚合情绪，不保留用户 ID/主页链接等可识别字段（当前 `user_type` 分类可保留为匿名统计）。
4. **来源水印**：每条信号入库保留 source_url、采集时间、授权依据字段，报告引用可回溯。
5. **停止按钮与配额台账**：按域名的采集配额与告警，防止误配置造成对目标站点的实质冲击（本身也降低 DoS 误判风险）。

## 8. 合规功能产品化建议（审核工作流、留痕、双人复核）

将合规从"义务"转化为可售卖的模块，既满足监管与采购审查，也构成本产品相对纯模型工具的壁垒。

### 8.1 审核工作流（机审 → 人审 → 复核）

```
内容输入 → 机审(11/15维打分+证据链) → 风险分流
                                      ├─ 绿(0-25)：自动通过，抽样送审(5%)
                                      ├─ 黄/橙(26-75)：单人审（审核员确认/改判）
                                      └─ 红(76+)：双人复核（初审+复审，意见冲突升级主管）
                                              ↓
                                        处置动作：放行/修改建议/驳回/上报
                                              ↓
                                        申诉通道（用户对结论异议 → 复核队列）
```

- **角色**：审核员、复审员、合规管理员（维护规则库与敏感日历）、只读审计员。
- **SLA**：红≤2h、橙≤8h、申诉≤24h；超时升级。
- **双人复核触发条件**：红线维度命中、名人/机构实体命中、未成年人相关内容、用户申诉、跨境平台发布。复核双盲（复审员看不到初审结论）降低从众偏差。

### 8.2 留痕（审计与自证）

- **判定留痕**：每次分析落库——输入哈希（原文可脱敏存储）、模型版本、prompt 版本、规则库版本、词库版本、各维度分数、证据链、最终结论、耗时。
- **操作留痕**：谁查看/导出/改判/驳回，改判必须填理由码；日志只增不删，保留≥6 个月（对齐网安法）。
- **规则留痕**：敏感词与规则条目变更走"提案→审批→生效→回滚"四态，变更记录含操作者与依据。
- **对客留痕**：报告页展示"评估时间、数据截止时间、模型与规则版本"，让用户知道结论时效边界。

### 8.3 规则与词库治理

- 单一事实源：`rulebook/`（机器可读 YAML/JSON）+ 版本号，prompt 中只引用规则 ID 不硬编码规则文本；
- 来源字段必填：监管文件 / 平台公约 / 行业惯例 / 案例回测，支持审计抽查；
- 双轨判定：词库/规则命中（可解释、可审计）与 LLM 语义判定（语境理解）交叉验证，词库命中而 LLM 未命中时强制进人审。

### 8.4 数据合规产品化

- **隐私中心**（用户侧）：同意记录、数据副本导出、一键删除、外发记录（哪次分析用了哪家模型）。
- **部署形态**：私有化（默认全本地，V3.2 已具备硬件自适应 Tier）＞ 专有云 ＞ SaaS（最后，且必须完成等保+备案+DPA）。
- **供应商管理**：LLM/爬虫/聚合源清单化，各自标注数据流向与合同状态。

### 8.5 对标结论（实践映射）

| 对标对象 | 借鉴点 | 落地到本产品 |
|----------|--------|--------------|
| 网易易盾/阿里绿网/腾讯天御 | 机审+人审队列、行业模板、私有化交付 | §8.1 工作流 + 行业合规包 |
| UGC 平台社区公约（微博/B 站/抖音） | 公开规则条目、处置梯度、申诉机制 | 规则库条目化 + 申诉通道 |
| 《网络信息内容生态治理规定》 | 19 类违法/不良信息红线 | 维度补全（§4.1） |
| 《生成式 AI 管理暂行办法》+《标识办法》 | 不得协助违法、生成内容标识 | 改写模块重定性 + 报告标识 |
| Santa Clara Principles / DSA | 透明度报告、通知-申诉-救济 | 透明度报表 + 异议复核 |
| Trust & Safety 行业（Meta/YouTube 政策体系） | 政策版本化、执行一致性衡量、政策更新节奏 | 平台规则版本化 + 回测一致性指标 |
