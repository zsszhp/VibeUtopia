## 2. 现有管线盘点（现状证据）

### 2.1 模块清单与角色

| 模块 | 行数量级 | 现状角色 | 原理性评价 |
|------|----------|----------|------------|
| `keyframe_extractor.py` | ~21KB | 三级降级抽帧（PySceneDetect→FFmpeg→OpenCV）+ pHash 去重 | 只捕捉镜头边界，镜头内短暂内容原理性盲区 |
| `delta_frame_extractor.py` | ~24KB | 帧差/SSIM/哈希 + 场景帧 | 像素级差异，语义不敏感 |
| `frame_sequence_analyzer.py` | ~36KB | 固定分段描述、因果链、动作事件、网格拼图 | 已有时序意识，但分段是固定 size 而非语义分段 |
| `frame_risk.py` | ~17KB | 逐帧 VLM 风险评分 + 规则兜底 | 帧级孤立评分，丢失叙事 |
| `frame_ocr.py` | ~9KB | OCR + 帧间文字去重 | 可用，保留 |
| `cross_modal_detector.py` | ~13KB | 画面-文案-音频冲突 + 规则降级 | 冲突被降格为"加分项"，未成为证据 |
| `multimodal_analyzer.py` | ~15KB | 三模态加权 + max 融合 | max 丢失联合信息（原理性缺陷） |
| `fine_grained/dense_frame_scanner.py` | ~10KB | 1fps 密扫 + 多窗口异常分 | 30 号成果，采样补丁有效，但非理解升级 |
| `fine_grained/map_auditor.py` 等四猎手 | ~50KB | 地图/代码/符号/时序异常 | 有价值，但缺"detector+VLM+知识库三段式协议"与反证检索 |
| `evidence_chain.py` | — | 交叉校验、传播路径、置信计算 | 雏形可用，缺四级下钻与置信分解 |
| `simulation/*` `trend_predictor.py` | 大 | 舆情仿真与趋势 | 与视频事件图断链 |

### 2.2 白皮书 §5 揭示的口径

- 融合公式：`文本1.0 + 视觉0.8 + 音频0.7 + OCR0.6 → max(加权)`；多模态同时 >60 时 +10
- 关键帧：ContentDetector 阈值 27.0、最短场景 15 帧、pHash 汉明 <8 判重、上限 50 帧
- 细粒度：1fps 上限 1200 帧，异常分 `max(diff(i,i±w))×1/√w`，高异常（≥0.7）必审
- 音频：faster-whisper base + VAD / Paraformer 双引擎

**结论**：现状 = "帧级证据原子工厂 + 静态规则融合"。缺事件中枢、缺叙事层、缺预算智能、缺舆论通道。与 31 号架构的差距是结构性的，不是调参能补的。

## 3. 论文逐项提炼

### 3.1 Video Understanding Survey（本地 PDF）

- 核心观点：视频理解任务谱系从 captioning/QA 到 temporal grounding 到 dense captioning；瓶颈集中在**长时依赖**与**细粒度定位**两端
- 借鉴：任务谱系定义了我们的评测维度（caption→event→grounding→risk）
- 不借鉴：综述不提供单一架构方案
- 落点：§8 评测方案的任务分层

### 3.2 Qwen2-VL（arXiv:2409.12191，本地 PDF）

- 核心思想：
  1. **Naive Dynamic Resolution**——图像按原始分辨率编码为可变数量 token，小文字不被固定 resize 压没
  2. **M-RoPE**——位置编码分解为时间/高度/宽度三维，视频帧获得显式时间位置
  3. 视频训练用帧率可变采样
- 借鉴：动态分辨率 = L4 区域放大的技术依据；M-RoPE 的时间维思想 = 所有事件必须带 TimeSpan 的模型侧依据
- 不借鉴：不把闭源 API 当唯一通道（可回溯性/成本）；不依赖其长视频直吞
- 落点：L0/L4；VLM 选择策略（qwen3-vl 系列仍作主视觉模型）

### 3.3 GLM-4V（本地 PDF）

- 核心思想：多任务专家化视觉语言对齐；指令跟随强
- 借鉴：任务化 prompt 范式（地图审核、符号审核、冲突判定分别定制 schema 化 prompt）
- 不借鉴：不依赖单一模型做全部判断（双确认原则）
- 落点：L4 Stage-2 的 prompt 工程

### 3.4 VideoLLaMA3（arXiv:2501.13106，arXiv abstract 已核验）

- 核心思想（abstract 原文口径）：**vision-centric**——
  1. 用高质量**图文**数据（而非海量视频文本）打底训练
  2. 视觉编码器接受**可变分辨率**图像，token 数随尺寸变化
  3. 视频输入按**相似度压缩视觉 token**，使表示更精准紧凑
  4. 四阶段训练：编码器适配→对齐→多任务→视频微调
- 借鉴：**按相似度压缩 token** = "冗余帧不花预算"的理论版——直接启发 L3 选帧智能体的 novelty 项；Event-Frame 双层视角支持"事件为单位、帧为证据"
- 不借鉴：训练基座模型（成本与算力不允许）；Foresight Token 需要训练态
- 落点：L3 密度公式 `novelty_v`；L1 多尺度

### 3.5 LLaVA-OneVision（arXiv:2408.03326）

- 核心思想：单模型统一单图/多图/视频；动态帧采样；视频被组织为图像 token 序列
- 借鉴：**事件簇可打包为多图输入**——比"一次一帧"高效，比"整段视频"可控；细粒度时序推理的多粒度输入协议
- 不借鉴：不追求单模型覆盖一切（细粒度猎手仍需专项检测器）
- 落点：L5 事件簇打包协议

### 3.6 TimeChat（时间敏感视频 LLM）

> 注：`references/参考论文与开源项目.md` 中记录的 arXiv ID（2312.02052）经核验指向另一篇论文（DUCK unlearning），**该 ID 有误**；TimeChat 正式发表于 CVPR 2024（Shao et al., "TimeChat: A Time-sensitive Multimodal Large Language Model for Long Video Understanding"），实施时按标题检索。此为参考资料勘误点。

- 核心思想：时间戳感知的视频 LLM——描述与回答必须绑定时间区间；帧采样与时间对齐耦合
- 借鉴：**"无时间定位的结论无效"** 升格为架构硬约束（P5）；时间戳感知编码思路
- 不借鉴：其长视频全量编码成本高；不自训
- 落点：TimeSpan 硬约束；L2 事件边界

### 3.7 VTimeLLM（arXiv:2311.18445，arXiv abstract 已核验）

- 核心思想（abstract 原文口径）：解决"现有 Video LLM 只能给全片粗描述、无法给出事件精确起止边界"的问题；**boundary-aware 三阶段训练**：图文对齐→多事件视频增强时序边界感知→高质量指令微调
- 借鉴：**时刻边界是一等公民**——事件不能只给中心帧/中心时刻，必须给 [t_s,t_e]；多事件视频边界感知训练数据的构造思路（合成多事件拼接视频）
- 不借鉴：训练流程本身；不追求端到端时刻检索精度竞赛
- 落点：L2 事件边界质量评测；L4 异常区间聚类边界与镜头边界对齐

### 3.8 InternVideo2（arXiv:2403.15377）

- 核心思想：多粒度时序建模的视频基础模型；masked video modeling + 视频-文本对齐
- 借鉴：**多粒度联合是必要的**——单一粒度（仅帧或仅全片）都损失信息；支撑 L1 四时尺并行设计
- 不借鉴：不自训基础模型
- 落点：L1 T0–T3 四层并行、互为先验

### 3.9 ActionFormer（arXiv:2202.07925）

- 核心思想：anchor-free 时序动作定位；FPN 多层级 + **分层回归范围** `regression_range=[(0,4),(4,8),...]`——低层检测极短事件、高层检测长事件；中心采样；Focal+DIoU
- 借鉴：多时间窗口并行评分（1/3/10/30 帧窗口）；短时事件优先；正负样本不平衡用 Focal 思想
- 不借鉴：纯动作类别定位（我们要的是风险类型）；其训练管线
- 落点：已被 30 号采用的多窗口异常分；31 号升级为语义异常分（ROI 嵌入 + 像素混合）

### 3.10 GOT-OCR2.0（arXiv:2409.01704）

- 核心思想：通用 OCR 理论——区域级 OCR 通过 prompt 指定：`[x1,y1,x2,y2] OCR:`（bbox 归一化 0–1000）、`[red] OCR:`（颜色标记）、动态裁切 1024 patch + 缩略图
- 借鉴：bbox prompt 区域识别；动态裁切保细节；颜色启发（代码编辑器语法高亮色）
- 不借鉴：不引入完整 GOT 训练栈
- 落点：L4 细粒度 OCR 与代码区检测（30 号已用，保留）

### 3.11 InternVL

- 核心思想：动态分辨率多 patch（find_closest_aspect_ratio 切 448×448）+ 全局缩略图；pixel shuffle 降采样省 token
- 借鉴：区域放大裁切策略 + "缩略图保全局语境"（语境闭包 P2 的实现技巧）
- 不借鉴：pixel shuffle 需训练态
- 落点：L4 `_amplify_region`（30 号已用）

### 3.12 SeViLA

- 核心思想：自链接"定位关键帧→回答"两段式；定位器与回答器协同
- 借鉴：**先定位后理解**——证明"智能选帧"是学术界独立成立的阶段，而非工程妥协
- 不借鉴：其自训练定位器
- 落点：L3 选帧智能体与 L5 理解层的分工

### 3.13 MomentDETR（arXiv:2104.02755）

- 核心思想：端到端时刻检索，DETR 范式（query-based，NMS-free）
- 借鉴：用少量可学习 query 表示"候选时刻"，天然稀疏——等价于"预算有限时选少数关键时刻"
- 不借鉴：其纯检索定位输出无内容理解；不主用
- 落点：作为 L3 选帧智能体的备选定位器（若后续要学习式定位替代密度启发式）

### 3.14 UniVTG（arXiv:2307.01566）

- 核心思想：统一时序定位框架，把 moment retrieval / temporal grounding / dense captioning 纳入同一套标注与评测
- 借鉴：**统一时间标注格式**——(video, query, [t_s, t_e]) 三元组贯穿所有任务；支持我们 VGOLD 的标注协议
- 不借鉴：不主用其模型
- 落点：VGOLD-200 标注协议设计

### 3.15 TimeSformer（arXiv:2102.05095）

- 核心思想：时空分离注意力（divided space-time attention），比全时空注意力省算力
- 借鉴：**空间与时间分开算**是高效多时尺建模的模型侧依据——支持 L1 四层"各算各的再融合"而非全片 3D 卷积
- 不借鉴：不自训编码器
- 落点：L1 T0–T3 分离计算的理论支撑

### 3.16 mPLUG-DocOwl1.5（arXiv:2403.12895）

- 核心思想：结构感知文字理解——把版面结构（标题/正文/图注）纳入 OCR 理解
- 借鉴：字幕/花字/弹幕/标题在画面中的**结构角色**不同，OCR 结果应带角色标签（而非纯文本）
- 不借鉴：不引入其文档预训练
- 落点：L0 OCR 流输出结构化标签（subtitle / watermark / sticker / folder_name / code）

### 3.17 MovieChat（arXiv:2404.17176）与 LongVILA（arXiv:2408.10188）

- 核心思想：MovieChat 用稀疏/浓缩记忆压缩长视频；LongVILA 用 256K 长上下文硬扛
- 借鉴：**记忆压缩优于硬扛长上下文**——L1-T3 全片级用"32/64 锚点摘要"而不是把全片塞进上下文
- 不借鉴：LongVILA 式长上下文直吞（成本与延迟不可控，且不可回溯）
- 落点：L1 T3 锚点摘要；S3 深析层的全片级输入

### 3.18 Whisper（本地 PDF）与音频侧

- 核心思想：大规模弱监督 ASR，鲁棒转写；词级时间戳能力（faster-whisper 继承）
- 借鉴：词级时间戳是 P4 模态绑定的前提条件（口播"自研"与画面 GitHub 必须对齐到同一秒）
- 不借鉴：不自训 ASR
- 落点：L0 ASR；音频情感分析继续走"转写文本情感"轻量路线（白皮书既有口径）

## 5. 关键设计决策与依据

| 决策 | 备选方案 | 选择 | 依据 |
|------|----------|------|------|
| 推理单位 | 帧 / 镜头 / 事件 / 全片 | **事件**（帧作证据） | Q2/Q3：风险在组合层涌现；帧无法承载组合语义 |
| 采样 | 均匀 1fps / 异常驱动 / 语义密度预算 | **语义密度+锚点+覆盖度** | SeViLA 先定位后理解；VideoLLaMA3 相似度压缩；纯异常驱动漏"不异常但关键"的 claim 帧 |
| 融合 | max 加权 / 拼接过 LLM / 事件级联合 | **事件级联合 + 涌现函数** | max 丢失冲突联合信息；拼接破坏时间绑定（Q6） |
| 细粒度 | 纯 VLM / 纯检测器 / 双确认 | **detector+VLM+知识库三段式** | 30 号实测：纯 VLM 小目标识别率 ~40%；纯检测器泛化差 |
| 时间定位 | 中心点 / 区间 | **区间 [t_s,t_e]** | VTimeLLM：边界是一等公民 |
| 置信度 | 单一分数 / 分解 | **四因子分解 + 分级输出** | 反伪精确（P6）；申诉场景需要 |
| 长视频 | Video-LLM 直吞 / 管线 / 混合 | **管线为主，直吞仅作叙事第二意见** | 直吞不可回溯→不可申诉；成本超预算 |
| 舆论预测 | 不做 / 独立文本舆情 / 事件图驱动 | **事件图→争议点→仿真** | 用户命题含"发布后舆论风险"；事件级才能映射立场张力 |

## 6. 痛点案例回放（对照新架构）

### 案例 A：几帧地图缺台湾

- 旧路径：场景切换若跳过该镜头 / 30s 均匀采样命中率低 → 漏；pHash 去重可能把有/无台湾的相似地图帧合并 → 二次漏
- 新路径：L3 密度发现"地图展示"为高 entity_salience 窗口 → 强制锚点保留 → L4 地图猎手 Stage-1 提议 → Stage-2 VLM 确认 → Stage-3 地理知识库核验 → 反证检索（他处是否完整）→ 四级证据链输出
- 预期：召回从 ~30% 提升到 ≥90%（30 号已定此目标，31 号用双确认与反证降低误报）

### 案例 B：几帧 GitHub 开源文件夹 + 口播"自研"

- 旧路径：OCR 能采到文件夹名，但"与自研 claim 的冲突"只在 cross_modal 里 +10 分，不构成"内容失实"结论
- 新路径：E_claim（口播自研）与 E_display（文件夹 ByteTrack）在事件图中连 `contradicts` 边 + `setup_payoff` 模式 → L6 判定"欲盖弥彰"语用模式 → L7 涌现函数输出"内容失实 + 叙事风险" → 舆论通道输出"技术诚信争议点，科技区受众高敏感"
- 预期：从"轻微冲突加分"变为"可定级、可下钻、可预测舆论"的完整结论

### 案例 C（新增压力测试）：单帧均合规的带节奏剪辑

- 旧路径：原理性不可见（每一帧都合规）
- 新路径：L1-T1 剪辑节奏异常（快切、选择性特写）+ L6 意图向量 provoke 高 + setup-payoff 检测 → 输出"语用风险线索（带置信分级）"
- 注意：此类只输出"线索"不自动定罪（P6 + 人审）

## 7. 评测对标

| 维度 | 学界常用 | 本项目采用 | 差异原因 |
|------|----------|------------|----------|
| Caption 质量 | CIDEr/METEOR | 不作主指标 | 风控不看文笔看漏检 |
| 时刻定位 | R@1 IoU=0.5/0.7 | Temporal-IoU 中位 | 风险区间常不规则 |
| 细粒度 | TextVQA 准确率 | Box-Recall + OCR 识别率 | 风控要召回优先 |
| 风险识别 | 内容审核 F1 | 事件级召回 + FP-rate + 伪精确率 | 审核场景误报代价高 |
| 可审计 | 少见 | Evidence-Fidelity（本项目新增） | 申诉/合规硬需求 |
| 舆论 | 趋势预测 MAPE | Spearman + 情景分支 | 舆论不确定性高，给区间 |

金标准 VGOLD-200 构造原则：**负样本必须与正样本"长得像"**（正常地图 vs 缺失地图），否则指标虚高。

### 7.1 指标精确定义

```
Event-Recall = |检出的风险事件 ∩ 标注风险事件| / |标注风险事件|
  （事件匹配条件：类型相同 且 Temporal-IoU ≥ 0.3）

Temporal-IoU = |[t_s^pred, t_e^pred] ∩ [t_s^gt, t_e^gt]| / |union|

Evidence-Fidelity = 抽样 50 条自动定级结论，人工核验四级链能否真实回放
  （回放到正确证据帧 = 1，回放失败/指错帧 = 0）

Pseudo-Precision-Rate = conf_total < 0.5 但被写入"结论"栏的条数 / 总结论数

成本效率 = Event-Recall / 单视频平均费用（元）
```

### 7.2 对照实验的显著性要求

- 每组实验跑 3 次（LLM 温度非零），报均值±标准差
- S2 vs S1 的 Event-Recall 提升需做配对检验（Wilcoxon），p < 0.05 才可宣称"更好"
- 消融组 S3 若某组件去掉后指标不降（p > 0.05），该组件应重新评估是否保留

## 8. 第一性原理推演底稿（结论回链）

从"视频是时间轴上的多模态话语"出发，推演出架构硬约束的过程：

1. 视频有时间性 → 结论必须带 TimeSpan（否则无法回放、无法对齐）→ P4/P5
2. 视频有组合性 → 推理单位必须大于帧（帧组合出新语义）→ P1 事件优先
3. 视频有多模态绑定 → 融合必须在统一时间轴上联合 → P4 模态绑定（拒绝 max 加权）
4. 视频有作者性 → 剪辑/节奏/镜头选择本身是信号 → L1 剪辑特征 + L6 意图推理
5. 视频有语用性 → 风险最终由受众解读决定 → L7 舆论通道（内容定级 ≠ 风险闭环）
6. 计算资源有限 → 必须预算感知 → P7 三级路由（拒绝"全量逐帧"）
7. 结论要可申诉 → 必须可回溯 + 反伪精确 → P5/P6

每条硬约束都能回链到一条不可否认的视频性质——这是"第一性原理"而非"经验调参"的判据。

## 10. 调研结论

1. **用户否定逐帧路线在学界有独立佐证**：SeViLA（先定位后理解）、VTimeLLM（边界感知）、TimeChat（时间戳绑定）、VideoLLaMA3（相似度压缩 token）都指向"选择+事件+时间定位"，而非"均匀看帧"。
2. **四类风险涌现（空间细节/时间结构/模态冲突/叙事语用）不可互相归约**，现有管线只覆盖前两类的一半；31 号架构的 L4–L7 分别对应补全。
3. **集百家所长的正确姿势是"机制移植而非模型照搬"**：借 ActionFormer 的多尺度窗口、GOT-OCR 的区域 prompt、VideoLLaMA3 的 token 压缩思想、内容安全分析的分层路由，全部落到事件图这一自有中枢上。
4. **可证伪性是本架构的验收底线**：VGOLD-200 + S0/S1/S2/S3 对照 + 消融，必须能证明"事件级 > 逐帧"，否则架构主张不成立。
5. **实施风险集中在事件图边界质量与叙事判定主观性**，故 P0 先上事件图+双确认（确定性收益），P1 再上叙事（主观性高，必须带置信分级与人审）。
