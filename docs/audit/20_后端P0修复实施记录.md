## 2. 改动明细

### 2.1 P0-1 `/api/v3` 双重前缀

**根因**：`main.py` 以 `prefix="/api/v3"` 挂载 `routes_v3.router`，而 `routes_v3.py` 装饰器路径又写全 `/api/v3/...`，实际注册为 `/api/v3/api/v3/...`；同文件内 `/fine-grained/*`、`/analysis/*` 为相对路径写法反而可用。前端 `V3_BASE='/api/v3'` 与文档 `/api/v3/*` 打到的都是 404。

**修复方案**（二选一中选「保留挂载前缀、装饰器改相对路径」）：

- 理由一：已可用的 `/api/v3/fine-grained/*`、`/api/v3/analysis/*` 路径保持不变，零回归。
- 理由二：全部 v3 端点收敛到 `/api/v3` 命名空间，与 `routes_local_models`（自带 `/api/v3/local-models` prefix）风格一致。

**改动**：`src/backend/routes_v3.py` 全部 45 处 `@router.*("/api/v3/xxx")` → `@router.*("/xxx")`（只动装饰器，不动 docstring）。

**前端**：`src/frontend/src/api/index.ts` 的 `V3_BASE = '/api/v3'` 本就与修复后的实际路径一致，**无需改动**。

**文档**：`docs/guides/23_API参考.md`、`25_运维手册.md` 中的 `/api/v3/*` 路径与修复后实际路径一致，无需改路径，仅补充健康检查章节。

### 2.2 P0-2 错误响应统一

前端错误读取约定：`e.response.data.detail`（见 `src/frontend/src/stores/index.ts`）。统一为 `{"detail": "<字符串>"}`。

**`src/backend/main.py` 新增三个全局处理器**：

| 处理器 | 状态码 | 响应体 |
|--------|--------|--------|
| `http_exception_handler`（main.py:64） | 4xx/5xx | `{"detail": "<消息>"}`（非字符串 detail 自动转字符串） |
| `validation_exception_handler`（main.py:73） | 422 | `{"detail": "请求参数校验失败: <字段: 消息; ...>"}`（detail 收敛为可展示字符串，不再是对象数组） |
| `unhandled_exception_handler`（main.py:84） | 500 | `{"detail": "服务器内部错误"}`（不外泄堆栈；完整堆栈仅入服务端日志） |

原有的 `HTTPException(detail=...)` 业务错误（如 400「内容太短」）行为不变，前端解析方式不变。

### 2.3 P0-3 `routes_story` 注册

**核实结论**：应注册。`routes_story.py` 实现完整（6 个端点 + 后台生成任务），`docs/guides/23_API参考.md`「人生故事生成端点」章节路径 `/api/v1/story/*` 与代码一致，缺口仅在 `main.py` 未 include。

## 6. 残留风险 / 后续建议

1. **零鉴权**：全部 REST/WS 端点仍无认证（审计 17 范围）；`/api/v3/llm-test`、`/api/v3/model-status` 匿名可触发付费调用/查看 Key 池统计，建议后续加 `require_ops_role`。
2. **限流缺失**：服务端无限流，匿名可打满 LLM 配额（审计 17）。
3. **业务层 500 消息**：部分端点 `HTTPException(500, detail=f"...{str(e)}")` 仍会把异常文本回给客户端（非密钥，但含内部细节）；全局兜底 handler 只覆盖未捕获异常。建议后续统一为「用户可读短语 + 服务端日志留全量」。
4. **CORS 默认白名单**仅覆盖本地开发端口；部署到 `*.monkeycode-ai.online` 等域名时需设置环境变量 `CORS_ALLOW_ORIGINS`（若前后端同域反代则不受影响）。
5. **`/api/v3/image/generate` 等付费端点**同样无鉴权，注意成本暴露面。
