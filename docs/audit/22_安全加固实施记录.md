### 4. 日志脱敏（日志卫生）

新增统一脱敏工具 `src/backend/services/log_sanitizer.py`：

- `redact_secrets(text)`：正则掩码 `ak_*`、`sk-*`、`Bearer <token>`、`api_key/token/secret/password=…` 赋值形态 → `<REDACTED>`
- `redact_context(context)`：递归脱敏错误上下文字典

接入点：

| 文件 | 接入 |
|------|------|
| `src/backend/services/error_handler.py` | `safe_execute` 中所有 `logger.warning/error` 的 `str(e)` 与 `error_context` 均过 `redact_secrets` / `redact_context` |
| `src/backend/services/error_monitor.py` | `record_error` 的 `error.context`、`record_unexpected` 的 `str(error)` 入库前脱敏 |
| `src/backend/services/llm_client.py` | 全部 fallback / 重试 / 400 错误日志与 `RuntimeError` 消息中的异常文本、`resp.text` 片段均过 `redact_secrets`（覆盖文本、VLM、图像生成三条调用链） |

**残留风险说明**：

- `exc_info=True` 的 traceback 本身不含请求头，但若未来在异常 `__str__` 中拼入 headers 仍有风险，已通过 `redact_secrets` 兜底。
- `llm_client` 中 `logger.warning("模型 %s …", key, …)` 的 `key` 变量是 `provider:model_id:key_index` 路由标签，**不是** API Key，无需脱敏。
- 建议后续在生产日志配置中禁用 DEBUG 级 payload 打印（见审计 17 修复建议）。

## 二、风险与密钥轮换提醒（必须执行）

1. **【紧急】LongCat Key 吊销轮换**（见 §1 遗留风险）：三个 Key 均已进入 Git 历史并推送双远端，任何仓库可见者可消耗配额。工作区清理 ≠ 泄漏闭环，**唯一根治是控制台吊销 + 换新 Key**。
2. **数据库口令轮换**：历史版本中 `vibeutopia2024`、`vibe_password`、`root_password`、`123456` 已入库并推送。已在用的 MySQL / Neo4j 实例应**立即改口令**，并同步更新本地 `.env`。
3. **`.env` 纪律**：`.env` 仅存本地，永不提交；新增密钥类配置一律走 `.env.example` 占位 + 真实值进 `.env`。
4. **文档示例口令**：所有文档示例已改占位符；后续文档新增示例时禁止写真实口令。
5. **CORS**：生产部署前必须在 `.env` 配置 `CORS_ALLOW_ORIGINS` 为真实域名，否则仅 localhost 开发端口可跨域访问。
