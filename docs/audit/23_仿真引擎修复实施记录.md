## 2. 修复内容

### 2.1 P0-1：engine.py 语法与结构

**文件**：`src/backend/services/simulation/engine.py`

1. **闭合 `_load_agents` 的 try/except/finally**
   - `try:` 块包含查询与 Agent 注册循环
   - 补 `except Exception` 记录加载失败、`finally: db.close()` 确保连接释放
2. **删除游离在 `_supplement_agents` 尾部的 `finally: db.close()`**
3. **数据库依赖降级**：`_load_agents` / `_persist_tick` 在 `SessionLocal` / models 导入失败（如无 sqlalchemy、无 MySQL）时记录 warning 并跳过，不再让导入异常打断初始化/持久化调用方
4. **修复 `_supplement_agents` 的死引用**
   - `ARCHETYPE_TEMPLATES` → `get_random_archetypes(pname, count)` + `archetype_to_dict`
   - 补充 Agent 人格改用原型库真实 schema（`L2_values` / `L4_behavior` / `L6_social`），与 `rule_engine.decide` 读取口径对齐（此前补充 Agent 的 `L2_personality` 与 rule_engine 读取的 `L2_values` 脱钩，行为等价随机体）
   - 原型库不可用时降级为简化人格，不中断
5. **层级分配修正**（原 `i < count // 2` 将一半补充 Agent 标为 A 级，而 A 级不参与 tick，等于僵尸）
   - A 级仅保留少量 KOL（约 `count // 10`）
   - 其余按影响力分 B/C

**验证**：`python -m py_compile engine.py` 通过；`from backend.services.simulation.engine import SimulationEngine` 与 `from backend.services.simulation import SimulationEngine` 均成功。

### 2.2 最小可运行路径：enhanced_analyzer Phase3

**文件**：`src/backend/services/enhanced_analyzer.py`

`_run_phase3` 重构为两段降级：

| 情况 | 行为 |
|------|------|
| 引擎导入失败 | `simulation_summary = {"error", "degraded": True, "degraded_reason": "engine_import_failed"}`，error 日志明确写"仿真引擎导入失败" |
| 引擎执行失败 | `degraded_reason": "engine_runtime_failed"`，error 日志明确写"仿真增强执行失败" |
| 成功 | 返回真实 tick 摘要，附 `engine_mode: "lightweight_tick_simulation"` |

不再把一切异常吞成笼统 `{"error": str(e)}` 且无从分辨原因。

### 2.3 P0-2：反事实诚实化

**文件**：`src/backend/services/counterfactual_sim.py`（重写核心逻辑）

#### （1）改写：调用已有 rewriter，失败返回明确错误

- 删除 `_generate_modified_sentence` 占位符实现（`[中性表述] {sentence[:20]}...`、第 5 字符插"可能"、`从另一个角度看，` 前缀）
- 非 delete 策略改为 `backend.services.rewriter.rewrite_sentence`（LLM 语义保留改写，含 `rewrite_note`）
  - `soften` 取保守版改写（rewrites[0]）
  - `replace` / `rephrase` 取清晰版改写（rewrites[-1]）
- **失败路径返回明确错误，不产出假句子**：
  - 改写服务不可用 / 调用异常 → `改写服务不可用` / `改写调用失败`
  - rewrites 为空 → `改写服务未返回有效改写结果，已拒绝生成占位改写句`
  - 红线维度（政治敏感/法律合规/民族宗教/事实错误/平台禁区）→ 透传 rewriter 的 `redline_note`（建议不予发布）
  - 转写噪声句 → 透传 `transcript_note`
  - 目标句为空 → `风险项缺少可改写的原句文本`

#### （2）评分：去掉固定衰减，改为重评估 / 区间启发式

删除 `_simulate_modified` 的 `reduction = min(original_score * 0.4, 30)` 恒等式与 `_llm_simulate`（"LLM 看两段文字打分"伪仿真）。

新优先级：

1. **static_reevaluation**（优先）：对改写后文案调用与原管线同一套 `assess_risks` 重跑静态评估，用 `calculate_overall_score` 出总分
2. **heuristic_range**（降级）：重评估不可用时给出**区间 + 方向性**估计
   - `delete`：目标维度预期下降区间 `[base-40, base-10]`（句子移除后证据减少），其他维度 ±5 不确定性
   - `replace/soften/rephrase`：目标维度区间 `[base-25, base+15]`，**允许上升**

#### （3）输出：区间 / 方向性 + 免责，不再"风险必降"

`CounterfactualResult` 新增诚实化字段：

| 字段 | 含义 |
|------|------|
| `method` | `heuristic_rewrite_estimate` / `static_reevaluation` |
| `disclaimer` | 固定文案「启发式预估，非全量仿真。…」 |
| `improvement_range` | 风险分变化预估区间 `{low, high}`（仅启发式路径；improvement = before − after，**正值=风险下降，负值=风险升高**） |
| `direction_hint` | `likely_down` / `likely_up` / `uncertain` |
| `confidence` | `low`（启发式）/ `medium`（重评估） |
| `before.method` / `after.method` | 单侧评分来源，`risk_items_baseline` / `static_reevaluation` / `heuristic_range` |
| `strategy.rewrite_note` | rewriter 的改写说明 |

`_generate_recommendation` 重写为方向性表述：

- 「启发式预估：××策略**可能**降低风险面（风险分变化约 a ~ b 分…）」
- 「启发式预估：××策略效果**不确定**，风险面可能下降也可能升高」
- 「启发式预估：××策略**可能使风险面升高**，请谨慎采用」

并强制附上 `DISCLAIMER`。不再出现「预计风险可降低 X 分」的确定性承诺。

1. **Tick 仿真预测力未验证**：引擎可跑 ≠ 输出优于随机；仍缺 vs 基线的回测（审计 P0-3 / P1-7）

3. **A 级 Agent 仍不参与 tick 循环**（`_execute_tick` 只驱动 B/C）：本次只把补充 Agent 的 A 级占比从 50% 收敛到约 10%，KOL 独立 LLM 决策未实现（P1-4 残留）
4. **Memory/Reflection 仍不进决策**（P1-2）；GA-S3 `GroupAgent` 仍未实例化（P1-1）
5. **decision_advisor 的「预计风险降低 X 分」**仍是确定性话术，属另一模块，本次未改
6. **`_estimate_platform_reactions` 仍是线性启发式**，仅作方向参考，已在模块 docstring 标明
