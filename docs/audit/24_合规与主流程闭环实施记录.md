## 2. 合规 P0 实施详情

### 2.1 A1 改写提示词定性修正

**问题定性**（审计 R6 / P0-5）：原 `rewrite.txt` 目标函数为「不能让人感觉改过」「仅消除风险触发点」，与产品自身「规避审核=红线」自相矛盾，存在滑向「洗稿/绕审辅助工具」的定性风险。

**整改方案**：

1. **重写目标函数**：从「消除风险触发点且不让人感觉改过」→「透明的安全表达优化：保留原意、降低误伤、不用于规避平台审核」。
2. **输出必须保留风险说明**：每条改写附 `rewrite_note`，说明调整了什么、为什么更安全；禁止伪装原文未改动。
3. **红线维度禁改写**：政治敏感/法律合规/民族宗教/事实错误/平台禁区 五类，仅返回「该内容建议不予发布」，`rewrites` 为空。
4. **转写噪声分支保留**：`is_transcript_noise=true` 时不改写，仅提示核实原文。

**变更文件**：

- `src/backend/prompts/rewrite.txt`：全文重写（33 行 → 约 50 行）
- `src/backend/services/rewriter.py`：
  - 新增 `REDLINE_DIMENSIONS` 常量（对齐 `risk_assessment_v2.txt` 红线标准）
  - 红线维度直接返回 `is_redline=true` + `redline_note`，不调用 LLM
  - 新增 `_normalize_rewrites()`：统一 `rewrites` 为 `[{text, rewrite_note}]`，兼容旧字符串列表
- `src/backend/routes.py`（get_review_result suggestions 解析）：
  - 支持新格式 `rewrites` 对象列表
  - 红线项输出 `is_redline=true` + `redline_note` 作为 suggestion
  - 保留 `rewrite_note` 字段随报告返回

**绕审表述核查**：

对 `rewrite.txt` 全文 grep「不能让人感觉|仅消除风险触发点|规避审核|绕过审核|洗稿|不让人感觉」，唯一命中为第 31 行红线提示：

```text
"redline_note": "该内容触及红线维度，建议不予发布。改写建议不适用于规避审核用途。",
```

该句为**禁止性表述**（明确不适用于规避审核），符合合规要求，非绕审目标函数。

**输出格式（新）**：

```json
{
  "original": "原句文本",
  "is_transcript_noise": false,
  "is_redline": false,
  "rewrites": [
    { "text": "表达优化版本1", "rewrite_note": "说明：调整了哪些表达、为什么这样更安全" }
  ]
}
```

红线维度：

```json
{
  "is_redline": true,
  "redline_note": "该内容触及红线维度，建议不予发布。改写建议不适用于规避审核用途。",
  "rewrites": []
}
```

### 3.2 B5 topic_recommender 接入 API

**问题定性**（差距分析 P1-2）：`TopicRecommender` 类完整实现（LLM+规则+风险预筛），但无任何路由引用，Idea 2「选题推荐」完全不可达。

**整改**：在 `routes_v3.py` 新增端点：

```
POST /api/v3/blogger/topics/recommend
```

**请求体**：

```json
{
  "blogger_profile": { "topics": {"primary_topics": ["美妆", "生活"]}, "expression": {"tone": "轻松"}, "risk": {"risk_tolerance": "moderate"} },
  "hot_topics": [{"title": "热点标题", "platform": "weibo", "strength": 80}],
  "blogger_id": "blogger_001",
  "blogger_name": "示例博主"
}
```

- `hot_topics` 可选；缺省时自动从信号系统 `SignalRecord` 取热度 Top20。
- `blogger_profile` 影响风格匹配与风险容忍度。

**响应体**：

```json
{
  "blogger_id": "blogger_001",
  "blogger_name": "示例博主",
  "hot_topics_used": 12,
  "summary": "推荐总结",
  "error": null,
  "recommendations": [
    {
      "topic": "选题标题",
      "angle": "独特切入点",
      "reason": "推荐理由",
      "trend_score": 0.85,
      "style_match": 0.72,
      "risk_level": "safe",
      "risk_note": "",
      "estimated_reach": "中等",
      "priority": 4
    }
  ]
}
```

**调用示例（curl）**：

```bash
curl -X POST "http://localhost:8000/api/v3/blogger/topics/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "blogger_profile": {"topics": {"primary_topics": ["数码测评"]}, "expression": {"tone": "专业"}, "risk": {"risk_tolerance": "moderate"}},
    "blogger_id": "demo_001",
    "blogger_name": "数码博主"
  }'
```

**调用示例（Python）**：

```python
import requests

resp = requests.post("http://localhost:8000/api/v3/blogger/topics/recommend", json={
    "blogger_profile": {
        "topics": {"primary_topics": ["数码测评"]},
        "expression": {"tone": "专业"},
        "risk": {"risk_tolerance": "moderate"},
    },
    "blogger_id": "demo_001",
    "blogger_name": "数码博主",
})
for rec in resp.json()["recommendations"]:
    print(rec["topic"], rec["priority"], rec["risk_level"])
```

**能力说明**：LLM 推荐失败时自动降级规则推荐；每个选题经关键词风险预筛（high/medium/low/safe），高风险选题自动降优先级。

> 前端 BloggerProfile 面板接入本次未做（时间盒内优先保证 API 可用），后续可挂到 BloggerProfile 组件。

### 3.3 B6 depth 参数生效

**问题定性**（差距分析 P0-3）：UI 提供 quick/standard/deep/large_scale 四档，`routes.py` 仅存 `Task.depth`，`analyzer.py` 全文无 depth 引用——深度选项纯装饰。

**整改**：depth 从提交 → 分析引擎全链路生效，最小实现三个开关：

| 档位 | Agent 数/平台 | Agent 仿真 | 平台仿真 | 超时 | 预估时长 |
|------|--------------|-----------|---------|------|---------|
| quick | 0（跳过） | ✗ | ✓ | 60s | 60s |
| standard | 5 | ✓ | ✓ | 180s | 180s |
| deep | 15 | ✓ | ✓ | 600s | 600s |
| large_scale | 30 | ✓ | ✓ | 1800s | 1800s |

**变更文件**：

1. `src/backend/services/agent_simulator.py`：
   - 新增 `DEPTH_AGENTS = {"quick": 0, "standard": 5, "deep": 15, "large_scale": 30}`
   - `simulate_platform_with_agents(text, platform, agents_count=None)`：`agents_count<=0` 时返回跳过标记，不生成人格
   - `simulate_all_platforms_with_agents(text, depth="standard")`：按档位取 Agent 数
2. `src/backend/services/analyzer.py`：
   - `run_analysis(task_id, text, depth="standard")` 签名扩展
   - 新增 `depth_config`：控制 `agent_sim`/`platform_sim` 开关与超时
   - quick 档 `_do_agent_sim` 直接返回空列表并记日志
   - 进度广播 detail 带上当前 depth
3. `src/backend/routes.py`：
   - `background_tasks.add_task(run_analysis, task_id, combined_text, depth)`
   - depth 从 `req.options.depth` 读取，默认 standard

**文档同步**：预估时长映射 `_get_estimated_duration` 本就按四档返回（quick 60s / standard 180s / deep 600s / large_scale 1800s），与实现一致。

### 3.4 B7 video_files 路径校验（安全最小补丁）

**问题定性**（审计 R12 / P0-3）：`video_files` 接受任意路径，无目录限制；上传文件名未消毒，存在路径穿越/任意文件读取面。

**整改**：

1. **`_validate_video_path(video_path)`**：
   - 拒绝 null 字节
   - `os.path.realpath` 解析，消除 `../` 与符号链接
   - 必须位于 `src/uploads/` 目录内（`startswith(upload_dir + os.sep)`）
   - 必须是存在的普通文件
   - 不合法返回 `None`，review 端点直接 400

2. **`_sanitize_filename(filename)`**：
   - `os.path.basename` 去掉路径成分
   - 正则 `r'[^\w\u4e00-\u9fff.\-]'` 白名单消毒（保留字母/数字/中文/下划线/连字符/点）
   - 防止空名与 `.`/`..`
   - 截断 120 字符

3. **`_get_upload_dir()`**：统一上传目录获取，消除重复路径拼接。

**变更文件**：`src/backend/routes.py`（新增 3 个安全函数 + review/upload 两端接入）。

**覆盖**：路径穿越（`../../etc/passwd`）✗ 拒绝、绝对路径越权（`C:\Windows\...`）✗ 拒绝、null 字节注入 ✗ 拒绝、危险文件名（`../evil.sh`）✓ 消毒。
