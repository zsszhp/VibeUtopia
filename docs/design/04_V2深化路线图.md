# VibeUtopia 蓝图路线图

## 文档定位
- 本文档在主线中的角色：定义产品各阶段目标、交付物、Go/No-Go规则和验收标准
- 与"发前风控优先"的关系：每个阶段必须回答"是否提升风控准确率"

## 本文档边界
- 本文档负责：阶段划分、交付物、验收标准、Go/No-Go规则、依赖关系
- 本文档不负责：功能需求细节（见`01_产品需求文档(PRD).md`）、技术架构细节（见`02_系统架构设计.md`）

## 对准确率的直接贡献
- 机制1：每阶段有明确的准确率提升目标，确保演进方向不偏离
- 机制2：Go/No-Go规则确保每个阶段的投入有可验证的产出
- 验证方式：回测对比、人工复检、一致性检查

## 阶段1：回归核心 — 单入口串联

> **目标**：将入口收敛为1个，核心流程跑通，建立回测案例库并测出准确率基线
>
> **Go/No-Go**：3个测试案例风险等级正确率≥2/3，且 docker-compose up ≤10分钟跑通 → 继续；否则继续修核心流程

### 交付物

- [x] Vue3 + Naive UI 暗色主题前端，单入口"内容预审工作台"
- [x] 完全废弃Streamlit前端
- [x] 三种输入模式：仅视频 / 仅文案 / 混合输入
- [x] 核心流程串联：上传→视频理解→文案理解→舆论推演→风险报告
- [x] **建立回测案例库（40+真实历史案例）**，为全阶段提供准确率验证基准
- [x] 后台模块自动串联，用户无感
- [x] 移除多余用户入口和页面
- [x] 移除PaddleOCR/PaddlePaddle本地依赖，改用API或本地GLM-OCR
- [x] 移除yt-dlp（仅支持本地视频）
- [x] 移除Redis依赖

### 验收标准（量化版）

1. 3个测试案例（高/中/低风险各1个）报告风险等级正确率 ≥ 2/3
2. 开发者在新机器使用 `docker-compose up` 到跑通流程 ≤ 10分钟
3. 用回测案例库（20+案例）跑出第一版准确率基线（不设要求，仅记录）
4. 报告包含7维风险评级+证据链+改写建议

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 前端重构工作量大 | 中 | 优先核心流程，可视化渐进增强 |
| 移除依赖导致功能回退 | 低 | API替代方案提前验证 |

## 阶段2：深度打磨

> **目标**：不急于铺开平台，而是将5大核心平台做深做透，引入平台权重体系，建立Prompt版本管理
>
> **Go/No-Go**：回测案例库命中率≥60%，且P0平台影响占比≥70% → 继续；否则继续打磨单平台

### 交付物

- [x] P0核心平台深度覆盖：微博、B站、小红书、抖音、知乎（共5个平台）
- [x] 原型扩展：每平台原型从6个扩展到20+个（覆盖主流/争议/极端/边缘/跨界群体）
- [x] 平台权重体系引入：不同平台的结果按权重（P0=1.0）影响总风险分
- [x] 每个平台：人格模板 + prompt模板 + 模拟器 + 传播特征
- [x] Prompt版本管理机制：支持 A/B Test 对比不同 Prompt 效果

### 验收标准（量化版）

1. 5个核心平台每平台拥有 ≥ 20 个具备差异化的人格原型
2. 回测案例库（20+案例）的风险等级命中率 ≥ 60%
3. 同一测试案例在不同平台预测出的情绪有明显可辨识的差异
4. P0平台（权重1.0）的评估结果在总分中占比 ≥ 70%

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 平台特性差异大，模拟器难统一 | 中 | 统一PlatformAction接口+平台特化适配 |
| 原型设计工作量大 | 中 | 参考CGSS人口统计+LLM辅助生成 |

## 阶段3：模型优化 + 人生故事生成

> **目标**：接入最新多模态API，引入人生故事驱动人格系统，让Agent更真实；向 P1 平台渐进扩展
>
> **Go/No-Go**：A/B回测对比，人生故事Agent命中率提升≥15%，且ChromaDB延迟≤100ms → 继续；否则保留属性Agent

### 交付物

- [x] 接入最新多模态API（Qwen3-VL-Plus / GLM-4V / DeepSeek-V3）
- [x] 接入阿里Paraformer API（音频转写主力）
- [x] 模型路由策略：按任务类型自动选模型+硬件自适应
- [x] **人生故事驱动人格系统**：
  - AI访谈生成器（A-tier Agent，6轮结构化访谈→数万字人生故事）
  - 人口统计采样+LLM丰富（B-tier Agent）
  - 模板变体+递增扩展（C-tier Agent）
  - 人生故事→Memory Stream记忆条目转化
  - ChromaDB向量检索接入（替代Milvus）
  - 人格完善性自动验证流水线（7维度+Big Five一致性）
- [x] 报告质量优化：更可操作的风险标注和修改建议

### 验收标准（量化版）

1. A/B 回测证明：人生故事驱动的Agent 比 属性标签Agent 的命中率提升 ≥ 15%
2. 人工抽样评审人生故事质量评分 ≥ 7/10
3. ChromaDB 检索延迟 ≤ 100ms（在1000+记忆条目下）
4. 多模态API在 画面理解、OCR、音频转写 测试各1个案例完全正确

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 人生故事生成成本高 | 中 | A-tier仅用于1-2%核心Agent |
| API模型版本更新频繁 | 低 | 模型路由支持配置化切换 |

- [x] 历史报告对比

1. Big Five 性格量表重复测试 r > 0.7

4. 总体回测案例命中率 ≥ 75%（较上阶段继续提升）

## V3.4：细粒度视频理解

> **目标**：解决视频中短暂画面（十几帧）和小区域细节的检测与理解问题，堵住"几帧定生死"的风控漏洞
>
> **Go/No-Go**：细粒度案例库（20+案例）短暂画面检出率≥85%，地图完整性审核召回率≥90%，增量耗时≤30秒/10分钟视频 → 继续；否则降级为仅地图审核

### 背景

现有视频理解管线存在三大盲区：
1. **短暂画面漏检**：地图画面仅出现3-5秒，均匀采样30秒一帧时漏检率~70%
2. **小区域细节丢失**：台湾缺失仅占画面1-2%，文件夹名仅占0.5%，VLM整帧处理时信息严重压缩
3. **语义关联缺失**：文件夹名"ByteTrack"与GitHub开源项目的关联，VLM缺乏代码溯源知识

典型塌房案例：
- 博主放地图时缺失台湾，地图仅出现几帧，整个地图也只占画面一小部分
- 何同学展示代码文件夹画面仅几帧，被观众发现是GitHub开源项目，卷入抄袭风波

### 技术可行性

| 问题 | 可行性 | 核心方案 |
|------|--------|---------|
| 短暂画面漏检 | ✅ 可行 | 密集帧扫描(1fps)+帧差异异常检测 |
| 小区域细节丢失 | ✅ 可行 | 区域检测+裁剪放大(4-5x)+细粒度OCR/VLM |
| 地图完整性审核 | ✅ 可行 | VLM+地理知识库比对(台湾/南海诸岛等) |
| 代码/文件夹溯源 | ⚠️ 部分可行 | OCR+GitHub Search API，受OCR准确率限制 |
| 敏感符号检测 | ✅ 可行 | YOLOv8区域检测+VLM细审 |

### 交付物

- [ ] **密集帧扫描器**：1fps全量抽帧+帧差异评分+异常帧筛选，确保短暂画面不被遗漏
- [ ] **区域放大分析器**：文字/地图/代码/符号四类区域检测+裁剪放大+细粒度分析
- [ ] **地图完整性审核器**：OCR+VLM+地理知识库比对，检测地图缺失关键区域
- [ ] **代码溯源检测器**：OCR+GitHub Search API，检测视频中的代码是否来自开源项目
- [ ] **敏感符号检测器**：YOLOv8区域检测+VLM细审，检测争议性标志/旗帜/手势
- [ ] **细粒度风险补充报告**：与现有多模态报告融合，新增地图审核+代码溯源+敏感符号+时序异常
- [ ] **细粒度风险案例库**：20+真实案例（含地图缺失、代码暴露、敏感符号等），用于验收测试

### 验收标准（量化版）

1. 短暂画面检出率（3-5秒画面）≥ 85%
2. 小区域文字识别率（画面占比<5%的文字）≥ 80%
3. 地图完整性审核召回率 ≥ 90%
4. 代码溯源检出率 ≥ 60%
5. 敏感符号检测召回率 ≥ 85%
6. 细粒度分析增量耗时 ≤ 30秒/10分钟视频
7. 细粒度分析增量成本 ≤ ¥2/视频（Lite模式）

### 主要风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| 密集帧扫描VLM调用成本高 | 中 | 帧差异预筛选，仅5-15%帧需VLM分析 |
| 区域放大后OCR准确率仍不足 | 中 | 超分辨率增强+多次OCR取交集 |
| GitHub Search API限流 | 中 | 本地代码库索引+批量查询缓存 |
| 地图分类器误判 | 低 | VLM二次确认+低置信度标注 |

## 仿真启用与保留条件

- **启用条件**：静态评估达到风险阈值或用户主动选择深度分析
- **保留条件**：仿真相对静态评估在回测中带来稳定准确率提升
- **降级条件**：若提升不稳定，保留热点关联与实体风险链，减少仿真成本

## 关键流程/结构

- 输入：前一阶段完成的交付物和验收结果
- 处理：按阶段目标开发→验收→Go/No-Go决策
- 输出：通过验收的阶段交付物

## 依赖与降级

- 依赖：多模态API可用性、LLM API可用性、硬件条件
- 失败降级策略：每个阶段有明确的No-Go处理方案，不会因某个阶段失败导致整体停滞

## 验收标准

- 指标：各阶段验收标准见上文
- 阈值：Go/No-Go条件中定义
- 通过条件：所有验收标准达标+Go/No-Go决策通过
