# VibeUtopia 人格工厂与记忆系统设计

## 文档定位
- 本文档在主线中的角色：定义后端人格生成与记忆管理能力——7层人格工厂、Life Story驱动、Memory Stream架构、知识图谱引擎、社会关系网络。这是一个**后端能力层**，无用户入口，仅被仿真引擎和分析模块内部调用
- 与"发前风控优先"的关系：人格工厂为仿真引擎提供高质量的Agent，记忆系统确保Agent行为有上下文、有连贯性。这些能力越强，仿真结果越可信，风控准确率越高。但用户永远只走"提交内容→获取报告"主链路

## 本文档边界
- 本文档负责：7层人格结构定义、Life Story驱动的人格生成（A/B/C三级）、Memory Stream架构（Stanford Generative Agents）、存储架构（MySQL + ChromaDB + 文件系统 + Neo4j）、知识图谱引擎（Neo4j）、社会关系网络生成器、人格一致性校验、平台沉浸概念
- 本文档不负责：仿真引擎内部实现（见`08_仿真运行层设计.md`）、风险评估逻辑（见`09_分析决策层设计.md`）、信号采集实现（见`06_信号采集层设计.md`）、仿真增强机制（见`10_仿真增强风控设计.md`）、前端展示（见`13_前端升级设计.md`）

## 对准确率的直接贡献
- 机制1：7层人格结构 + Life Story驱动确保Agent有真实的人生经历和内在一致性，使仿真中的Agent行为更接近真人反应，从而提升仿真预测的可信度
- 机制2：Memory Stream的三因子检索（Recency + Importance + Relevance）+ Reflection机制确保Agent在仿真中基于记忆做出连贯决策，而非无状态反应，减少仿真随机性
- 机制3：知识图谱为社会关系网络提供实体和因果链基础，使Agent的知识背景（L3）与现实世界信息对齐，减少"无知Agent"导致的仿真偏差
- 验证方式：人格一致性校验通过率（7维度 + Big Five一致性）、回测中Agent行为与真实舆论反应的方向一致性

## 关键流程/结构
- 输入：种子事件（来自信号采集层）、CGSS人口统计数据、知识图谱实体
- 处理：Life Story生成（A/B/C三级）→ 7层人格填充 → 一致性校验 → Memory Stream初始化 → 社会关系网络生成 → 平台沉浸（Agent吸收热点）
- 输出：完整的AgentProfile（含7层人格 + Life Story + Memory Stream + 社会关系），供仿真引擎调度

## 依赖与降级
- 依赖：LLM API（A-tier访谈生成需要高质量模型）、ChromaDB（内嵌式，零部署）、MySQL（人格持久化）、Neo4j（知识图谱+社会关系，Lite模式可跳过）
- 失败降级策略：Neo4j不可用时跳过知识图谱注入和社会关系图，Agent仍可基于L1-L5运行；LLM API降级时从A-tier访谈降级到B-tier采样填充或C-tier模板变体；ChromaDB不可用时Memory Stream降级为MySQL全文检索

## 验收标准
- 指标：人格一致性校验通过率、A-tier生成完整Life Story的字数/轮数、Memory Stream检索准确率
- 阈值：人格一致性校验通过率>85%；A-tier生成6轮访谈，每轮产出2000+字；Memory Stream三因子检索Top-5命中率>70%
- 通过条件：100个Agent样本中，85%以上通过7维度+Big Five一致性校验；Memory Stream在三因子加权下检索结果与人工标注相关性>0.7

## 1. 核心定位：后端能力层

人格工厂与记忆系统不是一个独立产品、独立入口、独立流程。它是仿真引擎的后端能力支撑，仅在仿真运行层需要创建Agent时被调用。用户永远不直接与人格工厂交互。

```
主链路（用户可见）:
  用户提交内容 → 内容理解 → 风险评估 → 报告输出

后台能力（系统自动调用，无用户入口）:
  ┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
  │  信号采集层   │────▶│  人格工厂与记忆系统 │────▶│  仿真引擎     │
  │  (种子事件)   │     │  (Agent生成)      │     │  (Agent调度)  │
  └──────────────┘     └──────────────────┘     └──────────────┘
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
              ┌─────────┐ ┌──────┐ ┌──────────┐
              │7层人格   │ │Life  │ │Memory    │
              │(L1-L7)  │ │Story │ │Stream    │
              └─────────┘ └──────┘ └──────────┘
```

设计原则：
- **人格先行**：7层人格结构从稳定到动态逐层构建，是本项目的核心差异化优势
- **Life Story驱动**：用人生故事而非属性列表驱动Agent行为，确保深度和连贯性
- **记忆分级**：Memory Stream + 语义记忆双层架构，不同生命周期的记忆存储在不同介质
- **内部机制**：人格动态演化和世界状态管理是内部机制，不是产品叙事

### 2.2 A-tier: AI访谈生成器

A-tier是人格工厂的旗舰能力。通过6轮结构化AI访谈，为每个核心Agent生成数万字的完整人生故事。

```python
class LifeStoryInterviewer:
    """A-tier AI访谈生成器 - 6轮结构化访谈"""

    ROUNDS = [
        {
            "round": 1,
            "theme": "身份与成长",
            "questions": [
                "请描述你从哪里来，你的家庭背景是什么样的？",
                "你的童年和少年时代有什么塑造性经历？",
                "你是如何走到今天这个位置的？",
            ],
            "target_words": 2000,
        },
        {
            "round": 2,
            "theme": "价值观与信仰",
            "questions": [
                "什么事情是你绝对不能妥协的？为什么？",
                "你如何看待公平和正义？",
                "有没有什么经历彻底改变了你的世界观？",
            ],
            "target_words": 2000,
        },
        {
            "round": 3,
            "theme": "社会立场与态度",
            "questions": [
                "你对当前社会的最大担忧是什么？",
                "哪些社会议题最能引发你的强烈反应？",
                "你觉得自己属于哪个'阵营'？为什么？",
            ],
            "target_words": 2000,
        },
        {
            "round": 4,
            "theme": "知识与信息世界",
            "questions": [
                "你平时通过什么渠道获取信息？为什么信任这些来源？",
                "有哪些话题你觉得自己了解很深？有哪些你承认不了解？",
                "你最近学到的最重要的新知识是什么？",
            ],
            "target_words": 2000,
        },
        {
            "round": 5,
            "theme": "社交与关系",
            "questions": [
                "你的社交圈子是什么样的？你最看重朋友什么品质？",
                "你在网上和现实中是同一个人吗？有什么不同？",
                "有没有什么人际关系深刻影响了你？",
            ],
            "target_words": 2000,
        },
        {
            "round": 6,
            "theme": "日常与未来",
            "questions": [
                "描述你典型的一天。什么时候最开心？什么时候最焦虑？",
                "你对未来有什么期待和担忧？",
                "如果有人要写你的故事，你希望他们记住什么？",
            ],
            "target_words": 2000,
        },
    ]

    async def conduct_interview(self, archetype: str,
                                 seed_event: str) -> LifeStory:
        """执行6轮访谈，生成完整人生故事"""

        story_parts = []
        context = f"你是一个{archetype}类型的人。请以第一人称回答。"

        for round_config in self.ROUNDS:
            # 每轮基于前几轮的回答深入追问
            response = await self.llm.chat(
                model=self.tier1_model,
                messages=[
                    {"role": "system", "content": context},
                    {"role": "user", "content": self._build_round_prompt(
                        round_config, story_parts, seed_event
                    )}
                ]
            )
            story_parts.append({
                "round": round_config["round"],
                "theme": round_config["theme"],
                "content": response.content,
                "word_count": len(response.content),
            })
            # 追加到上下文，后续轮次可引用
            context += f"\n\n第{round_config['round']}轮回答：{response.content[:500]}..."

        return LifeStory(
            archetype=archetype,
            rounds=story_parts,
            total_words=sum(p["word_count"] for p in story_parts),
        )
```

### 2.3 B-tier: 人口采样 + LLM丰富

```python
class CGSSSampler:
    """B-tier: CGSS人口统计数据采样 + LLM丰富"""

    async def sample_and_enrich(self, num_agents: int,
                                 seed_event: str) -> List[AgentProfile]:
        """从CGSS数据采样基础属性，LLM丰富其余层级"""

        profiles = []
        for _ in range(num_agents):
            # Step 1: 从CGSS分布中采样L1基础属性
            l1 = self._sample_from_cgss()  # 年龄/性别/收入/教育/职业/地域

            # Step 2: LLM推理L2-L5（基于L1 + 社会常识）
            l2_through_l5 = await self.llm.enrich_persona(
                basic_attributes=l1,
                seed_event=seed_event,
            )

            # Step 3: 生成精简Life Story（1000-2000字）
            story = await self.llm.generate_brief_story(
                l1=l1, l2_l5=l2_through_l5
            )

            profiles.append(AgentProfile(
                tier="B",
                layer1=l1,
                **l2_through_l5,
                life_story=story,
            ))

        return profiles

    def _sample_from_cgss(self) -> Layer1Basic:
        """从CGSS统计分布中采样"""
        # 年龄：正态分布(μ=35, σ=12)
        # 性别：0.48男/0.52女（CGSS 2021）
        # 收入：按地区分层的对数正态分布
        # 教育：按年龄组分层的分类分布
        # 职业：按教育+地区条件概率
        # 地域：按城市化率加权
```

### 2.5 Life Story → Memory Stream 转换

Life Story生成后，需要将其分解为Memory Stream的初始条目，使Agent在仿真开始时已拥有"过去的记忆"。

```python
class StoryToMemoryConverter:
    """将Life Story转换为Memory Stream初始条目"""

    async def convert(self, life_story: LifeStory) -> List[MemoryEntry]:
        """将人生故事拆解为记忆条目"""

        entries = []

        # 1. 从每轮访谈中提取关键事件
        for round_data in life_story.rounds:
            key_events = await self.llm.extract_key_events(
                round_data["content"]
            )
            for event in key_events:
                entries.append(MemoryEntry(
                    memory_type="observation",
                    content=event.description,
                    importance=self._assess_importance(event),
                    timestamp=event.estimated_time,
                    embedding=await self.embed(event.description),
                ))

        # 2. 从价值观描述中生成reflection条目
        reflections = await self.llm.extract_reflections(life_story)
        for reflection in reflections:
            entries.append(MemoryEntry(
                memory_type="reflection",
                content=reflection.content,
                importance=0.7,  # 反思类记忆重要性较高
                timestamp=reflection.estimated_time,
                embedding=await self.embed(reflection.content),
            ))

        # 3. 从日常描述中生成plan条目
        plans = await self.llm.extract_routine_plans(life_story)
        for plan in plans:
            entries.append(MemoryEntry(
                memory_type="plan",
                content=plan.content,
                importance=0.3,  # 日常计划重要性较低
                timestamp=plan.estimated_time,
                embedding=await self.embed(plan.content),
            ))

        return entries
```

### 2.6 人格完整性校验

生成的人格必须通过7维度一致性校验 + Big Five人格特质一致性校验：

```python
class PersonaValidator:
    """人格完整性校验器"""

    DIMENSIONS = [
        "demographic_consistency",    # L1内部一致：年龄+教育+职业+收入是否合理
        "value_coherence",           # L2内部一致：价值观之间是否矛盾
        "knowledge_plausibility",    # L3合理性：知识背景是否与职业/教育匹配
        "behavior_alignment",        # L4与L2对齐：行为模式是否与价值观一致
        "constraint_coherence",      # L5与L4对齐：自我约束是否与行为模式兼容
        "social_plausibility",       # L6合理性：社会关系是否与身份匹配
        "story_persona_alignment",   # Life Story与7层人格是否一致
    ]

    async def validate(self, profile: AgentProfile) -> ValidationResult:
        """7维度 + Big Five一致性校验"""

        # 1. 7维度校验
        dimension_scores = {}
        for dim in self.DIMENSIONS:
            score = await self._check_dimension(profile, dim)
            dimension_scores[dim] = score

        # 2. Big Five一致性校验
        # 从Life Story中推断Big Five分数
        inferred_big5 = await self._infer_big5_from_story(profile.life_story)
        # 从L2价值观中推断Big Five分数
        declared_big5 = await self._infer_big5_from_values(profile.layer2_values)
        # 两者相关系数应>0.6
        big5_consistency = self._correlation(inferred_big5, declared_big5)

        overall_pass = (
            all(s >= 0.7 for s in dimension_scores.values())
            and big5_consistency >= 0.6
        )

        return ValidationResult(
            dimension_scores=dimension_scores,
            big5_consistency=big5_consistency,
            overall_pass=overall_pass,
```

## 4. Memory Stream 架构

### 4.1 设计理念

基于Stanford Generative Agents论文的Memory Stream架构，为每个Agent提供连贯的记忆检索能力。Memory Stream是Agent行为的"上下文引擎"——Agent每次做决策时，从Memory Stream中检索最相关的记忆，确保行为有连贯性。

### 4.2 三因子检索

```
┌──────────────────────────────────────────────────────────┐
│              Memory Stream 三因子检索                       │
│                                                           │
│  输入: 查询上下文 (当前感知到的事件/内容)                   │
│                                                           │
│  因子1: Recency (近期性) — 权重0.5                         │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 最近访问的记忆权重更高                              │  │
│  │ score = e^(-0.005 × hours_since_last_access)       │  │
│  │ 刚访问的记忆: score ≈ 1.0                          │  │
│  │ 24小时前的记忆: score ≈ 0.89                       │  │
│  │ 7天前的记忆: score ≈ 0.43                          │  │
│  └────────────────────────────────────────────────────┘  │
│                                                           │
│  因子2: Importance (重要性) — 权重0.3                      │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 每条记忆创建时由LLM评估重要性(1-10)                 │  │
│  │ 日常琐事: 1-3                                     │  │
│  │ 社交互动: 4-6                                     │  │
│  │ 重大事件/态度转变: 7-10                            │  │
│  │ score = importance / 10.0                          │  │
│  └────────────────────────────────────────────────────┘  │
│                                                           │
│  因子3: Relevance (相关性) — 权重0.2                       │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 查询与记忆的语义相似度                              │  │
│  │ 通过ChromaDB向量检索实现                           │  │
│  │ score = cosine_similarity(query_embedding, memory)  │  │
│  └────────────────────────────────────────────────────┘  │
│                                                           │
│  综合得分 = 0.5×Recency + 0.3×Importance + 0.2×Relevance  │
│  返回: Top-K 条目 (默认K=10)                               │
└──────────────────────────────────────────────────────────┘
```

### 4.3 记忆类型

| 记忆类型 | 说明 | 来源 | 重要性范围 | 示例 |
|----------|------|------|-----------|------|
| observation | 对外部事件的观察 | 仿真中感知到的事件 | 1-8 | "看到大VXX发表了关于YY的帖子" |
| reflection | 对过往记忆的反思总结 | Reflection机制触发时生成 | 5-10 | "我发现自己对政策问题越来越敏感" |
| plan | 行为计划 | Agent自主规划或响应事件 | 2-6 | "明天要发一篇关于XX的深度分析" |

### 4.4 Reflection 机制

当Agent累积的observation记忆的重要性之和超过阈值时，触发Reflection——Agent回顾最近的记忆，生成更高层次的洞察。

```python
class ReflectionTrigger:
    """Reflection触发机制"""

    IMPORTANCE_THRESHOLD = 10  # 累积重要性阈值

    def should_reflect(self, agent_id: str) -> bool:
        """判断是否触发Reflection"""
        # 获取最近未反射过的observation记忆
        recent_obs = self.memory_store.get_recent_unreflected(agent_id)
        cumulative_importance = sum(obs.importance for obs in recent_obs)

        return cumulative_importance >= self.IMPORTANCE_THRESHOLD

    async def execute_reflection(self, agent_id: str) -> List[MemoryEntry]:
        """执行Reflection，生成新的反思记忆"""

        # 1. 获取触发Reflection的记忆集合
        recent_memories = self.memory_store.get_recent_unreflected(agent_id)

        # 2. LLM生成反思问题
        questions = await self.llm.generate_reflection_questions(recent_memories)

        # 3. 对每个问题，检索相关记忆并生成反思
        reflections = []
        for question in questions:
            related = await self.memory_retriever.retrieve(
                agent_id, question, top_k=5
            )
            reflection_text = await self.llm.reflect(question, related)

            reflections.append(MemoryEntry(
                memory_type="reflection",
                content=reflection_text,
                importance=await self.llm.assess_importance(reflection_text),
                embedding=await self.embed(reflection_text),
            ))

        return reflections
```

### 4.5 Memory Stream 存储实现

```python
class MemoryStreamStore:
    """Memory Stream存储 - ChromaDB + MySQL"""

    def __init__(self, chroma_client, mysql_pool):
        self.chroma = chroma_client
        self.mysql = mysql_pool

    async def add_entry(self, agent_id: str, entry: MemoryEntry):
        """添加记忆条目"""
        # ChromaDB: 存储向量，用于Relevance检索
        collection = self.chroma.get_or_create_collection(
            name=f"agent_{agent_id}_memory",
            metadata={"hnsw:space": "cosine"}
        )
        collection.add(
            ids=[entry.entry_id],
            embeddings=[entry.embedding],
            documents=[entry.content],
            metadatas=[{
                "type": entry.memory_type,
                "importance": entry.importance,
                "created_at": entry.timestamp.isoformat(),
                "last_accessed": entry.timestamp.isoformat(),
            }]
        )

        # MySQL: 存储完整元数据，用于Recency和Importance排序
        async with self.mysql.acquire() as conn:
            await conn.execute(
                """INSERT INTO memory_entries
                   (entry_id, agent_id, type, content, importance,
                    created_at, last_accessed)
                   VALUES (?, ?, ?, ?, ?, ?, ?)""",
                (entry.entry_id, agent_id, entry.memory_type,
                 entry.content, entry.importance,
                 entry.timestamp, entry.timestamp)
            )

    async def retrieve(self, agent_id: str, query: str,
                        top_k: int = 10) -> List[MemoryEntry]:
        """三因子检索"""
        query_embedding = await self.embed(query)

        # 1. ChromaDB向量检索 (Relevance)
        collection = self.chroma.get_collection(f"agent_{agent_id}_memory")
        vector_results = collection.query(
            query_embeddings=[query_embedding],
            n_results=top_k * 3,  # 多取一些，后续重排
        )

        # 2. 获取候选记忆的完整信息
        candidate_ids = vector_results["ids"][0]
        candidates = await self._load_entries(agent_id, candidate_ids)

        # 3. 三因子评分 + 重排
        now = datetime.now()
        scored = []
        for entry, relevance in zip(candidates, vector_results["distances"][0]):
            recency = math.exp(-0.005 * (now - entry.last_accessed).total_seconds() / 3600)
            importance = entry.importance / 10.0
            total = 0.5 * recency + 0.3 * importance + 0.2 * relevance
            scored.append((entry, total))

        scored.sort(key=lambda x: x[1], reverse=True)

        # 4. 更新last_accessed (Recency衰减依赖此字段)
        for entry, _ in scored[:top_k]:
            await self._update_last_accessed(entry.entry_id, now)

        return [entry for entry, _ in scored[:top_k]]
```

### 5.2 本体生成器

LLM分析种子文档，生成图的本体定义（实体类型+关系类型）：

```python
class OntologyGenerator:
    """本体生成器 - LLM分析文档生成图谱本体"""

    PROMPT_TEMPLATE = """

            {{
                "name": "Person",

                "name": "INFLUENCES",
```

```python
class EntityExtractor:
    """实体关系抽取器"""

    def __init__(self, llm_client, ner_model=None):
        self.llm = llm_client
        self.ner = ner_model  # 可选的NER模型，用于预标注

    async def extract_from_document(self, document: str,
                                     ontology: GraphOntology,
                                     chunk_size: int = 2000) -> ExtractionResult:
        """从文档中抽取实体和关系"""
        chunks = self._split_document(document, chunk_size)
        all_entities = []
        all_relations = []

        # 并行处理文档块
        tasks = [self._extract_from_chunk(chunk, ontology) for chunk in chunks]
        results = await asyncio.gather(*tasks)

        for entities, relations in results:
            all_entities.extend(entities)
            all_relations.extend(relations)

        # 去重合并
        merged_entities = self._merge_entities(all_entities)
        merged_relations = self._merge_relations(all_relations)

        return ExtractionResult(entities=merged_entities, relations=merged_relations)

    async def _extract_from_chunk(self, chunk: str, ontology: GraphOntology):
        """LLM从单个文档块抽取实体和关系"""
```

## 6. 社会关系网络生成器

### 6.1 关系类型定义

| 关系类型 | 方向 | 生成依据 | 示例 |
|----------|------|----------|------|
| 关注 (FOLLOWS) | 单向 | 属性相似度+影响力 | 普通用户关注大V |
| 互关 (MUTUAL_FOLLOW) | 双向 | 亲密关系+属性相似 | 朋友/同事 |
| 同社群 (SAME_COMMUNITY) | 无向 | 兴趣/地域/职业 | "科技圈""养猫群" |
| 价值观同盟 (ALLIED) | 无向 | 立场一致 | 同一议题的支持者 |
| 对立关系 (OPPOSED) | 无向 | 立场对立 | 性别议题的对立双方 |

### 6.2 网络生成算法

```
┌──────────────────────────────────────────────────────┐
│              社会关系网络生成4步算法                     │
│                                                       │
│  Step 1: 基于属性的相似度计算                           │
│  ┌────────────────────────────────────────────────┐  │
│  │ 计算Agent间的多维相似度：                        │  │
│  │ - 地域相似度 (同城市=1, 同省=0.7, 同国=0.3)     │  │
│  │ - 职业相似度 (同行业=1, 相关行业=0.5)            │  │
│  │ - 年龄相似度 (差5岁内=1, 差10岁=0.5)            │  │
│  │ - 价值观相似度 (立场一致性)                       │  │
│  │ - 兴趣重叠度 (话题交集)                          │  │
│  │                                                │  │
│  │ 综合相似度 = 加权平均 → 关注概率                │  │
│  │ 相似度>0.6 → 50%概率关注                        │  │
│  │ 相似度0.3-0.6 → 10%概率关注                     │  │
│  │ 相似度<0.3 → 1%概率关注(偶然发现)               │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 2: 小世界网络结构                                │
│  ┌────────────────────────────────────────────────┐  │
│  │ 基于Watts-Strogatz模型：                        │  │
│  │ - 高聚类系数：同社区的人互相连接                  │  │
│  │ - 短路径长度：通过少数"桥梁"可到达任何人          │  │
│  │ - 重连概率p=0.1：10%的边随机重连                 │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 3: 幂律分布的影响力                              │
│  ┌────────────────────────────────────────────────┐  │
│  │ 基于Barabási-Albert模型：                       │  │
│  │ - 少数大V：粉丝数占前1%的Agent拥有50%的关注      │  │
│  │ - 中腰部：10%的Agent有中等粉丝                   │  │
│  │ - 长尾：89%的Agent粉丝很少                      │  │
│  │                                                │  │
│  │ 优先连接：新Agent更可能关注已有大量粉丝的Agent    │  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  Step 4: 社群结构                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │ 社区检测算法：                                   │  │
│  │ - Neo4j可用: Louvain算法社区检测                 │  │
│  │ - Neo4j不可用: 基于属性聚类的简单分组            │  │
│  │ 兴趣圈："科技圈""追星族""养宠圈"等               │  │
│  │ 立场圈："女权圈""男权圈""自由派""保守派"         │  │
│  │ 地域圈："北上广""川渝""东北"                     │  │
│  │ 跨圈桥梁：少数Agent同时属于多个社群              │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
```

### 6.3 影响力分配

```python
class InfluenceDistributor:
    """影响力分配器 - 幂律分布"""

    def distribute(self, num_agents: int) -> List[float]:
        """
        分配影响力值(0-1)，遵循幂律分布：
        - 前1% Agent: influence > 0.8 (大V)
        - 前10% Agent: influence 0.3-0.8 (中腰部)
        - 其余89% Agent: influence < 0.3 (普通用户)
        """
        # 使用Pareto分布
        influences = np.random.pareto(a=1.5, size=num_agents)
        # 归一化到0-1
        influences = (influences - influences.min()) / (influences.max() - influences.min())
        return influences.tolist()
```

## 7. 平台沉浸概念

### 7.1 设计理念

Agent在初始化后、正式进入仿真前，需要经历一个"平台沉浸"阶段——模拟真实用户"刷平台"的过程，让Agent吸收当前热点，形成初始态度。这确保Agent不是"白纸"进入仿真，而是带着对当前热点的认知和立场。

### 7.2 平台沉浸流程

```
┌──────────────────────────────────────────────────────────┐
│                  平台沉浸流程                               │
│                                                           │
│  输入: AgentProfile (7层人格 + Memory Stream)              │
│                                                           │
│  Step 1: 浏览热榜                                         │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 从信号采集层获取当前各平台热榜内容                  │  │
│  │ 根据Agent的info_sources(L3)选择性浏览               │  │
│  │ 例: "知乎用户"优先浏览知乎热榜                     │  │
│  └────────────────────┬───────────────────────────────┘  │
│                       ▼                                    │
│  Step 2: 选择性吸收                                       │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 根据人格特征筛选关注的内容:                         │  │
│  │ - 与expertise(L3)相关的内容 → 关注                 │  │
│  │ - 与social_stances(L2)相关的议题 → 形成态度        │  │
│  │ - cognitive_blindspots(L3)内容 → 忽略或浅浏览      │  │
│  │ 每个关注的内容生成一条observation记忆               │  │
│  └────────────────────┬───────────────────────────────┘  │
│                       ▼                                    │
│  Step 3: 形成初始态度                                     │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 对当前热点事件生成初始立场:                         │  │
│  │ LLM基于人格7层 + 浏览到的内容 → 推理初始态度        │  │
│  │ 态度写入Memory Stream (observation类型)             │  │
│  └────────────────────┬───────────────────────────────┘  │
│                       ▼                                    │
│  输出: Agent带着"已知热点"和"初始态度"进入仿真             │
└──────────────────────────────────────────────────────────┘
```

### 7.3 实现

```python
class PlatformImmersion:
    """平台沉浸 - Agent初始化后吸收当前热点"""

    async def immerse(self, agent: AgentProfile,
                       hot_topics: List[HotTopic]) -> ImmersionResult:
        """执行平台沉浸"""

        # 1. 根据Agent信息来源偏好筛选平台
        relevant_topics = self._filter_by_platform_preference(
            hot_topics, agent.layer3_knowledge.info_sources
        )

        # 2. 根据人格特征选择性吸收
        absorbed = []
        for topic in relevant_topics:
            # 评估Agent对此话题的关注概率
            attention_prob = self._calc_attention_probability(agent, topic)
            if random() < attention_prob:
                # 生成observation记忆
                observation = MemoryEntry(
                    memory_type="observation",
                    content=f"看到{topic.platform}上的热点：{topic.title}",
                    importance=self._assess_importance(agent, topic),
                    embedding=await self.embed(topic.title),
                )
                absorbed.append(observation)

        # 3. 对核心热点形成初始态度
        for topic in relevant_topics[:5]:  # 只对Top5热点表态
            stance = await self.llm.infer_initial_stance(
                agent_profile=agent,
                topic=topic,
            )
            stance_observation = MemoryEntry(
                memory_type="observation",
                content=f"对{topic.title}的态度：{stance.attitude}，原因：{stance.reasoning}",
                importance=stance.emotional_intensity * 10,
                embedding=await self.embed(stance.attitude),
            )
            absorbed.append(stance_observation)

        return ImmersionResult(
            agent_id=agent.agent_id,
            absorbed_topics=len(absorbed),
            memory_entries=absorbed,
        )

    def _calc_attention_probability(self, agent: AgentProfile,
                                      topic: HotTopic) -> float:
        """计算Agent对某话题的关注概率"""
        prob = 0.3  # 基础概率

        # 与专业领域相关 → +0.3
        if any(exp in topic.keywords for exp in agent.layer3_knowledge.expertise):
            prob += 0.3

        # 与价值观相关 → +0.2
        if any(stance in topic.tags for stance in agent.layer2_values.social_stances):
            prob += 0.2

        # 高影响力Agent更关注时事 → +0.1
        if agent.layer6_social.influence_level > 0.5:
            prob += 0.1

        return min(prob, 0.95)
```

```python
class PersonaFactoryEventBus:
    """人格工厂内部事件总线 - asyncio.Queue"""

    def __init__(self):
        # 替代Redis Streams的内存消息队列
        self._queues: Dict[str, asyncio.Queue] = {}

    async def publish(self, channel: str, message: dict):
        """发布消息到指定频道"""
        if channel not in self._queues:
            self._queues[channel] = asyncio.Queue(maxsize=10000)
        await self._queues[channel].put(message)

    async def subscribe(self, channel: str) -> AsyncIterator[dict]:
        """订阅指定频道的消息"""
        if channel not in self._queues:
            self._queues[channel] = asyncio.Queue(maxsize=10000)
        while True:
            msg = await self._queues[channel].get()
            yield msg

    # 频道定义
    CHANNELS = {
        "persona.created": "人格创建完成",
        "persona.validated": "人格校验完成（通过/失败）",
        "memory.initialized": "Memory Stream初始化完成",
        "social.generated": "社会关系网络生成完成",
        "immersion.completed": "平台沉浸完成",
```

## 9. 人格动态演化（内部机制）

### 9.1 定位

人格动态演化不是独立的产品功能，而是仿真运行过程中的内部机制。Agent在仿真中经历事件后，其L7动态状态层会更新，极少数情况下L2价值观层可能微调。这些变化通过Memory Stream记录，确保可追溯。

### 9.2 演化触发条件

| 触发类型 | 条件 | 影响层级 | 示例 |
|----------|------|----------|------|
| 重大事件冲击 | 情感强度>0.8的事件 | L7→可能L2 | "目睹XX事件后对XX群体态度转变" |
| 渐进态度偏移 | 多次同类经历累积 | L7 | "连续看到3次XX论点后立场微调" |
| 社交影响 | 关注的人态度变化 | L7→L2 | "关注的大V转反对后自己也开始反对" |
| 信息更新 | 接触新知识 | L3 | "了解到XX事实后修正了认知盲区" |
| 行为习惯调整 | 自我反思 | L4 | "发现深夜发帖总后悔后调整习惯" |

### 9.3 演化约束

```
┌──────────────────────────────────────────────────────┐
│                  人格演化约束                           │
│                                                       │
│  核心原则：人格演化必须渐进且可解释                      │
│                                                       │
│  1. 稳定性约束                                        │
│     L1基础属性: 不变（年龄自然增长除外）                 │
│     L2价值观: 极少变化，需"重大事件冲击"                 │
│     L3知识背景: 偶尔扩展，不会遗忘                      │
│     L4行为模式: 可调整，但不会突变                      │
│     L5纠偏层: 极少变化                                 │
│     L6社会关系: 可增减，每仿真后更新                     │
│     L7动态状态: 频繁更新，每次仿真后                    │
│                                                       │
│  2. 一致性约束                                        │
│     演化后的人格必须通过质量校验                        │
│     不允许出现"自相矛盾"的人格状态                      │
│                                                       │
│  3. 可追溯约束                                        │
│     每次演化记录: 变化内容+触发原因+时间戳               │
│     通过Memory Stream的reflection记忆可回溯             │
│                                                       │
│  4. 幅度约束                                          │
│     单次仿真态度偏移不超过30%                           │
│     避免Agent在短时间内极端转变                         │
└──────────────────────────────────────────────────────┘
```

### 9.4 演化流程

```python
class PersonaEvolver:
    """人格演化器（内部机制，非独立产品）"""

    async def evolve_after_simulation(self, agent_id: str,
                                       simulation_traces: List[SimulationTrace]):
        """仿真后人格演化"""

        # 1. 分析仿真中的关键经历
        key_experiences = self._extract_key_experiences(simulation_traces)

        # 2. 评估对每层的影响
        impacts = await self._assess_impacts(agent_id, key_experiences)

        # 3. 应用演化（受约束）
        for impact in impacts:
            if impact.target_layer == 2 and impact.magnitude > 0.3:
                # L2价值观变化需要重大事件，限制幅度
                impact.magnitude = min(impact.magnitude, 0.3)
            await self._apply_impact(agent_id, impact)

        # 4. 一致性校验
        is_consistent = await self._validate_consistency(agent_id)
        if not is_consistent:
            await self._repair_inconsistency(agent_id)

        # 5. 通过Memory Stream记录演化
        for impact in impacts:
            await self.memory_store.add_entry(agent_id, MemoryEntry(
                memory_type="reflection",
                content=f"因{impact.reason}，我对{impact.topic}的态度从{impact.from_val}变为{impact.to_val}",
                importance=impact.magnitude * 10,
                embedding=await self.embed(impact.description),
            ))
```

```
完整AgentProfile → 供仿真引擎调度
```

### 10.2 记忆检索流程

```
Agent决策时需要记忆上下文
    │
    ▼
Memory Stream三因子检索
    │
    ├── Recency(0.5): 越近期的记忆权重越高
    ├── Importance(0.3): 越重要的记忆权重越高
    └── Relevance(0.2): 与当前上下文越相关权重越高
    │
    ▼
Top-K记忆条目 + 语义记忆(MySQL)
    │
    ▼
Agent基于记忆上下文做决策
```
