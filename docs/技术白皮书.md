## 1. 项目概述

### 1.1 定位

VibeUtopia 是一个**发布前风控与舆论仿真平台**，核心能力是在内容正式发布前，通过 AI 仿真预测其在不同社交平台上的传播路径、舆论反应和潜在风险，帮助创作者和运营团队提前规避翻车。

### 1.2 核心能力链路

```
28+平台信号采集 → 多模态内容理解 → 人格化仿真推演 → 传播动力学建模 → 风险评估 → 决策建议
```

### 1.3 解决的核心问题

| 问题 | 传统方式 | VibeUtopia 方式 |
|------|---------|----------------|
| 内容风险预判 | 人工审核，主观经验 | 七维风险评估 + 证据链 + 置信度 |
| 舆论反应预测 | 发布后观察 | 100-10000 Agent 仿真推演 |
| 传播路径预判 | 无法预测 | 6 阶段传播模型 + 极化预警 |
| 多平台差异 | 统一标准 | 28+平台独立画像 + 5平台深度模拟 |
| 视频隐藏风险 | 抽帧抽查 | 1fps 全量扫描 + 细粒度专项检测 |

## 4. 信号采集系统

### 4.1 设计理念

信号采集系统是平台的"感知器官"，持续监听 28+ 社交平台的热点动态，为风控分析提供实时外部信号。系统采用**调度器驱动的三层流水线**架构，支持 4 种调度模式。

### 4.2 架构设计

```
SignalScheduler（调度中枢，APScheduler AsyncIOScheduler）
    │
    ├── HotlistFetcher（热榜采集层）
    │   └── NewsNow API → 13 个平台并发抓取
    │
    ├── RssFetcher（RSS 补充层）
    │   └── feedparser → 3 个 RSS 源
    │
    ├── IncrementalDetector（增量检测层）
    │   └── 与数据库历史对比 → 新上榜/排名变化/下榜
    │
    ├── EventDetector（事件检测层）
    │   └── Jaccard 聚类 → 信号强度评估 → 因果推理
    │
    ├── KeywordExtractor（关键词提取层）
    │   └── LLM 提取 3-5 个搜索关键词
    │
    ├── DeepCrawler（深度爬取层）
    │   └── ApiCrawler → 5 个平台 API 搜索评论
    │
    └── SentimentAnnotator（情感标注层）
        └── LLM 批量情感分析 → 规则兜底
```

### 4.3 平台覆盖

#### 热榜采集（13 个平台，通过 NewsNow API）

微博、百度、知乎、B站、抖音、今日头条、贴吧、澎湃新闻、华尔街见闻、财联社、凤凰网、快手、小红书

#### RSS 补充源（3 个）

Hacker News、雅虎财经、澎湃新闻

#### 深度爬取（5 个平台，API 直连）

微博、知乎、B站、抖音、小红书

#### 平台权重体系（28 个平台画像）

| 级别 | 权重 | 平台 |
|------|------|------|
| P0 核心 | 1.0 | 微博、B站、小红书、抖音、知乎 |
| P1 次核心 | 0.7 | 快手、贴吧、豆瓣、微信视频号、虎扑、今日头条、TapTap、微信公众号、Twitter/X、Facebook、Instagram、YouTube、Telegram、Reddit |
| P2 长尾 | 0.4 | TikTok 国际版、LinkedIn、NGA、V2EX、脉脉、Boss 直聘、什么值得买、知乎专栏、即刻 |

每个平台画像包含：传播特征（速度/放大系数/茧房强度/极化倾向）、用户特征（规模/年龄/性别/教育）、内容特征（格式/长度/交互类型）、风险敏感度（11 个维度）、情绪基线、文化禁忌、审核严格度、行为模式。

### 4.4 调度模式

| 模式 | 热榜间隔 | RSS 间隔 | 事件检测间隔 | 深度爬取阈值 |
|------|---------|---------|-------------|-------------|
| realtime | 5 分钟 | 30 分钟 | 1 小时 | 0.7 |
| standard | 10 分钟 | 1 小时 | 1 小时 | 0.7 |
| economy | 30 分钟 | 2 小时 | 2 小时 | 0.9 |
| manual | 不自动调度 | 不自动调度 | 不自动调度 | 1.0 |

### 4.5 事件检测算法

1. **信号聚类**：Jaccard 相似度（阈值 0.4）将相关信号聚合为事件
2. **信号强度评估**：综合平台权重、排名位置、出现频次、跨平台覆盖
3. **因果推理**：基于时间先后和语义关联，推断事件间的因果关系（A 导致 B）
4. **增量检测**：24 小时滑动窗口，检测新上榜/排名变化/下榜事件

### 4.6 反爬与限流策略

- 请求间隔 100ms，并发抓取错开
- 最大重试 2 次，退避 3-5 秒随机延迟
- UA 伪装：热榜用桌面 Chrome，深度爬取按平台区分移动端/桌面端
- 每事件最多 3 个关键词，每关键词每平台最多 50 条评论

## 5. 视频理解与多模态分析

### 5.1 设计理念

视频内容的风险隐藏在画面、声音、文字多个模态中，且可能仅出现在极短的画面中（如闪帧）。VibeUtopia 采用**全链路降级容错 + 多模态融合加权**的设计，确保不遗漏任何风险信号。

### 5.2 视频处理完整流程

### 5.3 关键帧提取详解

**SceneDetect + OpenCV 的配合方式**：

1. SceneDetect 的 `ContentDetector` 扫描视频，识别场景切换点（基于帧间差异超过阈值 27.0）
2. 输出场景列表 `[(start_frame, end_frame), ...]`
3. 对每个场景，计算中间帧号 `mid = (start + end) // 2`
4. OpenCV 的 `VideoCapture.set(CAP_PROP_POS_FRAMES)` 定位到该帧，读取并缩放保存
5. 如果检测到的场景少于 3 个，自动补充固定间隔帧

**pHash 去重**：

- 将帧缩放到 8x8 灰度图
- 与均值比较生成 64 位哈希
- 汉明距离 < 8 视为重复帧
- 最终限制最多 50 帧，超出均匀采样

### 5.4 音频转写双引擎

| 引擎 | 场景 | 特点 |
|------|------|------|
| Faster-Whisper（本地） | 默认 | base 模型 + CPU int8 量化，VAD 过滤静音段，最短片段 2 秒 |
| Paraformer（阿里云端） | 增强模式 | 支持最长 3 小时长音频，说话人分离，句子级/词级时间戳 |

音频提取流程：FFmpeg 从视频提取音频为 WAV（16kHz, 单声道, PCM 16bit）。如果视频同目录已有音频文件（mp3/wav/aac/m4a/flac），直接复用，避免重复提取。

### 5.5 细粒度视频理解管线

解决"几帧定生死"的漏检问题，采用**先密后筛**策略：

```
1fps 全量抽帧（最多1200帧）
        │
        ▼
多尺度帧差异评分（借鉴 ActionFormer regression_range）
  ├── 窗口1（1帧）：检测闪帧
  ├── 窗口3（3帧）：检测极短暂画面（0.1-0.3秒）
  ├── 窗口10（10帧）：检测短暂画面（0.3-1秒）
  └── 窗口30（30帧）：检测中等画面（1-3秒）
        │
        ▼
异常帧分层筛选
  ├── 高异常帧（score >= 0.7）：必审
  └── 低异常帧（0.3 <= score < 0.7）：每5帧抽审1帧
        │
        ▼
4 个专项检测模块（并行）
  ├── 地图完整性审核：缺失台湾/南海诸岛等 → 风险 +30
  ├── 代码溯源检测：视频中的代码是否来自开源项目 → 风险 +20
  ├── 敏感符号检测：争议性标志/旗帜/手势 → 风险 +15
  └── 时序异常检测：短暂异常画面 → 风险 +10
```

**异常评分公式**：

对每个帧 i，在多个窗口 w 下计算与前后帧的差异：

```
window_anomaly = max(diff(i, i-w), diff(i, i+w)) × (1 / √w)
anomaly_score = max over all windows
```

### 5.6 跨模态冲突检测

三模态交叉校验：文案 vs 画面、文案 vs 音频、画面 vs 音频。

将三模态内容送入 LLM，检测：
- 内容矛盾（文案说正面，画面展示负面）
- 隐藏风险（表面无害，组合后产生歧义）
- 信息不一致（字幕与口述内容不同）

有隐藏风险 +15，冲突分数 >50 则 +10。LLM 失败时降级为关键词冲突检测。

## 6. 人格系统

### 6.1 设计理念

仿真的真实性取决于 Agent 人格的真实性。VibeUtopia 采用 **7 层人格架构 + 3 级生成质量**，从人口统计到叙事风格逐层构建，确保每个 Agent 都有独特且自洽的行为模式。

### 6.2 七层人格结构

| 层级 | 名称 | 内容 | 影响行为 |
|------|------|------|---------|
| L1 | 人口统计 | 年龄、性别、学历、职业、收入、居住地 | 基础属性，影响后续所有层 |
| L2 | 价值观与性格 | 政治立场、消费主义、民族主义、平等主义、环保主义 | 立场选择、内容偏好 |
| L3 | 知识背景 | 专业领域、爱好、认知水平、信息源 | 话题参与度、观点深度 |
| L4 | 行为模式 | 表达风格、互动偏好、冲突风格、活跃时段 | 发帖/评论/点赞概率 |
| L5 | 自我审查 | 审查程度、敏感触发词、禁忌话题 | 是否发言、措辞调整 |
| L6 | 社会关系 | 影响力等级、群体认同、从众性、领导力 | 传播力、阵营归属 |
| L7 | 叙事与演化 | 情绪基线、近期经历、人格趋势、韧性 | 表达方式、情绪倾向 |

### 6.3 三级人格生成

| 级别 | 方法 | 深度 | 成本 | 适用场景 |
|------|------|------|------|---------|
| A 级 | AI 访谈生成器 | 6 轮结构化访谈，数万字人生故事 | 高 | KOL/关键影响者 |
| B 级 | CGSS 采样 + LLM 丰富 | 千字故事 | 中 | 普通活跃用户 |
| C 级 | 模板变体 | 百字梗概 | 极低 | 背景填充用户 |

**A 级 AI 访谈流程**：

```
6 轮结构化访谈
  第1轮：童年与家庭 → 早期价值观形成
  第2轮：教育与成长 → 知识体系建立
  第3轮：职业与社会 → 社会角色定位
  第4轮：社交与关系 → 人际网络构建
  第5轮：价值观与信念 → 核心立场确立
  第6轮：网络行为 → 数字人格映射
        │
        ▼
提取 7 层人格 + Big Five 人格特质 + 初始记忆
```

**B 级 CGSS 采样**：按中国综合社会调查（CGSS）的人口统计权重采样 L1，LLM 推理 L2-L7。

**C 级模板变体**：从原型模板库（20+ 原型）选择基础模板，随机参数变体生成。

### 6.4 人格质量校验

**5 条硬规则**（不一致自动修复）：

1. 高学历 + 低认知水平 → 提升认知
2. 低收入 + 高消费倾向 → 调整消费观
3. 激进表达风格 + 潜水互动偏好 → 调整表达
4. 高自我审查 + 无敏感触发词 → 补充触发词
5. 积极情绪基线 + 负面近期经历 → 调整基线

**LLM 软校验**：让 LLM 评估 7 层人格自洽性。

综合评分 = 硬规则 60% + LLM 40%

### 6.5 社会关系网络生成

4 步算法：

1. **平台内小世界网络**：Watts-Strogatz 模型（k=4, beta=0.3），模拟真实社交网络的小世界特性
2. **跨平台桥接**：基于价值观余弦相似度连接不同平台的相似 Agent
3. **对立关系注入**：价值观差异大的 Agent 建立 oppose 关系
4. **权力节点生成**：5% 的 Agent 获得大量 follow 关系 + mentor 关系

5 种关系类型：follow / friend / oppose / mentor / same_org

### 6.6 图谱注入

- **L3 知识注入**：根据 Agent 职业和关注点，从 Neo4j 图谱搜索相关实体，注入信息源和知识领域
- **L6 社会关系注入**：根据关注领域搜索相关人物/组织，注入 KOL 关注列表和社交圈

## 7. 记忆系统

### 7.1 设计理念

基于 Stanford Generative Agents 论文的记忆架构，让 Agent 拥有记忆、反思和规划能力，使仿真行为更加真实。

### 7.2 三层记忆架构

| 层级 | 存储 | 内容 | 生命周期 |
|------|------|------|---------|
| 工作记忆 | 内存字典 | 当前分析上下文 | 任务结束后释放 |
| 情景记忆 | SQLite AgentMemory 表 | Agent 经历的事件 | 按权重衰减，半衰期 7 天 |
| 语义记忆 | SQLite AgentMemory 表 | LLM 从情景记忆提炼的长期认知 | 权重 0.8，较持久 |

**遗忘机制**：指数衰减 `weight = exp(-0.693 × age_days / half_life_days)`，超限按权重淘汰。

### 7.3 Memory Stream 向量存储

基于 ChromaDB 的向量存储，支持**三因子检索**：

| 因子 | 权重 | 计算方式 |
|------|------|---------|
| Recency（时效性） | 0.5 | `exp(-0.05 × hours_elapsed)` |
| Importance（重要性） | 0.3 | 存储时标注的 0-1 评分 |
| Relevance（相关性） | 0.2 | ChromaDB cosine 相似度 |

三种记忆类型：observation（观察）/ reflection（反思）/ plan（计划）

### 7.4 反思引擎

基于 Stanford Generative Agents 论文实现：

1. **触发条件**：累积未反射的 observation 记忆重要性之和 >= 10.0
2. **执行流程**：
   - 获取未反射的 observation 记忆
   - LLM 生成 2-3 个反思问题（如"我为什么对这类话题总是愤怒？"）
   - 对每个问题检索相关记忆
   - LLM 生成反思内容（200-400 字）
   - 评估反思重要性（0-1）
   - 批量存储 reflection 记忆

### 7.5 记忆初始化

将 Life Story 转换为 Memory Stream 初始条目：

- **observation 记忆**：从人生故事提取 5-15 个关键事件
- **reflection 记忆**：提取 3-8 个价值观反思
- **plan 记忆**：提取 3-6 个日常习惯和计划

## 9. 舆情仿真引擎

### 9.1 设计理念

Tick 驱动的多 Agent 社交仿真，模拟内容发布后在多个平台上的传播过程。通过不同层级的 Agent（LLM 驱动 vs 规则驱动）在成本和真实性之间取得平衡。

### 9.2 引擎架构

```
SimulationEngine（主引擎）
    │
    ├── TimeModel（时间模型）
    │   └── 8 时段制（深夜0.1 → 晚间0.9 活跃度）
    │
    ├── MessageBus（消息总线）
    │   └── 5 通道 asyncio.Queue
    │       ├── platform_feed    平台内容流
    │       ├── agent_actions    Agent 行为
    │       ├── system_events    系统事件
    │       ├── monitoring       监控数据
    │       └── intervention     干预指令
    │
    ├── Agent 层级体系
    │   ├── A 层：管理 Agent（Director/Watcher/Guardian）
    │   ├── B 层：市民 Agent（LLM 驱动，感知-思考-行动）
    │   ├── C 层：功能 Agent（规则引擎，纯规则无 LLM）
    │   └── GroupAgent（1 个代表 10-100 个相似个体，蒙特卡洛采样）
    │
    ├── 平台模拟器（5 个）
    │   ├── 微博模拟器
    │   ├── B站模拟器
    │   ├── 小红书模拟器
    │   ├── 知乎模拟器
    │   └── 抖音模拟器
    │
    ├── 传播动力学模块
    │   ├── SpreadModel（6 阶段传播模型）
    │   ├── PropagationTree（传播树）
    │   ├── Polarization（极化检测）
    │   └── InfluenceQuantifier（影响力量化）
    │
    └── 监控器
        ├── Director（调度决策：节奏控制/事件注入/结束判断）
        ├── Watcher（实时监控：态势感知/异常检测）
        └── Guardian（应急干预：异常行为干预）
```

### 9.3 Tick 执行流程

每个 Tick 执行 10 步：

```
1. 推进时间 → TimeModel.advance()
2. Director 调度决策（每12 tick）
3. B 层 Agent 行为（LLM 驱动，随机采样，Semaphore=3 并发控制）
4. C 层 Agent 行为（规则引擎批量处理）
5. 平台处理 action → 更新帖子/评论/点赞/转发/浏览
6. 传播模型更新 → 传播树/极化指数/传播动能
7. Watcher 监控（每6 tick）→ Guardian 干预
8. 记录 tick → SimulationTick 数据结构
9. 持久化 → SimulationRecord 写入数据库
10. 传播阶段变更通知 → WebSocket 推送前端
```

### 9.4 Agent 决策机制

#### B 级 Agent（LLM 驱动）

感知-思考-行动循环：

1. **感知**：获取 Agent 7 层人格 + 平台环境 + Feed 内容
2. **思考**：LLM 根据人格特征推理行为（"作为一个 35 岁的中学教师，看到这条内容我会..."）
3. **行动**：输出 1-3 个行为（post/comment/like/share/view），每个附带 reasoning
4. **兜底**：LLM 失败时生成 view 行为

#### C 级 Agent（规则引擎）

纯规则决策，无 LLM 调用：

| 行为 | 概率计算 |
|------|---------|
| 点赞 | 基础 0.2，受 L2.social_justice 和内容情感影响 |
| 评论 | 互动概率 × 0.3，使用 5 种表达风格模板 |
| 转发 | 由 L6.influence_level 决定（潜水者 0.02 → KOL 0.3） |
| 发帖 | 由 L4.interaction_preference 决定（潜水 0.05 → 创作者 0.5） |

#### GroupAgent（蒙特卡洛采样）

1. **perceive**：计算群组对内容的关注程度（立场对齐 × 活跃度）
2. **think**：蒙特卡洛采样每个个体的反应
3. **act**：将群组反应转化为代表性平台行为

### 9.5 仿真规模

| 级别 | Agent 数 | 仿真时长 | 成本 | 适用场景 |
|------|---------|---------|------|---------|
| lightweight | 100 | 6 小时 | < 1 元 | 快速预判 |
| standard | 500 | 24 小时 | ~5 元 | 常规分析 |
| deep | 2000 | 48 小时 | ~20 元 | 深度分析 |
| massive | 10000 | 72 小时 | ~100 元 | 关键内容 |

## 10. 传播动力学模型

### 10.1 六阶段传播模型

| 阶段 | 触发条件 | 描述 |
|------|---------|------|
| SEED（种子注入） | reach < 10 | 种子事件刚注入，少数大 V/活跃用户率先反应 |
| PRIMARY（初级传播） | reach 10-100, 极化 < 0.3 | 高影响力 Agent 率先反应 |
| COMMUNITY（社群扩散） | reach 100+, 深度 >= 2 | 通过关注链/超话/兴趣圈传播 |
| POLARIZATION（立场分化） | 极化 >= 0.4 | 评论区对立观点，中立方被迫选边 |
| MAINSTREAM（主流化） | 动能 > 3.0, reach > 500 | 上热搜 → 大众参与 → 主流媒体关注 |
| FADING（消退） | 动能连续 3 tick 下降 | 争议降温，新热点替代 |

### 10.2 传播动能计算

```
传播动能 = 互动增速 × 情感强度

互动增速 = (当前互动量 - 上 tick 互动量) / 上 tick 互动量
情感强度 = 负面情感占比 × 0.7 + 正面情感占比 × 0.3
```

### 10.3 极化指数计算

使用**双峰性系数（Bimodality Coefficient）**：

```
BC = (n-1)² × (skewness² + 1) / ((n-2)(n-3) × kurtosis)
```

| BC 值 | 分布形态 | 含义 |
|-------|---------|------|
| < 0.555 | 单峰 | 共识 |
| >= 0.555 | 双峰 | 极化 |

5 级预警：无极化(<0.2) → 轻微(<0.4) → 中度(<0.6) → 高度(<0.8) → 极端(>=0.8)

### 10.4 舆论转折预测

5 种转折类型：升级 / 缓解 / 反转 / 碎片化 / 共识形成

基于 3 个信号维度：
- 极化变化率 + 加速度（加速上升→升级，高位减速→缓解）
- 传播阶段（社群扩散→立场分化→可能反转）
- 阵营结构（中立群体过少→碎片化风险）

转折点检测：滑动窗口（大小 3）计算局部变化率，超过阈值 0.1 时标记。

### 10.5 传播影响因素量化

三因素加权模型：

| 因素 | 权重 | 子因素 |
|------|------|--------|
| Agent 因素 | 40% | 影响力(0.4) + 活跃度(0.2) + 立场强度(0.2) + 情绪唤醒(0.2) |
| 内容因素 | 30% | 情感强度(0.3) + 争议性(0.3) + 共鸣度(0.4) |
| 平台因素 | 30% | 算法权重(0.3) + 热搜放大(0.2) + 社群密度(0.2) + 情绪放大(0.3) |

5 个平台各有独立参数（如抖音算法权重 0.7、情绪放大 1.8；知乎算法权重 0.3、情绪放大 0.8）。

## 11. 风险评估体系

### 11.1 七维风险评估

| 维度 | 默认权重 | 说明 |
|------|---------|------|
| 政治敏感 | 1.5 | 涉及政治人物/事件/政策的敏感性 |
| 法律合规 | 1.5 | 违反法律法规的风险 |
| 民族宗教 | 1.3 | 涉及民族/宗教的敏感性 |
| 事实错误 | 1.3 | 事实性错误或虚假信息 |
| 平台禁区 | 1.0 | 违反平台社区规范 |
| 情绪极化 | 1.0 | 可能引发情绪对立 |
| 价值观倾向 | 1.0 | 价值观争议性 |
| 性别议题 | 0.8 | 性别相关争议 |
| 道德伦理 | 0.8 | 道德伦理争议 |
| 群体冒犯 | 1.0 | 对特定群体的冒犯性 |
| 时事踩雷 | 1.0 | 与当前热点事件的踩雷风险 |

**红线维度放大**：政治敏感/法律合规/民族宗教/事实错误/平台禁区分数放大 1.5 倍。

**整体评分规则**：
- 任一维度 HIGH → 整体不低于 50
- 多维度同时 HIGH → 额外 +15
- 加权评分后映射到 0-100

### 11.2 证据链构建

每个风险项关联证据链：风险句子 → 证据来源 → 推理过程 → 置信度

### 11.3 置信度计算

四因子置信度模型：

| 因子 | 权重 | 说明 |
|------|------|------|
| 数据质量 | 25% | 输入数据的完整性（转写质量、帧覆盖度） |
| 评估一致性 | 25% | 多次评估结果的一致程度 |
| 证据充分性 | 25% | 证据链的完整性和交叉验证数 |
| 平台验证 | 25% | 信号关联和平台仿真的验证程度 |

### 11.4 动态权重调整

基于信号和图谱动态调整维度权重：

- 信号关联度高 → 相关维度权重提升
- 实体风险链传播 → 下游维度权重提升
- 人生故事关联 → 特质风险映射调整

## 13. AI 多模型路由

### 13.1 设计理念

不同任务需要不同能力的模型：风险评估需要强推理，文本改写只需快速生成，视觉理解需要多模态能力。VibeUtopia 通过任务类型→模型级别→厂商路由的三层映射，实现智能调度。

### 13.2 三层路由架构

```
任务类型 → 模型级别 → 厂商/模型
   │           │          │
   ▼           ▼          ▼
risk_assessment → advanced → Qwen-Max
text_understanding → standard → DeepSeek-v4
rewrite → lite → Qwen-Turbo
```

### 13.3 任务级别映射

| 级别 | 任务类型 | 典型模型 |
|------|---------|---------|
| advanced | life_story_generation, persona_simulation, multimodal_analysis, risk_assessment | Qwen-Max, DeepSeek-v4 |
| standard | default, text_understanding, platform_simulation | DeepSeek-v4-flash, Qwen-Plus |
| lite | rewrite, json_extraction | Qwen-Turbo, DeepSeek-v3 |

### 13.4 四级 Fallback 策略

```
1. 同厂商同级别模型
2. 同厂商低级别模型
3. 跨厂商同级别模型
4. 跨厂商低级别模型
```

### 13.5 Key 池管理

- 多 Key 逗号分隔配置，轮换使用
- 429 限流自动冷却 300 秒
- 冷却结束自动回切
- `get_key_pool_status()` 监控每个 Key 的可用状态/调用次数/错误次数/剩余冷却时间

### 13.6 并发控制

| 调用类型 | 信号量 | 说明 |
|---------|--------|------|
| 文本模型 | 10 | _llm_semaphore |
| 视觉模型 | 5 | _vlm_semaphore |
| 图像生成 | 3 | _image_gen_semaphore |

### 13.7 运行时覆盖

`set_override(provider, model)` 无需重启服务即可切换模型。

## 16. 可恢复分析管线

### 16.1 设计理念

长视频分析可能因 API 限流/网络中断而失败。ResumableAnalyzer 提供 8 阶段检查点机制，中断后可从检查点恢复。

### 16.2 八阶段管道

```
1. 文案提取 → 检查点
2. 文本风险评估 → 检查点
3. 信号关联 → 检查点
4. 实体风险链 → 检查点
5. 平台仿真 → 检查点
6. 跨模态检测 → 检查点
7. 细粒度视频理解 → 检查点（帧级细粒度）
8. 报告生成 → 完成
```

### 16.3 限流感知

- 检测到 429 限流时暂停并保存状态
- 递增等待后重试（最多 5 次）
- 视频分析中最小恢复单元为单帧

## 17. 博主知识引擎

### 17.1 设计理念

为博主建立全视频知识索引，支持知识问答、内容检索、画像生成、矛盾检测和时间线分析。

### 17.2 索引构建流程

```
博主视频列表
    │
    ▼
视频切分（30秒固定时长 → 片段，每片段最多10帧）
    │
    ▼
多模态处理（并行）
  ├── VLM 视觉描述
  ├── ASR 转录
  └── OCR 文字识别
    │
    ▼
LLM 实体抽取（人物/组织/概念/产品/地点/话题/观点）
    │
    ▼
知识图谱构建（跨视频实体对齐合并）
    │
    ▼
向量存储（ChromaDB，支持语义检索）
    │
    ▼
增量索引（新视频无需重建已有索引）
```

### 17.3 核心能力

| 能力 | API | 说明 |
|------|-----|------|
| 知识问答 | `/ask` | 基于博主全部视频内容回答问题 |

| 矛盾检测 | `/contradictions` | 检测博主观点矛盾 |

## 18. 反事实仿真

### 18.1 设计理念

"如果我修改了这段文案，舆论反应会怎样变化？"——反事实仿真允许用户修改内容后重新仿真，对比修改前后的传播差异。

### 18.2 流程

```
原始内容 → 原始仿真结果
    │
    ▼
用户修改内容（改写风险句子）
    │
    ▼
修改后内容 → 重新仿真
    │
    ▼
对比分析：传播路径/极化程度/风险分数变化
```

## 19. 系统降级与容错

### 19.1 全链路降级策略

| 模块 | 首选 | 备选 | 兜底 |
|------|------|------|------|
| 数据库 | MySQL | SQLite | -- |
| 图数据库 | Neo4j | 内存字典 + MySQL | -- |
| 向量检索 | ChromaDB | MySQL 关键词检索 | -- |
| 关键帧提取 | SceneDetect + OpenCV | FFmpeg 固定间隔 | OpenCV 逐帧 |
| 音频转写 | Faster-Whisper | Paraformer 云端 | -- |
| OCR | VLM API | -- | -- |
| 画面风险 | VLM 视觉模型 | -- | 文件大小启发式 |
| Agent 决策 | LLM 驱动 | -- | 默认 view 行为 |
| 情感标注 | LLM 批量分析 | -- | 规则兜底 |
| 跨模态检测 | LLM 分析 | -- | 关键词冲突检测 |
| HTTP 客户端 | httpx | urllib | -- |

### 19.2 错误处理原则

- 所有外部调用（API/文件 IO/数据库）必须有错误处理
- 错误必须向上传播，禁止静默吞异常
- 跨模块调用失败必须通知上层
- 关键错误必须触发报警或通知用户
