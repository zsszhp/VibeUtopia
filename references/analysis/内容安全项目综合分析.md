## 一、各项目概述

### 1.1 Sensitive-lexicon

| 属性 | 说明 |
|------|------|
| GitHub | https://github.com/Konsheng/Sensitive-lexicon |
| 许可证 | MIT |
| 项目类型 | 中文敏感词库集合 + Go 检测服务 |
| 核心定位 | 为中文内容审核场景提供**词库基础设施**——一个持续更新的、覆盖政治/色情/暴恐/赌博/毒品/涉枪涉爆/贪腐/民生/非法网址等多领域的敏感词词典资源 |

**核心功能：**

- **多分类词库**：`Vocabulary/` 目录下按领域组织了 15 个词库文件，涵盖政治类型、色情词库、暴恐词库、广告类型、贪腐词库、涉枪涉爆、COVID-19、民生、GFW 补充、非法网址、新思想启蒙等，总计数万条词条
- **变体词覆盖**：词库中大量收录了谐音（如"法lg"→法轮功）、拆字（如"氵去车仑"）、拼音缩写（如"xjp"）、符号插入（如"法x功"）等绕过审核的变体形式
- **第三方兼容格式**：`ThirdPartyCompatibleFormats/` 目录提供了 TrChat 等平台的 JSON 格式适配
- **Go 检测服务**（dev 分支）：提供基于 Go 的 REST API 服务，支持 `/detect`、`/contains`、`/reload`、`/health` 端点，具备模糊匹配与词库热加载能力，可通过 Docker 部署
- **CI/CD**：GitHub Actions 自动打包发布，Tag 触发压缩构建

**目标用户**：需要在中文内容审核场景中快速集成敏感词过滤能力的开发者和内容审核者。

## 二、内容安全的不同技术路线对比

两个项目代表了内容安全领域的两条截然不同的技术路线，它们在方法论、适用场景、优劣势上形成鲜明对照：

### 2.1 路线对比总览

| 维度 | Sensitive-lexicon（基于规则/词库） | content-moderation-deep-learning（基于深度学习） |
|------|--------------------------------------|--------------------------------------------------|
| **方法论** | 人工/社区维护的敏感词词典 + 字符串匹配算法 | 深度神经网络（CNN/Transformer/多模态融合）自动学习违规模式 |
| **知识来源** | 人工标注的显式知识（词表） | 数据驱动的隐式知识（模型权重） |
| **可解释性** | 高——命中哪个词、哪个类别一目了然 | 低——模型决策过程为黑盒，难以追溯具体触发原因 |
| **语义理解** | 无——纯字面匹配，无法理解语境、反讽、隐喻 | 强——能捕获语义层面的违规内容 |
| **变体检测** | 依赖人工收录变体词，覆盖有限但精准 | 模型可自动泛化到未见过的变体形式 |
| **多模态能力** | 仅支持文本 | 覆盖文本、图像、音频、视频四种模态 |
| **部署成本** | 极低——纯文本文件，毫秒级匹配 | 高——需要 GPU 推理资源，模型训练成本大 |
| **更新维护** | 需人工持续更新词库，响应新词慢 | 模型重训练周期长，但可通过微调适应新场景 |
| **误报控制** | 难——"杀毒软件"命中"杀"字类误报常见 | 相对好——语义理解可区分上下文 |
| **漏报风险** | 规避手段（谐音/拆字/拼音）易绕过 | 对抗样本和新型违规模式仍可能漏报 |
| **语言覆盖** | 仅中文 | 多语言（以英文为主，覆盖多语种数据集） |
| **实时性** | 毫秒级响应 | 推理延迟取决于模型大小和硬件 |

### 2.2 技术路线的本质差异

```
┌─────────────────────────────────────────────────────────────────┐
│                    内容安全技术路线光谱                           │
│                                                                 │
│  规则驱动 ◄──────────────────────────────────────────► 数据驱动  │
│                                                                 │
│  Sensitive-lexicon                              content-moderation
│  ┌──────────────┐                               ┌──────────────┐
│  │ 人工词库     │                               │ 深度学习模型 │
│  │ 字符串匹配   │                               │ 多模态融合   │
│  │ 确定性规则   │                               │ 概率性预测   │
│  └──────────────┘                               └──────────────┘
│       ▲                                               ▲
│       │                                               │
│  高可解释性                                       高泛化能力
│  低部署成本                                       高语义理解
│  快速响应                                         多模态覆盖
│  无语义理解                                       低可解释性
│  易被绕过                                         高部署成本
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 互补关系

两条路线并非对立，而是**天然互补**：

1. **词库方案是深度学习方案的高效前置过滤器**——先用词库在毫秒级完成确定性拦截，再用模型处理语义层面的疑难 case
2. **词库为模型提供训练数据**——敏感词库可直接作为标注数据的一部分，辅助模型训练
3. **模型辅助词库更新**——深度学习模型可自动发现新型违规模式，反馈到词库中持续扩充
4. **词库兜底模型盲区**——对于模型置信度低的边界 case，词库匹配可作为确定性兜底

## 三、各项目的技术实现特点

### 3.1 Sensitive-lexicon 技术特点

#### 3.1.1 多维度分类词库体系

词库按领域精细分类，每个类别对应独立文件，便于按需加载：

| 词库文件 | 覆盖领域 | 词条特征 |
|----------|----------|----------|
| 政治类型.txt | 政治人物、政治体制、政治事件 | 含大量变体词（谐音、拆字、拼音缩写） |
| 色情词库.txt / 色情类型.txt | 色情、淫秽内容 | 直白词汇为主 |
| 暴恐词库.txt | 邪教、恐怖主义 | 含宗教极端、自残等 |
| 广告类型.txt | 广告、色情服务 | 混合了广告词和色情服务词 |
| 贪腐词库.txt | 贪污腐败、政治讽刺 | 含大量谐音变体 |
| 涉枪涉爆.txt | 武器、爆炸物制作 | 含制作方法类词条 |
| COVID-19词库.txt | 疫情相关敏感词 | 时效性强，含特定事件词 |
| GFW补充词库.txt | 防火墙相关 | 含政治事件日期、网址等 |
| 非法网址.txt | 违规网站域名 | 纯 URL 列表 |
| 民生词库.txt | 民生事件、药物毒品 | 混合类词库 |
| 新思想启蒙.txt | 网络亚文化术语 | 如"力工梭哈"等新兴词汇 |

#### 3.1.2 变体词对抗策略

词库中大量收录了用户绕过审核的常见变体形式，体现了对中文互联网审核对抗的深刻理解：

- **拼音缩写**：`xjp`、`flg`、`gcd`
- **谐音替换**：`法lg`、`供铲裆`、`氵去车仑`
- **拆字编码**：`三去车仑`、`车仑工力`
- **符号插入**：`法x功`、`法o功`、`法0功`
- **繁简混用**：`習近平`、`阿賓`
- **英文混编**：`falungong`、`dajiyuan`、`tuidang`

#### 3.1.3 Go 检测服务（dev 分支）

提供了生产级的检测服务化方案：

- **REST API**：`/detect`（检测）、`/contains`（判断是否包含）、`/reload`（热加载词库）、`/health`（健康检查）
- **模糊匹配**：支持 N-gram 编辑距离匹配，通过环境变量 `FUZZY_MIN_NGRAM`、`FUZZY_MAX_NGRAM`、`FUZZY_MAX_DISTANCE` 配置
- **词库热加载**：`/reload` 端点支持不重启服务更新词库
- **Docker 部署**：提供官方 Docker 镜像，一键启动

#### 3.1.4 第三方格式适配

`ThirdPartyCompatibleFormats/TrChat/SensitiveLexicon.json` 将词库转换为 TrChat 插件的 JSON 格式，包含 `lastUpdateDate` 和 `words` 数组字段，体现了对生态兼容性的考虑。

### 3.2 content-moderation-deep-learning 技术特点

#### 3.2.1 多模态审核技术全景

该项目以学术索引的形式，系统梳理了深度学习在内容审核中的技术演进：

**图像审核技术演进：**
- 早期：SVM + 手工特征（HoG、DCT）→ 精度有限
- 中期：CNN 迁移学习（InceptionV3、MobileNet、VGG16）→ 精度提升
- 当前 SOTA：Vision Transformer（ViT、ConvNeXT、EfficientNet）→ ICASSP 2023 论文验证

**视频审核技术演进：**
- 帧级分析：CNN 逐帧分类 → 效率低
- 时序建模：CNN + LSTM/GRU → 捕获时序信息
- 3D 卷积：I3D、SlowFast、X3D → 端到端时空建模
- Transformer：TimeSformer、ViViT、VideoMAE → 当前 SOTA

**多模态融合架构：**
- 同步多模态：CLIP（图像+文本）、VATT（视频+音频+文本）、Data2vec（语音+视觉+语言）
- 异步多模态：OmniMAE（图像+视频）、OMNIVORE（图像+视频+深度图）、PolyViT（图像+视频+音频）

**文本审核技术演进：**
- 传统：TF-IDF + MLP/SVM → 无法理解语义
- 深度学习：TextCNN、BiLSTM → 有限上下文
- 预训练模型：BERT、GPT → 强语义理解
- 最新：LLM 辅助标注（2025 年野生动物贸易检测论文）

#### 3.2.2 垂直领域深度覆盖

项目在以下垂直领域有深入的文献覆盖：

- **电影内容分级**：从 2017 到 2022 年的 9 篇论文，覆盖暴力/色情/毒品/粗俗语言的多标签分类
- **裸露检测**：ICASSP 2023 的 SOTA 比较分析，对比了 CNN 和 Transformer 在 LSPD、Nudenet、NDPI2k 数据集上的表现
- **野生动物犯罪检测**：2018-2025 年的 12 篇论文，覆盖在线交易检测、3D X 光安检、VLM 分析等前沿方向
- **社交媒体制**：包括韩国仇恨言论数据集的阈值优化研究、YouTube 儿童内容安全检测等

#### 3.2.3 数据集资源丰富

整理了 16 个公开数据集，涵盖：

| 模态 | 数据集 | 标注类型 |
|------|--------|----------|
| 图像 | Nudenet、Adult Content、Substance Use | 二分类（违规/正常） |
| 视频 | NDPI2k、NDPI800、Violent Scenes Dataset、VSD2014 | 多分类（暴力类型/色情程度） |
| 多模态 | LSPD、MM-Trailer、Movienet | 分类+检测 |
| 文本 | Movie Script Severity、Movie Script Dataset | 严重程度分级 |

#### 3.2.4 工具生态

列出了 9 个可直接使用的工具，从文本过滤（safetext）到视频处理（PySceneDetect、MoviePy）再到 NSFW 检测（LAION Safety Toolkit），形成了完整的工具链。

## 四、对 VibeUtopia 项目风控系统的参考价值

### 4.1 VibeUtopia 当前风控架构

VibeUtopia 当前的风险评估完全依赖 **LLM Prompt 驱动**的十一维评估体系：

```
文本输入 → LLM Prompt（risk_assessment_v2.txt）→ JSON 结构化输出
```

十一维度：政治敏感、法律合规、民族宗教、事实错误、平台禁区、性别议题、群体冒犯、道德伦理、时事踩雷、情绪极化、价值观倾向

**当前优势**：语义理解强、可解释性好（evidence 字段引用原文）、维度交叉分析

**当前短板**：无确定性兜底、无词库快速预筛、无图像/视频的本地模型审核能力、完全依赖 LLM 推理延迟和成本

### 4.2 Sensitive-lexicon 的参考价值

#### 4.2.1 词库预筛层——确定性兜底

**建议**：在 LLM 风险评估之前，增加基于 Sensitive-lexicon 词库的**确定性预筛层**：

```
文本输入 → 词库预筛（Trie/DFA 匹配）→ 命中结果 → LLM 语义评估 → 综合判定
                                    ↓
                              确定性拦截（红线词）
```

- **红线词直接拦截**：涉枪涉爆制作方法、暴恐煽动等红线内容，词库命中即可直接标记为 HIGH，无需等待 LLM 判断
- **降低 LLM 调用成本**：词库初筛可过滤大量明显的违规内容，减少 LLM 调用次数
- **加速响应时间**：Trie 树匹配毫秒级完成，用户可立即看到初步结果

#### 4.2.2 变体词检测——对抗绕过

**建议**：借鉴 Sensitive-lexicon 的变体词收录策略，在 VibeUtopia 中实现：

- **拼音归一化**：将文本转为拼音后匹配，检测 `xjp`、`flg` 等拼音缩写
- **繁简统一**：将繁体字统一转为简体后匹配
- **符号去除**：去除特殊字符后重新匹配，检测 `法x功` 等符号插入
- **拆字还原**：识别常见拆字模式并还原

#### 4.2.3 词库分类映射到十一维度

**建议**：将 Sensitive-lexicon 的词库分类映射到 VibeUtopia 的十一维度体系：

| Sensitive-lexicon 词库 | VibeUtopia 维度 |
|------------------------|-----------------|
| 政治类型.txt | 政治敏感 |
| 贪腐词库.txt | 政治敏感、道德伦理 |
| 色情词库.txt / 色情类型.txt | 道德伦理、平台禁区 |
| 暴恐词库.txt | 法律合规、道德伦理 |
| 涉枪涉爆.txt | 法律合规 |
| 广告类型.txt | 平台禁区、法律合规 |
| COVID-19词库.txt | 事实错误、时事踩雷 |
| 民生词库.txt | 群体冒犯、时事踩雷 |
| 新思想启蒙.txt | 价值观倾向 |

#### 4.2.4 Go 检测服务的参考

**建议**：参考 Sensitive-lexicon 的 Go 检测服务设计，在 VibeUtopia 中实现：

- **词库热加载 API**：无需重启服务即可更新词库
- **模糊匹配配置**：通过环境变量灵活调整匹配策略
- **健康检查端点**：监控词库服务状态

### 4.3 content-moderation-deep-learning 的参考价值

#### 4.3.1 多模态审核架构设计

**建议**：参考该项目索引的多模态架构，为 VibeUtopia V3 的多模态风控设计分层架构：

```

│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐  │

│  │        │ │ConvNeXT)│ │LLM)    │ │former) │  │
│  └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘  │
│       └───────────┴───────────┴───────────┘        │
│                    ↓                                │

```

#### 4.3.2 视频审核策略优化

**建议**：参考该项目索引的视频审核论文，优化 VibeUtopia 的视频风控：

- **场景检测前置**：使用 PySceneDetect 先切割场景，再对关键场景审核，而非逐帧扫描
- **关键帧 + 音频双轨分析**：当前 VibeUtopia 已实现关键帧提取 + OCR + 语音转录，可进一步引入 NSFW 模型对关键帧进行图像级审核
- **时序建模**：对于长视频，使用 TimeSformer/ViViT 等时序模型捕获动态违规内容

#### 4.3.3 数据集与模型选型参考

**建议**：参考该项目整理的数据集和 SOTA 模型，为 VibeUtopia 选择合适的预训练模型：

| 任务 | 推荐模型 | 参考论文 |
|------|----------|----------|
| 裸露检测 | EfficientNet-V2 / ConvNeXT | ICASSP 2023 Akyon et al. |
| 暴力检测 | ViViT / TimeSformer | VideoMAE (2022) |
| 文本毒性 | BERT-base-chinese / LLM | 多篇 |
| 多模态融合 | CLIP | Radford et al. (2021) |
| 端侧部署 | MobileNet V3 + SSD | On-Device Content Moderation (2021) |

#### 4.3.4 阈值优化策略

**建议**：参考 TruSThresh（2022 年论文）的阈值优化技术，为 VibeUtopia 的十一维评分体系设计动态阈值：

- 不同维度的阈值应不同（红线维度阈值低，动态维度阈值高）
- 阈值应随时事热度动态调整（时事踩雷维度）
- 多维度交叉时阈值应自动降低

### 4.4 综合建议：VibeUtopia 风控系统分层架构

结合两个项目的优势，建议 VibeUtopia 采用**三层风控架构**：

```
┌──────────────────────────────────────────────────────────┐
│                  第一层：确定性规则层                       │
│  基于 Sensitive-lexicon 词库的 Trie/DFA 匹配              │
│  - 红线词直接拦截（涉枪涉爆制作方法等）                    │
│  - 变体词检测（拼音/拆字/符号插入）                        │
│  - 非法网址黑名单匹配                                      │
│  - 响应时间：< 10ms                                        │
│  - 参考来源：Sensitive-lexicon                             │
├──────────────────────────────────────────────────────────┤
│                  第二层：深度学习模型层                     │
│  基于预训练模型的语义理解和多模态审核                       │
│  - 文本毒性检测（BERT/LLM）                                │
│  - 图像 NSFW/暴力检测（ViT/ConvNeXT）                     │
│  - 视频时序分析（TimeSformer）                             │
│  - 音频转写 + 文本审核                                     │
│  - 响应时间：100ms - 2s                                    │
│  - 参考来源：content-moderation-deep-learning              │
├──────────────────────────────────────────────────────────┤
│                  第三层：LLM 深度推理层                     │
│  基于 LLM 的十一维风险评估和交叉影响分析                    │
│  - 语义级风险评估（反讽/隐喻/上下文理解）                   │
│  - 维度交叉影响分析                                        │
│  - 句子级精准定位                                          │
│  - 安全改写建议                                            │
│  - 响应时间：2s - 10s                                     │
│  - 参考来源：VibeUtopia 现有架构                           │
├──────────────────────────────────────────────────────────┤
│                  融合决策层                                │
│  三层结果聚合 → 置信度加权 → 最终风险判定                   │
│  - 第一层命中 → 直接 HIGH（确定性拦截）                    │
│  - 第二层命中 → 提升 LLM 评估权重（模型辅助）              │
│  - 第三层评估 → 综合上下文给出最终判定                      │
│  - 三层均无命中 → LOW                                      │
└──────────────────────────────────────────────────────────┘
```

## 五、各自的局限性与不足

### 5.1 Sensitive-lexicon 的局限性

| 局限性 | 详细说明 | 影响程度 |
|--------|----------|----------|
| **无语义理解能力** | 纯字面匹配，无法区分"杀毒软件"和"杀人"中的"杀"字，无法识别反讽、隐喻等修辞手法 | 🔴 严重 |
| **易被新型绕过手段规避** | 虽然收录了大量变体词，但无法穷举所有可能的绕过方式（如新造词、图片隐写、零宽字符等） | 🔴 严重 |
| **误报率较高** | 缺乏上下文感知，正常文本中包含敏感词片段时容易误判（如"抗日战争"命中"战争"） | 🟡 中等 |
| **词库维护成本高** | 完全依赖人工/社区更新，新词入库滞后于实际出现时间，时效性不足 | 🟡 中等 |
| **词库质量参差不齐** | 不同词库文件存在词条重复（如色情词库与广告类型有交叉），部分词条归类不当 | 🟡 中等 |
| **仅覆盖中文** | 无法处理英文、日文等其他语言的敏感内容 | 🟡 中等 |
| **仅支持文本** | 无法处理图像、音频、视频等多模态内容 | 🔴 严重 |
| **缺乏置信度评分** | 匹配结果只有"命中/未命中"，没有概率化的置信度，不利于与模型结果融合 | 🟡 中等 |
| **Go 检测服务不成熟** | 检测服务仅在 dev 分支，主分支无代码，生产可用性存疑 | 🟡 中等 |
| **法律与伦理风险** | 词库中包含大量政治敏感词，使用需遵守当地法律法规，不当使用可能引发法律风险 | 🔴 严重 |

### 5.2 content-moderation-deep-learning 的局限性

| 局限性 | 详细说明 | 影响程度 |
|--------|----------|----------|
| **无实际代码实现** | 仅是论文/数据集/工具的索引列表，无可用代码，需要自行实现所有技术方案 | 🔴 严重 |
| **偏重英文场景** | 整理的数据集和论文以英文为主，对中文内容审核的参考价值有限 | 🟡 中等 |
| **缺乏中文社交媒体场景** | 未覆盖 B站/小红书/知乎/抖音等中国主流平台的内容审核需求 | 🔴 严重 |
| **论文索引更新滞后** | 最新论文截止到 2025 年初，缺少 2025-2026 年的最新进展（如 LLM-based 审核） | 🟡 中等 |
| **缺乏工程实践指导** | 只列出了"用什么"，没有"怎么用"的工程化指导（部署方案、性能优化、成本控制等） | 🟡 中等 |
| **模型选型缺乏基准** | 虽然列出了大量模型，但缺乏统一的基准测试对比，难以直接选型 | 🟡 中等 |
| **缺乏审核策略设计** | 未涉及审核流程设计（如多级审核、人工复审、申诉机制等） | 🟡 中等 |
| **未覆盖生成式 AI 内容** | 未涉及 AI 生成内容（Deepfake、AI 绘图等）的检测，这是当前内容安全的新挑战 | 🟡 中等 |
| **缺乏实时处理方案** | 整理的技术方案多为离线批处理，缺少流式/实时审核的工程方案 | 🟡 中等 |
| **阈值与决策策略缺失** | 虽有 TruSThresh 一篇阈值优化论文，但整体缺乏审核决策策略的系统性讨论 | 🟡 中等 |

### 5.3 两者共同的局限

| 共同局限 | 说明 |
|----------|------|
| **均不覆盖舆论仿真** | 两者都聚焦于"内容是否违规"的判定，不涉及"内容发布后可能引发的舆论反应"的预测——而这正是 VibeUtopia 的核心差异化能力 |
| **均缺乏人格模拟** | 无法模拟不同用户群体对内容的差异化反应 |
| **均无改写建议能力** | 只能判定风险，无法提供安全替代方案 |
| **均不处理跨模态风险** | 无法检测"文字正常但配图违规"或"音频正常但画面违规"的跨模态组合风险 |
| **均缺乏时效性感知** | 无法根据当前热点事件动态调整审核策略 |

## 六、总结

| 维度 | Sensitive-lexicon | content-moderation-deep-learning |
|------|-------------------|----------------------------------|
| **核心价值** | 中文敏感词库基础设施 | 多模态审核技术路线图 |
| **对 VibeUtopia 最直接的贡献** | 词库预筛层 + 变体词检测 | 多模态审核架构设计 + 模型选型 |
| **与 VibeUtopia 的互补点** | 为 LLM 评估提供确定性兜底 | 为 V3 多模态扩展提供技术路线 |
| **核心风险** | 误报率高、无语义理解 | 无代码、偏英文、缺工程指导 |
| **推荐集成优先级** | 🔴 高——可直接作为预筛层 | 🟡 中——作为 V3 规划参考 |

**核心结论**：Sensitive-lexicon 和 content-moderation-deep-learning 分别代表了内容安全的"规则驱动"和"数据驱动"两条路线。VibeUtopia 当前的 LLM 驱动方案属于更高级的"语义驱动"路线，但缺乏确定性兜底和多模态本地模型能力。建议采用**三层融合架构**（词库预筛 → 深度学习模型 → LLM 深度推理），将两条路线的优势整合到 VibeUtopia 的风控体系中，实现"确定性拦截 + 语义理解 + 深度推理"的协同防御。
