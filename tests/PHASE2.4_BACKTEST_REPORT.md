## 四、根本原因分析

### 4.1 API 配额问题

从日志中观察到：
```
模型 longcat Key1 标记为临时不可用，冷却 300 秒
模型 longcat:LongCat-Flash-Thinking-2601:0 配额耗尽
HTTP 429: {"error":{"message":"服务端模型可用容量超过限制","type":"rate_limit_error"}}
```

**影响**:
- 40% 的案例因 API 不可用而返回 0 分
- 如果排除 API 失败案例，实际准确率约为 76%（19/25 案例成功）

### 4.2 Prompt 评分规则问题

从失败案例看，模型对以下维度识别不准确：
1. **政治敏感** - 预期 75+，实际 65 分
2. **民族宗教** - 预期 80+，实际 0 分
3. **历史虚无主义** - 预期 80+，实际 0 分

可能原因：
- Prompt 中的红线维度评分规则未被严格执行
- 模型对"触碰即 HIGH 76+"的理解不足
- 维度交叉影响规则未生效

### 4.3 数据质量问题

部分案例的预期标签可能存在问题：
- "道德绑架式传播"预期 orange，但实际评估为 red（77 分）
- 这可能是因为文案中包含"诅咒式传播"等强风险信号

## 五、改进建议

### 5.1 短期措施（立即执行）

1. **修复 API 配额问题**
   - 增加 API Key 数量，实现轮换
   - 调整重试策略和冷却时间
   - 考虑降级到备用模型

2. **Prompt 规则强化**
   - 在 Prompt 开头强调红线维度评分标准
   - 添加 Few-Shot 示例，展示高风险案例的评分逻辑
   - 明确维度交叉影响的计算方式

3. **数据校验**
   - 人工审核 25 个案例的预期标签
   - 修正可能的标注错误
   - 补充案例说明和评分依据

### 5.2 中期优化（下一阶段）

1. **扩展回测案例库**
   - 当前 25 个案例，建议扩展到 50+ 个
   - 增加高风险案例比例（当前 28%）
   - 覆盖更多边缘场景

2. **Prompt 迭代优化**
   - 基于失败案例进行针对性优化
   - 使用 A/B 测试验证新 Prompt 效果
   - 建立 Prompt 版本迭代机制

3. **评估指标优化**
   - 引入更细粒度的评估维度
   - 计算各风险等级的精确率/召回率
   - 添加混淆矩阵分析
